## 審計項目與發現

### 1. truncateToolOutput 截斷邏輯 — UTF-8 字元邊界

**評分：C（需修復）**

`truncateToolOutput`（jsonl_parser.go:274-279）使用 `len(output)` 做 byte 長度比較，然後用 `output[:MaxToolOutputLength]` 做 byte 切割。這會在多位元組 UTF-8 字元的中間切斷，產生無效的 UTF-8 序列。

對比 `truncateString`（session_registry.go:346-357）正確使用 `[]rune` 轉換處理 UTF-8 邊界。

同樣的問題存在於 `serializeToolInput`（jsonl_parser.go:251-253），也是 byte 切割。

| 風險 | 說明 |
|------|------|
| 影響 | 前端收到無效 UTF-8 字串，可能導致 JSON 序列化失敗或渲染異常 |
| 嚴重度 | P2 中 |
| 建議 | 使用 `utf8.ValidString` 回退或改用 rune 切割；或使用 `strings.ToValidUTF8` 清理 |

**補充說明**：對於 tool output 場景，byte 切割的效能優於 rune 切割，且大多數 tool output 是 ASCII。若不想付 rune 轉換成本，可在 byte 切割後向前掃描至 UTF-8 字元邊界（最多回退 3 bytes）。

### 2. SetMemoryLimit 512MB 合理性

**評分：A（合理）**

512MB 作為軟上限合理：
- 本應用是背景監控服務，不是計算密集型
- `SetMemoryLimit` 是軟上限，不會 OOM kill，只促進更積極的 GC
- 搭配 eviction（2 小時）和事件數上限（500/session）形成多層防護
- 使用者可透過 `GOMEMLIMIT` 環境變數覆蓋

無需修改。

### 3. eviction 邏輯 race condition

**評分：A（安全）**

`ScanAndUpdateStatus`（session_registry.go:270）在開頭取得 `r.mu.Lock()` 寫鎖，整個迴圈（包括 eviction 的 `delete` 操作）都在鎖保護範圍內。

Go `for range` 迴圈中對 map 執行 `delete` 是語言規範允許的安全操作。

無 race condition 問題。

### 4. copy-to-new-slice 實作

**評分：A（正確）**

兩處 copy-to-new-slice 實作正確：

- `AppendEvent`（session_registry.go:370-374）：`make` 新 slice -> `copy` 尾部元素 -> 賦值替換
- `ScanAndUpdateStatus`（session_registry.go:307-309）：同樣模式

舊 backing array 的引用被完全切斷，可被 GC 回收。實作符合預期。

### 5. pprof endpoint 安全性

**評分：A（安全）**

`registerPprofEndpoint`（main.go:119-129）：
- 僅在 `CCSESSION_PPROF=1` 時啟用（嚴格字串比對）
- 伺服器綁定 `localhost:`（main.go:74），不暴露到外部網路
- 生產環境不設定此環境變數即完全不註冊路由

雙層防護（環境變數 + localhost 綁定）足夠安全。

### 6. 測試覆蓋

**評分：B（有缺口）**

| 功能 | 測試狀態 | 說明 |
|------|---------|------|
| AppendEvent eviction + copy-to-new | 有測試 | TestAppendEvent_EvictsOldestWhenExceedsMax |
| ScanAndUpdateStatus history trim | 有測試 | TestScanAndUpdateStatus_TrimsCompletedSessionHistory |
| completed 終態保護 | 有測試 | TestScanAndUpdateStatus_DoesNotRevertCompleted |
| **ScanAndUpdateStatus eviction（delete session）** | **無測試** | 缺少對 CompletedSessionEvictionTimeout 後 session 從 registry 移除的測試 |
| **truncateToolOutput** | **無測試** | 無獨立單元測試驗證截斷行為 |
| **serializeToolInput 截斷** | **無測試** | 無獨立單元測試 |
| pprof 環境變數控制 | **無測試** | main.go 函式，測試難度較高但可用 httptest |

缺少的測試項目：
- P2：ScanAndUpdateStatus eviction 測試（session 超時後應從 registry 消失）
- P2：truncateToolOutput 單元測試（含多位元組 UTF-8 邊界案例）
- P3：pprof 端點條件註冊測試

## 決策建議

**建議：可繼續推進，但 TD-001（UTF-8）應在當前版本修復。**

UTF-8 切斷問題雖然在大多數場景不會觸發（tool output 通常是 ASCII），但一旦觸發會導致 JSON 序列化失敗，影響前端顯示。修復成本低（約 5 行程式碼），建議不延後。
