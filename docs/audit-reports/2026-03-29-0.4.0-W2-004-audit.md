## 修改點逐項審核

### 修改 1：ref.read → ref.watch（第 96 行）

**評分：A**

```dart
final service = ref.watch(webSocketServiceProvider);
```

**正確性分析**：

- `ref.watch` 在 `@riverpod` Notifier 的 `build()` 中使用是標準做法。當 `webSocketServiceProvider` 重建（例如 WebSocket 斷線重連建立新 service）時，Riverpod 會自動使 ConversationNotifier invalidate 並重新執行 `build()`，從而重新訂閱新的 `messageStream`。
- 舊的 `_subscription` 在 `build()` 重新執行時由第 98 行 `_subscription?.cancel()` 正確清理。
- `ref.onDispose` 也會在 invalidate 時觸發，提供雙重清理保障。

**rebuild 頻率風險**：低。`webSocketServiceProvider` 是同步 provider，僅在 service 實例變更時觸發 rebuild，不會造成不必要的高頻重建。

**結論**：正確且必要的修改。

### 修改 2：ref.onDispose 新增 unsubscribeSession（第 115-122 行）

**評分：B**

```dart
ref.onDispose(() {
  _subscription?.cancel();
  _subscription = null;
  final currentSessionId = state.valueOrNull?.sessionId;
  if (currentSessionId != null) {
    service.unsubscribeSession(currentSessionId);
  }
});
```

**正確性分析**：

- `service` 變數透過閉包捕獲 `build()` 中 `ref.watch` 的結果。在 dispose 時，這個 service 實例仍然是有效的引用。
- `state.valueOrNull?.sessionId` 安全取值，null 時跳過 unsubscribe，避免 NPE。

**[中風險] service 閉包捕獲與 rebuild 的交互**：

當 `webSocketServiceProvider` 重建時，`build()` 重新執行。此時 `ref.onDispose` 的舊閉包會被呼叫，其中捕獲的 `service` 是舊的 service 實例。接著新的 `build()` 會註冊新的 `ref.onDispose` 捕獲新的 service。

這個行為在以下場景是正確的：
- 面板關閉（provider dispose）：呼叫最新的 onDispose，使用最新的 service 發送 unsubscribe。正確。
- WebSocket 重連（provider rebuild）：舊 onDispose 使用舊 service 發送 unsubscribe。但舊 service 的 WebSocket 連線可能已斷開，unsubscribe 訊息無法送達。新 build 中 `_resubscribeCurrentSession` 會在重連後重新訂閱。**實際影響低**，但邏輯上存在一個「向已斷線的 service 發送 unsubscribe」的無效操作。

**建議**：可在 `unsubscribeSession` 實作中加入連線狀態檢查，或在 onDispose 閉包中加入 guard。非阻塞性問題，建議記錄為低優先技術債。

### 已覆蓋場景

### [缺口] 未覆蓋場景

| 缺失測試 | 風險 | 優先級 |
|---------|------|--------|
| container.dispose() 時是否呼叫 unsubscribeSession | 這是修改 2 的核心場景（面板關閉） | P1 |
| webSocketServiceProvider rebuild 時自動重訂閱 | 這是修改 1 的核心場景 | P1 |

**說明**：現有測試僅覆蓋 `loadSession`/`leaveSession` 中的 unsubscribe 邏輯（這些在本次修改前就存在）。本次新增的兩個核心行為——「provider dispose 時 onDispose 呼叫 unsubscribeSession」和「watch 觸發自動重建」——沒有直接測試。

**建議新增測試**：

1. **dispose 時 unsubscribe**：initNotifier → loadSession → container.dispose() → verify unsubscribeSession called
2. **service rebuild 時重訂閱**：需要模擬 webSocketServiceProvider 重建，驗證新 service 的 messageStream 被重新訂閱
