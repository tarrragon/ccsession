# Phase 1 功能規格設計：ticket create 建立前重複偵測查詢機制

## 1. 功能需求分析

### 1.1 核心問題

PC-013 案例 2 揭示的問題：PM 在建立修復 Ticket 前，未查詢同版本既有的 pending tickets，導致建立出與 W3-001.2 重複的 Ticket。此問題的根因是「重複查詢」依賴人工記憶，缺乏系統化防護。

### 1.2 使用者角色與場景

**使用者角色**：PM（rosemary-project-manager）、任何使用 `/ticket create` 的代理人

**正常使用場景**：
- PM 執行 `ticket create --wave 3 --action 實作 --target 某功能` 建立新 Ticket
- 系統在儲存前自動掃描同版本 pending tickets 的標題和目標
- 若無相似 Ticket，靜默通過（無輸出）
- 若有相似 Ticket，輸出 WARNING 提示，並繼續建立（不阻止）

**異常場景**：
- 同版本 pending tickets 目錄不存在（首次建立）：靜默通過
- 版本偵測失敗：不執行重複偵測（已有 version 錯誤處理在上游）
- 相似度計算發生異常：靜默通過，不阻止建立流程

### 1.3 現有系統分析

在 `create.py` 的 `execute()` 函式中，現有建立流程順序為：

1. 解析版本、wave、seq
2. 驗證 Ticket ID 格式
3. 處理各欄位（where_files、blocked_by 等）
4. 驗證 blockedBy 引用和循環依賴
5. 儲存 Ticket 檔案
6. 輸出建立成功訊息
7. 更新 parent children（如有）
8. 輸出建立後檢查清單（`_print_create_checklist`）

**重複偵測的整合點**：步驟 4（blockedBy 驗證）之後、步驟 5（儲存）之前。在此位置：
- Ticket ID 已確定（避免對自身重複偵測）
- 欄位資料已準備好（可取 title 和 what 進行比對）
- 尚未儲存（使用者還有機會選擇放棄）

## 2. 功能規格設計

### 2.1 輸入定義

**偵測觸發條件**：
- 每次執行 `ticket create` 命令時（根任務和子任務均觸發）
- 輸入資料：
  - `version`（str）：目標版本號
  - `new_title`（str）：即將建立的 Ticket 標題（`args.title or f"{args.action} {args.target}"`）
  - `new_what`（str）：即將建立的 Ticket 目標描述（`args.what or f"{args.action} {args.target}"`）
  - `new_ticket_id`（str）：即將建立的 Ticket ID（用於排除自身）

### 2.2 輸出規格

**無相似 Ticket 時**：無任何輸出（靜默通過）

**發現相似 Ticket 時**：
```
[WARNING] 發現 {count} 個可能重複的 pending Ticket，請確認是否需要建立新 Ticket：
   - {ticket_id}: {title}
   - {ticket_id}: {title}
   建議：執行 /ticket track list 查看所有現有 Ticket 後再決定
```

**輸出位置**：在建立成功訊息之前輸出（作為前置警告）

### 2.3 正常流程設計

```
execute() 中，blockedBy 驗證通過後：
    |
    v
呼叫 detect_duplicate_tickets(version, new_title, new_what, new_ticket_id)
    |
    v
載入同版本 pending tickets（使用現有 list_tickets()）
    |
    v
過濾：排除 completed、in_progress、blocked 等非 pending 狀態
排除：自身 ticket_id（子任務建立時避免對 parent 產生誤判）
    |
    v
對每個 pending ticket 計算相似度：
  compare_ticket_similarity(new_title, new_what, candidate)
    |
    v
收集相似度 >= 閾值的 Ticket 列表
    |
    v
若列表非空 → print(format_warning(DuplicateDetectionMessages.SIMILAR_TICKETS_WARNING, ...))
若列表為空 → 靜默通過
    |
    v
返回（不影響後續儲存流程）
```

### 2.4 異常處理策略

| 異常情況 | 處理方式 | 理由 |
|---------|---------|------|
| `list_tickets()` 拋出例外 | try/except 靜默通過，不阻止建立 | 重複偵測是輔助功能，不應阻斷核心流程 |
| 相似度計算拋出例外 | 跳過該 Ticket，繼續比對其他 Ticket | 單一比對失敗不影響整體偵測 |
| pending tickets 目錄不存在 | `list_tickets()` 已返回空列表，自然通過 | 現有行為已處理 |

## 3. 邊界條件分析

### 3.1 相似度比對策略

**選擇：關鍵詞重疊比對（Jaccard 係數）**

理由：
- 不依賴外部套件（無 NLP 需求）
- 對中文 Ticket 標題友善（可字元分割或詞組比對）
- 計算複雜度低，不影響 create 效能

**實作方式**：
1. 將 `title` 和 `what` 合併為比對文字
2. 以中文字符和英文單詞為最小單位拆分為詞集合（token set）
3. 計算 Jaccard 係數：`|intersection| / |union|`
4. 設定閾值 `DUPLICATE_DETECTION_THRESHOLD = 0.3`（30% 重疊即提示）

**閾值設定理由**：
- 0.3 為寬鬆閾值，捕捉高度相似但非完全相同的 Ticket
- 過高（如 0.7）會遺漏真正重複的 Ticket（因標題用詞可能有差異）
- 過低（如 0.1）會產生大量誤報，干擾正常 create 流程

**範例**：
- `"實作 SRP 自動偵測機制"` vs `"新增 SRP 偵測功能"` → 重疊詞：SRP、偵測 → 約 0.33 → 觸發警告
- `"修復 WebSocket 連線問題"` vs `"實作重複偵測查詢"` → 無重疊 → 不觸發

### 3.2 比對範圍邊界

| 邊界條件 | 行為 |
|---------|------|
| pending tickets 為空 | 靜默通過（無相似 Ticket） |
| 只有子任務在 pending | 亦納入比對（子任務也可能重複） |
| 建立的是子任務（有 parent） | 同樣執行重複偵測（不豁免） |
| 不同 Wave 的 pending tickets | 納入比對（同版本範圍內均查詢） |
| title 為空字串 | 使用 `what` 欄位單獨比對 |
| what 為空字串 | 使用 `title` 欄位單獨比對 |
| 兩者均為空 | 跳過重複偵測（靜默通過） |

### 3.3 效能邊界

- 同版本 pending tickets 數量通常 < 50 個
- Jaccard 計算為線性時間，對少量 Ticket 無效能疑慮
- 不引入快取機制（每次 create 都應取得最新狀態）

## 4. API 介面定義

### 4.1 新增函式：`detect_duplicate_tickets`

**位置**：`create.py`（私有函式，以 `_` 開頭）

```python
def _detect_duplicate_tickets(
    version: str,
    new_title: str,
    new_what: str,
    new_ticket_id: str,
) -> None:
    """
    在建立 Ticket 前偵測可能的重複 Ticket。

    掃描同版本所有 pending 狀態的 Ticket，使用 Jaccard 係數計算
    標題和目標描述的相似度，若超過閾值則輸出 WARNING。

    此函式不影響建立流程（不拋出例外、不返回錯誤碼），
    僅提供資訊性警告供使用者參考。

    Args:
        version: 目標版本號（如 "0.1.2"）
        new_title: 即將建立的 Ticket 標題
        new_what: 即將建立的 Ticket 目標描述
        new_ticket_id: 即將建立的 Ticket ID（排除自身比對）
    """
```

**呼叫位置**：`execute()` 中，`_validate_blocked_by_references()` 通過後、`save_ticket()` 呼叫前

### 4.2 新增輔助函式：`_calculate_jaccard_similarity`

**位置**：`create.py`（私有輔助函式）

```python
def _calculate_jaccard_similarity(text_a: str, text_b: str) -> float:
    """
    計算兩段文字的 Jaccard 相似度係數。

    將文字拆分為字元和英文單詞的集合，計算集合交集與聯集的比值。

    Args:
        text_a: 第一段文字
        text_b: 第二段文字

    Returns:
        float: 相似度係數，範圍 [0.0, 1.0]
               0.0 = 完全不同，1.0 = 完全相同
    """
```

### 4.3 新增常數

**位置**：`constants.py`

```python
# ============================================================
# 重複偵測常數
# ============================================================

# Ticket 重複偵測相似度閾值
# 超過此閾值（Jaccard 係數）視為潛在重複
# 範圍：0.0 - 1.0，預設 0.3（30% 詞彙重疊）
DUPLICATE_DETECTION_THRESHOLD: float = 0.3
```

### 4.4 新增訊息常數

**位置**：`command_lifecycle_messages.py`，加入 `CreateMessages` 類別

```python
# 重複偵測警告訊息（W3-003）
DUPLICATE_TICKETS_WARNING_HEADER = (
    "[WARNING] 發現 {count} 個可能重複的 pending Ticket，請確認是否需要建立新 Ticket："
)
DUPLICATE_TICKETS_WARNING_ITEM = "   - {ticket_id}: {title}"
DUPLICATE_TICKETS_WARNING_SUGGESTION = (
    "   建議：執行 /ticket track list 查看所有現有 Ticket 後再決定"
)
```

### 4.5 模組間互動

```
execute() [create.py]
    |
    +-- 呼叫 list_tickets(version) [ticket_loader.py]
    |       → 返回同版本所有 Ticket 列表
    |
    +-- 呼叫 _detect_duplicate_tickets() [create.py, 私有]
            |
            +-- 過濾 pending 狀態 Ticket（STATUS_PENDING from constants.py）
            |
            +-- 呼叫 _calculate_jaccard_similarity() [create.py, 私有]
            |
            +-- 輸出 format_warning(CreateMessages.DUPLICATE_TICKETS_...) [messages.py]
```

## 5. 驗收標準設定

### 5.1 功能正確性驗證

| 驗收條件 | 驗證方式 |
|---------|---------|
| 建立時自動掃描同版本 pending tickets | 執行 `ticket create` 並確認有觸發 `list_tickets()` |
| 偵測到相似 Ticket 時顯示 WARNING | 預先建立相似 pending Ticket 後再 create，確認有 WARNING 輸出 |
| WARNING 包含 Ticket ID 和標題 | 確認輸出格式包含 ID 和 title |
| 不阻止建立（WARNING 後仍建立成功） | 確認 create 返回 0 且 Ticket 檔案存在 |
| 無相似 Ticket 時靜默通過 | 確認無多餘輸出 |

### 5.2 效能要求

- 重複偵測執行時間 < 100ms（對於 < 50 個 pending tickets）
- 不影響正常 create 執行時間（可接受 < 500ms 額外延遲）

### 5.3 使用者體驗期望

- WARNING 訊息清楚顯示哪些 Ticket 可能重複（ID + 標題）
- 提供後續操作建議（`/ticket track list`）
- 不因重複偵測失敗而阻斷建立流程（容錯設計）

## 6. 行為場景提取（Given-When-Then）

### 場景 1：建立前發現相似 pending Ticket（正常警告流程）

```
Given: 版本 0.1.2 存在 pending Ticket "0.1.2-W3-001.2"，標題為「實作 SRP 自動偵測機制」
When: PM 執行 ticket create --wave 3 --action 實作 --target SRP偵測功能
Then: 系統輸出 WARNING 提示「發現 1 個可能重複的 pending Ticket」
      並包含 "0.1.2-W3-001.2: 實作 SRP 自動偵測機制"
      且 Ticket 仍然建立成功（返回 exit code 0）
```

### 場景 2：無相似 Ticket 時靜默通過（正常非警告流程）

```
Given: 版本 0.1.2 的所有 pending Ticket 標題與即將建立的 Ticket 無重疊
When: PM 執行 ticket create --wave 3 --action 建立 --target WebSocket路由
Then: 系統不輸出任何重複偵測相關訊息
      Ticket 正常建立（返回 exit code 0）
```

### 場景 3：同版本無 pending Ticket（首次建立場景）

```
Given: 版本 0.1.2 的 tickets 目錄為空（或所有 Ticket 均已完成）
When: PM 執行 ticket create --wave 1 --action 建立 --target 某功能
Then: 無重複偵測 WARNING 輸出
      Ticket 正常建立（返回 exit code 0）
```

### 場景 4：建立子任務時亦執行重複偵測（子任務邊界）

```
Given: 版本 0.1.2 存在 pending Ticket，標題與子任務相似
When: PM 執行 ticket create --parent 0.1.2-W3-001 --action 實作 --target 相似功能
Then: 系統輸出 WARNING 提示相似 Ticket
      子任務仍然建立成功（不因子任務身份豁免）
```

### 場景 5：重複偵測內部錯誤時容錯（異常流程）

```
Given: list_tickets() 因目錄問題拋出例外
When: PM 執行 ticket create
Then: 系統靜默跳過重複偵測（無錯誤輸出）
      Ticket 正常建立（返回 exit code 0）
      重複偵測錯誤不暴露給使用者
```

### 場景 6：已完成或進行中的相似 Ticket 不觸發警告（狀態過濾邊界）

```
Given: 版本 0.1.2 存在 completed 狀態的 Ticket，標題與即將建立的 Ticket 相似
When: PM 執行 ticket create
Then: 無重複偵測 WARNING（completed 不在偵測範圍）
      Ticket 正常建立（返回 exit code 0）
```
