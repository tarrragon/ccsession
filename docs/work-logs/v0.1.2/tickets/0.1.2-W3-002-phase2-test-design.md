## 1. 測試策略規劃

### 1.1 分層測試決策

根據 Phase 1 功能設計，SRP 偵測機制涉及以下層級：

| 層級 | 組件 | 測試策略 | 原因 |
|------|------|----------|------|
| Domain/Logic | `_detect_srp_multi_target()` | 單元測試（純函式） | 邏輯複雜，邊界條件多 |
| Domain/Logic | `_detect_srp_cross_module()` | 單元測試（純函式） | 字串匹配邏輯，邊界條件多 |
| Application | `detect_srp_violations()` | 單元測試 + 整合測試 | 協調函式，需驗證回傳值語義 |
| Presentation | `_print_create_checklist()` | 整合測試 | 驗證 create 流程中的呼叫 |

**分層設計決策**：
- `_detect_srp_multi_target` 和 `_detect_srp_cross_module` 必須使用 **Sociable Unit Tests**（直接實例化字串，無 Mock）
- `detect_srp_violations` 為協調函式，串聯兩個偵測器，需驗證回傳值的一致性
- 整合測試驗證在 create 流程中的呼叫位置和警告輸出

### 1.2 測試覆蓋率目標

| 目標 | 標準 | 達成方式 |
|------|------|----------|
| 函式行數覆蓋率 | 100% | 所有程式碼路徑需測試 |
| 分支覆蓋率 | 100% | Guard Clause、if/else 分支全覆蓋 |
| 邊界條件覆蓋率 | 100% | 空值、None、空字串、閾值邊界 |
| 正反面場景 | 100% | 正常通過 + 異常拒絕 + 邊界情況 |

## 2. 測試案例設計

### 2.1 `_detect_srp_multi_target()` 測試

#### 場景 1：what 含並列連接詞「和」
- **Given**: what 文字為「實作 create 層偵測和 SA 層審查」
- **When**: `_detect_srp_multi_target("實作 create 層偵測和 SA 層審查")` 被呼叫
- **Then**:
  - 回傳值為 `(True, ["和"])`
  - 找到的連接詞清單包含「和」

#### 場景 2：what 含並列連接詞「與」
- **Given**: what 文字為「新增功能 X 與優化功能 Y」
- **When**: `_detect_srp_multi_target("新增功能 X 與優化功能 Y")` 被呼叫
- **Then**:
  - 回傳值為 `(True, ["與"])`

#### 場景 3：what 含並列連接詞「及」
- **Given**: what 文字為「建立模組 A 及更新模組 B」
- **When**: `_detect_srp_multi_target("建立模組 A 及更新模組 B")` 被呼叫
- **Then**:
  - 回傳值為 `(True, ["及"])`

#### 場景 4：what 含並列連接詞「並」
- **Given**: what 文字為「重構 X 並新增 Y」
- **When**: `_detect_srp_multi_target("重構 X 並新增 Y")` 被呼叫
- **Then**:
  - 回傳值為 `(True, ["並"])`

#### 場景 5：what 含並列連接詞「同時」
- **Given**: what 文字為「同時修復 A 和更新 B」
- **When**: `_detect_srp_multi_target("同時修復 A 和更新 B")` 被呼叫
- **Then**:
  - 回傳值為 `(True, ["和"])`（「和」也被找到）
  - 如有「同時」也被列出，回傳 `(True, ["同時", "和"])`

#### 場景 6：what 含多個並列連接詞
- **Given**: what 文字為「實作 A 和修復 B 及優化 C」
- **When**: `_detect_srp_multi_target("實作 A 和修復 B 及優化 C")` 被呼叫
- **Then**:
  - 回傳值為 `(True, ["和", "及"])`
  - 找到所有連接詞

#### 場景 7：what 不含連接詞
- **Given**: what 文字為「實作 SRP 自動偵測機制」
- **When**: `_detect_srp_multi_target("實作 SRP 自動偵測機制")` 被呼叫
- **Then**:
  - 回傳值為 `(False, [])`

#### 場景 8：what 含「的」修飾詞（不觸發）
- **Given**: what 文字為「實作 SRP 自動偵測機制的雙層分工」
- **When**: `_detect_srp_multi_target("實作 SRP 自動偵測機制的雙層分工")` 被呼叫
- **Then**:
  - 回傳值為 `(False, [])`（「的」不是並列連接詞）

#### 場景 9：what 為空字串
- **Given**: what 文字為 `""`
- **When**: `_detect_srp_multi_target("")` 被呼叫
- **Then**:
  - 回傳值為 `(False, [])`
  - 不拋出例外

#### 場景 10：what 為 None（邊界條件，Guard Clause）
- **Given**: what 為 None
- **When**: `_detect_srp_multi_target(None)` 被呼叫（如果函式接受 None）或呼叫端先檢查
- **Then**:
  - 如函式有 Guard Clause：回傳 `(False, [])`，不拋出例外
  - 如無 Guard Clause：呼叫端應先檢查，函式簽名明確不接受 None

#### 場景 11：what 只包含連接詞
- **Given**: what 文字為「和」
- **When**: `_detect_srp_multi_target("和")` 被呼叫
- **Then**:
  - 回傳值為 `(False, [])`（無實質動詞+目標結構）

#### 場景 12：what 含連接詞但在句末
- **Given**: what 文字為「實作功能和」
- **When**: `_detect_srp_multi_target("實作功能和")` 被呼叫
- **Then**:
  - 回傳值可能為 `(True, ["和"])` 或 `(False, [])`
  - 測試要明確記錄設計決策

#### 場景 13：what 含多個相同連接詞
- **Given**: what 文字為「實作 A 和修復 B 和優化 C」
- **When**: `_detect_srp_multi_target("實作 A 和修復 B 和優化 C")` 被呼叫
- **Then**:
  - 回傳值為 `(True, ["和", "和"])` 或 `(True, ["和"])` （設計決策：是否去重）

### 2.2 `_detect_srp_cross_module()` 測試

#### 場景 1：驗收條件提及 3 個不同模組（超過閾值 2）
- **Given**: acceptance 為 `["確保 create.py 實作正確", "驗證 acceptance_auditor.py 邏輯", "檢查 constants.py 常數"]`
- **When**: `_detect_srp_cross_module(acceptance)` 被呼叫
- **Then**:
  - 前置驗證：識別出 `create`、`acceptance_auditor`、`constants` 三個模組
  - 回傳值為 `(True, ["create", "acceptance_auditor", "constants"])` 或類似格式
  - 表示偵測到跨模組

#### 場景 2：驗收條件提及 2 個模組（等於閾值，不觸發）
- **Given**: acceptance 為 `["create.py 實作完成", "constants.py 常數定義完成"]`
- **When**: `_detect_srp_cross_module(acceptance)` 被呼叫
- **Then**:
  - 回傳值為 `(False, [])`（等於閾值 2，不超過，不觸發）

#### 場景 3：驗收條件提及 1 個模組
- **Given**: acceptance 為 `["create.py 實作完成", "create 命令執行成功"]`
- **When**: `_detect_srp_cross_module(acceptance)` 被呼叫
- **Then**:
  - 回傳值為 `(False, [])`（同模組）

#### 場景 4：驗收條件無法識別模組（純中文）
- **Given**: acceptance 為 `["實作完成", "測試通過", "文件完成"]`
- **When**: `_detect_srp_cross_module(acceptance)` 被呼叫
- **Then**:
  - 回傳值為 `(False, [])`（無法識別時不誤報）

#### 場景 5：驗收條件為空陣列
- **Given**: acceptance 為 `[]`
- **When**: `_detect_srp_cross_module([])` 被呼叫
- **Then**:
  - 回傳值為 `(False, [])`
  - 不拋出例外

#### 場景 6：驗收條件為 None（邊界條件）
- **Given**: acceptance 為 None
- **When**: `_detect_srp_cross_module(None)` 被呼叫
- **Then**:
  - 函式應有 Guard Clause
  - 回傳值為 `(False, [])`，不拋出例外

#### 場景 7：驗收條件含類別名稱（PascalCase）
- **Given**: acceptance 為 `["SrpDetector 類別設計", "CreateMessages 常數新增", "ParallelAnalyzer 整合"]`
- **When**: `_detect_srp_cross_module(acceptance)` 被呼叫
- **Then**:
  - 前置驗證：識別出 `SrpDetector`、`CreateMessages`、`ParallelAnalyzer` 三個類別/模組
  - 回傳值為 `(True, [...])`

#### 場景 8：驗收條件混合檔案路徑和類別名稱
- **Given**: acceptance 為 `["ticket_system/lib/acceptance_auditor.py 新增函式", "CreateMessages 新增常數", "constants.py 新增定義"]`
- **When**: `_detect_srp_cross_module(acceptance)` 被呼叫
- **Then**:
  - 前置驗證：識別出 3 個不同模組
  - 回傳值為 `(True, [...])`

#### 場景 9：驗收條件含重複模組名稱
- **Given**: acceptance 為 `["create.py 功能 1", "create.py 功能 2", "acceptance_auditor.py 功能 1", "acceptance_auditor.py 功能 2"]`
- **When**: `_detect_srp_cross_module(acceptance)` 被呼叫
- **Then**:
  - 前置驗證：識別出 `create` 和 `acceptance_auditor` 兩個不同模組
  - 回傳值為 `(False, [])`（2 個模組，不超過閾值）

#### 場景 10：驗收條件清單含非字串元素
- **Given**: acceptance 為 `["create.py 實作", 123, None, "constants.py 定義"]`
- **When**: `_detect_srp_cross_module(acceptance)` 被呼叫
- **Then**:
  - 函式應優雅處理非字串元素
  - 回傳值為 `(False, [])` 或僅處理字串元素

### 2.3 `detect_srp_violations()` 整合測試

#### 場景 1：what 含連接詞，acceptance 為空
- **Given**:
  - what = 「實作 A 和修復 B」
  - acceptance = None 或 []
- **When**: `detect_srp_violations("實作 A 和修復 B", None)` 被呼叫
- **Then**:
  - 前置驗證：what 文字偵測成功
  - 回傳值為 `(True, [warning_message])`（有 SRP 疑慮）
  - warning_message 格式符合 Phase 1 定義

#### 場景 2：what 無連接詞，acceptance 含 3 個模組
- **Given**:
  - what = 「實作 SRP 機制」
  - acceptance = `["create.py 實作", "auditor.py 檢查", "constants.py 定義"]`
- **When**: `detect_srp_violations("實作 SRP 機制", acceptance)` 被呼叫
- **Then**:
  - 前置驗證：acceptance 跨模組偵測成功
  - 回傳值為 `(True, [warning_message])`（跨模組警告）

#### 場景 3：what 含連接詞，acceptance 也含 3 個模組
- **Given**:
  - what = 「實作 A 和修復 B」
  - acceptance = `["create.py 實作", "auditor.py 檢查", "constants.py 定義"]`
- **When**: `detect_srp_violations("實作 A 和修復 B", acceptance)` 被呼叫
- **Then**:
  - 前置驗證：兩個偵測器都觸發
  - 回傳值為 `(True, [warning1, warning2])`（兩個警告訊息）

#### 場景 4：what 無連接詞，acceptance 無跨模組
- **Given**:
  - what = 「實作 SRP 機制」
  - acceptance = `["功能實作完成", "測試通過"]`
- **When**: `detect_srp_violations("實作 SRP 機制", acceptance)` 被呼叫
- **Then**:
  - 前置驗證：兩個偵測器都不觸發
  - 回傳值為 `(False, [])`（無 SRP 疑慮）

#### 場景 5：what 為 None
- **Given**:
  - what = None
  - acceptance = []
- **When**: `detect_srp_violations(None, [])` 被呼叫
- **Then**:
  - 前置驗證：函式應有 Guard Clause 或呼叫端先檢查
  - 回傳值為 `(False, [])`，不拋出例外

#### 場景 6：both 為 None
- **Given**:
  - what = None
  - acceptance = None
- **When**: `detect_srp_violations(None, None)` 被呼叫
- **Then**:
  - 回傳值為 `(False, [])`，不拋出例外

#### 場景 7：acceptance 為空陣列
- **Given**:
  - what = 「實作 A 和修復 B」
  - acceptance = []
- **When**: `detect_srp_violations("實作 A 和修復 B", [])` 被呼叫
- **Then**:
  - what 偵測觸發
  - 回傳值為 `(True, [warning_from_what])`

#### 場景 8：acceptance 清單含 None 元素
- **Given**:
  - what = 「實作 SRP」
  - acceptance = `["create.py 實作", None, "constants.py 定義"]`

## 3. 邊界條件和異常情況分析

### 3.1 what 欄位邊界條件

| 情境 | 輸入 | 預期行為 |
|------|------|----------|
| 空字串 | `""` | 回傳 `(False, [])`，不觸發 |
| 僅空白 | `"   "` | 回傳 `(False, [])` |
| 僅連接詞 | `"和"` | 回傳 `(False, [])`，無實質內容 |
| 連接詞在句末 | `"實作功能和"` | 設計決策：可能誤報 |
| 多個相同連接詞 | `"A和B和C"` | 識別所有「和」或去重 |
| 混合連接詞 | `"A和B及C並D"` | 識別所有連接詞 |
| 含特殊字符 | `"實作A(和)修復B"` | 依設計決策，可能誤判 |
| 繁體中文連接詞 | 見 Phase 1 清單 | 完整覆蓋五個連接詞 |

### 3.2 acceptance 欄位邊界條件

| 情境 | 輸入 | 預期行為 |
|------|------|----------|
| 空陣列 | `[]` | 回傳 `(False, [])`，跳過檢查 |
| 單一條目（一模組） | `["create.py 實作"]` | 回傳 `(False, [])` |
| 兩個模組（等於閾值） | 兩個檔案 | 回傳 `(False, [])`，不超過 |
| 三個以上模組 | 三個檔案 | 回傳 `(True, [modules])`，觸發 |
| 無法識別模組 | `["功能實作完成"]` | 回傳 `(False, [])`，不誤報 |
| 混合識別類型 | 檔案 + 類別 + 模組名 | 依識別邏輯計算模組數 |
| 非字串元素 | `[123, None]` | 優雅處理或跳過 |

## 4. 警告訊息格式驗證

### 4.1 what 多目標警告

**期望格式**（來自 Phase 1）：
```
[WARNING] what 欄位含連接詞「{conjunctions}」，疑似包含多個獨立目標
          Atomic Ticket 原則：一個 Ticket = 一個 Action + 一個 Target
          建議：考慮拆分為多個 Ticket，或確認目標確實是單一職責
```

**測試項目**：
- 訊息中包含找到的連接詞清單
- 訊息包含「Atomic Ticket 原則」說明
- 訊息包含「建議」行動指引

### 4.2 acceptance 跨模組警告

**期望格式**（來自 Phase 1）：
```
[WARNING] 驗收條件涉及多個模組（{modules}），疑似包含多個職責
          Atomic Ticket 原則：所有驗收條件應指向同一目標
          建議：確認是否需要拆分為多個獨立 Ticket
```

**測試項目**：
- 訊息中包含偵測到的模組清單
- 訊息包含「Atomic Ticket 原則」說明
- 訊息包含「建議」行動指引

## 5. 測試環境設置規劃

### 5.1 Mock 物件設計

**函式特性**：兩個偵測函式都是純函式，無外部依賴
- 輸入：字串（what）、清單（acceptance）
- 輸出：元組（bool，清單）
- 無 Mock 需求

**測試資料組織**：
- 使用 Fixture 組織測試資料（acceptance 清單）
- 使用參數化測試（@pytest.mark.parametrize）覆蓋多個連接詞

### 5.2 測試資料準備

**what 文字樣本**：
```python
WHAT_SAMPLES = {
    "conjunction_和": "實作 create 層偵測和 SA 層審查",
    "conjunction_與": "新增功能 X 與優化功能 Y",
    "conjunction_及": "建立模組 A 及更新模組 B",
    "conjunction_並": "重構 X 並新增 Y",
    "conjunction_同時": "同時修復 A 和更新 B",
    "no_conjunction": "實作 SRP 自動偵測機制",
    "modifier_的": "實作 SRP 自動偵測機制的雙層分工",
    "empty": "",
    "only_conjunction": "和",
}
```

**acceptance 樣本**：
```python
ACCEPTANCE_SAMPLES = {
    "create_auditor_constants": [
        "確保 create.py 實作正確",
        "驗證 acceptance_auditor.py 邏輯",
        "檢查 constants.py 常數"
    ],
    "two_modules": [
        "create.py 實作完成",
        "constants.py 定義完成"
    ],
    "single_module": [
        "create.py 實作完成",
        "create 命令執行成功"
    ],
    "no_module": [
        "實作完成",
        "測試通過"
    ],
}
```

### 5.3 測試隔離策略

- **隔離範圍**：單元測試，無 Fixture 依賴
- **清理方式**：測試後自動清理（無外部狀態）
- **並行性**：所有測試可並行執行

## 7. 行為鏈式推演（BDD）

### 7.1 what 欄位偵測行為鏈

**鏈式順序：A（前置）→ B（行為）→ C（結果）**

```
A: what 文字被輸入到函式
   |
   +-- 前置驗證：什麼是「含連接詞」？
   |   `連接詞 = 並列邏輯的語法信號`
   |
   v
B: 函式掃描 what 文字，尋找連接詞（和/與/及/並/同時）
   |
   +-- 中間狀態 1：掃描完成，找到 0 個或 N 個連接詞
   +-- 中間狀態 2：連接詞位置記錄
   |
   v
C: 回傳 (has_conjunction, found_list)
   |
   +-- 若找到連接詞 → (True, [連接詞清單])
   +-- 若未找到 → (False, [])
```

**前置驗證斷言**（測試程式碼中應有）：
```python
# 場景：what 含「和」
what_text = "實作 A 和修復 B"
# 前置驗證：what 文字已準備
assert what_text is not None
assert isinstance(what_text, str)
assert len(what_text) > 0
# 前置驗證：「和」在清單中
assert "和" in SRP_WHAT_CONJUNCTIONS
# 然後執行 When
has_conj, found = _detect_srp_multi_target(what_text)
# Then 驗證結果
assert has_conj is True
assert "和" in found
```

### 7.2 acceptance 跨模組偵測行為鏈

```
A: acceptance 清單被輸入到函式
   |
   +-- 前置驗證：acceptance 是有效的清單
   |   `acceptance != None and isinstance(acceptance, list)`
   |
   v
B: 函式掃描 acceptance 清單中每個條目，提取模組名稱
   |
   +-- 中間狀態 1：掃描 acceptance 清單，計數不同模組
   +-- 中間狀態 2：模組清單已識別
   +-- 中間狀態 3：模組計數 = len(unique_modules)
   |
   v
C: 回傳 (is_cross_module, detected_modules)
   |
   +-- 若模組數 > 閾值 → (True, [模組清單])
   +-- 若模組數 <= 閾值或無法識別 → (False, [])
```

**前置驗證斷言**：
```python
# 場景：acceptance 含 3 個模組
acceptance = [
    "確保 create.py 實作正確",
    "驗證 acceptance_auditor.py 邏輯",
    "檢查 constants.py 常數"
]
# 前置驗證：acceptance 是清單
assert isinstance(acceptance, list)
assert len(acceptance) > 0
# 前置驗證：每個條目可識別模組
expected_modules_count = 3
# 然後執行 When
is_cross, modules = _detect_srp_cross_module(acceptance)
# Then 驗證結果
assert is_cross is True
assert len(modules) >= expected_modules_count  # 去重後至少 3 個
```

### 7.3 detect_srp_violations 協調行為鏈

```
A: what 和 acceptance 被輸入到協調函式
   |
   +-- 前置驗證：兩個輸入有效
   |   `what is not None and acceptance is None or isinstance(...)`
   |
   v
B: 函式串聯呼叫 _detect_srp_multi_target 和 _detect_srp_cross_module
   |
   +-- 中間狀態 1：what 偵測執行，產出 result1
   +-- 中間狀態 2：acceptance 偵測執行，產出 result2
   +-- 中間狀態 3：結果合併
   |
   v
C: 回傳 (has_any_issue, warning_messages)
   |
   +-- 若任一偵測器報告問題 → (True, [警告清單])
   +-- 若兩個都無問題 → (False, [])
```
