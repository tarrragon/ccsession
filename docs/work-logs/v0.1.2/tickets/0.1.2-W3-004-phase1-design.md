# Phase 1 功能規格設計：錯誤學習雙通道記錄保護機制

## 1. 需求分析

### 1.1 問題根因

場景 #16（錯誤學習經驗確認）目前只在 COMMIT_HANDOFF_REMINDER 文字中提及「選擇『記錄』→ /error-pattern add」，但：

1. 文字描述缺乏強制性約束：僅說明流程，未說明 memory 和 error-pattern 必須**同時**執行（雙通道）。
2. commit-handoff-hook 無偵測能力：Hook 不會在使用者選擇「記錄」後確認是否已執行 /error-pattern add，也不知道使用者是否只寫了 memory 而未寫 error-pattern。
3. askuserquestion-rules.md 場景 #16 未明確雙通道要求：目前規則只提「錯誤學習確認」，未說明記錄需同時走 memory 和 error-pattern 兩個通道。

### 1.2 業務影響

PM 記錄用戶回饋時只存 memory 未同步寫入 error-pattern，導致：
- error-pattern 庫（.claude/error-patterns/）無法累積實際遇到的錯誤模式
- 未來相同錯誤發生時，缺少可查詢的 error-pattern 記錄
- 違反專案的雙通道記錄要求（memory 為跨對話記憶，error-pattern 為可查詢知識庫）

### 1.3 雙通道定義

| 通道 | 位置 | 用途 | 格式 |
|------|------|------|------|
| memory | 使用者的 auto-memory（.claude/projects/.../memory/*.md） | 跨對話個人記憶，會在每次對話載入 | Markdown 自由格式 |
| error-pattern | .claude/error-patterns/ | 可查詢的結構化錯誤模式知識庫 | 分類目錄下的 Markdown |

兩個通道互補：memory 保存個人上下文和偏好，error-pattern 保存可重用的結構化模式。**記錄錯誤學習時必須同時寫入兩個通道**。

## 2. 使用者場景分析

### 使用者角色

- PM（rosemary-project-manager）：在 commit 後 Checkpoint 1.5 執行場景 #16 確認

### 場景識別

場景 A：PM 選擇「無需記錄」（正常流程）
```
Given: PM 完成 git commit
When: AskUserQuestion #16 呈現選項
Then: PM 選擇「無需記錄」，流程正常進入 #11 Handoff
```

場景 B：PM 選擇「記錄」並正確執行雙通道（預期正確流程）
```
Given: PM 選擇「記錄錯誤學習」
When: PM 依序執行 /error-pattern add 和更新 memory
Then: 兩個通道都已記錄，流程進入下一輪 #16 確認
```

場景 C：PM 選擇「記錄」但只寫 memory 未執行 /error-pattern add（問題場景）
```
Given: PM 選擇「記錄錯誤學習」
When: PM 更新 memory 但未執行 /error-pattern add
Then: [現況] Hook 無法偵測，流程靜默繼續
      [目標] Hook 在下次 commit 後輸出 WARNING，提醒雙通道要求
```

場景 D：PM 選擇「記錄」但只執行 /error-pattern add 未更新 memory（次要問題）
```
Given: PM 選擇「記錄錯誤學習」
When: PM 執行 /error-pattern add 但未更新 memory
Then: 規則文字應提醒必須同時更新 memory
```

## 3. 功能規格設計

### 3.1 變更範圍

本 Ticket 涉及兩個檔案的變更：

| 檔案 | 變更類型 | 變更目的 |
|------|---------|---------|
| `.claude/hooks/commit-handoff-hook.py` | 功能增強 | 在 COMMIT_HANDOFF_REMINDER 中強化 #16 雙通道提醒文字 |
| `.claude/rules/core/askuserquestion-rules.md` | 規則更新 | 場景 #16 明確要求雙通道（memory + error-pattern） |

注意：`ask_user_question_reminders.py` 中的 `COMMIT_HANDOFF_REMINDER` 常數即為 Hook 輸出的提醒文字，需在此更新 #16 的說明。

### 3.2 askuserquestion-rules.md 場景 #16 更新規格

**目前文字**（場景 #16 欄位）：
```
錯誤學習經驗確認 | commit 完成後（#11a/#11b 之前）；docs:/chore:/style: 等 commit 自動跳過；選項簡化為二元確認
```

**更新目標**：明確說明選擇「記錄」後的雙通道要求。

**新增規則**（在場景 #16 行後方補充說明）：

```markdown
場景 #16 雙通道要求（強制）：
選擇「記錄」時，必須同時執行：
  1. /error-pattern add（寫入 .claude/error-patterns/）
  2. 更新 memory（寫入使用者 auto-memory）
只執行其中一個通道不符合雙通道要求。
```

### 3.3 COMMIT_HANDOFF_REMINDER 更新規格

**影響範圍**：`ask_user_question_reminders.py` 中的 `AskUserQuestionReminders.COMMIT_HANDOFF_REMINDER`

**目前 #16 說明文字**：
```
[第一步 - 強制，不可跳過] AskUserQuestion #16（錯誤學習確認）：
  即使非 Ticket 工作，commit 後仍必須執行。無「非正式任務」豁免（規則 4）。
  → ToolSearch("select:AskUserQuestion") 載入後使用
  → 選項：無需記錄 (Recommended) / 記錄錯誤學習
  → 選擇「記錄」→ /error-pattern add → 重新確認 #16 直到選擇「無需記錄」
```

**目標更新**：在「選擇『記錄』」後補充雙通道要求：
```
  → 選擇「記錄」→ [雙通道必須同時執行]：
      (1) /error-pattern add（寫入 .claude/error-patterns/）
      (2) 更新 memory（寫入使用者 auto-memory）
      → 重新確認 #16 直到選擇「無需記錄」

[WARNING] 只寫 memory 不執行 /error-pattern add，或反之，均違反雙通道要求
```

### 3.4 未執行 /error-pattern add 的 WARNING 提醒機制

**設計決策**：Hook 偵測雙通道缺失的可行性分析

評估三種偵測方式：

| 方式 | 可行性 | 說明 |
|------|-------|------|
| 偵測 memory 寫入但無新 error-pattern 檔案 | 低 | Hook 在 commit 執行後才觸發，無法知道使用者「選擇了記錄但只做了一半」 |
| 在 COMMIT_HANDOFF_REMINDER 中加入強制文字 | 高 | 每次相關 commit 後直接輸出雙通道要求文字，引導 PM 正確執行 |
| 偵測 /error-pattern add 是否被執行過 | 中 | 需掃描檔案 mtime，複雜且不可靠（PM 可能在非 commit 時執行） |

**結論**：採用「在 COMMIT_HANDOFF_REMINDER 強化文字提醒」方式，理由：
1. Hook 觸發時機（commit 後）即為流程入口，在此提醒最有效
2. 文字提醒比偵測機制更可靠（不依賴外部狀態掃描）
3. 實作簡單，不需要新增複雜偵測邏輯

**WARNING 輸出時機和位置**：在 `COMMIT_HANDOFF_REMINDER` 的 #16 說明中直接嵌入 WARNING 文字，當 commit 類型觸發 #16 時自動呈現。

## 4. API 介面定義

### 4.1 COMMIT_HANDOFF_REMINDER 更新規格

**模組**：`.claude/hooks/lib/ask_user_question_reminders.py`
**常數**：`AskUserQuestionReminders.COMMIT_HANDOFF_REMINDER`
**變更類型**：字串常數更新（不影響介面簽名）

**變更位置**：找到以下片段並更新：
```python
  → 選擇「記錄」→ /error-pattern add → 重新確認 #16 直到選擇「無需記錄」
```

**更新為**：
```python
  → 選擇「記錄」→ [雙通道，兩項必須同時執行]：
      (1) /error-pattern add（寫入 .claude/error-patterns/，結構化知識庫）
      (2) 更新 memory（寫入使用者 auto-memory，跨對話記憶）
  → 重新確認 #16 直到選擇「無需記錄」

[WARNING] 雙通道要求：只寫 memory 或只執行 /error-pattern add 均不符合規範
```

### 4.2 askuserquestion-rules.md 場景 #16 更新規格

**位置**：場景列表表格中第 16 行的「觸發條件」欄位說明末尾
**新增說明小節**：在場景列表下方，執行順序約束上方，新增獨立的「場景 #16 雙通道要求」說明區塊

**新增規則區塊**（Markdown 格式）：

```markdown
### 場景 #16 雙通道記錄要求（強制）

選擇「記錄錯誤學習」後，必須同時執行雙通道記錄：

| 通道 | 操作 | 位置 | 說明 |
|------|------|------|------|
| error-pattern | /error-pattern add | .claude/error-patterns/ | 結構化可查詢知識庫 |
| memory | 更新使用者 auto-memory | .claude/projects/.../memory/ | 跨對話個人記憶 |

禁止只寫單一通道：只寫 memory 不執行 /error-pattern add，或反之，均違反雙通道要求。
```

## 5. 邊界條件分析

### 5.1 commit 類型過濾（現有行為，不變更）

| commit 類型 | #16 行為 | 雙通道要求 |
|------------|---------|-----------|
| docs/chore/style/revert/test/ci/build | 跳過 #16 | 不適用 |
| fix/bug/patch | 強制觸發 | 適用 |
| feat 及其他 | 觸發二元確認 | 適用（選擇「記錄」時） |

### 5.2 subagent 環境（現有行為，不變更）

subagent 環境中 commit-handoff-hook 已自動跳過，雙通道要求不影響 subagent 流程。

### 5.3 PM 未使用 AskUserQuestion #16 的情況

PM 跳過 #16 直接進入 #11 Handoff 時，本機制無法攔截。此為現有問題，超出本 Ticket 範圍。

### 5.4 memory 更新的定義邊界

「更新 memory」指 PM 在 auto-memory 中新增或更新相關記憶條目（.claude/projects/.../memory/*.md）。不要求固定格式，但 error-pattern 有固定格式要求（需執行 /error-pattern add 指令）。

## 6. 驗收標準

### 6.1 驗收條件對應

| 驗收條件 | 對應設計 | 驗證方式 |
|---------|---------|---------|
| commit-handoff-hook 在 #16 選擇「記錄」時，提醒需同時寫入 memory 和 error-pattern | COMMIT_HANDOFF_REMINDER 文字更新包含雙通道說明 | 閱讀更新後的常數文字，確認包含兩個通道的具體說明 |
| askuserquestion-rules.md 場景 #16 規則明確要求雙通道 | 新增「場景 #16 雙通道記錄要求」規則區塊 | 閱讀更新後的規則文件，確認有獨立的雙通道說明 |
| 未執行 /error-pattern add 時 Hook 輸出 WARNING 提醒 | WARNING 文字嵌入在 COMMIT_HANDOFF_REMINDER 中，每次觸發 #16 時均輸出 | 閱讀常數文字確認包含 WARNING 標示 |
| 既有 Hook 測試通過 | 文字常數更新不影響 Hook 邏輯 | 執行既有測試套件 |

### 6.2 行為場景驗收（Given-When-Then）

場景 1：COMMIT_HANDOFF_REMINDER 包含雙通道要求文字
```
Given: commit 類型為 feat（觸發 #16）
When: commit-handoff-hook 偵測到 git commit 成功
Then: additionalContext 中的 COMMIT_HANDOFF_REMINDER 文字包含：
      - "/error-pattern add" 的明確提及
      - "更新 memory" 或 "auto-memory" 的明確提及
      - "[WARNING] 雙通道" 或類似警告標示
```

場景 2：askuserquestion-rules.md 包含雙通道規則
```
Given: 開發者閱讀場景 #16 說明
When: 查閱 askuserquestion-rules.md 的場景 #16 相關章節
Then: 文件中存在「雙通道」或「double-channel」相關說明，且同時列出 error-pattern 和 memory 兩個通道
```

場景 3：docs/chore commit 跳過 #16（邊界條件，行為不變）
```
Given: commit 類型為 docs（SKIP_SCENE16_COMMIT_PREFIXES 中）
When: commit-handoff-hook 偵測到 git commit 成功
Then: 輸出 COMMIT_HANDOFF_SKIP16_REMINDER（不包含雙通道要求），不觸發 #16
```
