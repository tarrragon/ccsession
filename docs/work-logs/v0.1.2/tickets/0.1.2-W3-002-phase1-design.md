## 1. 功能需求分析

### 1.1 核心問題

Wave 2 最終審查時，PM 將 9 個不相關問題合併為 1 個 Ticket，違反 Atomic Ticket 原則（單一職責原則，SRP）。系統當時沒有任何自動偵測機制，導致問題只能透過人工審查發現。

### 1.2 解決目標

建立雙層防護機制，在 Ticket 建立階段就提前提示潛在的 SRP 違規，降低不合規 Ticket 進入後續 TDD 流程的風險。

### 1.3 使用者場景

**場景 1：create 層輕量提示（正常流程）**
- Given: PM 使用 `/ticket create --what "實作 A 和修復 B"` 建立 Ticket
- When: create 命令執行完成後
- Then: 系統輸出 WARNING 提示「what 欄位含連接詞，疑似多個目標」，建議考慮拆分，不阻止建立

**場景 2：create 層跨模組驗收偵測**
- Given: PM 建立 Ticket 並指定驗收條件指向不同模組的多個不相關檔案
- When: create 命令執行完成後
- Then: 系統輸出 WARNING 提示「驗收條件跨多個不相關模組，疑似多個職責」，不阻止建立

**場景 3：SA 層詳細檢查**
- Given: saffron-system-analyst 在 Phase 0 審查一個 Ticket
- When: SA 執行 SRP 四大檢查（語義/修改原因/驗收一致性/依賴獨立性）
- Then: SA 依據標準化規則輸出詳細分析結果，若發現違規建議拆分

**場景 4：偵測到 SRP 違規**
- Given: what 欄位為「實作 A 和修復 B 及優化 C」
- When: create 執行
- Then: 輸出 WARNING（不阻止），訊息說明偵測到的連接詞及建議拆分方式

**場景 5：合法的多目標（不觸發誤報）**
- Given: what 欄位為「實作 SRP 自動偵測機制的雙層分工」
- When: create 執行
- Then: 不輸出 SRP 相關 WARNING（「的」不是連接詞，不觸發）

## 2. 偵測規則定義

### 2.1 create 層：what 欄位多目標特徵偵測

#### 偵測目標

`what` 欄位文字中是否存在連接詞，暗示多個獨立目標並列。

#### 偵測連接詞清單（SRP_WHAT_CONJUNCTIONS）

| 連接詞 | 範例觸發文字 |
|--------|------------|
| 和 | 「實作 A 和修復 B」 |
| 與 | 「新增功能 X 與優化功能 Y」 |
| 及 | 「建立模組 A 及更新模組 B」 |
| 並 | 「重構 X 並新增 Y」 |
| 同時 | 「同時修復 A 和更新 B」 |

#### 偵測規則說明

連接詞必須出現在兩個「動詞+名詞」結構之間，才視為多目標特徵。純粹的修飾詞不觸發。

**觸發範例**：
- 「實作 create 層和 SA 層」→ 觸發（兩個層次並列）
- 「修復 Bug A 及優化效能」→ 觸發（兩個不同行動）

**不觸發範例**：
- 「實作 SRP 自動偵測機制的雙層分工」→ 不觸發（「的」不是並列連接詞）
- 「建立新增和更新的統一介面」→ 偵測邏輯需考量此類情況

#### 偵測邏輯

```python
def detect_srp_multi_target_in_what(what_text: str) -> tuple[bool, list[str]]:
    """
    偵測 what 欄位是否含多目標連接詞特徵。

    Args:
        what_text: Ticket 的 what 欄位文字

    Returns:
        (is_suspicious, found_conjunctions)
        - is_suspicious: True 表示偵測到疑似多目標
        - found_conjunctions: 找到的連接詞清單
    """
```

### 2.2 create 層：驗收條件跨模組偵測

#### 偵測目標

驗收條件（acceptance list）中的各條目是否指向不相關的多個模組或系統層級。

#### 跨模組判定規則（SRP_MODULE_DETECTION）

從驗收條件文字中擷取提及的模組名稱（Python 模組路徑格式或類別名稱），若超過 `SRP_ACCEPTANCE_MODULE_THRESHOLD` 個不同模組，則視為跨模組。

**模組識別方式**：

| 識別方式 | 範例 |
|---------|------|
| 檔案路徑（.py 結尾） | `create.py`、`acceptance_auditor.py` |
| Python 模組命名（snake_case 模組名） | `ticket_loader`、`constants` |
| 類別名稱（PascalCase 名稱） | `CreateMessages`、`SrpDetector` |

**跨模組閾值**（SRP_ACCEPTANCE_MODULE_THRESHOLD）：預設 2 個模組

若偵測到驗收條件指向 3 個以上不同模組，輸出 WARNING。

**注意事項**：此偵測為輔助提示，誤報率可能較高，僅輸出建議性 WARNING，不視為嚴重問題。

#### 偵測邏輯

```python
def detect_srp_cross_module_in_acceptance(
    acceptance_list: list[str],
) -> tuple[bool, list[str]]:
    """
    偵測驗收條件是否跨多個不相關模組。

    Args:
        acceptance_list: 驗收條件清單

    Returns:
        (is_cross_module, detected_modules)
        - is_cross_module: True 表示偵測到跨模組特徵
        - detected_modules: 識別到的模組名稱清單
    """
```

### 2.3 SA 層：SRP 四大檢查職責定義

SA（saffron-system-analyst）在 Phase 0 審查中新增以下四個 SRP 專屬檢查項目：

| 檢查項 | 對應原則 | 判斷問題 |
|-------|--------|---------|
| 語義檢查 | 原子性 | Ticket 能否用「動詞 + 單一目標」表達？ |
| 修改原因檢查 | 唯一性 | 只有一個原因會導致此 Ticket 需要修改嗎？ |
| 驗收一致性檢查 | 一致性 | 所有驗收條件都指向同一個目標嗎？ |
| 依賴獨立性檢查 | 獨立性 | 若拆分，各部分是否不會產生循環依賴？ |

這四個檢查對應 `atomic-ticket-methodology.md` 第「單一職責評估方式」章節的四大評估原則。

## 3. API 介面定義

### 3.1 新增函式：`detect_srp_violations`

**位置**：`.claude/skills/ticket/ticket_system/lib/acceptance_auditor.py`

```python
def detect_srp_violations(
    what_text: str,
    acceptance_list: Optional[List[str]],
) -> Tuple[bool, List[str]]:
    """
    偵測 Ticket 是否有潛在的 SRP（單一職責原則）違規。

    執行兩項輕量偵測：
    1. what 欄位多目標連接詞偵測
    2. 驗收條件跨模組偵測

    此函式僅用於建立時的輕量提示，不作為阻止建立的依據。
    詳細 SRP 審查由 SA 層（saffron-system-analyst）在 Phase 0 執行。

    Args:
        what_text: Ticket 的 what 欄位文字（不可為 None）
        acceptance_list: 驗收條件清單（可為 None）

    Returns:
        Tuple[bool, List[str]]:
        - (False, [])：未偵測到 SRP 疑慮
        - (True, [warning_messages])：偵測到疑慮，回傳警告訊息清單

    Note:
        回傳值第一個元素為 True 表示「有疑慮」（與 detect_vague_acceptance 的語義不同）。
        偵測結果只用於輸出 WARNING，不影響 create 命令的回傳碼。
    """
```

**子函式（私有輔助函式）**：

```python
def _detect_srp_cross_module(acceptance_list: List[str]) -> Tuple[bool, List[str]]:

    Args:
        acceptance_list: 驗收條件清單

    Returns:
        (is_cross_module, detected_modules):
        - is_cross_module: 是否偵測到跨模組特徵
        - detected_modules: 識別到的模組名稱清單
    """
```

### 5.2 設計一致性保證

新增的 `detect_srp_violations` 函式與現有的 `detect_vague_acceptance` 函式採用相同的設計模式：

| 設計面向 | detect_vague_acceptance | detect_srp_violations |
|---------|------------------------|----------------------|
| 回傳型別 | `Tuple[bool, List[str]]` | `Tuple[bool, List[str]]` |
| 第一個值語義 | True = 無嚴重問題（反向） | True = 有疑慮（正向） |
| 第二個值 | 警告訊息清單 | 警告訊息清單 |
| 阻止建立 | 否 | 否 |
| 輸出方式 | `format_warning()` | `format_warning()` |

**注意**：回傳值第一個元素語義與 `detect_vague_acceptance` 相反（True 表示「有疑慮」vs「無嚴重問題」），呼叫端需注意。建議在呼叫處加上清晰的變數命名：

```python
# 清晰的變數命名避免語義混淆
has_srp_issue, srp_warnings = detect_srp_violations(what_text, acceptance)
```

- `accept_auditor.py` 的 `run_audit` 函式不加入 SRP 偵測（`run_audit` 用於驗收時詳細審查，SRP 偵測屬於建立時輕量提示）

- `execute` 函式主要流程不變，SRP 偵測只在 `_print_create_checklist` 中呼叫

## 7. 邊界條件分析

### 7.1 what 欄位偵測邊界條件

| 情境 | what 欄位內容 | 預期行為 |
|------|-------------|---------|
| 正常單一目標 | 「實作 SRP 偵測機制」 | 不觸發 WARNING |
| 含連接詞的單一目標 | 「實作新增和更新的統一 API」 | 觸發 WARNING（可能誤報，但 PM 可判斷） |
| 明確多目標 | 「修復 Bug A 和實作功能 B」 | 觸發 WARNING |
| 空字串 | `""` | 不觸發（無文字可偵測） |
| None | None | 不觸發（Guard Clause） |
| 只有連接詞 | 「和」 | 不觸發（無實質動詞+目標結構） |

### 7.2 驗收條件跨模組偵測邊界條件

| 情境 | 驗收條件 | 預期行為 |
|------|---------|---------|
| 空清單 | `[]` | 不觸發 |
| None | None | 不觸發（Guard Clause） |
| 單一模組多條 | 全部提及 `create.py` | 不觸發（同模組） |
| 兩個模組 | 提及 `create.py` 和 `constants.py` | 不觸發（等於閾值 2，不超過） |
| 三個以上模組 | 提及 3 個以上不同模組 | 觸發 WARNING |
| 無法識別模組 | 純中文描述，無模組名稱 | 不觸發（無法識別時不誤報） |

### 7.3 非阻止性確保

兩種偵測函式均為純函式，不修改任何狀態，不拋出例外（所有邊界條件都以 Guard Clause 處理並回傳安全預設值）。

## 9. 行為場景（Given-When-Then）

### 場景 1：what 欄位含連接詞「和」
- Given: Ticket what 欄位為「實作 create 層偵測和 SA 層審查」
- When: `detect_srp_violations("實作 create 層偵測和 SA 層審查", [])` 被呼叫
- Then: 回傳 `(True, ["[WARNING] what 欄位含連接詞「和」..."])`

### 場景 2：what 欄位無連接詞
- Given: Ticket what 欄位為「實作 SRP 自動偵測機制」
- When: `detect_srp_violations("實作 SRP 自動偵測機制", [])` 被呼叫
- Then: 回傳 `(False, [])`

### 場景 3：驗收條件含三個模組
- Given: 驗收條件提及 `create.py`、`acceptance_auditor.py`、`constants.py` 三個模組
- When: `detect_srp_violations("任意 what", ["...create.py...", "...acceptance_auditor.py...", "...constants.py..."])` 被呼叫
- Then: 回傳 `(True, ["[WARNING] 驗收條件涉及多個模組..."])`

### 場景 4：驗收條件含兩個模組（不觸發）
- Given: 驗收條件提及 `create.py` 和 `constants.py` 兩個模組
- When: `detect_srp_violations("任意 what", ["...create.py...", "...constants.py..."])` 被呼叫
- Then: 回傳 `(False, [])` 或只含 what 觸發的警告（跨模組不觸發）

### 場景 5：what 為 None（邊界條件）
- Given: Ticket 未提供 what 欄位
- When: `detect_srp_violations(None, None)` 被呼叫
- Then: 回傳 `(False, [])`，不拋出例外

### 場景 6：create 命令完整流程
- Given: PM 執行 `ticket create --wave 3 --action 實作 --target "A和修復B" --what "實作A和修復B" ...`
- When: create 命令成功建立 Ticket
- Then: 輸出中包含 `[WARNING] what 欄位含連接詞...`，且 exit code = 0
