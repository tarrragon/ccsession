## Step 2: Hook 實作（agent-dispatch-validation-hook.py）

### 產出物

- **行數**: ~350 行
- **功能**: 三衝突檢查 + 雙通道日誌

### 三衝突檢查實作

#### 2.1 衝突檢查 1：Agent 衝突（cannot_work_with）
```python
def check_agent_conflict(agent_a, agent_b, registry) -> list
```

**規則**：若 agent_b 的 conflict_avoidance 中存在 cannot_work_with 包含 agent_a，則衝突

**場景測試** - ARCH-005 回溯：
- parsley 和 cinnamon 不可同一 Ticket 並行（共用 ui/lib/**/*.dart）
- 同一 agent 不可重複派發

#### 2.2 衝突檢查 2：TDD 相序驗證（must_complete_before）
```python
def check_phase_sequence(agent_a, agent_b, registry) -> list
```

**規則**：若 agent_b 的 conflict_avoidance 中 must_complete_before 包含 agent_a，則 agent_a 必須先完成

**場景**：Phase 1→2→3a→3b→4b 嚴格序列驗證

#### 2.3 衝突檢查 3：檔案寫入衝突（ARCH-005）
```python
def check_file_conflict(agent_a, agent_b, registry) -> list
def patterns_overlap(pattern_a, pattern_b) -> bool
```

**保守策略**：目錄前綴相同視為潛在交集（接受 false positive）

**場景**：
- parsley: `ui/lib/**/*.dart`, `ui/test/**/*_test.dart`
- cinnamon: `ui/lib/**/*.dart`, `docs/work-logs/**/*.md`
- 衝突：`ui/lib/**/*.dart` 重疊 → 不可並行

- **行數**: ~200 行
- **功能**: 評分演算法 + 推薦查詢

### 推薦評分演算法

#### 3.1 評分公式
```
total_score = artifact_match_score + phase_match_score + precondition_score - penalties
```

**各項配置**（根據 Phase 3a 設計）：

| 項目 | 滿分 | 計算方式 | 含義 |
|------|------|---------|------|
| artifact_match_score | 40 | 40 × (匹配 artifact 數 / 總 artifact 數) | 輸入匹配程度 |
| precondition_score | 30 | 30（簡化：認為已滿足） | 前置條件 |
| phase_match_score | 20 | 若 TDD Phase 符合則 +20 | Phase 相符 |
| file_conflict_penalty | -100 | 檔案衝突時扣分 | 衝突懲罰 |

#### 3.2 CLI 介面
```
dispatch_recommender.py <ticket-id> <artifact-type> [tdd-phase]
```

**輸出格式**：
