## 2. 虛擬碼設計

### 2.1 輔助函式：`_is_in_detection_scope()`

```pseudo
函式 _is_in_detection_scope(ticket: dict) -> bool:
    """判斷 Ticket 是否在重複偵測掃描範圍內。

    邏輯：
    - pending 狀態 → 總是在範圍內（現有邏輯）
    - in_progress 狀態 → 總是在範圍內（新增）
    - completed 狀態 → 需判斷是否在 7 天時間窗口內（新增）
    - 其他狀態 → 不在範圍內
    """

    狀態 = ticket.get("status")

    如果 狀態 == STATUS_PENDING:
        返回 true

    如果 狀態 == STATUS_IN_PROGRESS:
        返回 true

    如果 狀態 == STATUS_COMPLETED:
        completed_at_str = ticket.get("completed_at")

        # 保守策略：無時間戳 → 排除（視為超期）
        如果 completed_at_str 為 null 或 "":
            返回 false

        # 嘗試解析時間戳
        試試:
            completed_at = 解析ISO時間(completed_at_str)
            window_start = 現在時間 - timedelta(days=7)

            # 時間窗口判斷：closed-open interval [window_start, now)
            # 邏輯：completed_at >= window_start
            # 即：7天內的完成時間都包含
            返回 completed_at >= window_start

        異常捕捉(ValueError 或 TypeError):
            # 格式異常 → 排除（保守策略）
            返回 false

    # blocked 或其他狀態
    返回 false
```

**虛擬碼執行流程說明**：
- 第一層判斷：狀態分類（pending/in_progress/completed/其他）
- 第二層判斷（completed）：時間戳檢查 → 解析 → 比較
- 異常路徑：3 條靜默返回，不拋出異常

### 2.2 輔助函式：`_get_status_label()`

```pseudo
函式 _get_status_label(status: str) -> str:
    """根據 Ticket 狀態返回顯示標籤。

    邏輯：
    - in_progress 狀態 → 返回「進行中」（中文）
    - completed 狀態 → 返回「已完成」（中文）
    - pending 狀態 → 返回空字串（向下相容，不顯示標籤）
    - 其他 → 返回空字串
    """

    如果 status == STATUS_IN_PROGRESS:
        返回 CreateMessages.DUPLICATE_STATUS_LABEL_IN_PROGRESS
        # 預期值：「進行中」

    如果 status == STATUS_COMPLETED:
        返回 CreateMessages.DUPLICATE_STATUS_LABEL_COMPLETED
        # 預期值：「已完成」

    # pending 和其他狀態：不顯示標籤
    返回 ""
```

**虛擬碼執行流程說明**：
- 直接映射邏輯，3 種分支
- 查表返回常數（依賴 Stage A 定義）

### 2.3 修改函式：`_detect_duplicate_tickets()`

修改邏輯集中在**步驟 B-3**（候選 Ticket 過濾）和**步驟 D**（警告輸出格式）：

```pseudo
函式 _detect_duplicate_tickets(version, new_title, new_what, new_ticket_id):
    """偵測重複 Ticket 並輸出警告。

    修改點：
    1. 步驟 B-3：使用 _is_in_detection_scope() 過濾候選 Ticket
    2. 步驟 D：使用 _get_status_label() 為警告項目添加狀態標籤
    """

    步驟 A：驗證輸入
        如果 (title 為空) AND (what 為空):
            返回（提前退出）

    步驟 B：載入同版本 Ticket
        B-1：計算排除 ID 清單
            excluded_ids = {自身 ID, 父任務 ID}
            （不變）

        B-2：掃描清單
            candidates = []
            對於 list_tickets(version) 中的每個 ticket:
                如果 ticket.id 在 excluded_ids 中:
                    跳過

                # 新邏輯：使用 _is_in_detection_scope() 判斷是否掃描
                如果 _is_in_detection_scope(ticket):
                    candidates 追加 ticket

        B-3：若無候選 Ticket 則提前返回
            如果 candidates 為空:
                返回

    步驟 C：相似度計算
        matches = []
        試試:
            對於 candidates 中的每個 ticket:
                試試:
                    similarity = 計算Jaccard相似度(new_title + new_what,
                                                 ticket.title + ticket.what)
                    如果 similarity >= DUPLICATE_DETECTION_THRESHOLD:
                        matches 追加 (ticket, similarity)
                異常:
                    # 單項計算異常 → 跳過該項
                    繼續下一項
        異常:
            # 外層異常 → 靜默返回
            返回

    步驟 D：輸出結果
        如果 matches 為空:
            返回（無重複）

        # 新邏輯：為每個匹配項添加狀態標籤
        警告行列表 = []
        對於 matches 中的每個 (ticket, similarity):
            status_label = _get_status_label(ticket.status)

            # 格式化警告行
            如果 status_label 為空:
                警告行 = f"   - {ticket.id}: {ticket.title}"
            否則:
                警告行 = f"   - {ticket.id}: {ticket.title} [{status_label}]"

            警告行列表 追加 警告行

        # 輸出警告
        輸出 "[WARNING] 發現 {len(matches)} 個可能重複的 Ticket，請確認是否需要建立新 Ticket："
        對於 警告行列表 中的每一行:
            輸出 該行
        輸出 "   建議：執行 /ticket track list 查看所有現有 Ticket 後再決定"
```

**修改點詳解**：

| 修改點 | 原邏輯 | 新邏輯 | 理由 |
|--------|--------|--------|------|
| B-2/B-3 候選過濾 | `status == STATUS_PENDING` | `_is_in_detection_scope(ticket)` | 擴展掃描範圍至 in_progress 和 7 天內 completed |
| D 警告格式 | `{ticket_id}: {title}` | `{ticket_id}: {title} [{status_label}]`（選擇性） | 為 in_progress/completed 添加狀態標籤 |
| D 狀態標籤取得 | N/A | 呼叫 `_get_status_label()` | 集中管理標籤邏輯 |

## 3. 資料結構選擇

### 3.1 時間窗口資料模型

```
時間窗口定義（closed-open interval）:
- 基準時間（window_start）= datetime.now() - timedelta(days=7)
- 包含範圍：completed_at >= window_start 的所有 completed Ticket
- 排除範圍：completed_at < window_start 的所有 completed Ticket

數學表示：
  T ∈ [window_start, now)
  window_start = now - 7 days
  即：最近 7 天的完成 Ticket

邊界定義：
  completed_at = now - 7 days 00:00:00 → 不包含（< window_start）
  completed_at = now - 6 days 23:59:59 → 包含（>= window_start）
```

### 3.2 狀態標籤映射表

```
狀態 → 標籤映射（字典形式）：

status_label_map = {
    STATUS_PENDING: "",                    # pending 不顯示標籤
    STATUS_IN_PROGRESS: "進行中",          # in_progress 顯示「進行中」
    STATUS_COMPLETED: "已完成",            # completed 顯示「已完成」
    STATUS_BLOCKED: "",                    # blocked 不在掃描範圍內（如遇到則不顯示）
}

實作方式：
- 不建立實際字典，而是在 _get_status_label() 中硬碼 if/else
- 原因：mapping 檔案中已存在的 status 常數，無需額外資料結構
```

## 8. 語言特定實作注意事項

### Python 考量

**版本要求**：
- `datetime.fromisoformat()` 需 Python 3.7+（已滿足）
- `timedelta` 標準庫（無依賴問題）

**效能最佳化**：
1. `_is_in_detection_scope()` 應在循環外計算 `window_start` 一次
   ```python
   window_start = datetime.now() - timedelta(days=DUPLICATE_DETECTION_COMPLETED_WINDOW_DAYS)
   for ticket in candidates:
       # 使用 window_start，不在迴圈內重複計算
   ```

2. 狀態字串比較使用常數而非字面值
   ```python
   if status == STATUS_IN_PROGRESS:  # 好
   if status == "in_progress":       # 應避免
   ```

3. 例外捕捉遵循既有雙層結構
   ```python
   try:  # 外層：全局異常
       for ticket in candidates:
           try:  # 內層：單項異常
               similarity = ...
           except ValueError:
               continue
   except Exception:
       return
   ```

**可能的技術挑戰**：
1. `datetime` 序列化 — JSONL 格式中的 `completed_at` 可能包含毫秒或時區資訊，需嚴謹的格式判斷
2. 浮點時間戳比較 — `completed_at >= window_start` 邊界可能因時區換算產生偏差，需人工驗證
3. Mock 複雜度 — 測試需 Mock `datetime.now()` 和 `list_tickets()` 同時，需謹慎設計 fixture
