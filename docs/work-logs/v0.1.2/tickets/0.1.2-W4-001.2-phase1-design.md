## 1. 需求分析

### 1.1 核心問題

本 Ticket 修正三個獨立品質問題，由 W3 三人組審查識別：

## 2. 功能規格設計

### 2.1 問題一：魔法數字 `max_display = 10`

**現況分析**

```python
# branch-status-reminder.py:106-113（現況）
max_display = 10
for i, line in enumerate(lines[:max_display]):
    hook_output(f"   {line}", "info")

if total_changes > max_display:
    remaining = total_changes - max_display
    hook_output(f"   ...還有 {remaining} 個", "info")
```

數字 `10` 出現兩次，缺乏語義說明。閱讀者需要從上下文推斷其含義。

**修改方案**

在 `branch-status-reminder.py` 頂部定義具名常數：

```python
# 顯示設定常數
MAX_UNCOMMITTED_FILES_DISPLAY = 10  # 未提交變更顯示上限，超過則折疊顯示
```

引用方式：

```python
for i, line in enumerate(lines[:MAX_UNCOMMITTED_FILES_DISPLAY]):
    hook_output(f"   {line}", "info")

if total_changes > MAX_UNCOMMITTED_FILES_DISPLAY:
    remaining = total_changes - MAX_UNCOMMITTED_FILES_DISPLAY
    hook_output(f"   ...還有 {remaining} 個", "info")
```

**常數定義位置決策**

本常數為 branch-status-reminder.py 私有配置，目前無其他模組使用相同數值。

判斷：定義在 `branch-status-reminder.py` 頂部（module-level 常數），不需要抽取至獨立 constants 模組。

理由：
- 符合 quality-common.md 規則 1.3.2「單一檔案使用 → 檔案頂部模組常數」
- 避免過度工程化（premature abstraction）

**接受條件驗證方式**：搜尋 branch-status-reminder.py 確認無裸露數字 `10` 用於此目的。

### 2.2 問題二：git 查詢邏輯歸屬（核心設計）

**現況分析**

`_report_uncommitted_changes()` 函式包含兩個職責：
1. 執行 git 查詢並取得原始資料（屬於 git 工具層）
2. 格式化並輸出結果給使用者（屬於 Hook 呈現層）

目前職責 1 和職責 2 混合在同一函式中，違反單一責任原則，且 git 查詢邏輯無法被其他 Hook 重用。

**修改方案：新增 `get_uncommitted_files()` 至 git_utils.py**

**函式簽名設計**

```python
def get_uncommitted_files() -> list[str]:
```

**設計決策說明**

| 決策點 | 選項 | 採用 | 理由 |
|--------|------|------|------|
| 回傳型別 | `list[str]` | 採用 | 每行代表一個檔案狀態（git porcelain 格式），呼叫端可自行決定顯示邏輯 |
| 回傳型別 | `dict` | 不採用 | 解析 porcelain 格式增加複雜度，且目前呼叫端僅需原始行字串 |
| 參數設計 | 無參數 | 採用 | 查詢當前工作目錄，與其他 git_utils 函式一致（如 `get_current_branch()`） |
| 參數設計 | 接受 `cwd` 參數 | 不採用 | 超出目前使用需求，可在未來需要時再添加 |
| 錯誤處理 | 失敗回傳空 list | 採用 | 與 `get_worktree_list()` 一致（失敗回傳 `[]`） |
| 空行過濾 | 函式內過濾 | 採用 | 封裝內部細節，呼叫端不需要知道 porcelain 輸出格式 |

**完整函式規格**

```python
def get_uncommitted_files() -> list[str]:
    """
    獲取未提交變更的檔案列表

    執行 git status --porcelain，返回所有未提交變更的狀態行。
    每行格式為 git porcelain 格式（如 " M file.txt"、"?? new.txt"）。
    空輸出或 git 命令失敗時返回空列表。

    Returns:
        list[str]: 未提交變更的狀態行列表，如果沒有變更或命令失敗則返回空列表

    Example:
        files = get_uncommitted_files()
        if files:
            print(f"有 {len(files)} 個未提交變更")
        for line in files:
            print(f"  {line}")
    """
    success, output = run_git_command(["status", "--porcelain"])

    if not success or not output:
        return []

    lines = output.split("\n")
    return [line for line in lines if line.strip()]
```

**修改後的 `_report_uncommitted_changes()` 函式**

呼叫端函式職責簡化為純呈現層：

```python
def _report_uncommitted_changes(logger: logging.Logger) -> None:
    """
    偵測並報告未提交的變更

    使用 git_utils.get_uncommitted_files() 獲取變更列表，
    如果超過 MAX_UNCOMMITTED_FILES_DISPLAY 個檔案，只顯示前 N 個並提示還有多少個。
    如果沒有未提交變更，則不輸出任何內容。

    Args:
        logger: logging 實例，用於記錄錯誤
    """
    files = get_uncommitted_files()

    if not files:
        return

    total_changes = len(files)

    # 輸出未提交變更摘要
    hook_output(f"[branch-status-reminder] 偵測到 {total_changes} 個未提交變更：", "info")

    # 列出前 MAX_UNCOMMITTED_FILES_DISPLAY 個變更
    for line in files[:MAX_UNCOMMITTED_FILES_DISPLAY]:
        hook_output(f"   {line}", "info")

    # 如果超過上限，顯示還有多少個
    if total_changes > MAX_UNCOMMITTED_FILES_DISPLAY:
        remaining = total_changes - MAX_UNCOMMITTED_FILES_DISPLAY
        hook_output(f"   ...還有 {remaining} 個", "info")

    hook_output("[提示] 這些變更可能來自其他 session，建議先確認後再開始工作", "info")
    hook_output("", "info")
```

**import 調整**

在 branch-status-reminder.py 的 import 區段新增 `get_uncommitted_files`：

```python
from git_utils import (
    get_current_branch,
    get_project_root,
    get_worktree_list,
    is_protected_branch,
    is_allowed_branch,
    is_in_worktree,
    run_git_command,
    get_uncommitted_files,   # 新增
)
```

同時在 fallback import 區段新增對應的 fallback 定義：

```python
def get_uncommitted_files() -> list:
    return []  # 無法查詢時回傳空列表，功能降級
```

### 2.3 問題三：死碼 `total_changes == 0`

**現況分析**

```python
# branch-status-reminder.py:94-100（現況）
# 解析 git status --porcelain 輸出
lines = output.split("\n")
lines = [line for line in lines if line.strip()]  # 過濾空行

total_changes = len(lines)
if total_changes == 0:     # <-- 死碼
    return
```

執行路徑分析：
- 行 90-91：`if not output: return`（output 為空字串時已提前返回）
- 行 96：`lines` 過濾空行後，若 `output` 非空則 `lines` 不可能為空（git porcelain 輸出每個變更至少一行）
- 因此行 99-100 的 `if total_changes == 0: return` 永遠不會執行

**修改方案**

重構後此問題自然消除：
- `get_uncommitted_files()` 已在函式內部處理空列表邏輯
- `_report_uncommitted_changes()` 改為 `if not files: return`，語義清晰且正確

不需要額外操作，死碼隨重構一併移除。

## 3. API 介面定義

### 3.1 新增函式（git_utils.py）

| 項目 | 規格 |
|------|------|
| 函式名稱 | `get_uncommitted_files` |
| 位置 | `.claude/lib/git_utils.py` |
| 插入位置 | 建議放在 `get_project_root()` 之後、`get_worktree_list()` 之前（依功能類型排序：查詢類函式） |

| 型別 | `int` |

| 函式 | 變更類型 | 說明 |
|------|---------|------|

## 5. 邊界條件分析

| 情況 | 預期行為 |
|------|---------|
| git 未安裝或不在 git repo | `run_git_command` 回傳失敗，`get_uncommitted_files()` 回傳 `[]`，`_report_uncommitted_changes` 靜默返回 |
| 無未提交變更 | `get_uncommitted_files()` 回傳 `[]`，`_report_uncommitted_changes` 靜默返回 |
| 恰好 10 個未提交變更 | 顯示全部 10 個，不顯示「...還有 N 個」摘要 |
| 超過 10 個未提交變更 | 顯示前 10 個，顯示「...還有 N 個」摘要 |
| ImportError（git_utils 無法載入） | fallback `get_uncommitted_files` 回傳 `[]`，Hook 靜默不報告 |

## 7. 行為場景（Given-When-Then）

### 場景 1：`get_uncommitted_files` - 有未提交變更（正常流程）

```
Given: 工作目錄有 3 個未提交的檔案變更
When: 呼叫 get_uncommitted_files()
Then: 回傳包含 3 個 git porcelain 格式字串的 list
```

### 場景 2：`get_uncommitted_files` - 無未提交變更（正常流程）

```
Given: 工作目錄乾淨（無未提交變更）
When: 呼叫 get_uncommitted_files()
Then: 回傳空 list []
```

### 場景 3：`get_uncommitted_files` - git 命令失敗（異常流程）

```
Given: 不在 git repo 中，或 git 未安裝
When: 呼叫 get_uncommitted_files()
Then: 靜默回傳空 list []，不拋出例外
```

### 場景 4：`_report_uncommitted_changes` - 超過顯示上限（邊界條件）

```
Given: 工作目錄有 15 個未提交的檔案變更
When: _report_uncommitted_changes(logger) 被呼叫
Then: 顯示前 MAX_UNCOMMITTED_FILES_DISPLAY(=10) 個變更
      顯示「...還有 5 個」摘要訊息
```

### 場景 5：`_report_uncommitted_changes` - 恰好達到顯示上限（邊界條件）

```
Given: 工作目錄有 10 個未提交的檔案變更
When: _report_uncommitted_changes(logger) 被呼叫
Then: 顯示全部 10 個變更
      不顯示「...還有 N 個」摘要訊息
```

### 場景 6：Hook ImportError 降級（異常流程）

```
Given: git_utils 模組無法載入（ImportError）
When: branch-status-reminder Hook 執行，觸發 _report_uncommitted_changes
Then: fallback get_uncommitted_files() 回傳 []
      函式靜默返回，不報告任何變更
      Hook 正常完成，不阻塞 Session
```
