## 核心實作

### 1. ValidationResult 容器
```python
@dataclass
class ValidationResult:
    errors: list[str]      # Layer 1-3 失敗（阻止轉移）
    warnings: list[str]    # Layer 4 失敗或 legacy 降級（提示）
    infos: list[str]       # 資訊性提示
    
    @property
    def can_proceed(self) -> bool:
        return len(self.errors) == 0
```

### 3. 四層驗證邏輯

#### Layer 1：存在性驗證（Existence Check）
- 檢查：必要 artifact 檔案存在
- 行為：ERROR（雙方都阻止）
- 實作：前綴匹配查找
- 故障例子：找不到 `{ticket-id}-phase1-design.md`

#### Layer 2：格式驗證（Format Check）
- 檢查：frontmatter YAML 可解析
- 行為：新文件 ERROR / legacy WARNING
- 實作：`yaml.safe_load()` + exception handling
- 故障例子：YAML 語法錯誤

#### Layer 3：結構驗證（Structure Check）
- 檢查：必要 Section 存在（`## Section 名稱` 匹配）
- 行為：新文件 ERROR / legacy WARNING
- 實作：regex `^##\s+(.+?)$` 提取 Section 名稱
- 故障例子：缺少「驗收條件」Section

#### Layer 4：內容驗證（Content Check）
- 檢查：內容符合規範（長度、格式、欄位）
- 行為：始終 WARNING（不阻止）
- 實作：正則表達式驗證
- 故障例子：
  - 驗收條件 < 3 條
  - direction 欄位不符合 `^to-(sibling|parent|child|context-refresh)(?::[\\w.-]+)?$` 

### 4. Legacy 文件判定（IMP-011 防護）

判定標準（二擇一）：
1. `mtime < contracts.yaml` 建立時間（2026-03-24）
2. frontmatter 缺少 `phase` 欄位

降級策略：
- Layer 2 ERROR → WARNING
- Layer 3 ERROR → WARNING  
- Layer 4 始終 WARNING

安全降級：無法取得 mtime 或 frontmatter 時，預設視為 legacy。

### 5. 前綴匹配解析（IMP-011 核心）

**問題背景**：
```
path_pattern: "{ticket-id}-phase1-design.md"
實際檔案：    "0.1.2-W1-002-phase1-design.md"（主）
           "0.1.2-W1-002-feature-spec.md"（備）
精確匹配失敗，前綴匹配成功
```

**實作**：
```python
def _resolve_artifact_path(ticket_id, artifact_spec, ticket_dir):
    prefix = path_pattern.replace("{ticket-id}", ticket_id)
    base = re.sub(r"\.(md|dart)$", "", prefix)
    # 前綴匹配：startswith() 而非 == 精確匹配
    candidates = [f for f in os.listdir(ticket_dir) if f.startswith(base)]
    if candidates:
        return os.path.join(ticket_dir, candidates[0])
    
    # 嘗試 alternate_patterns
    for alt_pattern in artifact_spec.get("alternate_patterns", []):
        ...
```

**支援的格式變體**：
- `{ticket-id}-phase1-design.md`（主）
- `{ticket-id}-feature-spec.md`（備）
- `{ticket-id}-feature-design.md`（備）
- 等等（由 contracts.yaml 定義）

### 6. complete_phase 整合函式

執行流程：
1. 初始化 `PhaseContractValidator(contracts_path)`
2. 執行 `validator.validate(ticket_id, phase, ticket_dir)`
3. 輸出驗證結果（[ERROR] 和 [WARNING] 前綴）
4. 呼叫 `_write_validation_log()` 寫入 Ticket log
5. 根據 `result.can_proceed` 返回 bool
