修正 phase-contract-validator-hook DRY 違反：完成共用模組重構

---

## Problem Analysis

### 問題根因

phase-contract-validator-hook.py 包含 462 行完整的驗證邏輯，同時 .claude/lib/phase_contract_validator.py 也包含相同邏輯副本，導致：
1. **DRY 違反**：同一業務邏輯存在兩份獨立副本
2. **維護成本高**：修改邏輯時必須同時更新兩個檔案
3. **一致性風險**：兩份副本可能因維護不同步而出現差異

### 影響範圍

- `.claude/hooks/phase-contract-validator-hook.py`（462 行重複邏輯）
- `.claude/lib/phase_contract_validator.py`（副本）
- 任何導入 `PhaseContractValidator` 的 Hook 或模組

### 相關 Error Pattern

無已知 error pattern，屬於代碼品質優化任務

---

## Solution

### 實施策略

1. **新增 `.claude/lib/hook_utils.py`**
   - 提取 `ValidationResult` 和 `PhaseContractValidator` 類別到共用模組
   - 保留完整的四層驗證邏輯和 legacy 判定機制
   - 414 行共用邏輯，供所有 Hook 導入使用

2. **重構 `.claude/hooks/phase-contract-validator-hook.py`**
   - 從 462 行完整邏輯降低至 74 行（僅 Hook 入口點）
   - 導入 `hook_utils.PhaseContractValidator`
   - 保留 `format_validation_result()` 函式供 Hook 格式化輸出
   - 保留命令行測試入口點（`__main__` 塊）

### 向後相容性

- `.claude/lib/phase_contract_validator.py` 保持原樣，供現有代碼引用
- `PhaseContractValidator` 和 `ValidationResult` 的公開 API 無變更
- 所有 Hook 和測試可繼續正常運作

### 優化效果

**程式碼重複減少統計**：
- 原本：462 行（Hook）+ 462 行（lib 副本）= 924 行重複邏輯
- 重構後：74 行（Hook）+ 414 行（hook_utils）= 488 行共用邏輯
- **節省 436 行（47% 減少）**，完全符合 DRY 原則
