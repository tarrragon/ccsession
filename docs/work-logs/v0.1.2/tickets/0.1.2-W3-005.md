## Problem Analysis

## PoC 可行性分析結論：完全可行

### 核心發現

1. **Hook 輸入格式已驗證**：PostToolUse Hook 接收 tool_input.prompt 和 tool_input.description，包含關鍵字（三人組/多視角）

2. **跨 call 狀態追蹤有成熟先例**：
   - session-context-guard-hook.py：已實作 ppid-based 計數器（讀取/遞增/重設）
   - handoff-prompt-reminder-hook.py：已實作 ppid-based JSON 狀態檔 + fcntl.flock 原子操作
   - 模式：/tmp/claude-{purpose}-{ppid} 自動 session 隔離

3. **批次結束信號可行**：UserPromptSubmit Hook 在用戶下一次輸入時觸發，天然作為「上一批 Agent call 結束」信號

4. **Agent matcher 需新增**：settings.json PostToolUse 區段尚無 Agent matcher，但格式明確可新增

### 技術方案

雙 Hook 組合：
- PostToolUse（Agent matcher）：每次 Agent call 時偵測關鍵字 + 遞增計數器
- UserPromptSubmit：讀取上一批計數，若 actual < expected 輸出 WARNING，重設狀態

狀態檔：/tmp/claude-dispatch-batch-{ppid}.json
內容：{ expected: 3, actual: N, keywords: [...], batch_started_at: timestamp }

### SA 質疑的回應

SA 認為「Hook 難以跨越 tool call 邊界」—— 但 session-context-guard-hook.py 已證明 ppid-based 計數器模式可行，且本專案已有 3 個跨 call 狀態追蹤實作。

## 分析結論與建議方案

### 結論：Hook 方案完全可行

基於 PoC 調查，確認「雙 Hook 組合 + ppid 狀態檔」方案技術可行：

1. **PostToolUse Hook**（Agent matcher）
   - 每次 Agent tool 呼叫時觸發
   - 偵測 tool_input.prompt/description 中的關鍵字（三人組/多視角/固定三人組）
   - 寫入狀態檔：/tmp/claude-dispatch-batch-{ppid}.json
   - 狀態內容：{ expected: N, actual: count, keywords: [...], batch_started_at: ISO }

2. **UserPromptSubmit Hook**（全局觸發）
   - 用戶下一次輸入時觸發（批次結束信號）
   - 讀取狀態檔，比對 actual vs expected
   - actual < expected → WARNING 輸出到 stderr
   - 重設/刪除狀態檔

### 技術方案細節

- 狀態隔離：ppid（os.getppid()）自動隔離不同 session
- 過期機制：時間戳 > 5 分鐘自動忽略（避免殘留影響）
- 併發安全：fcntl.flock 原子寫入（參考 handoff-prompt-reminder-hook.py）
- 參考實作：session-context-guard-hook.py 計數器模式

### 修改檔案清單

- 新增：.claude/hooks/dispatch-count-guard-hook.py（PostToolUse 邏輯）
- 修改：.claude/hooks/lib/constants.py（關鍵字常數）
- 修改：.claude/settings.json（新增 Agent matcher + UserPromptSubmit 配置）
