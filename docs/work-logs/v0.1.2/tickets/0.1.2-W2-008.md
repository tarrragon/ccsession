## 設計核心要點

1. **觸發時機**：PreToolUse（Agent 派發前），而非 PostToolUse
   - 理由：在派發前偵測衝突，提早提醒 PM 而非事後驗證
   - 與 parallel-dispatch-verification-hook 形成派發前後的對稱防護

2. **偵測範圍**：同 Wave 中 pending/in_progress 的活躍 Ticket
   - 排除：completed、blocked、不同版本、不同 Wave 的 Ticket
   - 排除：where.files 為空的 Ticket（跳過但不報錯）

3. **衝突判定**：Write-Write（檔案寫入重疊）
   - 目錄前綴匹配：目錄路徑與具體檔案均視為衝突
   - 父子 Ticket 重疊：例外情況，允許（序列執行）

4. **輸出策略**：exit 0 + WARNING 訊息
   - 不阻塊派發，提供可操作的衝突警告
   - 為每個衝突提供 3+ 個解決選項（調整 where.files、建立依賴、序列派發）

5. **邊界情況**：完整定義了 7 個邊界條件（空 where.files、目錄前綴、父子關係、跨 Wave、異常狀態等）

## 設計產出

- 完整功能規格：0.1.2-W2-008-phase1-design.md
- 演算法流程：5 步驟派發前檢查
- 輸出格式：WARNING 訊息含衝突分析 + 建議行動
- 測試場景清單：4 大類 12+ 個測試場景
- 與現有系統整合方案：與 parallel-dispatch-verification-hook 的協作模式

## 關鍵設計決策

| 決策點 | 選擇 | 理由 |
|--------|------|------|
| 觸發時機 | PreToolUse | 派發前防護，提早攔截 |
| 檢查範圍 | 同 Wave 活躍 Ticket | 同時派發的任務才會衝突 |
| 父子重疊 | 允許 | 子任務序列執行，無並行衝突風險 |
| 退出碼 | 0（Warning） | 衝突非 fatal，決策權在 PM |
| 日誌模式 | 雙通道（stderr + 檔案） | 遵循品質基線規則 4 |
