```python
def _report_uncommitted_changes(logger: logging.Logger) -> None:
    """
    偵測並報告未提交的變更

    使用 git_utils.get_uncommitted_files() 獲取變更列表，
    如果超過 MAX_UNCOMMITTED_FILES_DISPLAY 個檔案，只顯示前 N 個並提示還有多少個。
    如果沒有未提交變更，則不輸出任何內容。

    files = get_uncommitted_files()

    if not files:
        return

    total_changes = len(files)

    hook_output(f"[branch-status-reminder] 偵測到 {total_changes} 個未提交變更：", "info")

    for line in files[:MAX_UNCOMMITTED_FILES_DISPLAY]:

        remaining = total_changes - MAX_UNCOMMITTED_FILES_DISPLAY

    hook_output("[提示] 這些變更可能來自其他 session，建議先確認後再開始工作", "info")
```

## 2. 資料結構選擇

### 2.1 git_utils.get_uncommitted_files 回傳型別

**選擇**：`list[str]`（git porcelain 格式的狀態行列表）

**理由**：
- 每行代表一個檔案的狀態（如 ` M file.txt`、`?? new.txt`）
- 呼叫端可自行決定顯示邏輯或進一步處理
- Phase 1 評估表（表格 I-2）已決策，確認 `list[str]` 優於 `dict`（減少複雜度）

### 2.2 常數型別

**選擇**：`int`（單一數字值）

**定義**：
```python
MAX_UNCOMMITTED_FILES_DISPLAY = 10
```

**位置**：branch-status-reminder.py 頂部（import 之後、函式定義之前）

**理由**：符合 quality-common.md 規則 1.3.2「單一檔案使用 → 檔案頂部模組常數」

## 7. 語言特定實作注意事項

### Python 考量

#### 型別標註

```python
def get_uncommitted_files() -> list[str]:
    # 使用 Python 3.10+ 原生 list[str]，不用 List[str]
    pass
```

- 確認使用 `list[str]`（Python 3.10+ 語法）而非 `List[str]`（typing 模組）
- 與 git_utils.py 既有函式一致（已使用 `tuple[bool, str]` 等語法）

#### 列表推導式最佳化

```python
# 現有做法（優化空間）
lines = [line for line in lines if line.strip()]

# 備選（更簡潔）
lines = [line for line in output.split("\n") if line.strip()]
```

實作時可直接在 split 後執行過濾，無需中間變數。

#### import 順序（PEP 8）

在 branch-status-reminder.py 的 import 區段新增 `get_uncommitted_files` 時，遵循既有順序：
1. 標準庫（sys, subprocess, logging, pathlib）
2. 相對 import（hook_utils, common_functions）
3. git_utils 中的多函式 import

```
認知負擔指數 = 變數數 + 分支數 + 巢狀深度 + 依賴數
```

- 分支數：1（success AND output check）
- 巢狀深度：2（if-split-filter）
- 依賴數：1（run_git_command）
- **指數 = 4 + 1 + 2 + 1 = 8**

- 分支數：2（if not files，if total_changes > limit）

- 依賴數：2（get_uncommitted_files, hook_output）
- **指數 = 3 + 2 + 1 + 2 = 8**
