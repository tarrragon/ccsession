### v0.1.2 多視角審查發現的系統性品質問題

**審查日期**：2026-03-23
**審查對象**：W1-001~004（4 個 Protocol 正規化 Ticket）
**審查方式**：4 個 saffron-system-analyst 並行五視角審查

**發現的共通問題模式**：

| 問題模式 | 出現次數 | 嚴重度 | 說明 |
|---------|---------|--------|------|
| 驗收條件含糊（缺量化標準） | 4/4 | 高 | 「遷移邏輯完整」「向後相容 100%」等無法客觀判定 |
| Problem Analysis 空白 | 4/4 | 高 | 代理人無法獨立執行，需自行補充大量調查 |
| 依賴關係未標記 | 3/4 | 高 | W1-002 未標 blockedBy W1-001；W1-004 未標 blockedBy W1-002/003 |
| who 未指定執行代理人 | 4/4 | 中 | 均為 pending，未指派 |
| how.strategy 過於籠統 | 4/4 | 中 | 單行策略描述，無法指導實作 |
| 認知負擔超閾值（需拆分） | 4/4 | 高 | 指數 20~162，全部超過閾值 10 |
| where.files 不完整 | 2/4 | 中 | 缺少受影響的 Hook 和規則檔 |

**根因推測**：
1. ticket create CLI 模板未強制要求具體驗收條件格式
2. Problem Analysis 區段只有 placeholder，無引導問題
3. 依賴分析不在 create 流程中（建立後才由審核發現）
4. 認知負擔評估不在 create 流程中

### 子任務審查補充發現（第二輪審查，同日）

**審查對象**：W1-001.1~.3、W1-002.1~.3、W1-003.1~.3（9 個子任務）
**審查方式**：3 個 saffron-system-analyst 分組審查

**子任務特有的問題模式**：

|---------|---------|--------|------|

## 根因驗證結果

4 個根因全部成立，附 1 個額外發現。

### 根因 1：驗收條件預設模板含糊（成立，高優先）

**程式碼位置**：`ticket_builder.py` 第 32-71 行 `DEFAULT_ACCEPTANCE_CRITERIA`

**現狀**：IMP 類型預設為 `["任務實作完成", "相關測試通過", "無程式碼品質警告"]`，完全不可量化。4V 提示只在建立完成後輸出靜態文字（`create.py` 第 365-366 行），不影響實際寫入的條件。`acceptance_auditor.py` 的驗收檢查只驗 `[x]` 勾選狀態，不驗描述品質。

**改善方案**：
- **A1-1**（模板強化）：將 `DEFAULT_ACCEPTANCE_CRITERIA` 改為含量化佔位符的模板（如 `"指定功能實作完成，通過 N 個測試案例"`）
- **A1-2**（驗證規則）：在 `acceptance_auditor.py` 新增「含糊條件偵測」，掃描「完成」「驗證通過」等模糊詞彙並輸出 WARN
- **A1-3**（建立時警告）：使用預設條件時額外輸出警告，提醒需修改

**影響範圍**：ticket_builder.py、acceptance_auditor.py、command_lifecycle_messages.py
**優先級**：高 — 影響所有未指定 --acceptance 的 Ticket

### 根因 2：Problem Analysis 為不可見的 HTML 註解（部分成立，中優先）

**程式碼位置**：`ticket_builder.py` 第 484-493 行 `create_ticket_body()`

**現狀**：PA 區段使用 `<!-- -->` HTML 註解，代理人閱讀時不顯示。引導內容只面向建立者，不面向執行者。`acceptance_auditor.py` 將 HTML 註解識別為 placeholder（空白）。

**改善方案**：
- **A2-1**（結構化 PA 模板）：將 PA 區段改為帶佔位文字的結構化格式（問題根因/影響範圍/相關 Error Pattern 三個子區段）
- **A2-2**（保留引導）：HTML 註解保留為開發指引，但加在結構化區段之後作為備註

**影響範圍**：ticket_builder.py（create_ticket_body()）
**優先級**：中 — UX 問題，修改模板風險低

### 根因 3：依賴分析靠手動無自動檢查（部分成立，中優先）

**程式碼位置**：`create.py` 第 228-230 行

**現狀**：`--blocked-by` 完全被動接受輸入，不做存在性驗證。`ticket_validator.py` 有循環依賴檢測（第 525-586 行）但不在 create 路徑中呼叫。建立後 checklist 只有靜態一行文字。

**改善方案**：
- **A3-1**（存在性驗證）：create 時驗證 blocked_by 中的 Ticket ID 是否存在，不存在則 WARNING
- **A3-2**（啟發式提示）：checklist 中依任務類型提供依賴判斷指引
- **A3-3**（循環偵測前移）：將 validate_blocked_by() 加入 create 路徑

**影響範圍**：create.py、command_lifecycle_messages.py
**優先級**：中

### 根因 4：無認知負擔自動評估（完全成立，低優先）

**程式碼位置**：`create.py` 第 179-330 行（無任何評估邏輯）

**現狀**：checklist 只有靜態提示。where_files 允許空值（"待定義"），無法可靠計算認知負擔。ParallelAnalyzer 只分析檔案衝突不算認知負擔。

**改善方案**：
- **A4-1**（初步評估）：where_files > 5 個時自動 WARNING 並建議拆分
- **A4-2**（輔助函式）：ticket_builder.py 新增 estimate_cognitive_load() 基於可量化指標
- **A4-3**（空值警告）：where_files 為空時提示「無法評估認知負擔」

**影響範圍**：create.py、ticket_builder.py、command_lifecycle_messages.py
**優先級**：低 — 依賴 where_files 必填性改善

### 額外發現：子任務欄位不繼承

**程式碼位置**：`create.py` 第 190-204 行

**現狀**：`--parent` 建立子任務只繼承 wave 號和序號，where_layer、why、who 等欄位全部重設預設值，父 Ticket 上下文完全遺失。

**改善方案**：
- **A5-1**（自動繼承）：載入 parent Ticket 後將 where_layer、why、who 作為子任務預設值
- **A5-2**（blockedBy 提示）：子任務建立後提示「是否需要設定 blockedBy 其他兄弟子任務？」

**影響範圍**：create.py
**優先級**：中
