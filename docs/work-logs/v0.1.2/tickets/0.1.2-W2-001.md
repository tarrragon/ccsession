## Problem Analysis

### v0.1.2 多視角審查發現的系統性品質問題

**審查日期**：2026-03-23
**審查對象**：W1-001~004（4 個 Protocol 正規化 Ticket）
**審查方式**：4 個 saffron-system-analyst 並行五視角審查

**發現的共通問題模式**：

| 問題模式 | 出現次數 | 嚴重度 | 說明 |
|---------|---------|--------|------|
| 驗收條件含糊（缺量化標準） | 4/4 | 高 | 「遷移邏輯完整」「向後相容 100%」等無法客觀判定 |
| Problem Analysis 空白 | 4/4 | 高 | 代理人無法獨立執行，需自行補充大量調查 |
| 依賴關係未標記 | 3/4 | 高 | W1-002 未標 blockedBy W1-001；W1-004 未標 blockedBy W1-002/003 |
| who 未指定執行代理人 | 4/4 | 中 | 均為 pending，未指派 |
| how.strategy 過於籠統 | 4/4 | 中 | 單行策略描述，無法指導實作 |
| 認知負擔超閾值（需拆分） | 4/4 | 高 | 指數 20~162，全部超過閾值 10 |
| where.files 不完整 | 2/4 | 中 | 缺少受影響的 Hook 和規則檔 |

**根因推測**：
1. ticket create CLI 模板未強制要求具體驗收條件格式
2. Problem Analysis 區段只有 placeholder，無引導問題
3. 依賴分析不在 create 流程中（建立後才由審核發現）
4. 認知負擔評估不在 create 流程中

### 子任務審查補充發現（第二輪審查，同日）

**審查對象**：W1-001.1~.3、W1-002.1~.3、W1-003.1~.3（9 個子任務）
**審查方式**：3 個 saffron-system-analyst 分組審查

**子任務特有的問題模式**：

| 問題模式 | 出現次數 | 嚴重度 | 說明 |
|---------|---------|--------|------|
| Problem Analysis 空白（不繼承父任務） | 9/9 | 高 | 子任務未從父任務摘錄相關設計決策和背景 |
| blockedBy 未正確設定 | 3/9 | 高 | 序列子任務間的依賴未標記（如 .2 應 blockedBy .1） |
| where.files 只列主檔案 | 7/9 | 中 | 缺少依賴輸入檔、測試檔案、受影響的現有檔案 |
| when/why/layer 為「待定義」 | 3/9 | 中 | 未從父任務繼承基本欄位 |
| 認知負擔仍超閾值 | 1/9 | 中 | W1-001.3 (Hook+dry-run) ~15，建議再拆分 |

**根因補充**：
1. `ticket create --parent` 建立子任務時，**不自動繼承父任務的 Problem Analysis、why、when、layer**
2. 子任務的 `blockedBy` 需要手動設定，CLI 不會從並行分析結果自動推導
3. 子任務的 `where.files` 只接受 CLI 參數，不會從父任務的分析報告或 how.strategy 提取完整檔案清單

**改善方向建議**：
- ticket create --parent 時自動繼承父任務的 why、when、where.layer
- 子任務建立後自動提示：「是否需要設定 blockedBy 其他兄弟子任務？」
- Problem Analysis 區段應包含引導問題（而非空白 placeholder），例如：
  - 「從父任務 {parent_id} 摘錄相關段落：」
  - 「列出本子任務的具體修改範圍和受影響檔案：」
  - 「引用分析報告中的設計決策：」

**參考資料**：
- 完整審查報告在本次 session 對話中（7 個 saffron agent 產出）
- 設計決策已記錄：docs/work-logs/v0.1.1/tickets/0.1.1-W14-001-analysis.md（附錄）
