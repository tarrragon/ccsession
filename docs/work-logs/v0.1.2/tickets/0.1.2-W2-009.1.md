## Problem Analysis

根因：Phase Contract Validator 中的 legacy 判定邏輯有兩個 P0 級 bug：
1. **mtime 比較邏輯**（第 378 行）：日期字符串 '2026-03-24' 無時間部分，與秒級時間戳比較時未設置日期邊界（UTC 0:00:00），導致邊界條件不一致。
2. **frontmatter.phase 檢查邏輯**（第 389 行）：代碼檢查缺少 'phase' 欄位就判定為 legacy，但根據 contracts.yaml（第 44-47 行），phase 欄位在 frontmatter_schema 中為 optional=false。此邏輯導致符合規範的新文件被誤判為 legacy。

結果：non-legacy 文件被誤判為 legacy，降級了正常的 Layer 2/3 error 驗證。

修復策略（IMP-044）：
1. **mtime 比較改進**：將 threshold date 字符串 '2026-03-24' 轉換為 datetime 對象並明確設置為當天的 UTC 0:00:00 邊界（使用 .replace(hour=0, minute=0, second=0, microsecond=0)）。確保時間比較時使用一致的時區和粒度。

2. **移除不合理的 frontmatter 檢查**：完全移除「缺少 phase 欄位判定為 legacy」的邏輯（原第 381-393 行）。根據 contracts.yaml schema，phase 是 optional 欄位，不應作為 legacy 判定條件。

3. **簡化判定標準**：Legacy 判定現在只基於一個條件：檔案 mtime 嚴格早於 threshold date（不包含 threshold 當天）。邏輯清晰，避免混淆。
