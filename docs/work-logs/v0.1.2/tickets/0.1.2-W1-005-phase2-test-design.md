# 0.1.2-W1-005 Phase 2 測試設計

## 1. 測試策略

### 1.1 測試層級與分布

Protocol Version 機制涉及三個層級的測試：

| 層級 | 模組 | 測試類型 | 優先級 |
|------|------|---------|--------|
| **Unit** | constants.py | 常數和正則表達式驗證 | 高 |
| **Unit** | migrations.py | 遷移邏輯 | 高 |
| **Unit** | protocol-version-check-hook.py | Hook 邏輯 | 高 |
| **Integration** | Ticket 載入全流程 | Hook 觸發 + 遷移完整性 | 中 |
| **E2E** | dry-run 驗證腳本 | 全量 ticket 遷移 | 中 |

### 1.2 測試優先級排序

**優先級 P0（必須）**：遷移邏輯正確性、無資訊遺失、格式驗證
**優先級 P1（重要）**：Hook 觸發時機、邊界條件處理
**優先級 P2（參考）**：錯誤訊息格式、日誌輸出

## 9. 設計決策記錄

### 決策 1：為何採用 5 個測試檔案而非單一檔案？

**選擇**：按功能模組拆分測試檔案
- test_constants.py：常數定義
- test_migrations.py：遷移邏輯
- test_protocol_version_check_hook.py：Hook 行為
- test_migration_integration.py：端對端流程
- test_migration_dryrun.py：全量驗證

**理由**：
- 降低單一檔案的認知負擔
- 便於 Phase 3b 並行實作
- 各檔案可獨立驗證對應子任務

### 決策 2：為何 Hook 測試不包括實際文件 I/O？

**選擇**：Mock file I/O，測試 Hook 邏輯而非系統 I/O
**理由**：
- 遵循 Sociable Unit Tests 原則（只隔離外部依賴）
- 避免測試環境中需要建立真實 ticket 檔案
- Phase 3b dry-run 驗證時會測試真實文件

### 決策 3：為何 TC-201.2 測試非 ticket 檔案路徑？

**選擇**：明確測試 Hook 的路徑過濾邏輯
**理由**：
- 驗證 Hook 不會在無關檔案上觸發
- 確保 Hook 在全域適用時的選擇性

## 10. 其他測試相關注意事項

### 10.1 測試命名規範

所有測試函式遵循 `test_{功能}_{場景}` 格式：
```python
def test_constants_protocol_version_current_defined():
    """TC-001: 驗證常數定義"""
    pass

def test_migrate_ticket_v1_to_v2_preserves_fields(standard_ticket_v1):
    """TC-106: 驗證無資訊遺失"""
    pass
```

### 10.2 斷言方式

優先使用 assert 而非 unittest assertion，遵循 pytest 規範：
```python
# 優先
assert result["protocol_version"] == "2.0"

# 次要（需要時使用自訂訊息）
assert result["id"] == ticket_data["id"], "ID 應保留不變"
```

### 10.3 錯誤訊息檢查

對於驗證 _migration_warning 欄位的測試，驗證訊息內容（而非只驗證存在）：
```python
assert "_migration_warning" in result
assert "格式異常" in result["_migration_warning"]
```
