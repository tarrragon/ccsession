## Problem Analysis

### 派發決策規則散落位置

**現狀**：Agent 派發規則分散在 5+ 個檔案（待接手者驗證）：
- .claude/rules/core/decision-tree.md — 第五層 TDD Phase 代理人、第二層半檔案類型派發
- .claude/rules/flows/incident-response.md — 錯誤分類派發對應表
- .claude/rules/guides/query-vs-research.md — 查詢類派發
- .claude/rules/guides/parallel-dispatch.md — 並行派發條件
- .claude/agents/*.md — 各 agent 自然語言能力描述（30+ 個檔案）

**架構定位（已確認）**：
- Registry 是「能力資料層」（Source of Truth）：誰能做什麼、接受什麼、產出什麼
- decision-tree.md 仍是 PM 的「決策引擎」：行為判斷、流程路由、任務分類
- 架構分工：decision-tree（判斷需要什麼能力）→ registry（查詢誰有這個能力）→ Hook（驗證）
- Registry **不取代** decision-tree 的決策邏輯

**衝突檢查範圍（已確認，三種全覆蓋）**：
1. Agent 同時派發衝突（不相容 agent 同時執行）
2. TDD Phase 相序衝突（Phase 執行順序違反）
3. 檔案寫入衝突（ARCH-005：多 agent 同時寫同一檔案）

**關鍵設計問題（待 Phase 1 解決）**：
- Registry 與現有 .md 定義如何共存？（建議：registry 為機器讀取，.md 保留人類可讀的詳細指引）
- 新增 agent 時的維護流程？（需同時更新 registry + .md）
