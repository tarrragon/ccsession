## Problem Analysis

### 問題根因

場景 #16（錯誤學習經驗確認）的現有流程只提及「/error-pattern add」，未強制說明必須同時更新 memory（雙通道）。askuserquestion-rules.md 場景 #16 說明也缺少雙通道要求。導致 PM 可能只更新其中一個通道而未察覺違規。

### 影響範圍

- `.claude/hooks/lib/ask_user_question_reminders.py`：COMMIT_HANDOFF_REMINDER 常數中的 #16 說明文字
- `.claude/rules/core/askuserquestion-rules.md`：場景 #16 規則說明，缺少雙通道要求

1. **採用文字常數更新而非新增偵測邏輯**：Hook 在 commit 後才觸發，無法可靠偵測「選擇了記錄但只做一半」的情況；直接在 COMMIT_HANDOFF_REMINDER 中嵌入雙通道要求文字更可靠。

2. **兩個修改對象**：
   - `ask_user_question_reminders.py`：更新 COMMIT_HANDOFF_REMINDER 常數中的 #16 說明，加入雙通道要求和 WARNING 文字
   - `askuserquestion-rules.md`：新增「場景 #16 雙通道記錄要求」獨立說明區塊

3. **不影響現有 Hook 邏輯**：屬於文字常數更新，不需修改 is_git_commit_command、extract_commit_type 等函式
