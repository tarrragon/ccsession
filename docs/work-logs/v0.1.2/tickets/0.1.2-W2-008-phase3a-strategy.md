### 1.3 關鍵實作決策

**決策 1：路徑規範化的順序**

| 步驟 | 原因 |
|------|------|
| 1. 反斜線→正斜線 | Windows 相容性，必須在其他步驟前 |
| 2. 簡化多重斜線 `//` | 避免 `./` 移除後失效 |
| 3. 移除 `./` 前綴 | 去除相對路徑標記 |
| 4. 移除尾斜線 | 統一目錄表示（`lib/` → `lib`） |
| 5. 轉小寫 | 跨平台一致性 |

**決策 2：衝突偵測的前綴匹配算法**

```python
# 虛擬碼：路徑前綴匹配

def paths_conflict(a: str, b: str) -> bool:
    """判斷兩個路徑是否衝突"""
    # 完全相同
    if a == b:
        return True

    # 前綴包含（處理 "lib/" vs "lib/create.py" 情況）
    # 需要確保前綴後接 "/" 或為完整路徑段

    if a.startswith(b + "/"):
        return True  # b 是 a 的父目錄

    if b.startswith(a + "/"):
        return True  # a 是 b 的父目錄

    return False


def find_conflicts(where_files: list[str], other_files: list[str]) -> list[str]:
    """找出衝突的檔案"""
    conflicts = []

    for file_a in where_files:
        for file_b in other_files:
            if paths_conflict(file_a, file_b):
                conflicts.append(file_a)
                break  # 只需要記錄一次

    return conflicts
```

**決策 3：父子 Ticket 重疊的識別**

```python
# 虛擬碼：檢查父子關係

def is_parent_child_overlap(
    target_parent_id: str | None,
    other_parent_id: str | None,
    target_id: str,
    other_id: str
) -> bool:
    """判斷兩個 Ticket 是否為父子關係"""
    # 情況 1：target 是 other 的父
    if other_parent_id == target_id:
        return True

    # 情況 2：other 是 target 的父
    if target_parent_id == other_id:
        return True

    # 情況 3：兩者有共同父（兄弟）但不同「角度」
    # 在衝突篩選時判斷（父子允許重疊，兄弟需要報警）

    return False
```

**決策 4：Ticket 篩選的條件優先級**

```
篩選條件（AND 關係，全部符合才納入檢查）：
1. 版本相同（從 Ticket ID 提取）
2. Wave 相同（從 Ticket ID 提取）
3. 狀態為 pending 或 in_progress（排除 completed/blocked）
4. 不是目標 Ticket 本身
5. where.files 非空（沒有 where.files 的 Ticket 跳過，不報錯）
```

## 2. 資料結構選擇

### 2.1 ConflictInfo 資料類

```python
# 虛擬碼：衝突資訊資料結構

class ConflictInfo:
    """單個衝突的詳細資訊"""

    # 基本資訊
    target_ticket_id: str           # 派發目標（如 0.1.2-W2-003）
    conflicting_ticket_id: str      # 衝突對象（如 0.1.2-W2-001.1）

    # 衝突詳情
    conflicting_files: list[str]    # 重疊的檔案清單（已規範化）
    is_parent_child: bool           # 是否為父子關係

    # 衝突類型（用於訊息分類）
    conflict_type: str              # 'brother'|'unrelated'|'parent'|'none'

    # 額外上下文（用於訊息生成）
    common_parent_id: str | None    # 若為兄弟，共同父 ID
    target_parent_id: str | None    # 目標 Ticket 的父
    other_parent_id: str | None     # 衝突 Ticket 的父
```

### 2.2 選擇理由

| 選擇 | 原因 |
|------|------|
| 使用類別而非字典 | 類型安全，IDE 自動完成，訊息生成時明確欄位 |
| 包含 parent_id 資訊 | 支援父子關係的判斷和訊息分類 |
| 包含 conflict_type 列舉 | 訊息層可根據類型調整說詞（兄弟/無關語氣不同） |
| 使用清單而非集合 | 便於訊息排序，防止順序隨機 |

## 7. 語言特定實作注意事項

### Python 考量

**版本**：Python 3.11+（使用 `log/slog` 標準庫）

| 項目 | 做法 | 說明 |
|------|------|------|
| 型別標註 | 完整標註所有公開函式 | 提高可維護性 |
| 常數管理 | 所有常數在模組頂部 | 便於維護和測試 |
| 日誌 | 使用 hook_logging 模組 | 遵循 quality-baseline.md 雙通道要求 |
| 異常處理 | try-except 必須有 logger | 禁止靜默失敗（except 區塊必須記錄） |
| 字串格式化 | f-string | Python 3.11+ 的慣例 |
| 路徑操作 | pathlib.Path | 更安全的跨平台支援 |

**最佳化建議**：
- 避免重複掃描檔案系統（考慮快取或傳入已掃描的清單）
- 正則表達式編譯時預編譯（re.compile）
- 大量衝突時考慮分批輸出而不是全部累積

**可能的技術挑戰**：
- Windows vs Unix 路徑分隔符（normalize_path 已處理）
- YAML 解析的 where.files 可能為 list 或 dict（需容錯）
- Git 命令超時（set timeout）
