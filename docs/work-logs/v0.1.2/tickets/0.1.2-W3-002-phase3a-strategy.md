## 1. 實作策略設計

### 核心目標

設計一個語言無關的 SRP（單一職責原則）偵測機制，分為兩層實作：

1. **create 層**（輕量提示）：在 Ticket 建立時，對 what 欄位和驗收條件進行快速偵測，輸出 WARNING 提示但不阻止建立
2. **SA 層**（詳細檢查）：在 Phase 0 SA 審查中，執行四大檢查（語義/修改原因/驗收一致性/依賴獨立性）

### 實作順序（優先度排列）

**第一優先**：定義常數和工具函式
- 新增 SRP_WHAT_CONJUNCTIONS 常數清單（並列連接詞）
- 新增 SRP_ACCEPTANCE_MODULE_THRESHOLD 常數（模組數閾值）
- 新增訊息常數（SRP_MULTI_TARGET_WARNING, SRP_CROSS_MODULE_WARNING）

**第二優先**：實作兩個基礎偵測函式
- `_detect_srp_multi_target(what_text)` → 私有函式，偵測 what 欄位中的並列連接詞
- `_detect_srp_cross_module(acceptance_list)` → 私有函式，偵測驗收條件中的跨模組特徵

**第三優先**：實作協調函式
- `detect_srp_violations(what_text, acceptance_list)` → 公開函式，串聯兩個偵測器，回傳統一的結果格式

**第四優先**：整合至 create 命令
- 在 `_print_create_checklist` 函式中呼叫 `detect_srp_violations`
- 在認知負擔評估之後、驗收條件格式檢查之前插入呼叫點
- 輸出 WARNING 訊息（非阻止性）

**第五優先**：擴充 SA 層職責
- 在 saffron-system-analyst.md 中新增「SRP 四大檢查」章節
- 定義檢查項目、判斷問題、通過標準
- 更新 SA 審查報告模板

## 2. 虛擬碼和邏輯流程

### 2.1 `_detect_srp_multi_target(what_text)` 虛擬碼

```
函式：_detect_srp_multi_target(what_text: str) → (bool, list[str])

前置條件：
  - what_text 可為任何字串值

執行步驟：
1. Guard Clause：
   - 若 what_text 為 None 或空字串 → 回傳 (False, [])
   - 若 what_text 長度 < 2 → 回傳 (False, [])

2. 初始化：
   - found_conjunctions ← 空清單
   - conjunction_set ← SRP_WHAT_CONJUNCTIONS（連接詞清單）

3. 掃描並列連接詞：
   FOR 每個連接詞 IN conjunction_set:
     - 搜尋連接詞在 what_text 中是否出現
     - IF 出現 THEN:
         - 將連接詞添加至 found_conjunctions
       ENDIF
   ENDFOR

4. 判斷結果：
   - IF found_conjunctions 為空 THEN:
       回傳 (False, [])
     ELSE:
       回傳 (True, found_conjunctions)
   ENDIF

後置條件：
  - 回傳值為 (bool, list) 格式
  - 不拋出例外
  - 不修改輸入參數
```

### 2.2 `_detect_srp_cross_module(acceptance_list)` 虛擬碼

```
函式：_detect_srp_cross_module(acceptance_list: list[str]) → (bool, list[str])

前置條件：
  - acceptance_list 可為 None 或任何清單

執行步驟：
1. Guard Clause：
   - 若 acceptance_list 為 None → 回傳 (False, [])
   - 若 acceptance_list 為空清單 → 回傳 (False, [])

2. 初始化：
   - detected_modules ← 空集合（使用集合自動去重）
   - module_threshold ← SRP_ACCEPTANCE_MODULE_THRESHOLD（預設 2）

3. 掃描驗收條件並提取模組名稱：
   FOR 每個 acceptance_item IN acceptance_list:
     - IF acceptance_item 為 None 或非字串 THEN:
         跳過此項
       ENDIF

     - 執行模組識別（三種識別方式優先級）：
       a) 識別方式 1：檔案路徑（含 .py）
          搜尋模式：xxx.py / xxx_yyy.py
          提取模組名稱（去除 .py）

       b) 識別方式 2：Python 模組名（snake_case）
          搜尋模式：ticket_loader, constants, create

       c) 識別方式 3：類別名稱（PascalCase）
          搜尋模式：CreateMessages, SrpDetector

     - IF 找到模組名稱 THEN:
         - 規範化模組名稱（轉小寫、移除副檔名）
         - 添加至 detected_modules 集合
       ENDIF
   ENDFOR

4. 判斷結果：
   - module_count ← detected_modules 的大小

   - IF module_count > module_threshold THEN:
       回傳 (True, [detected_modules 的清單表示])
     ELSE:
       回傳 (False, [])
   ENDIF

後置條件：
  - 回傳值為 (bool, list) 格式
  - 不拋出例外
  - 無法識別模組時不誤報
```

### 2.3 `detect_srp_violations(what_text, acceptance_list)` 虛擬碼

```
函式：detect_srp_violations(what_text: str, acceptance_list: list[str]) → (bool, list[str])

前置條件：
  - what_text 可為任何值（預期字串或 None）
  - acceptance_list 可為任何值（預期清單或 None）

執行步驟：
1. Guard Clause：
   - 若 what_text 為 None 或空字串 THEN:
       what_text ← ""
   ENDIF

2. 初始化：
   - warning_messages ← 空清單
   - has_any_issue ← False

3. 執行 what 欄位偵測：
   - (has_what_issue, conjunctions) ← _detect_srp_multi_target(what_text)

   - IF has_what_issue THEN:
       - 構建警告訊息：
         message ← format SRP_MULTI_TARGET_WARNING with conjunctions
       - 添加至 warning_messages
       - has_any_issue ← True
   ENDIF

4. 執行 acceptance 欄位偵測：
   - (has_accept_issue, modules) ← _detect_srp_cross_module(acceptance_list)

   - IF has_accept_issue THEN:
       - 構建警告訊息：
         message ← format SRP_CROSS_MODULE_WARNING with modules
       - 添加至 warning_messages
       - has_any_issue ← True
   ENDIF

5. 回傳結果：
   - IF has_any_issue THEN:
       回傳 (True, warning_messages)
     ELSE:
       回傳 (False, [])
   ENDIF

後置條件：
  - 回傳值第一元素為 True 表示「有疑慮」（與 detect_vague_acceptance 相反語義）
  - 不拋出例外
  - warning_messages 為非空清單（當有疑慮時）
```

### 2.4 create 命令整合流程

```
在 _print_create_checklist 函式中：

執行步驟：
1. 位置確認：
   - 在 _print_cognitive_load_assessment() 呼叫之後
   - 在驗收條件格式提示（ACCEPTANCE_4V_CHECK）之前
   - 在含糊驗收偵測（detect_vague_acceptance）之前

2. Guard Clause：
   - IF new_ticket 為 None THEN:
       跳過 SRP 偵測
   ENDIF

3. 提取資料：
   - what_text ← new_ticket.get("what", "") or ""
   - acceptance ← new_ticket.get("acceptance", []) or []

4. 呼叫 SRP 偵測：
   - (has_srp_issue, srp_warnings) ← detect_srp_violations(what_text, acceptance)

5. 輸出警告：
   - IF has_srp_issue THEN:
       FOR 每個 warning IN srp_warnings:
         - print format_warning(warning)
   ENDIF

6. 後續流程：
   - 繼續現有流程（驗收條件格式、含糊驗收等）
   - SRP 警告不影響 exit code（非阻止性）
```

## 3. 資料結構選擇

### 常數設計

**SRP_WHAT_CONJUNCTIONS**
- 類型：字串清單
- 值：`["和", "與", "及", "並", "同時"]`
- 用途：定義並列連接詞的完整清單
- 維護優勢：集中定義，便於後續擴充

**SRP_ACCEPTANCE_MODULE_THRESHOLD**
- 類型：整數
- 值：2
- 用途：驗收條件跨模組偵測的閾值（超過則觸發 WARNING）
- 設計理由：允許 1-2 個模組（合理範圍），3 個以上視為跨模組

### 訊息常數設計

**SRP_MULTI_TARGET_WARNING**
```
[WARNING] what 欄位含連接詞「{conjunctions}」，疑似包含多個獨立目標
          Atomic Ticket 原則：一個 Ticket = 一個 Action + 一個 Target
          建議：考慮拆分為多個 Ticket，或確認目標確實是單一職責
```

**SRP_CROSS_MODULE_WARNING**
```
[WARNING] 驗收條件涉及多個模組（{modules}），疑似包含多個職責
          Atomic Ticket 原則：所有驗收條件應指向同一目標
          建議：確認是否需要拆分為多個獨立 Ticket
```

### 回傳值語義說明

| 函式 | 回傳值第一元素 | 語義 |
|-----|--------------|------|
| `_detect_srp_multi_target` | True | 偵測到連接詞（疑慮） |
| `_detect_srp_multi_target` | False | 未偵測到連接詞（正常） |
| `_detect_srp_cross_module` | True | 偵測到跨模組（疑慮） |
| `_detect_srp_cross_module` | False | 未偵測到跨模組（正常） |
| `detect_srp_violations` | True | 有 SRP 疑慮（警告） |
| `detect_srp_violations` | False | 無 SRP 疑慮（正常） |

**注意**：`detect_srp_violations` 的回傳值語義與 `detect_vague_acceptance` 相反
- `detect_vague_acceptance`: True = 無嚴重問題（反向）
- `detect_srp_violations`: True = 有疑慮（正向）

## 7. 權宜方案與技術債務

### 最小可行實作

**create 層設計**（本 Ticket 範圍）：
- 使用簡單的字串 `in` 運算子進行連接詞匹配
- 使用正則表達式或字串分割進行模組識別
- 模組識別採用三層優先級（檔案路徑 > snake_case > PascalCase）

**SA 層設計**（Phase 1 擴充，文件層面）：
- 四大檢查採用人工審查，不自動化
- 提供標準化檢查清單，便於 SA 代理人操作

### 已知限制

1. **連接詞偵測的誤報風險**：
   - 「的」字修飾詞可能在某些句式中誤認為連接詞
   - 未來可改進：使用 NLP 或更複雜的文法規則

2. **模組識別的誤報風險**：
   - 驗收條件中若含有類似「constants」等通用詞可能被誤認為模組
   - 未來可改進：維護模組白名單，而非通用識別

3. **閾值設定的侷限**：
   - SRP_ACCEPTANCE_MODULE_THRESHOLD = 2 是固定值
   - 未來可改進：根據 Ticket 類型動態調整閾值

### 技術債務標記（Phase 4 建議）

| 債務 ID | 描述 | 優先級 | Phase 4 建議 |

| TD-SRP-001 | 連接詞偵測不使用 NLP，誤報風險高 | 低 | 後續版本考慮 NLP 集成 |
| TD-SRP-002 | 模組識別採用啟發式方法，可能失準 | 低 | 建立模組白名單或檔案擴掃 |

## 9. 語言特定實作注意事項

### Python 考量

**字串匹配**：
- 使用 `in` 運算子進行子字串搜尋（O(n) 時間複雜度，足夠）
- 可選：使用 `re.search()` 進行更複雜的模式匹配（Phase 4 優化）

**模組識別邏輯**：
- 優先級 1：使用正則表達式 `r'(\w+)\.py'` 識別檔案路徑
- 優先級 2：使用 `re.findall(r'[a-z_]+', text)` 識別 snake_case 模組名
- 優先級 3：使用 `re.findall(r'[A-Z][a-zA-Z]+', text)` 識別 PascalCase 類別名

**集合去重**：
- 使用 Python 的 `set` 自動去重模組名稱
- 最後轉換為 `list()` 供回傳

**例外處理**：
- 所有函式都使用 Guard Clause 避免拋出例外
- 不使用 `try-except`（不需要，邏輯簡單）

**型別標註**：
- 所有參數和回傳值都有完整的型別標註
- 使用 `Optional[List[str]]` 標註可選參數
