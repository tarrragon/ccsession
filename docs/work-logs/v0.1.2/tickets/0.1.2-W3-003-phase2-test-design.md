# Phase 2 測試設計：ticket create 建立前重複偵測查詢機制

---

## 1. 測試策略規劃

### 1.1 分層測試決策

根據程式碼層級選擇測試策略：

| 層級 | 模組 | 測試策略 | 理由 |
|------|------|---------|------|
| Domain（複雜邏輯） | `_calculate_jaccard_similarity` | 單元測試（純算法） | 計算邏輯獨立，需完整覆蓋 |
| UseCase（行為邏輯） | `_detect_duplicate_tickets` | BDD 測試（Given-When-Then） | 業務流程，需驗證行為順序 |
| Integration | `execute()` 中的呼叫整合 | 整合測試 | 驗證呼叫時機、資料流 |

### 1.2 Sociable Unit Tests 原則應用

| 依賴 | Mock 策略 |
|------|----------|
| `list_tickets()` | Mock（外部依賴） |
| `constants.DUPLICATE_DETECTION_THRESHOLD` | 不 Mock（內部邏輯） |
| `format_warning()` | Mock（驗證調用） |
| YAML 檔案系統 | Mock（外部依賴） |

### 1.3 測試覆蓋率目標

- `_calculate_jaccard_similarity()` 覆蓋率：100%（所有路徑）
- `_detect_duplicate_tickets()` 覆蓋率：100%（所有行為路徑）
- 執行層整合點覆蓋率：100%（確保正確呼叫時機）

## 2. 相似度計算單元測試設計（`_calculate_jaccard_similarity`）

### 2.1 基礎演算法測試

#### 測試案例 U-001：完全相同文字
```
Given: text_a = "實作 SRP 偵測", text_b = "實作 SRP 偵測"
When: 呼叫 _calculate_jaccard_similarity(text_a, text_b)
Then: 返回 1.0（完全匹配）
```

**前置驗證**：
```
assert text_a is not None and text_a != ""
assert text_b is not None and text_b != ""
```

#### 測試案例 U-002：完全不同文字
```
Given: text_a = "WebSocket 連線", text_b = "權限驗證系統"
When: 呼叫 _calculate_jaccard_similarity(text_a, text_b)
Then: 返回 0.0（無交集）
```

#### 測試案例 U-003：部分重疊（中文）
```
Given: text_a = "實作 SRP 自動偵測機制"
       text_b = "新增 SRP 偵測功能"
When: 呼叫 _calculate_jaccard_similarity(text_a, text_b)
Then: 返回約 0.33（詞集：{SRP, 偵測}，計算詞彙交集／聯集）
驗證: 0.25 <= 返回值 <= 0.4（容差範圍）
```

#### 測試案例 U-004：部分重疊（英文）
```
Given: text_a = "fix WebSocket connection issue"
       text_b = "handle WebSocket disconnection error"
When: 呼叫 _calculate_jaccard_similarity(text_a, text_b)
Then: 返回約 0.33（詞集：{WebSocket}）
驗證: 返回值 > 0.2
```

### 2.2 邊界條件測試

#### 測試案例 U-005：空字串
```
Given: text_a = "", text_b = "實作 SRP"
When: 呼叫 _calculate_jaccard_similarity(text_a, text_b)
Then: 返回 0.0（空字串與非空字串無交集）
```

#### 測試案例 U-006：兩個空字串
```
Given: text_a = "", text_b = ""
When: 呼叫 _calculate_jaccard_similarity(text_a, text_b)
Then: 返回 1.0 或 0.0（定義清楚，詳見實作約定）
備註: 空字串的相似度定義需在設計時確認
```

#### 測試案例 U-007：單一字元
```
Given: text_a = "X", text_b = "X"
When: 呼叫 _calculate_jaccard_similarity(text_a, text_b)
Then: 返回 1.0
```

#### 測試案例 U-008：大小寫差異
```
Given: text_a = "WebSocket", text_b = "websocket"
When: 呼叫 _calculate_jaccard_similarity(text_a, text_b)
Then: 返回 1.0（應不區分大小寫） 或
      < 1.0（區分大小寫）
驗證: 實作需明確定義大小寫處理策略
```

#### 測試案例 U-009：特殊字符與標點符號
```
Given: text_a = "實作 SRP 自動偵測機制 (v1.0)"
       text_b = "實作 SRP 自動偵測機制"
When: 呼叫 _calculate_jaccard_similarity(text_a, text_b)
Then: 特殊字符被忽略或保留（需明確約定）
驗證: 無例外拋出，返回有效相似度值
```

#### 測試案例 U-010：長文字（效能邊界）
```
Given: text_a = "a" * 1000 + "shared_term" + "b" * 1000
       text_b = "c" * 1000 + "shared_term" + "d" * 1000
When: 呼叫 _calculate_jaccard_similarity(text_a, text_b)
Then: 執行時間 < 50ms，返回 0.0 < 值 < 1.0
```

### 2.3 異常情境測試

#### 測試案例 U-011：None 值輸入
```
Given: text_a = None, text_b = "實作"
When: 呼叫 _calculate_jaccard_similarity(text_a, text_b)
Then: 拋出 TypeError（或進行輸入驗證）
```

#### 測試案例 U-012：非字串型別輸入
```
Given: text_a = 123, text_b = "456"
When: 呼叫 _calculate_jaccard_similarity(text_a, text_b)
Then: 拋出 TypeError 或自動轉換為字串
驗證: 實作決策需明確
```

## 3. 重複偵測行為測試（`_detect_duplicate_tickets`）

### 3.1 正常流程：發現相似 Ticket

#### 場景 B-001：單個相似 pending Ticket（標題重疊）
```
Given: 版本為 "0.1.2"
       版本目錄存在 3 個 pending Ticket：
       - 0.1.2-W3-001.2: 標題 "實作 SRP 自動偵測機制", 狀態 pending
       - 0.1.2-W2-005: 標題 "修復 WebSocket 連線問題", 狀態 pending
       - 0.1.2-W3-002: 標題 "新增 API 驗證", 狀態 pending

前置驗證:
       - list_tickets 已呼叫並返回上述 3 個 Ticket
       - 過濾機制確認只有 3 個 pending（排除 completed/in_progress）

When: 呼叫 _detect_duplicate_tickets(
        version="0.1.2",
        new_title="實作 SRP 偵測功能",
        new_what="新增 SRP 自動偵測",
        new_ticket_id="0.1.2-W3-003"
      )

Then: 系統輸出 WARNING，包含：
       - 錯誤訊號：「發現 1 個可能重複的 pending Ticket」
       - 相似 Ticket ID: 0.1.2-W3-001.2
       - 相似 Ticket 標題: 實作 SRP 自動偵測機制
       - 建議訊息：「執行 /ticket track list 查看所有現有 Ticket 後再決定」

驗證: 無例外拋出，函式返回 None
```

**前置驗證邏輯**（A → B）:
1. 確認 `list_tickets("0.1.2")` 已被呼叫
2. 確認返回的清單包含 pending 狀態的 Ticket
3. 確認相似度計算邏輯被觸發（模擬 Jaccard >= 0.3）
4. 確認格式化訊息被正確組裝

#### 場景 B-002：多個相似 Ticket
```
Given: 版本為 "0.1.2"
       版本目錄存在 2 個相似的 pending Ticket：
       - 0.1.2-W3-001: 標題 "實作 SRP 機制", 狀態 pending
       - 0.1.2-W3-001.2: 標題 "實作 SRP 自動偵測", 狀態 pending

前置驗證:
       - 兩個 Ticket 的相似度均 >= 0.3
       - 過濾正確識別為 pending

When: 呼叫 _detect_duplicate_tickets(
        version="0.1.2",
        new_title="實作 SRP 偵測功能",
        new_what="自動識別 SRP 違規",
        new_ticket_id="0.1.2-W3-003"
      )

Then: 系統輸出 WARNING，包含：
       - 「發現 2 個可能重複的 pending Ticket」
       - 列出兩個 Ticket ID 和標題

驗證: 返回 None，無例外
```

#### 場景 B-003：無相似 Ticket（正常非警告流程）
```
Given: 版本為 "0.1.2"
       版本目錄存在 2 個 pending Ticket：
       - 0.1.2-W3-001: 標題 "實作 SRP 機制", 狀態 pending
       - 0.1.2-W2-005: 標題 "修復 WebSocket 連線", 狀態 pending

前置驗證:
       - 即將建立的 Ticket 標題 "建立 WebSocket 路由"
       - 與兩個 pending Ticket 相似度均 < 0.3

When: 呼叫 _detect_duplicate_tickets(
        version="0.1.2",
        new_title="建立 WebSocket 路由",
        new_what="實作路由轉發邏輯",
        new_ticket_id="0.1.2-W3-003"
      )

Then: 無任何輸出（靜默通過）
驗證: 返回 None，無例外拋出
```

## 6. Mock 設計規劃

### 6.1 外部依賴 Mock

| 依賴 | Mock 名稱 | 模擬行為 |
|------|----------|---------|
| `list_tickets()` | `mock_list_tickets` | 返回測試用 Ticket 列表 |
| `format_warning()` | `mock_format_warning` | 返回格式化警告訊息 |
| `print()` | `mock_print` | 驗證輸出被調用 |
| 檔案系統 | `tmp_path` (pytest fixture) | 建立臨時 Ticket 目錄 |

### 6.2 Mock 配置範例

```python
# 測試相似 Ticket 提示的 Mock 設置
@pytest.fixture
def mock_list_tickets(mocker):
    """Mock list_tickets 返回預定義的 Ticket 清單"""
    def _mock_list_tickets(version):
        if version == "0.1.2":
            return [
```

## 9. 完整行為鏈式推演

### 9.1 正常流程行為鏈

```
A. 前置條件（Given）：
   ├─ 版本存在（verified by list_tickets）
   ├─ 存在 pending Ticket（status == "pending"）
   ├─ pending Ticket 標題已載入
   ├─ 新建 Ticket 參數已準備（title, what, id）
   └─ 相似度閾值已定義（THRESHOLD = 0.3）

B. 行為執行（When）：
   ├─ 呼叫 _detect_duplicate_tickets()
   ├─ 迭代 pending Ticket 清單
   ├─ 計算相似度（_calculate_jaccard_similarity）
   ├─ 比較相似度 >= 0.3
   └─ 收集相似 Ticket 列表

C. 結果驗證（Then）：
   ├─ 相似列表非空 → 輸出 WARNING
   ├─ WARNING 包含 Ticket ID 和標題
   ├─ 提供 /ticket track list 建議
   └─ 函式返回 None（不阻止建立）

D. 後續行為（Continue）：
   ├─ 執行 save_ticket()
   ├─ 建立成功輸出
   ├─ Ticket 檔案存在
   └─ 返回 exit code 0
```

### 9.2 異常流程行為鏈

```
A. 前置異常（Given Exception）：
   ├─ list_tickets() 拋出 FileNotFoundError
   ├─ 或 _calculate_jaccard_similarity 拋出 UnicodeError
   └─ 異常被 try/except 捕捉

B. 容錯執行（When Exception）：
   ├─ 例外被靜默捕捉
   ├─ 無錯誤訊息輸出
   └─ 返回 None（靜默通過）

C. 結果確認（Then Exception）：
   ├─ 建立流程繼續
   ├─ Ticket 正常儲存
   └─ 無異常傳播
```

### 9.3 邊界流程行為鏈

```
四個維度的行為分支：

1. 正常流程：發現相似 → 輸出 WARNING → 繼續建立
   場景：B-001, B-002, I-001, I-002

2. 異常流程：內部錯誤 → 靜默通過 → 繼續建立
   場景：B-011, B-012, I-004

3. 邊界條件：狀態過濾、內容為空、自身排除
   場景：B-004, B-005, B-008, B-009, B-010, B-007

4. 中斷操作：無相似 Ticket 時靜默通過
   場景：B-003, B-006, B-013
```

## 11. 測試設計決策記錄

### 11.1 Jaccard 相似度選擇理由

- **選擇**：Jaccard 係數（集合交集 / 聯集）
- **替代方案**：編輯距離、餘弦相似度、Levenshtein
- **決策**：
  1. 不依賴外部套件，符合「簡單為主」原則
  2. 對中文友善（以字元為最小單位）
  3. O(n) 線性複雜度，無效能疑慮
  4. 直觀易懂，容易調整閾值

### 11.2 閾值設置 0.3 的理由

- **過高（0.7）**：遺漏真正重複（標題用詞可能有差異）
- **過低（0.1）**：產生大量誤報，干擾使用者
- **選擇 0.3**：30% 詞彙重疊，捕捉明顯相似但非完全相同的 Ticket
- **允許調整**：在後續 Phase 3b 實作時根據實測反饋微調

### 11.3 容錯設計理由

- **原則**：重複偵測是輔助功能，不應阻斷核心建立流程
- **異常處理**：try/except 捕捉所有內部異常，靜默通過
- **好處**：
  1. 使用者體驗不受影響（無卡頓）
  2. 系統穩定性保證
  3. 問題可通過 Hook 日誌追蹤
