## 1. 測試策略規劃

### 1.1 測試分層決策

基於 hybrid-testing-strategy-methodology.md（分層測試決策樹）：

| 模組 | Layer | 複雜度 | 選策略 | 理由 |
|------|-------|--------|--------|------|
| `git_utils.get_uncommitted_files()` | Layer 5 (Domain, git 工具層) | 中 | 單元測試 | git 查詢邏輯，無 I/O 依賴，用 mock subprocess |
| `branch-status-reminder._report_uncommitted_changes()` | Layer 2 (Behavior, 呈現層) | 中 | 整合測試 | 聚焦行為（input → hook_output），需驗證行為序列 |
| Hook 整體流程 | Layer 1 (UI) | 高 | 整合測試 | SessionStart Hook 的完整行為，驗證靜默 vs 報告邏輯 |

### 1.2 Sociable Unit Tests 原則應用

**Mock 策略**（遵循 behavior-first-tdd-methodology.md）：

| 依賴類型 | Mock 策略 | 原因 |
|---------|---------|------|
| `subprocess.run`（git 命令） | Mock | 外部依賴，測試不關心 subprocess 細節 |
| `hook_output()`（輸出函式） | Mock | 外部依賴，驗證輸出呼叫 |
| `logger`（logging） | Mock 或使用真實 | Logger 內邏輯簡單，可用真實；驗證呼叫時 Mock |
| Domain 邏輯（列表過濾、常數判斷） | 不 Mock | 核心業務邏輯，使用真實 |

**單元 = Module**（1 個或多個類別）：
- `get_uncommitted_files()` = 獨立 git 工具函式，作為一個 module
- `_report_uncommitted_changes()` = Hook 呈現層邏輯，作為一個 module

### 2.1 `get_uncommitted_files()` 單元測試（git_utils.py）

#### 測試目標
驗證函式能正確執行 `git status --porcelain`，解析並過濾空行，以及在失敗時優雅降級。

#### 場景 1：有未提交變更（正常流程）

**Given**: 工作目錄有 3 個未提交變更（檔案修改、新檔案、刪除檔案）

**When**: 呼叫 `get_uncommitted_files()`

**Then**:
- 預期呼叫 `run_git_command(["status", "--porcelain"])`
- 回傳包含 3 個 git porcelain 格式字串的 list
- 順序和內容與 git 輸出一致

**測試程式碼框架**:
```python
@patch('git_utils.run_git_command')
def test_get_uncommitted_files_with_changes(self, mock_run):
    """測試有未提交變更時的正常回傳"""
    # Arrange
    git_output = " M file1.py\n?? new_file.txt\n D deleted.py"
    mock_run.return_value = (True, git_output)

    # Act
    result = get_uncommitted_files()

    # Assert
    self.assertEqual(len(result), 3)
    self.assertEqual(result[0], " M file1.py")
    self.assertEqual(result[1], "?? new_file.txt")
    self.assertEqual(result[2], " D deleted.py")
    mock_run.assert_called_once_with(["status", "--porcelain"])
```

**邊界驗證**:
- [ ] 確認過濾空行：git 輸出尾部空行被移除
- [ ] 確認順序保持：list 中的順序與原始 git 輸出一致

## 3. 測試環境設置規劃

### 3.1 Mock 物件設計

| Mock 目標 | 使用方式 | 設定方式 |
|----------|---------|---------|
| `subprocess.run` | 在 `test_git_utils.py` | `@patch('subprocess.run')` |
| `git_utils.run_git_command` | 在 `branch-status-reminder` 測試 | `@patch('branch_status_reminder.run_git_command')` 或 `@patch('git_utils.run_git_command')` |
| `hook_output()` | 驗證輸出呼叫 | `@patch('branch_status_reminder.hook_output')` |
| `logging.Logger` | 記錄驗證 | `MagicMock()` 或 `@patch('logging.Logger')` |

### 3.2 測試資料

| 資料類型 | 範例 |
|---------|------|
| git porcelain 格式 | `" M file.py"`, `"?? new.txt"`, `" D deleted.py"` |
| 檔案數量變體 | 0, 5, 10 (boundary), 15, 100 (large) |
| 分支名稱 | `main`, `develop`, `feat/JIRA-001`, `fix/bug-123` |
| Worktree 狀態 | True/False |

### 3.3 測試清理

- Mock 會自動在每個測試後重置（unittest.mock 預設行為）
- Logger 實例為 Mock，無持久狀態
- 無檔案 I/O，無需清理

### 3.4 測試隔離與獨立性
