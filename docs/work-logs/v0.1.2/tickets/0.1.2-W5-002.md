---

## Problem Analysis

### 問題根因

get_uncommitted_files() 函式的命名欺騙：函式執行 `git status --porcelain`，回傳的是 **git porcelain 狀態行**（如 " M file.txt"、"?? new.txt"），但函式名稱 `get_uncommitted_files` 暗示回傳的是檔案名清單，造成消費端易於誤解。

### 影響範圍

- .claude/lib/git_utils.py：函式定義
- .claude/hooks/branch-status-reminder.py：消費端，使用該函式報告未提交變更
- 無對應單元測試
- MAX_UNCOMMITTED_FILES_DISPLAY 常數定義在消費端而非提供端（職責混亂）

### 相關 Error Pattern

無相關已知錯誤模式（新發現）

---

## Solution

### 實作策略

1. **重新命名函式**
   - get_uncommitted_files() → get_uncommitted_status_lines()
   - 更新 docstring 中的 Example 變數名（files → status_lines）
   - 更新模組 docstring

2. **同步呼叫端**
   - branch-status-reminder.py：更新 import、函式呼叫、變數名、docstring
   - 搜尋確認無其他呼叫端（已驗證）

3. **補充單元測試**
   - 新增 TestUncommittedStatusLines 測試類（4 個測試）
   - test_has_uncommitted_changes：有變更時回傳非空列表
   - test_no_uncommitted_changes：無變更時回傳空列表
   - test_git_command_failure：git 失敗時回傳空列表
   - test_porcelain_format_preserved：porcelain 格式保留

### 實作成果

✓ git_utils.py：函式定義重新命名 + docstring 更新
✓ branch-status-reminder.py：所有呼叫同步更新
✓ test_git_utils.py：新增 4 個單元測試
✓ 無遺漏的舊引用（已用 grep 驗證）
✓ git commit: 962f536（merge commit）
