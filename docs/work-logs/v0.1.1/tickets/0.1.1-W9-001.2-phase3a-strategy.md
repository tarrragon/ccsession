## 1. 實作策略概述

### 核心改寫邏輯

將 `create_feature_worktree()` 函式的兩步操作（`git checkout -b` + `git worktree add`）改為單一原子命令（`git worktree add -b`）。

**關鍵改變**：
- 移除第 96 行的 `git checkout -b {branch} {base_branch}`
- 移除第 103-104 行的手動回滾邏輯（`git branch -D`）
- 新增第 101 行為 `git worktree add -b {branch} {worktree_abs_path} {base_branch}`
- 更新 dry-run 輸出（第 140-142 行）以反映單一命令

### 實作複雜度評估

| 維度 | 評估 |

## 2. 虛擬碼和邏輯流程

### 2.1 主函式虛擬碼：create_feature_worktree()

```pseudocode
函式 create_feature_worktree(branch, worktree_path, base_branch="main")

  # Step 1: 路徑轉換和驗證
  worktree_abs_path = 轉換為絕對路徑(worktree_path)

  # Step 2: 前置驗證（三層防禦）
  如果 worktree 已存在(worktree_abs_path):
    返回 (False, "Worktree 路徑已存在: {abs_path}")

  如果 分支已存在(branch):
    返回 (False, "分支已存在: {branch}")

  如果 NOT 分支已存在(base_branch):
    返回 (False, "基礎分支不存在: {base_branch}")

  # Step 3: 執行單一原子命令
  成功, 訊息 = 執行git命令(["worktree", "add", "-b", branch, worktree_abs_path, base_branch])

  如果 NOT 成功:
    # 原子操作失敗：git 已自動清理，無需手動回滾
    返回 (False, f"創建 worktree 失敗: {訊息}")

  # Step 4: 成功回傳
  返回 (True, f"成功創建分支 '{branch}' 和 worktree '{abs_path}'")

結束函式
```

**特別注意**：
- **無回滾邏輯** — 原子操作失敗時，git 內部保證自動清理
- **主工作目錄 HEAD 不受影響** — `git worktree add -b` 不切換主工作目錄

### 2.2 輔助函式虛擬碼：驗證層

```pseudocode
函式 worktree_exists(path)
  返回 路徑是否存在(path)
結束函式

函式 branch_exists(branch)
  成功, _ = 執行git命令(["rev-parse", "--verify", branch])
  返回 成功
結束函式
```

### 2.3 CLI 主入口虛擬碼：main()

```pseudocode
函式 main()

  # Step 1: 解析命令列參數
  args = 解析參數(--branch, --worktree, --base, --dry-run)

  # Step 2: dry-run 模式
  如果 args.dry_run:
    輸出("=== Dry Run 模式 ===")
    輸出("將要執行的操作:")
    輸出("  git worktree add -b {branch} {abs_path} {base}")
    輸出()
    輸出("實際執行請移除 --dry-run 參數")
    返回 0

  # Step 3: 輸出執行資訊
  輸出("正在創建 feature worktree...")
  輸出("  分支: {branch}")
  輸出("  基礎: {base}")
  輸出("  路徑: {abs_path}")
  輸出()

  # Step 4: 呼叫核心函式
  成功, 訊息 = create_feature_worktree(branch, worktree_path, base_branch)

  # Step 5: 輸出結果
  如果 成功:
    輸出("✅ {訊息}")
    輸出()
    輸出("下一步:")
    輸出("  cd {abs_path}")
    返回 0
  其他:
    輸出("❌ {訊息}")
    返回 1

結束函式
```

## 7. 需要移除的舊程式碼

### 7.1 第 96 行：git checkout -b 命令

**移除程式碼**：
```python
success, msg = run_git_command(["checkout", "-b", branch, base_branch])
if not success:
    return False, f"創建分支失敗: {msg}"
```

**移除原因**：
- 此步驟切換主工作目錄 HEAD，導致狀態污染
- 改用 `git worktree add -b` 原子命令後，此步驟由原子命令內部處理
- 無需額外驗證錯誤（原子命令失敗時統一處理）

### 7.2 第 103-104 行：手動回滾邏輯

**移除程式碼**：
```python
# 回滾：刪除剛創建的分支
run_git_command(["branch", "-D", branch])
```

**移除原因**：
- `git worktree add -b` 是原子操作，失敗時 git 內部已自動清理
- 無需手動刪除分支，刪除操作本身可能失敗（分支被其他 worktree 引用）
- 簡化錯誤處理邏輯

## 13. 交接給 Phase 3b 的必要資訊

### 實作者需要明確的點

1. **命令順序**：`git worktree add -b {branch} {abs_path} {base_branch}`
   - `-b` 旗標必須跟在 `add` 之後
   - 分支名在前，路徑在中，base 在後

2. **無回滾邏輯**：原子命令失敗時，git 已自動清理

3. **主工作目錄 HEAD 保護**：
   - 原子命令執行後，主工作目錄 HEAD **不改變**

4. **dry-run 輸出格式**：
   ```
   === Dry Run 模式 ===
   將要執行的操作:
     git worktree add -b {branch} {abs_path} {base}

   實際執行請移除 --dry-run 參數
   ```

5. **所有測試均使用 Mock**：
   - `run_git_command()` 已 Mock，無需真實 git 環境
   - Phase 3b 實作測試時直接執行 pytest（無需額外設置）
