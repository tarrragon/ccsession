## 事件描述

### 發生了什麼

W9-002.3 派發 basil-hook-architect 執行 Hook 改造（編輯 3 個 Python 檔案）。
basil 讀取 .claude/rules/forbidden/skip-gate.md 後，誤將自己視為「主線程」，拒絕編輯程式碼。

### decision_tree_path 應該提供的保護

Ticket 的 decision_tree_path 欄位設計目的：
- entry_point：告訴代理人「任務從決策樹哪裡進入」
- final_decision：告訴代理人「PM 做了什麼決策」
- rationale：告訴代理人「為什麼派發給你」

W9-002.3 的 decision_tree_path：
- entry_point: 第五層 TDD 階段判斷 → Phase 3b
- final_decision: 派發 basil-hook-architect 實作 Hook 改造
- rationale: Phase 3a 策略完成，W9-002.3 與 W9-002.1 無檔案衝突可並行

**這些資訊已經明確告訴 basil：你是被 PM 派來寫程式碼的開發者。**
但 basil 仍然誤判。

### 分析方向

1. decision_tree_path 是否被代理人實際讀取和理解？
2. 代理人讀取規則時是否有「這條規則適用於我嗎？」的判斷機制？
3. agent 定義檔中是否有足夠的「職責邊界聲明」讓代理人自我定位？
4. dispatch_reason 和 decision_tree_path 的資訊是否足以覆蓋 skip-gate 規則的影響？
5. 需要什麼樣的補強才能確保代理人不會再犯同樣的錯誤？

### 優先級理由

P0：這是框架級保護機制的失效。如果代理人無法正確辨識自己的職責，所有 Phase 3b 派發都可能受影響。W12-005 和 W12-006 是此問題的衍生後果，應在此問題解決後再處理。
## Solution

## Solution - 三層防護機制失效根因分析

### 層級 1：decision_tree_path 資訊完整但無判斷機制

decision_tree_path 在 W9-002.3 中的信息完整無缺，明確告知 basil：
- 派發決策：第五層 TDD 階段判斷 → Phase 3b
- 派發理由：派發 basil-hook-architect 實作 Hook 改造
- 派發原因：Phase 3a 策略完成，與 W9-002.1 無檔案衝突可並行

**問題**：basil 讀到這些信息後，應能理解「我被派來編輯程式碼」，但實際上誤判了。缺陷不在信息本身，而在**代理人無法從派發信息推導出「這是我的職責」**的判斷能力。

### 層級 2：規則系統缺乏角色區分機制

skip-gate.md 中明確寫「主線程禁止編輯程式碼」，但：
- 規則本身未包含 `applies_to: [rosemary-project-manager]` 標註
- 代理人讀到規則時，無法判斷「這條規則是否適用於我」
- basil 採取保守做法：假設全局禁止 → 拒絕編輯

**影響範圍**（所有包含「主線程禁止」的規則都有此問題）：
- skip-gate.md Level 3（主線程編輯限制）
- skip-gate.md Level 1（主線程禁止直接修復）
- decision-tree.md 中多個「主線程必須親自處理」的規則

### 層級 3：Agent 定義檔缺乏職責邊界聲明

basil-hook-architect.md 完整定義了：
- 觸發條件（何時派發）
- 核心職責（設計和實作 Hook）
- 禁止行為（不修改業務邏輯）
- 與其他代理人的邊界

**但缺少關鍵信息**：
- 職責等級聲明（「我是執行者，不是 PM」）
- 判斷標準（「如何判斷任務屬於我」）
- 拒絕規則（「什麼時候拒絕任務」）
- 規則適用性指導（「PM 規則何時不適用於我」）

---

### 根本原因總結

| 層級 | 機制 | 設計目的 | 實際失效 |
|------|------|---------|---------|
| **1** | decision_tree_path | 告訴代理人派發理由 | 信息完整但無判斷機制 |
| **2** | 規則 applies_to 標註 | 區分全局規則 vs 角色規則 | 缺乏 applies_to 欄位 |
| **3** | Agent 定義檔 | 提供職責邊界和判斷標準 | 定義不完整，缺乏指導 |

防護鏈條的三層都有問題，導致：
1. 代理人無法判斷「這條規則是否適用於我」
2. 代理人採取保守做法（假設適用）
3. 代理人拒絕自己的工作，導致任務失敗

---

## 補強方案

### 短期補強（規則層面）

1. **skip-gate.md 增加角色標註**
   - 所有「主線程禁止」規則都加上 `applies_to: [rosemary-project-manager]`

2. **decision-tree.md 等規則增加角色標註**
   - 所有「PM 禁止」「PM 必須」的規則都加上角色限定

### 中期補強（Agent 定義檔層面）

3. **Agent 定義檔加入職責等級聲明**
   - 明確聲明「你是執行者，不是 PM」
   - 提供「如何判斷任務屬於我」的決策規則
   - 說明「PM 規則何時不適用於我」

### 長期補強（框架層面）

4. **Hook 系統增加規則適用性驗證**
   - 解析規則的 applies_to 欄位
   - 自動過濾不適用的規則
   - 只向代理人呈現「適用於你」的規則

---

## 預期效果

執行上述補強後：
- 代理人能清楚判斷「這條規則是否適用於我」
- 代理人不會再因「PM 的禁止」而拒絕自己的工作
- decision_tree_path 的防護作用能真正發揮
- 類似誤判事件大幅降低
