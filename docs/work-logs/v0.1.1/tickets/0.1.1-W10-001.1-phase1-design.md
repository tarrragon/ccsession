# Phase 1 功能規格設計：/worktree merge + cleanup 子命令

## 一、功能需求分析

### 核心問題

worktree SKILL 目前提供 `create` 和 `status` 兩個子命令，覆蓋 worktree 生命週期的「建立」和「查看」階段。

生命週期尚缺的兩個階段：

| 缺失階段 | 子命令 | 業務需求 |
|---------|-------|---------|
| 合併 | `merge` | 開發者完成 Ticket 後，需要將 worktree 的分支合併回 main，且必須確認 Ticket 已正式完成才能合併 |
| 清理 | `cleanup` | 合併後的 worktree 目錄應被移除，但需要防止誤刪未合併或有未保存工作的 worktree |

### 使用者場景

| 使用者 | 操作 | 期望結果 |
|--------|------|---------|
| 開發者完成一個 Ticket | 執行 `/worktree merge 0.1.1-W9-002` | 獲得可直接貼上執行的 git merge 指令，或收到阻擋提示說明原因 |
| 開發者確認分支已合併 | 執行 `/worktree cleanup 0.1.1-W9-002` | 指定 worktree 被移除（通過三閘門安全檢查後） |
| 開發者想知道哪些 worktree 可清理 | 執行 `/worktree cleanup`（無參數） | 列出所有已合併且安全可清理的 worktree |
| 開發者強制清理有警告的 worktree | 執行 `/worktree cleanup 0.1.1-W9-002 --force` | 跳過警告直接清理（仍拒絕有未 commit 的情況） |

## 二、merge 子命令功能規格

### 設計哲學

merge 子命令採用「**引導式合併**」模式：

- 不自動執行 git merge（避免衝突和不可預期的 branch 狀態）
- 負責前置驗證（Ticket 狀態、working tree 乾淨度、ahead/behind 狀態）
- 驗證通過後輸出完整的 git merge 指令供使用者執行

### 正常流程

```
/worktree merge <ticket-id>
    |
    v
[Step 1] 驗證 Ticket ID 格式
    格式不合法 → 輸出錯誤，exit 1
    |
    v
[Step 2] 尋找對應的 worktree
    找不到 → 輸出錯誤（含現有 worktree 列表），exit 1
    |
    v
[Step 3] 驗證 Ticket 狀態為 completed
    狀態非 completed → 輸出阻擋提示（說明需先 complete Ticket），exit 1
    |
    v
[Step 4] 驗證 working tree 乾淨
    有未 commit 的變更 → 輸出阻擋提示（列出未 commit 數量），exit 1
    |
    v
[Step 5] 計算 ahead/behind 狀態
    ahead == 0 → 輸出警告（沒有新 commit 可合併）
    behind > 0 → 輸出提示（建議先 rebase）
    |
    v
[Step 6] 輸出 git merge 指令
    輸出完整可複製的指令（含說明），exit 0
```

### 異常情況處理

| 異常情況 | 處理方式 | exit code |
|---------|---------|-----------|
| Ticket ID 格式不合法 | 輸出格式說明，exit 1 | 1 |
| 找不到對應 worktree | 輸出錯誤 + 現有 worktree 列表 | 1 |
| Ticket 狀態非 completed | 輸出阻擋提示，建議先執行 `/ticket track complete` | 1 |
| Ticket 查詢失敗（ticket CLI 不可用） | 輸出警告說明無法驗證狀態，仍輸出 merge 指令 | 0（降級） |
| working tree 有未 commit 變更 | 輸出阻擋提示（列出變更數量） | 1 |
| ahead == 0（沒有新 commit） | 輸出警告但仍給出指令，讓使用者決定 | 0（警告） |
| behind > 0（落後 main） | 輸出 rebase 建議，仍給出 merge 指令 | 0（提示） |

### 邊界條件

| 邊界條件 | 預期行為 |
|---------|---------|
| 分支已合併到 main（ahead == 0, behind == 0） | 警告「此分支可能已合併」，仍輸出指令 |
| detached HEAD worktree | 無法辨識 Ticket，輸出錯誤說明 |
| Ticket ID 有 TDD 後綴（如 -phase1-design） | 驗證通過（TICKET_ID_PATTERN 支援後綴），以帶後綴的 ID 查詢 |
| ticket track 查詢超時 | 捕捉逾時例外，降級為警告輸出（不中斷流程） |

## 三、cleanup 子命令功能規格

### 三閘門安全模型

cleanup 以三層閘門防止誤刪：

| 閘門 | 條件 | 行為 | 可繞過 |
|------|------|------|--------|
| Level 1（拒絕閘門） | 有未 commit 的變更 | 拒絕清理，exit 1 | 否（--force 也無效） |
| Level 2（警告閘門） | ahead > 0 但 origin 無對應分支（未 push） | 警告，詢問確認 | 是（--force 略過） |
| Level 3（警告閘門） | 分支未合併到 main（ahead > 0 且 main 無此 commit） | 警告，詢問確認 | 是（--force 略過） |

**Level 1 永不可繞過**的設計理由：有未 commit 的工作代表開發者可能正在進行中的任務，任何情況下強制刪除都可能造成不可恢復的資料遺失。

### 掃描模式（無參數）

```
/worktree cleanup
    |
    v
[Step 1] 取得所有 worktree 列表
    |
    v
[Step 2] 篩選非主倉庫的 worktree
    |
    v
[Step 3] 逐一評估安全性
    uncommitted > 0 → 標記為「不安全（有未 commit 變更）」
    ahead > 0 且未 push → 標記為「警告（未 push）」
    ahead > 0 且未合併 → 標記為「警告（未合併）」
    ahead == 0 且已合併 → 標記為「建議清理」
    |
    v
[Step 4] 輸出分類報告
    「建議清理」的 worktree 列出指令
    「警告」的 worktree 提示使用 --force
    「不安全」的 worktree 提示先 commit
    |
    exit 0
```

### 精確模式（指定 ticket-id）

```
/worktree cleanup <ticket-id>
    |
    v
[Step 1] 驗證 Ticket ID 格式
    |
    v
[Step 2] 尋找對應的 worktree
    找不到 → 輸出錯誤，exit 1
    |
    v
[Step 3] Level 1 閘門：未 commit 檢查
    uncommitted > 0 → 輸出拒絕訊息，exit 1（--force 無效）
    |
    v
[Step 4] Level 2 閘門：未 push 檢查
    未 push（ahead > 0，origin 無對應分支或落後）→ 輸出警告
    非 --force → 輸出確認提示，exit 1
    --force → 繼續執行
    |
    v
[Step 5] Level 3 閘門：未合併檢查
    未合併（分支 commit 不在 main 中）→ 輸出警告
    非 --force → 輸出確認提示，exit 1
    --force → 繼續執行
    |
    v
[Step 6] 執行清理
    git worktree remove <path>
    git branch -d <branch>（合併後安全刪除）
    輸出清理結果
    exit 0
```

### 異常情況處理

| 異常情況 | 處理方式 | exit code |
|---------|---------|-----------|
| Ticket ID 格式不合法 | 輸出格式說明，exit 1 | 1 |
| 找不到對應 worktree | 輸出錯誤 + 現有 worktree 列表 | 1 |
| Level 1：有未 commit 變更 | 拒絕，列出變更數量，建議先 commit | 1 |
| Level 2（警告）：未 push | 警告 + 如何確認後繼續 | 1（無 --force）/ 繼續（--force） |
| Level 3（警告）：未合併 | 警告 + 建議先 merge | 1（無 --force）/ 繼續（--force） |
| git worktree remove 失敗 | 輸出詳細錯誤訊息 | 1 |
| git branch -d 失敗（已合併但 -d 失敗） | 輸出警告（worktree 已移除但分支未刪除） | 0（部分成功） |
| 沒有任何 worktree 可清理（掃描模式） | 輸出「目前沒有需要清理的 worktree」 | 0 |

### 邊界條件

| 邊界條件 | 預期行為 |
|---------|---------|
| --force + 有未 commit 變更 | 仍拒絕（Level 1 永不可繞過） |
| 主倉庫（main/master） | 掃描模式跳過，精確模式拒絕（protected branch） |
| 無法辨識 Ticket 的 worktree | 掃描模式列出「無法辨識」警告，但不建議清理 |
| worktree 目錄已不存在（孤立記錄） | git worktree prune 後重試，或輸出說明 |
| git branch -d 拒絕（分支未合併到任何地方） | 降級提示使用 git branch -D，但不自動執行 |

## 六、訊息常數設計

### 訊息集中管理原則

所有使用者可見字串集中在 `scripts/messages.py`（新增檔案）：

```python
"""
Worktree SKILL 訊息常數
集中管理所有使用者可見的提示、警告和錯誤訊息。
"""

# ===== merge 訊息 =====

class MergeMessages:
    # 阻擋訊息（exit 1）
    TICKET_NOT_COMPLETED = "[阻擋] Ticket {ticket_id} 狀態為 {status}，尚未完成。\n請先執行：\n  /ticket track complete {ticket_id}"
    DIRTY_WORKING_TREE = "[阻擋] Working tree 有 {count} 個未 commit 的變更。\n請先 commit 或 stash 後再執行 merge。"
    WORKTREE_NOT_FOUND = "[錯誤] 找不到 Ticket {ticket_id} 對應的 worktree。"

    # 警告訊息（不阻擋，exit 0）
    TICKET_STATUS_UNAVAILABLE = "[警告] 無法查詢 Ticket 狀態（ticket CLI 不可用）。\n跳過狀態驗證，請自行確認 Ticket 已完成。"
    NO_NEW_COMMITS = "[提示] 此分支沒有超前 {base} 的新 commit（ahead = 0）。\n可能此分支已合併，或尚未進行任何開發。"
    BRANCH_BEHIND_BASE = "[提示] 此分支落後 {base} {count} 個 commit。\n建議先執行 rebase：\n  git rebase {base}"

    # 成功輸出
    MERGE_COMMAND_HEADER = "驗證通過。執行以下指令合併分支："
    MERGE_COMMAND_HINT = "（合併後建議執行 /worktree cleanup {ticket_id} 清理 worktree）"


# ===== cleanup 訊息 =====

class CleanupMessages:

    LEVEL1_REJECTED = "[拒絕] Working tree 有 {count} 個未 commit 的變更。\n此安全閘門無法繞過（--force 無效）。\n請先 commit 或 stash 後再清理。"

    SCAN_HEADER = "Worktree 清理建議報告"
    SCAN_SAFE_TO_CLEAN = "建議清理（已合併，無未儲存工作）："
    SCAN_WARNING = "需注意（警告）："
    SCAN_UNSAFE = "不安全（有未 commit 變更）："
    SCAN_NO_CLEANUP_NEEDED = "目前沒有需要清理的 worktree。"
    SCAN_CLEANUP_HINT = "  執行清理：/worktree cleanup {ticket_id}"
```

## 七、CLI 介面設計

### merge 子命令 argparse

```
用法：worktree merge <ticket-id>

位置參數：
  ticket-id     Ticket ID（例如：0.1.1-W9-002）

說明：
  執行前置驗證（Ticket 狀態、working tree 乾淨度、ahead/behind），
  通過後輸出 git merge --no-ff 指令供執行。
  此命令不會自動執行 git merge。
```

### cleanup 子命令 argparse

```
用法：worktree cleanup [ticket-id] [--force]

位置參數（可選）：
  ticket-id     Ticket ID（若省略，則執行掃描模式列出所有可清理的 worktree）

選項：
  --force       略過 Level 2（未 push）和 Level 3（未合併）警告閘門。
                注意：Level 1（未 commit）永遠無法略過。

說明：
  三閘門安全清理：
    Level 1（拒絕）：有未 commit 變更 → 永遠拒絕，--force 無效
    Level 2（警告）：未 push 到 origin → 警告，--force 可略過
    Level 3（警告）：分支未合併到 main → 警告，--force 可略過
```

## 八、行為場景提取（Given-When-Then）

### merge 子命令場景

#### 場景 1：正常合併流程（主要流程）

```
場景 1: merge — 成功輸出指令（正常流程）
Given: Ticket 0.1.1-W9-002 狀態為 completed
       worktree feat/0.1.1-W9-002 存在
       working tree 乾淨（uncommitted == 0）
       ahead = 3，behind = 0
When: 執行 /worktree merge 0.1.1-W9-002
Then: 輸出合併前驗證摘要（Ticket 狀態、clean、ahead/behind）
      輸出 git checkout main 指令
      輸出 git merge --no-ff feat/0.1.1-W9-002 指令
      exit code 為 0
```

#### 場景 2：Ticket 未完成（阻擋）

```
場景 2: merge — Ticket 未完成被阻擋（異常流程）
Given: Ticket 0.1.1-W9-002 狀態為 in_progress
       worktree 存在，working tree 乾淨
When: 執行 /worktree merge 0.1.1-W9-002
Then: 輸出 [阻擋] 提示，說明 Ticket 狀態為 in_progress
      輸出建議：/ticket track complete 0.1.1-W9-002
      exit code 為 1
      不輸出 git merge 指令
```

#### 場景 3：Working tree 有未 commit 變更（阻擋）

```
場景 3: merge — working tree 不乾淨被阻擋（異常流程）
Given: Ticket 0.1.1-W9-002 狀態為 completed
       worktree 存在
       working tree 有 2 個未 commit 的變更
When: 執行 /worktree merge 0.1.1-W9-002
Then: 輸出 [阻擋] 提示，說明有 2 個未 commit 變更
      建議先 commit 或 stash
      exit code 為 1
      不輸出 git merge 指令
```

#### 場景 4：ticket CLI 不可用（降級警告）

```
場景 4: merge — Ticket CLI 不可用，降級輸出（邊界條件）
Given: ticket 命令不存在或執行失敗
       worktree 存在，working tree 乾淨，ahead = 3
When: 執行 /worktree merge 0.1.1-W9-002
Then: 輸出 [警告] 說明無法驗證 Ticket 狀態
      仍輸出 git merge --no-ff 指令
      exit code 為 0
```

#### 場景 5：分支落後 main（提示）

```
場景 5: merge — 分支落後 main 的提示（邊界條件）
Given: Ticket 0.1.1-W9-002 狀態為 completed
       working tree 乾淨，ahead = 3，behind = 2
When: 執行 /worktree merge 0.1.1-W9-002
Then: 輸出 [提示] 說明分支落後 main 2 個 commit
      建議先執行 git rebase main
      仍輸出 git merge --no-ff 指令
      exit code 為 0
```

### cleanup 子命令場景

#### 場景 6：精確清理成功（正常流程）

```
場景 6: cleanup — 精確清理成功（正常流程）
Given: Ticket 0.1.1-W9-001 對應 worktree 存在
       Level 1 通過：uncommitted == 0
       Level 2 通過：已 push 到 origin
       Level 3 通過：feat/0.1.1-W9-001 已合併到 main
When: 執行 /worktree cleanup 0.1.1-W9-001
Then: 輸出三閘門通過摘要
      執行 git worktree remove
      執行 git branch -d feat/0.1.1-W9-001
      輸出清理完成訊息（路徑 + 分支）
      exit code 為 0
```

#### 場景 7：Level 1 拒絕（永不可繞過）

```
場景 7: cleanup — Level 1 拒絕（異常流程）
Given: Ticket 0.1.1-W10-001.1 對應 worktree 有 3 個未 commit 變更
When: 執行 /worktree cleanup 0.1.1-W10-001.1（含或不含 --force）
Then: 輸出 [拒絕] 說明有 3 個未 commit 變更
      說明此閘門無法以 --force 略過
      exit code 為 1
      不執行任何清理動作
```

#### 場景 8：Level 3 警告，無 --force（阻擋）

```
場景 8: cleanup — Level 3 警告，無 --force（異常流程）
Given: Ticket 0.1.1-W9-002 對應 worktree 未 commit 為 0，已 push
       但分支尚未合併到 main（ahead = 3）
When: 執行 /worktree cleanup 0.1.1-W9-002（不加 --force）
Then: 輸出 Level 1 通過，Level 2 通過
      輸出 [警告] 分支未合併到 main
      提示使用 --force 可略過
      exit code 為 1
      不執行清理
```

#### 場景 9：Level 3 警告，加 --force（略過）

```
場景 9: cleanup — Level 3 警告，加 --force（邊界條件）
Given: 同場景 8 條件，但加上 --force 參數
When: 執行 /worktree cleanup 0.1.1-W9-002 --force
Then: 輸出 Level 1 通過，Level 2 通過
      輸出 [警告] 說明略過 Level 3（未合併）
      執行清理（git worktree remove + git branch -d）
      exit code 為 0
```

#### 場景 10：掃描模式，有混合狀態的 worktree

```
場景 10: cleanup — 掃描模式，輸出分類報告（正常流程）
Given: 存在 3 個 worktree（不含主倉庫）：
       - W9-001：已合併，乾淨 → 建議清理
       - W9-002：未合併，有 push → 警告
       - W10-001.1：有 3 個未 commit 變更 → 不安全
When: 執行 /worktree cleanup（無參數）
Then: 輸出報告標題
      「建議清理」區塊列出 W9-001 + 清理指令
      「需注意」區塊列出 W9-002 + --force 提示
      「不安全」區塊列出 W10-001.1 + commit 提示
      exit code 為 0
```

#### 場景 11：掃描模式，沒有任何 worktree

```
場景 11: cleanup — 掃描模式，無 worktree（邊界條件）
Given: 只有主倉庫（main），沒有任何 worktree
When: 執行 /worktree cleanup（無參數）
Then: 輸出「目前沒有需要清理的 worktree。」
      exit code 為 0
```

## 九、驗收標準

### merge 子命令驗收

| ID | 驗收條件 | 對應場景 |
|----|---------|---------|
| AC-M1 | Ticket 狀態非 completed 時，拒絕輸出 merge 指令，exit 1 | 場景 2 |
| AC-M2 | Working tree 有未 commit 變更時，拒絕輸出 merge 指令，exit 1 | 場景 3 |
| AC-M3 | 驗證全部通過時，輸出 `git checkout main` + `git merge --no-ff <branch>` 兩行指令 | 場景 1 |
| AC-M4 | 分支落後 main 時，輸出 rebase 建議但仍輸出 merge 指令（不阻擋） | 場景 5 |
| AC-M5 | ticket CLI 不可用時，降級輸出警告並仍給出 merge 指令（exit 0） | 場景 4 |
| AC-M6 | 找不到對應 worktree 時，輸出錯誤 + 現有 worktree 列表，exit 1 | 邊界條件 |
| AC-M7 | 不自動執行 git merge（僅輸出指令，不呼叫 subprocess 執行 merge） | 設計約束 |

### cleanup 子命令驗收

| ID | 驗收條件 | 對應場景 |
|----|---------|---------|
| AC-C1 | 有未 commit 變更時，即使加 --force 也拒絕清理，exit 1 | 場景 7 |
| AC-C2 | 分支未合併到 main 時（無 --force），輸出警告並 exit 1 | 場景 8 |
| AC-C3 | 分支未合併到 main 時（加 --force），略過警告執行清理 | 場景 9 |
| AC-C4 | 無參數執行時，輸出分類報告（建議清理 / 警告 / 不安全），exit 0 | 場景 10 |
| AC-C5 | 精確模式三閘門全通過後，執行 git worktree remove + git branch -d | 場景 6 |
| AC-C6 | 無任何 worktree 時，輸出提示訊息，exit 0 | 場景 11 |
| AC-C7 | git branch -d 失敗時，輸出部分成功提示（worktree 已移除但分支未刪除） | 邊界條件 |

### Handoff 到 Phase 2 的關鍵資訊

- **merge 核心行為**：三個前置驗證（Ticket 狀態 → working tree → ahead/behind）全部通過才輸出指令；任一失敗則阻擋
- **merge 降級行為**：ticket CLI 失敗視為「可繼續但需提示」，不視為阻擋
- **cleanup Level 1 不可繞過**：即使 `--force`，有未 commit 變更永遠拒絕
- **cleanup Level 2/3 可繞過**：`--force` 略過警告，但仍輸出警告訊息
- **測試 mock 策略**：`subprocess.run`（ticket query）、`run_git_command` 均需 mock；掃描模式需 mock `get_worktree_list()`
- **訊息字串**：全部從 `messages.py` 引入，測試斷言應比對訊息常數而非硬編碼字串
