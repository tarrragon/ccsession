## 1. 實作策略設計

### 1.1 核心邏輯總覽

兩個檔案（hook_base.py 和 paths.py）的 `get_project_root()` 函式都需要實作相同的優先順序邏輯。實作策略基於 Phase 1 設計的 4 層優先級模式。

**關鍵修改點**：將 `git rev-parse --show-toplevel` 提升至優先級 2（高於現有的 CLAUDE.md/go.mod/pubspec.yaml 搜尋），以解決 worktree 環境下路徑不正確的問題。

### 1.2 4 層優先順序虛擬碼

```
FUNCTION get_project_root() -> Path:

    // 層級 1：環境變數優先
    IF CLAUDE_PROJECT_DIR 環境變數已設定:
        RETURN Path(CLAUDE_PROJECT_DIR)
    END IF

    // 層級 2：git rev-parse（新增，worktree 修復的關鍵）
    TRY:
        result = EXECUTE subprocess("git rev-parse --show-toplevel", timeout=5s)
        IF result.returncode == 0:
            RETURN Path(result.stdout.strip())
        END IF
    EXCEPT FileNotFoundError:
        // git 命令不存在，進入 fallback
        LOG DEBUG: "git 命令不存在，進入 fallback 流程"
    EXCEPT subprocess.TimeoutExpired:
        // git 命令超時，進入 fallback
        LOG DEBUG: "git rev-parse 超時，進入 fallback 流程"
    EXCEPT subprocess.CalledProcessError:
        // git 命令回傳非 0，進入 fallback
        LOG DEBUG: "git rev-parse 失敗，進入 fallback 流程"
    END TRY

    // 層級 3：CLAUDE.md 搜尋（保留現有邏輯，作為 fallback）
    // 僅在 git 失敗後執行

    [針對 hook_base.py]
        current_dir = Path.cwd()
        FOR i FROM 0 TO CLAUDE_MD_SEARCH_DEPTH-1:
            IF (current_dir / "CLAUDE.md").exists():
                RETURN current_dir
            END IF
            IF current_dir.parent == current_dir:  // 已到達根目錄
                BREAK
            END IF
            current_dir = current_dir.parent
        END FOR
    [END]

    [針對 paths.py - 保留原有的多標記搜尋]
        current_dir = Path.cwd()
        markers = ["CLAUDE.md", "go.mod", "pubspec.yaml"]
        WHILE current_dir.parent != current_dir:  // 無限迴圈，直到根目錄
            FOR EACH marker IN markers:
                IF (current_dir / marker).exists():
                    RETURN current_dir
                END IF
            END FOR
            current_dir = current_dir.parent
        END WHILE
    [END]

    // 層級 4：最終 fallback
    RETURN Path.cwd()

END FUNCTION
```

### 1.3 異常處理策略

| 異常類型 | 捕捉條件 | 處理動作 | 進入層級 |
|---------|---------|---------|---------|
| `FileNotFoundError` | subprocess.run 拋出 | 記錄 DEBUG 日誌，進入 fallback | 層級 3 |
| `subprocess.TimeoutExpired` | git 命令超過 5 秒 | 記錄 DEBUG 日誌，進入 fallback | 層級 3 |
| `subprocess.CalledProcessError` | git 回傳非 0（僅在 check=True 時） | 檢查 returncode，進行條件進入 | 層級 3 |
| **所有異常均不拋出**（設計要求） | 永遠 fallback 而非崩潰 | 邊界條件：空環境變數、無效路徑 | 層級 3/4 |

**實作要點**：使用 `subprocess.run()` 而非 `subprocess.check_call()`，以便在 returncode != 0 時進行條件判斷而非拋出異常。

### 1.4 兩個檔案的對稱性設計

| 面向 | hook_base.py | paths.py | 差異說明 |
|------|------------|---------|---------|
| 環境變數 | CLAUDE_PROJECT_DIR 優先 | 相同 | 完全相同 |
| git rev-parse | 新增，優先級 2 | 新增，優先級 2 | 完全相同 |
| 層級 3 fallback | CLAUDE.md 搜尋（有深度限制） | CLAUDE.md → go.mod → pubspec.yaml（無深度限制） | **故意設計不同**，保留各自原有邏輯 |
| 層級 4 fallback | Path.cwd() | Path.cwd() | 完全相同 |
| 函式簽名 | `get_project_root() -> Path` | `get_project_root() -> Path` | 完全相同，無需修改呼叫端 |

**設計決策**：層級 3 fallback 故意設計不同原因（詳見 Phase 1 決策記錄）：
- hook_utils 和 ticket_system 是獨立子系統，各自維護自己的邏輯
- 提取共用函式會造成循環依賴風險
- 兩個實作簡單（< 20 行），重複是可接受的

## 2. 資料結構選擇

### 2.1 使用的資料結構

| 資料結構 | 用途 | 選擇理由 |
|---------|------|---------|
| `pathlib.Path` | 回傳值型別 | 與現有簽名一致，支援 `/` 路徑拼接，不需修改呼叫端 |
| `str`（環境變數值） | 臨時變數 | `os.getenv()` 回傳 str，直接轉換為 Path |
| `subprocess.CompletedProcess` | git 命令結果 | 標準庫物件，支援 returncode、stdout、stderr 檢查 |
| `list[str]`（markers） | 標記檔案名稱清單 | paths.py 原有邏輯，保留 |

### 2.2 新增常數定義

| 常數 | 值 | 所在檔案 | 用途 |
|------|-----|---------|------|
| `GIT_TOPLEVEL_TIMEOUT` | `5` | hook_base.py | git rev-parse 執行超時時限（秒） |
| `GIT_TOPLEVEL_TIMEOUT` | `5` | paths.py | 相同定義 |

**放置位置**：各檔案的「常數定義」區塊頂部，與現有 `ENV_PROJECT_DIR` 和 `CLAUDE_MD_SEARCH_DEPTH` 並列。

## 3. 資料流程圖

```
輸入：get_project_root() 函式呼叫
  |
  v
[檢查環境變數]
  CLAUDE_PROJECT_DIR 已設定?
  |
  +--YES--> 回傳 Path(env_value) ─┐
  |                                |
  +--NO---v                        |
        [執行 git rev-parse]        |
        subprocess("git rev-parse --show-toplevel", timeout=5s)
        |                          |
        +--成功(rc=0)---> 回傳 Path(stdout.strip()) ─┤
        |                                           |
        +--FileNotFoundError     |
        +--TimeoutExpired        |
        +--失敗(rc!=0)---v       |
                       [CLAUDE.md/marker 搜尋]      |
                       |                            |
                       +--找到---> 回傳 Path ─┤
                       |                    |
                       +--未找到---v        |
                                 [cwd fallback]
                                 回傳 Path.cwd()
                                           |
  +-------────────────────────────────────┴→ 輸出：Path 物件
```

**資料流轉換**：
1. 環境變數值（str）→ Path 物件
2. subprocess stdout（str with newline）→ strip() → Path 物件
3. 搜尋結果（Path 物件）或 cwd（Path 物件）→ 直接回傳

## 4. 控制流程圖

```
START: get_project_root()
  |
  v
[Decision 1] 環境變數已設定?
  |
  YES --> RETURN env_path (Layer 1)
  |
  NO
  |
  v
[Decision 2] git 命令可用 & 成功?
  |
  YES --> RETURN git_toplevel (Layer 2)
  |
  NO
  |
  v (進入異常處理)
[Try Block] subprocess.run()
  |
  EXCEPT FileNotFoundError:
    |
    v
  LOG: git not found
  GOTO Layer 3
  |
  EXCEPT TimeoutExpired:
    |
    v
  LOG: git timeout
  GOTO Layer 3
  |
  EXCEPT (returncode != 0):
    |
    v
  LOG: git failed
  GOTO Layer 3

[Layer 3] CLAUDE.md / marker 搜尋
  |
  v
[Decision 3] 搜尋成功?
  |
  YES --> RETURN found_path (Layer 3)
  |
  NO
  |
  v
[Layer 4] cwd fallback
  |
  v
  RETURN Path.cwd()

END: 回傳 Path 物件 (永不失敗)
```

**流程特性**：
- 每個層級都是條件式進入（不會跳過）
- 異常都被捕捉，不會拋出給呼叫端
- 最終總會回傳一個有效的 Path 物件

## 5. 關鍵實作指引

### 5.1 第一階段目標（hook_base.py 修改）

**目標測試**：
- `test_hook_base_env_var_priority` — 環境變數優先
- `test_hook_base_git_revparse_success` — git rev-parse 成功（worktree 修復的核心）
- `test_hook_base_worktree_git_revparse` — worktree 環境驗證

**優先順序**：
1. 新增 `import subprocess` 到 hook_base.py 的 import 區塊
2. 新增 `GIT_TOPLEVEL_TIMEOUT = 5` 常數
3. 在 `_find_project_root()` 中插入 git rev-parse 邏輯（Step 2，介於環境變數與 CLAUDE.md 搜尋之間）
4. 包裝 subprocess 呼叫在 try-except 區塊中，捕捉三種異常：
   - `FileNotFoundError`（git 不存在）
   - `subprocess.TimeoutExpired`（超時）
   - 條件判斷 `returncode != 0`（非 0 返回值）

**實作要點**：
```
新的 _find_project_root() 結構：

def _find_project_root() -> Path:
    # Layer 1: 環境變數（保留現有邏輯）
    env_dir = os.getenv(ENV_PROJECT_DIR)
    if env_dir:
        return Path(env_dir)

    # Layer 2: git rev-parse（新增）
    try:
        result = subprocess.run(
            ["git", "rev-parse", "--show-toplevel"],
            capture_output=True,
            text=True,
            timeout=GIT_TOPLEVEL_TIMEOUT
        )
        if result.returncode == 0:
            return Path(result.stdout.strip())
    except (FileNotFoundError, subprocess.TimeoutExpired):
        pass  // 進入 fallback

    # Layer 3: CLAUDE.md 搜尋（保留現有邏輯）
    current_dir = Path.cwd()
    for _ in range(CLAUDE_MD_SEARCH_DEPTH):
        if (current_dir / "CLAUDE.md").exists():
            return current_dir
        parent = current_dir.parent
        if parent == current_dir:
            break
        current_dir = parent

    # Layer 4: cwd fallback（保留現有邏輯）
    return Path.cwd()
```

**目標測試**：
- `test_paths_env_var_priority` — 環境變數優先
- `test_paths_git_revparse_success` — git rev-parse 優先（替代現有的 go.mod/pubspec.yaml）
- `test_paths_worktree_git_revparse` — worktree 環境驗證

**整合策略**：

2. 在 `get_project_root()` 中插入 git rev-parse 邏輯（Step 2）
3. 保留原有的 CLAUDE.md → go.mod → pubspec.yaml 搜尋順序（作為 git 失敗時的 fallback）

**實作要點**：
```
新的 get_project_root() 結構：

def get_project_root() -> Path:
    # Layer 1: 環境變數（保留現有邏輯）
    claude_project_dir = os.environ.get("CLAUDE_PROJECT_DIR")
    if claude_project_dir:
        return Path(claude_project_dir)

    # Layer 2: git rev-parse（新增）
    try:
        result = subprocess.run(
            ["git", "rev-parse", "--show-toplevel"],
            capture_output=True,
            text=True,
            timeout=GIT_TOPLEVEL_TIMEOUT
        )
        if result.returncode == 0:
            return Path(result.stdout.strip())
    except (FileNotFoundError, subprocess.TimeoutExpired):
        pass  // 進入 fallback

    # Layer 3: marker 搜尋（保留現有邏輯）
    markers = ["CLAUDE.md", "go.mod", "pubspec.yaml"]
    current = Path.cwd()
    while current != current.parent:
        for marker in markers:
            if (current / marker).exists():
                return current
        current = current.parent

    # Layer 4: cwd fallback（保留現有邏輯）
    return Path.cwd()
```

## 7. 語言特定實作注意事項

### 7.1 Python 考量

| 項目 | 考量 | 實作建議 |
|------|------|---------|
| **subprocess 模組** | Python 3.7+ `subprocess.run()` 標準用法 | 使用 `capture_output=True` 和 `text=True`，避免編碼問題 |
| **pathlib.Path** | 跨平台路徑處理 | 使用 Path 物件而非字符串，支援 `/` 拼接 |
| **異常類型** | Python 異常層級 | `FileNotFoundError`（子類 OSError）、`subprocess.TimeoutExpired` 獨立異常 |
| **timeout 參數** | Python 3.3+ 支援 | 使用 `timeout=5` 參數，秒為單位 |
| **text vs encoding** | Python 3.7+ 默認 | `text=True` 自動轉換為字符串（等同舊版 `universal_newlines=True`） |
| **strip() 方法** | 字符串方法 | stdout.strip() 移除尾部換行符和空格 |

### 7.2 效能最佳化建議

| 建議 | 理由 | Phase |
|------|------|-------|
| git rev-parse 放在層級 2（優先執行） | worktree 場景最常見，提早返回減少後續搜尋 | Phase 3b |
| 環境變數檢查不使用 try-except | 簡單且快速，CLAUDE_PROJECT_DIR 設定通常明確 | Phase 3b（現有） |
| CLAUDE.md 搜尋使用 exists() 而非 is_file() | 避免額外的檔案系統呼叫 | Phase 3b（現有） |
| 無需 cwd 快取 | 呼叫端責任快取結果，不在本函式實現 | Phase 3b |

### 7.3 可能的技術挑戰

| 挑戰 | 症狀 | 解決方案 |
|------|------|---------|
| **git 命令找不到** | FileNotFoundError 在 PATH 為空的環境 | 捕捉異常，進入 fallback |
| **git 超時** | subprocess.TimeoutExpired，特別是 git 掛載 | 5 秒 timeout 應足夠本地操作 |
| **編碼問題** | stdout 包含非 UTF-8 字符（罕見） | `text=True` 使用系統默認編碼，通常無問題 |
| **symlink 解析** | git 回傳實際路徑，不是 symlink | Path 物件可正確處理，無需特殊邏輯 |
| **Windows 路徑** | git 可能回傳 `/c/Users/...`（MSYS 格式） | Path(git_output) 會自動轉換（pathlib 內部處理） |
