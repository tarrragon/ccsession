## Solution

### 實現摘要

已成功擴充 acceptance-gate-hook，為 ANA 類型 Ticket 新增後續 Ticket 檢查功能。

#### 1. hook_messages.py - 新增訊息常數
- 新增 `GateMessages.ANA_MISSING_SPAWNED_TICKETS_WARNING` 訊息常數
- 訊息清晰說明 ANA Ticket 應有後續可追蹤 Ticket 的業務需求
- 包含建議操作步驟供使用者參考

#### 2. acceptance-gate-hook.py - 核心邏輯擴充

**TicketFrontmatter 型別定義**
- 新增 `spawned_tickets: str` 欄位支援

**新增函式 - is_ana_type()**
- 判斷 Ticket 類型是否為 ANA（不區分大小寫）
- 用於條件判斷，只對 ANA 類型 Ticket 執行檢查

**新增函式 - extract_spawned_tickets_from_frontmatter()**
- 從 frontmatter 提取 spawned_tickets 欄位
- 支援 YAML 清單格式：`- {ticket_id}`
- 與 extract_children_from_frontmatter() 相同的實現模式

**新增函式 - check_ana_has_spawned_tickets()**
- 驗證 ANA Ticket 是否有後續 Ticket
- 檢查 children 或 spawned_tickets 是否非空
- 輸出結果：
  - 缺少後續 Ticket → 輸出 WARNING（雙通道：logger + stderr）
  - 有後續 Ticket → 正常通過（無警告）
  - **不阻擋執行**（仍為警告，不影響流程）

#### 3. 工作流整合

**check_acceptance_status() 函式**
- 步驟 2.5 新增 ANA 檢查（在驗收記錄檢查後）
- 觸發條件：無前置警告訊息 + type == "ANA"
- 保留現有邏輯結構，向後相容

**檢查順序**
1. 子任務完成度檢查（可阻擋）
2. 驗收記錄驗證（警告）
2.5. ANA 後續 Ticket 檢查（警告，新增）
3. Error-pattern 新增檢查
4. Pending sibling tickets 檢查

#### 4. 技術特性

- **雙通道日誌**：使用 `logger.warning()` + `sys.stderr.write()` 確保警告對用戶可見
- **向後相容**：無修改現有邏輯，僅添加新檢查
- **YAML 格式一致**：spawned_tickets 使用與 children 相同的 YAML 清單格式
- **非阻擋特性**：此檢查為警告性質，不會阻止 complete 執行
