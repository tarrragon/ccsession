## 1. 測試策略規劃

### 1.1 分層測試決策

根據混合測試策略，為 worktree SKILL 設計分層測試：

| 層級 | 模組 | 測試策略 | 原因 |
|------|------|---------|------|
| **Layer 5（Domain 邏輯）** | 命名推導、Ticket ID 解析 | 單元測試（快速、獨立） | 純算法邏輯，無 I/O 依賴 |
| **Layer 4（Behavior）** | Branch 狀態計算、反推邏輯 | 單元測試 | 業務轉換邏輯，可 Mock git |
| **Layer 3（UseCase）** | create_feature_worktree、status 蒐集 | 整合測試（BDD） | 涉及 git 命令執行和副作用 |
| **Layer 2（Hook）** | is_in_worktree、路徑豁免判斷 | 單元測試 + 整合測試 | 業務邏輯 + git 系統呼叫 |
| **Layer 1（Hook 入口）** | branch-verify-hook、branch-status-reminder | 整合測試 | 完整 Hook 流程驗證 |

### 1.2 Mock 策略（Sociable Unit Tests）

應用 Sociable Unit Tests 原則：只 Mock 外部依賴（git、檔案系統），使用真實 Domain Entities（Ticket ID、Branch Name）。

| 依賴類型 | 處理方式 | 理由 |
|---------|---------|------|
| **git 命令執行** | Mock（subprocess/run_git_command） | 外部系統，隔離 I/O |
| **檔案系統操作** | Mock（os.path.exists、os.listdir） | 外部依賴，避免測試間污染 |
| **Ticket ID、Branch Name** | 不 Mock，使用真實物件 | 內層業務邏輯，直接測試 |
| **worktree 資訊結構** | 使用真實字典/物件 | 內層資料結構 |

### 1.3 測試覆蓋率目標

| 模組 | 目標 | 說明 |
|------|------|------|
| parse_ticket_id() | 100% | 正常、格式錯誤、邊界情況 |
| derive_branch_name() | 100% | 正常、各級子任務（.1、.2 等） |
| derive_worktree_path() | 100% | 正常、目錄路徑計算、邊界 |
| extract_ticket_id_from_branch() | 100% | 合法、非 feat/、detached HEAD |
| cmd_create() | 95%+ | 主要流程、錯誤情境（Git 失敗模擬可豁免） |
| cmd_status() | 95%+ | 全部、特定、無 worktree 情況 |
| is_in_worktree() | 100% | 主倉庫、worktree、非 git 目錄 |
| is_exempt_path_on_protected_branch() | 100% | 豁免、非豁免、邊界路徑 |

## 3. 具體測試案例設計

### 3.1 W9-002.5.1：命名推導和驗證測試

#### 測試類別 1：parse_ticket_id() 驗證

**場景 1.1：正常格式**

```
Given: ticket_id = "0.1.1-W9-002"
When: parse_ticket_id("0.1.1-W9-002")
Then: 返回 True
```

**場景 1.2：子任務格式**

```
Given: ticket_id = "0.1.1-W9-002.1" 或 "0.1.1-W9-002.1.2.3"
When: parse_ticket_id(ticket_id)
Then: 返回 True（支援多層子任務）
```

**場景 1.3：無效格式 - 缺少 W**

```
Given: ticket_id = "0.1.1-001"（缺少 W）
When: parse_ticket_id("0.1.1-001")
Then: 返回 False
```

**場景 1.4：無效格式 - 自由文字**

```
Given: ticket_id = "my-feature"（不符合版本格式）
When: parse_ticket_id("my-feature")
Then: 返回 False
```

**場景 1.5：無效格式 - 版本號錯誤**

```
Given: ticket_id = "v0.1.1-W9-002"（含 v 前綴）
When: parse_ticket_id("v0.1.1-W9-002")
Then: 返回 False
```

**場景 1.6：邊界 - 單層版本**

```
Given: ticket_id = "0-W9-002"（版本號只有一層數字）
When: parse_ticket_id("0-W9-002")
Then: 返回 False（正規表達式要求 \d+\.\d+\.\d+）
```

#### 測試類別 2：derive_branch_name() 推導

**場景 2.1：根任務推導**

```
Given: ticket_id = "0.1.1-W9-002"（通過 parse_ticket_id 驗證）
When: derive_branch_name("0.1.1-W9-002")
Then: 返回 "feat/0.1.1-W9-002"
```

**場景 2.2：子任務推導**

```
Given: ticket_id = "0.1.1-W9-002.1"
When: derive_branch_name("0.1.1-W9-002.1")
Then: 返回 "feat/0.1.1-W9-002.1"
```

**場景 2.3：多層子任務推導**

```
Given: ticket_id = "0.1.1-W9-002.1.2.3"
When: derive_branch_name("0.1.1-W9-002.1.2.3")
Then: 返回 "feat/0.1.1-W9-002.1.2.3"
```

#### 測試類別 3：derive_worktree_path() 推導

**場景 3.1：基本路徑推導**

```
Given: project_root = "/Users/mac-eric/project/ccsession"
       ticket_id = "0.1.1-W9-002.1"
When: derive_worktree_path("0.1.1-W9-002.1")
Then: 返回 "/Users/mac-eric/project/ccsession-0.1.1-W9-002.1"
      邏輯驗證：
        parent_dir = "/Users/mac-eric/project"
        project_name = "ccsession"
        path = "{parent_dir}/{project_name}-{ticket_id}"
```

**場景 3.2：特殊字元目錄名（專案目錄含點）**

```
Given: project_root = "/path/to/my.project"
       ticket_id = "0.1.0-W1-001"
When: derive_worktree_path("0.1.0-W1-001")
Then: 返回 "/path/to/my.project-0.1.0-W1-001"
      (os.path.basename 直接提取，不過濾)
```

**場景 5.3：worktree 路徑已存在**

```

  (前置驗證)
  - 分支、路徑檢查通過

  - exit code = 1
```

| `run_git_command()` | `monkeypatch.setattr` + 返回函式 | 按場景配置返回值或異常 |

| `get_worktree_list()` | mock 回傳值 | 返回預定義 worktree 列表 |

### 5.2 測試隔離策略

- **每個測試獨立初始化** Mock（使用 fixture，避免全域狀態污染）

- **git 命令全部 Mock**（不實際執行 git），確保快速執行
- **測試間無順序依賴**（使用 `-v` 亂序執行驗證）

### 5.3 測試執行清理

- pytest 自動清理 `tmp_path`
- Mock 自動恢復（monkeypatch 作用域）
- 無需手動清理檔案或 git 資源

優先使用具體斷言，避免模糊檢查：

```python
# 正確：明確檢查返回值
assert result == "feat/0.1.1-W9-002.1"

# 正確：檢查例外
with pytest.raises(ValueError, match="無效的 Ticket ID 格式"):
    parse_ticket_id("invalid")

# 不推薦：過度模糊
assert "feat" in result
```

def test_derive_branch_name(ticket_id, expected):
