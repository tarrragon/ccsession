# Phase 2 測試設計：/worktree merge + cleanup 子命令

## 一、測試策略規劃

### 整體設計原則

采用 **Sociable Unit Tests** 原則：
- **測試單位**：merge 和 cleanup 子命令本身（作為模組層級單元）
- **隔離範圍**：只隔離外部依賴（git 命令、ticket CLI）
- **真實資訊**：不 mock worktree_manager 內部的輔助函式，只 mock 真正的外部邊界（subprocess、shell 命令）
- **行為驗證**：測試用戶可見的行為（exit code、輸出訊息），不測試內部實作結構

### 分層測試策略

| 層級 | 測試對象 | 工具 | 優先級 |
|------|---------|------|--------|
| **Layer 1：功能單元層** | cmd_merge()、cmd_cleanup() | pytest（assert 返回值 + 輸出驗證） | 高 |
| **Layer 2：邊界條件層** | Level 1/2/3 閘門、format validation | pytest + mock subprocess | 高 |
| **Layer 3：集成驗證層** | 多個工具函式協作（get_worktree_list + 前置驗證） | pytest + 模擬完整 git 狀態 | 中 |
| **Layer 4：end-to-end** | 實際 git 命令執行（可選集成測試） | tox + 真實 git repo | 低 |

### Mock 策略

| 依賴 | Mock 方式 | 原因 |
|------|---------|------|
| `subprocess.run`（git 命令執行） | Mock 完整回傳 | git 命令執行依賴真實 repo，測試中不應依賴 |
| `subprocess.run`（ticket CLI） | Mock 返回值或異常 | ticket CLI 是外部工具，測試應模擬其結果 |
| `run_git_command` wrapper | 不 mock（使用其行為） | run_git_command 是內部輔助函式，應測試其與 git 命令的協作 |
| worktree 資訊（path, branch） | Mock get_worktree_list() | worktree 信息是系統狀態，測試應提供固定狀態 |
| 檔案系統（os.path.exists 等） | Mock | 避免依賴測試環境的檔案結構 |

## 二、merge 子命令測試設計

### 測試檔案結構

**新增檔案**：`tests/test_worktree_merge.py`

### 前置條件驗證（行為鏈式設計）

merge 命令的驗證順序形成前置條件鏈：
```
輸入 ticket_id
  ↓ (驗證1) Ticket ID 格式合法
worktree 找到
  ↓ (驗證2) Ticket 狀態為 completed
worktree working tree 乾淨
  ↓ (驗證3) ahead/behind 計算成功
所有前置條件滿足 → 輸出指令
```

**前置驗證原則**：
- 每個測試場景應先 `Then（前置驗證）` 確認前置條件存在，再執行 `When` 行為
- 如果前置條件失敗，不執行後續行為

### 測試場景與案例

## 三、cleanup 子命令測試設計

### 測試檔案結構

**新增檔案**：`tests/test_worktree_cleanup.py`

### Level 1/2/3 閘門的前置條件驗證

cleanup 採用三層閘門模型，測試設計應驗證每層閘門的獨立行為：

```
Level 1（拒絕）: uncommitted > 0
  ↓ 永不可繞過，--force 無效

Level 2（警告）: ahead > 0 且未 push
  ↓ 可被 --force 略過

Level 3（警告）: ahead > 0 且未合併到 main
  ↓ 可被 --force 略過

全部通過 → 執行 git worktree remove + git branch -d
```

**前置條件驗證原則**：
- 每個測試應先驗證「到達該閘門」的條件，再測試該閘門的行為
- 如果 Level 1 失敗，不測試 Level 2/3（因為邏輯會提前返回）

### 測試場景與案例

#### 場景 9：cleanup — 精確模式，三閘門全通過（成功清理）

**GWT 規格**：

```
Given: Ticket 0.1.1-W9-001 對應 worktree 存在
       Level 1 通過: uncommitted == 0（無未 commit 變更）
       Level 2 通過: 已 push 到 origin（origin/feat/0.1.1-W9-001 存在且與本地同步）
       Level 3 通過: feat/0.1.1-W9-001 已合併到 main
Then（前置驗證）: Ticket ID 格式合法 ✓
Then（前置驗證）: worktree 存在 ✓
Then（前置驗證）: Level 1 檢查：uncommitted == 0 ✓
Then（前置驗證）: Level 2 檢查：_is_branch_pushed() == True ✓
Then（前置驗證）: Level 3 檢查：_is_branch_merged_to_base() == True ✓
When: 執行 /worktree cleanup 0.1.1-W9-001
Then: 輸出三層閘門通過摘要
Then: 執行 subprocess 呼叫 git worktree remove /path
Then: 執行 subprocess 呼叫 git branch -d feat/0.1.1-W9-001
Then: 輸出清理完成訊息（含路徑、分支名稱）
Then: exit code 為 0
```

**測試函式名稱**：`test_cleanup_exact_success_all_gates_pass`

**Mock 需求**：

- `_is_branch_merged_to_base()`：返回 True

- `subprocess.run`（git branch -d）：成功

### 測試執行順序（建議）

為了驗證前置條件鏈，建議執行順序：

1. **格式驗證層**（快速失敗）：場景 8
2. **資訊查詢層**（前置檢查）：場景 7、17
3. **merge 驗證層**：場景 1（全通過）→ 場景 2、3（阻擋）→ 場景 4、5、6（警告）
4. **cleanup 閘門層**：
   - Level 1：場景 10（必拒絕）
   - Level 2：場景 11、12（警告+略過）
   - Level 3：場景 13、14（警告+略過）
5. **掃描模式**：場景 15、16
6. **部分失敗**：場景 18

### 訊息驗證策略

所有訊息都應從 `messages.py` 常數引入，測試應驗證訊息常數而非硬編碼字串：

```python
from worktree_manager.scripts.messages import MergeMessages, CleanupMessages

# ✓ 正確
assert MergeMessages.TICKET_NOT_COMPLETED in output

# ✗ 錯誤
assert "Ticket" in output and "狀態為" in output
```

### 編碼標準

- **命名規範**：`test_{命令}_{場景描述}_{預期結果}`
  - 例：`test_merge_blocked_ticket_not_completed`
  - 例：`test_cleanup_level1_rejected_without_force`

- **測試檔案路徑**：
  - `.claude/skills/worktree/tests/test_worktree_merge.py`（8 個場景）
  - `.claude/skills/worktree/tests/test_worktree_cleanup.py`（10 個場景）
  - `.claude/skills/worktree/tests/conftest.py`（補充 fixtures）

- **註解標準**：每個測試應有簡短的 docstring 說明場景編號和預期行為
  ```python
  def test_merge_blocked_ticket_not_completed():
      """場景 2: merge — Ticket 未完成被阻擋

      Ticket 狀態為 in_progress 時，應拒絕輸出 merge 指令。
      """
  ```

- **斷言順序**：先驗證 exit code，再驗證輸出訊息
  ```python
  assert result == 1  # exit code 優先
  assert "Ticket 0.1.1-W9-002" in output
  assert "in_progress" in output
  assert "git merge" not in output
  ```

- **訊息驗證**：從 `messages.py` 常數類別引入
  ```python
  from worktree_manager.scripts.messages import MergeMessages, CleanupMessages

  assert MergeMessages.TICKET_NOT_COMPLETED in output
  assert CleanupMessages.LEVEL1_REJECTED in output
  ```
