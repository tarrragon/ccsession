## Problem Analysis

### 重複代碼位置確認

**搜尋指令**：`grep -rn "_load_pyproject_toml\|_parse_pyproject\|_extract_.*_from_pyproject\|scan_skill_packages\|scan_custom_packages" --include="*.py"`

**確認的位置（已確認）**：

Hook 端掃描邏輯（.claude/hooks/package-version-sync-hook.py）：
- Line 266-334：`scan_skill_packages()` - 目錄遍歷 + 版本提取
- Line 337-356：`_load_pyproject_toml()` - TOML 解析

CLI 端掃描邏輯（.claude/skills/project-init/project_init/lib/package_manager.py）：
- Line 61-97：`scan_custom_packages()` - 目錄遍歷 + 版本提取
- Line 303-326：`_parse_pyproject()` - TOML 解析 + 快取
- Line 328-346：`_extract_version_from_pyproject()` - 版本提取
- Line 349-367：`_extract_package_name_from_pyproject()` - 包名提取
- Line 370-391：`_extract_cli_name_from_pyproject()` - CLI 名提取

**重複分析**：
- pyproject.toml 解析：~20 行重複（tomllib/tomli 邏輯完全相同）
- 版本/包名/CLI 名提取：~50 行重複（邏輯完全相同）

- 總計：~95 行可提取的重複代碼

## Solution

### Phase 1 設計完成

**階段產出**：設計文件 `0.1.1-W18-001-phase1-design.md`

**方案決定**：提取共用模組 `.claude/lib/pyproject_scanner.py`

**核心方案**：
1. 新建 `.claude/lib/pyproject_scanner.py` 共用模組
   - 集中 pyproject.toml 解析邏輯
   - 提供 5 個公開函數：load_pyproject_toml, extract_version/package_name/cli_name_from_pyproject, scan_skills_directory
   - 支援 Python 3.9+，無外部依賴

2. Hook 修改（.claude/hooks/package-version-sync-hook.py）
   - 移除 `_load_pyproject_toml()` (~20 行)
   - 修改 `scan_skill_packages()` 調用共用模組
   - 新增 sys.path.insert 導入共用模組

3. CLI 修改（.claude/skills/project-init/project_init/lib/package_manager.py）
   - 移除 `_parse_pyproject()` 和三個提取函數（~100 行）
   - 修改 `scan_custom_packages()` 調用共用模組，返回格式保持 `list[PackageInfo]`

**環境約束考慮**：
- Hook 運行在獨立環境，無法 import project-init 套件 → 使用 sys.path.insert(0, ...) 方案
- CLI 可直接 import .claude/lib 模組
- 共用模組使用標準庫 (tomllib/tomli)，無額外依賴

**驗收標準**：
- [ ] 新模組建立完成，代碼品質符合 quality-python.md
- [ ] Hook 測試通過：`.claude/hooks/tests/test_manual_verification.py`
- [ ] CLI 測試通過：`(cd .claude/skills/project-init && uv run pytest)`
- [ ] 重複代碼消除，~95 行重複代碼移至共用模組
- [ ] 所有層級都無程式碼品質警告
