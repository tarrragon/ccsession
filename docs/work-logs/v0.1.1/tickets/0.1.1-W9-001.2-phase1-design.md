# Phase 1 功能規格設計

## 功能需求分析

### 核心問題

`create_feature_worktree.py` 現行實作使用兩步操作：

1. `git checkout -b {branch} {base_branch}`（第 96 行）— 在主工作目錄切換並建立新分支
2. `git worktree add {path} {branch}`（第 101 行）— 在新路徑建立 worktree

**問題根因**：步驟一成功後，當前工作目錄的 HEAD 已切換到新分支。若步驟二失敗，雖然第 103-104 行嘗試用 `git branch -D {branch}` 回滾，但有兩個未處理風險：

- `git checkout -b` 執行後，主 worktree 的 HEAD 已改變，刪除分支並不能還原 HEAD 到原始狀態
- 若刪除分支本身也失敗（例如分支在另一個 worktree 有殘留），狀態污染無法清除

### 改進方案

使用 `git worktree add -b {branch} {path} {base_branch}` 單一原子命令：

- 此命令在指定路徑建立新 worktree，同時從 `{base_branch}` 建立新分支 `{branch}`
- 主工作目錄的 HEAD **不受影響**（原子操作內部完成，不切換主工作目錄）
- 若命令失敗，git 內部自動清理，無需手動回滾

## 功能規格設計

### 函式：create_feature_worktree

#### 現行簽名（不變）

```python
def create_feature_worktree(
    branch: str,
    worktree_path: str,
    base_branch: str = "main"
) -> tuple[bool, str]:
```

函式簽名**無需變更**。輸入參數、回傳型別與語義完全相同，僅內部實作替換。

#### 輸入定義

| 參數 | 型別 | 說明 | 限制 |
|------|------|------|------|
| `branch` | `str` | 新分支名稱 | 非空；不得已存在於 repo |
| `worktree_path` | `str` | worktree 目錄路徑（相對或絕對皆可） | 對應的絕對路徑不得已存在 |
| `base_branch` | `str` | 基礎分支（預設 `"main"`） | 必須已存在於 repo |

#### 輸出定義

| 回傳值 | 型別 | 說明 |
|--------|------|------|
| `(True, 成功訊息)` | `tuple[bool, str]` | 原子操作成功，worktree 和分支均已建立 |
| `(False, 錯誤訊息)` | `tuple[bool, str]` | 前置驗證失敗或原子操作失敗 |

### 正常流程（改寫後）

```
1. 轉換 worktree_path 為絕對路徑
2. 前置驗證：
   a. worktree 路徑不得已存在
   b. 分支不得已存在
   c. base_branch 必須已存在
3. 執行單一原子命令：
   git worktree add -b {branch} {worktree_abs_path} {base_branch}
4. 成功 → 回傳 (True, 成功訊息)
   失敗 → 回傳 (False, 錯誤訊息)（git 內部已自動清理，無需手動回滾）
```

### 錯誤處理策略（改寫後）

| 錯誤情境 | 處理方式 | 回傳訊息格式 |
|---------|---------|------------|
| worktree 路徑已存在 | 前置驗證攔截，不執行 git 命令 | `"Worktree 路徑已存在: {path}"` |
| 分支已存在 | 前置驗證攔截，不執行 git 命令 | `"分支已存在: {branch}"` |
| base_branch 不存在 | 前置驗證攔截，不執行 git 命令 | `"基礎分支不存在: {base_branch}"` |
| `git worktree add -b` 失敗（git 內部錯誤） | 直接回傳 git stderr，無需手動回滾 | `"創建 worktree 失敗: {stderr}"` |
| git 命令執行超時 | `run_git_command` 已處理 | `"命令執行超時"` |

**移除的回滾邏輯**：原第 103-104 行的 `run_git_command(["branch", "-D", branch])` 完全移除，因為 `git worktree add -b` 是原子操作，失敗時 git 自動清理，不留殘留狀態。

### dry-run 模式（輸出變更）

**現行輸出**（兩步操作描述）：

```
=== Dry Run 模式 ===
將要執行的操作:
  1. 從 '{base}' 創建分支 '{branch}'
  2. 創建 worktree 到 '{path}'
```

**改寫後輸出**（單一原子命令描述）：

```
=== Dry Run 模式 ===
將要執行的操作:
  git worktree add -b {branch} {abs_path} {base}

實際執行請移除 --dry-run 參數
```

改寫原因：dry-run 應如實反映實際執行的命令，讓使用者明確知道將執行的 git 指令。

## 邊界條件分析

| 邊界情境 | 預期行為 |
|---------|---------|
| `worktree_path` 為相對路徑 | 轉為絕對路徑後檢查，行為不變 |
| `branch` 包含斜線（如 `feat/abc`） | git 原生支援，無需特殊處理 |
| `base_branch` 為遠端追蹤分支（如 `origin/main`） | `git rev-parse --verify` 可驗證，`git worktree add -b` 可接受 |
| `base_branch` 就是當前 HEAD 所在分支 | 主 worktree HEAD 不受影響（原子操作特性） |
| git worktree add -b 部分成功後 OS 中斷 | git 內部事務保證，不在本函式處理範圍 |

## API 介面定義（修改前後對比）

### 函式簽名（不變）

```python
# 修改前後完全相同
def create_feature_worktree(
    branch: str,
    worktree_path: str,
    base_branch: str = "main"
) -> tuple[bool, str]:
```

### 內部實作對比

**修改前**（第 95-107 行）：

```python
# Step 1: 從基礎分支創建新分支（污染主工作目錄 HEAD）
success, msg = run_git_command(["checkout", "-b", branch, base_branch])
if not success:
    return False, f"創建分支失敗: {msg}"

# Step 2: 創建 worktree（若失敗需手動回滾）
success, msg = run_git_command(["worktree", "add", worktree_abs_path, branch])
if not success:
    # 回滾：刪除剛創建的分支（不完整：HEAD 未還原）
    run_git_command(["branch", "-D", branch])
    return False, f"創建 worktree 失敗: {msg}"

return True, f"成功創建分支 '{branch}' 和 worktree '{worktree_abs_path}'"
```

**修改後**（替換為單一原子操作）：

```python
# 單一原子命令：同時建立分支和 worktree，主工作目錄 HEAD 不受影響
success, msg = run_git_command(
    ["worktree", "add", "-b", branch, worktree_abs_path, base_branch]
)
if not success:
    # 原子操作失敗：git 自動清理，無需手動回滾
    return False, f"創建 worktree 失敗: {msg}"

return True, f"成功創建分支 '{branch}' 和 worktree '{worktree_abs_path}'"
```

### 呼叫端影響

CLI 入口 `main()` 函式的呼叫方式**完全不變**，外部介面無破壞性變更。

## 行為場景（Given-When-Then）

### 場景 1: 正常流程 — 成功建立

```
場景 1: git worktree add -b 成功執行
Given: branch 不存在、worktree_path 不存在、base_branch 存在
When: 呼叫 create_feature_worktree("feat/abc", "../project-abc", "main")
Then: 回傳 (True, "成功創建分支 'feat/abc' 和 worktree '{abs_path}'")
      主工作目錄 HEAD 未改變
      新 worktree 已建立於指定路徑
```

### 場景 2: 前置驗證失敗 — worktree 路徑已存在

```
場景 2: worktree 路徑已存在
Given: worktree_path 對應的絕對路徑已存在（目錄已有）
When: 呼叫 create_feature_worktree(...)
Then: 回傳 (False, "Worktree 路徑已存在: {abs_path}")
      未執行任何 git 命令
```

### 場景 3: 前置驗證失敗 — 分支已存在

```
場景 3: branch 已存在於 repo
Given: branch 名稱已被使用
When: 呼叫 create_feature_worktree(...)
Then: 回傳 (False, "分支已存在: {branch}")
      未執行任何 git 命令
```

### 場景 4: 前置驗證失敗 — base_branch 不存在

```
場景 4: base_branch 不存在
Given: base_branch 指定的分支在 repo 中不存在
When: 呼叫 create_feature_worktree(...)
Then: 回傳 (False, "基礎分支不存在: {base_branch}")
      未執行任何 git 命令
```

### 場景 5: 原子命令失敗

```
場景 5: git worktree add -b 執行失敗（例如磁碟空間不足）
Given: 前置驗證全部通過
When: git worktree add -b 命令回傳非零 exit code
Then: 回傳 (False, "創建 worktree 失敗: {stderr}")
      無殘留分支（git 原子操作保證）
      主工作目錄 HEAD 未改變
```

### 場景 6: dry-run 模式

```
場景 6: dry-run 模式輸出正確命令
Given: 執行時加上 --dry-run 旗標
When: 呼叫 main() 且 args.dry_run == True
Then: 輸出包含 "git worktree add -b {branch} {abs_path} {base}"
      不執行任何 git 命令
      程序正常退出（exit code 0）
```
