**發現的術語問題**：

1. sessionId vs sessionID：UC 文件（前端視角）使用 sessionId，UC-010 Go 層日誌欄位使用 sessionID。此為前後端語言慣例差異（Dart/Go 命名規範不同），文件上可加注說明，非邏輯衝突。屬於低優先級文件改善項目。

2. UC-006 A2 掃描規則中提到「history.jsonl」用於 session-to-project 映射，但 UC-008 第 8.1 節也提及此檔案，用途描述一致，無衝突。

### 七、改善建議

1. **優先補充 UC-010、UC-011 的 BDD Feature Files**：這是最重要的缺口。UC-010（日誌輸出）和 UC-011（格式變動偵測）都是 P0 優先級的橫切關注點，缺少 BDD 場景會影響後續 Phase 3b 實作的測試驗收。

2. **UC-010 feature file 重點場景建議**：
   - Go Backend 各層（File Watcher、JSONL Parser、Session Manager、WS Server）的 log 輸出格式驗證
   - Flutter 各層的 log 輸出格式驗證
   - Release 模式 DEBUG log 降級場景
   - Log 不包含對話內容（隱私保護）

3. **UC-011 feature file 重點場景建議**：
   - 頂層出現未知欄位時的 WARN log 輸出
   - content array 出現未知元素類型時的處理
   - Flutter Event Mapper 收到未知 type 的處理
   - WARN log deduplication（相同未知欄位不重複 log）
   - 整合場景：模擬 Claude 格式更新，確認 WARN log 可被 grep

4. **W1 產出整體評價**：9 個並行 Agent 的產出在內容一致性和邏輯正確性上表現優異，沒有發現跨 UC 的邏輯衝突。BDD 場景設計品質高，對 UC 驗收條件的覆蓋均超過 100%（補充了 UC 文件未涵蓋的精確邊界規格）。主要缺口是 UC-010 和 UC-011 的 BDD feature files 尚未產出，需要在 W2 前補完。
