# Execution Log

## Task Summary

SA 前置審查分析：todolist.yaml 版本配置與版本偵測機制的一致性問題

---

## Problem Analysis

### 現狀調查

**資料來源**:
- docs/todolist.yaml: current_version = 0.1.0
- docs/work-logs 目錄掃描結果:
  - v0.1.0: 359 個 Ticket
  - v0.1.1: 54 個 Ticket ← 當前開發版本
  - v0.2.0: 13 個 Ticket
  - v0.31.0: 2 個 Ticket

**版本偵測邏輯流程** (ticket_system/lib/version.py):
1. _parse_todolist_active_version() → 讀取 current_version (0.1.0)
2. 若查詢失敗 → _scan_worklog_directories() [Fallback] → 掃描最高版本

**症狀**:
- ticket track 命令偵測到 0.1.0
- handoff 命令找不到 v0.1.1 Ticket
- 54 個 v0.1.1 Ticket 在系統中「不可見」

**根本原因**: L1 (Monorepo 版本配置) 與 L2 (實際開發版本) 不同步

---

## Solution

### 架構分析

**三層版本定義** (按 monorepo-version-strategy.md):

| 層級 | 來源 | 當前值 | 角色 |
|------|------|--------|------|
| L1 Monorepo | docs/todolist.yaml (current_version) | 0.1.0 | 唯一的工作版本定義 |
| L2 UI | ui/pubspec.yaml | (待檢查) | 獨立於 L1 |
| L3 Server | server/go.mod | (無版本欄位) | 由 L1 決定 |

**設計問題**: L1 與 L2 分離，導致一致性難以維持

### 三方案比較

**方案 A：短期修復 - 手動更新 todolist.yaml**

修改:
```yaml
# 修改前
status: active
current_version: 0.1.0

# 修改後  
status: active
current_version: 0.1.1
previous_version: 0.1.0
```

- 成本: 低
- 風險: 低
- 效果: 立即解決
- 限制: 容易再次失同步

**建議**: 立即執行，作為第一階段修復

---

**方案 B：中期改進 - Hook 自動同步**

新增 Hook: `version-consistency-auto-sync-hook.py`

機制:
- 觸發時機: SessionStart
- 檢查 current_version vs 最高目錄版本
- 若不一致 → 自動更新 todolist.yaml
- 輸出 INFO 級別日誌通知

- 成本: 中 (新 Hook 開發)
- 風險: 中 (自動修改配置)
- 效果: 自動化同步，無需人工干預
- 優點: 每次對話開始都檢查一致性

**建議**: 短期修復完成後實施

---

**方案 C：長期方案 - 格式標準化**

遷移至 .claude 標準的 versions 列表格式:
```yaml
versions:
  - version: 0.1.1
    status: active
    name: "v0.1.1 - Worktree 支援"
  - version: 0.1.0
    status: archived
    name: "v0.1.0 - 初版"
```

- 成本: 高 (架構重構)
- 風險: 中 (格式變更)
- 效果: 長期一致性保証
- 優點: 支援多版本並行

**建議**: v0.2.0 準備時實施
