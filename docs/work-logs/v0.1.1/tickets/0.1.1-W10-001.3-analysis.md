# 0.1.1-W10-001.3：.claude/handoff/ 在 worktree 環境中的行為分析

## 問題背景

在使用 `git worktree add` 建立 worktree 時，gitignored 的目錄不會出現在 worktree 中。由於 `.claude/handoff/pending/` 被 `.gitignore` 排除，跨 worktree 的任務交接機制完全失效。

## 現狀分析

### 1. .gitignore 設定

根據 `.gitignore` 檔案，以下路徑被排除：

```
# Claude Code logs and temp files
.claude/hook-logs/
.claude/worktrees/
.claude/tool-results/
.claude/handoff/archive/
.claude/handoff/pending/
```

**確認事項**：
- `archive/` 和 `pending/` 都被 gitignore
- `.claude/handoff/.gitignore` 內部也定義了 `pending/` 的排除規則
- `archive/` 雖然被 gitignore，但內包含大量歷史記錄的 JSON 檔案（81 個檔案）

### 2. Handoff 機制原理

根據程式碼分析：

| 組件 | 職責 | 儲存位置 |
|------|------|---------|
| **handoff.py** | 建立 handoff 檔案（handoff/pending/{ticket_id}.json） | pending/ |
| **resume.py** | 讀取 pending 目錄，恢復任務 | pending/ |
| **lifecycle.py** | 整合 handoff/resume 命令 | pending/ 和 archive/ |

**重要流程**（來自 handoff.py 和 resume.py）：

1. **Handoff 流程**（handoff.py: `_create_handoff_file`）：
   - Ticket 完成後，在 `.claude/handoff/pending/{ticket_id}.json` 建立交接檔案
   - 檔案包含：ticket_id、direction、timestamp、from_status、title、what、chain

2. **Resume 流程**（resume.py: `list_pending_handoffs`）：
   - 掃描 `pending/` 目錄，列出所有待恢復任務
   - 過濾「stale handoff」（來源 ticket 已 completed）
   - 提供 resume 命令恢復任務

3. **Stale GC 流程**（handoff_gc.py）：
   - 清理已完成的 handoff
   - 從 pending 移至 archive

### 3. Worktree 中的行為

當執行 `git worktree add` 時：

```bash
git worktree add ../worktree-name feat/branch-name
```

Git 的行為：
- 建立新的工作目錄副本
- **Git 追蹤的檔案**：複製到 worktree
- **Gitignored 的檔案**：不出現在 worktree 中

**結果**：在 worktree 中沒有 `.claude/handoff/pending/` 目錄

### 4. 跨 Worktree 任務交接的失效情況

| 情境 | 主 Repo 行為 | Worktree 行為 | 結果 |
|------|------------|-------------|------|
| 主 repo 完成 Ticket，執行 `ticket handoff` | 在 pending/ 建立 handoff 檔案 | ❌ 看不到 pending/ 目錄 | 交接失效 |
| Worktree 要 resume 任務 | N/A | 執行 `ticket resume --list` | ❌ 找不到任何 handoff |
| 返回主 repo 後 | 仍有 pending handoff（本地存在） | N/A | ✓ 可以在主 repo 中 resume |

## 兩種策略對比

### 策略 A：Session-Local（每個 Worktree 独立 Handoff）

**定義**：每個 session（主 repo + worktrees）各有獨立的 handoff 目錄，不跨 session 共享。

**實作方式**：
- `.claude/handoff/` 仍在主 repo 中，gitignored
- 在各 worktree 內自動建立臨時 `.claude/handoff/` 目錄
- 不在 git 中追蹤 worktree 的 handoff 檔案

**優點**：
- 簡單易實作：只需檢查目錄存在性
- 環境隔離：各 worktree 工作不會相互影響
- 無 git 污染：不需要修改 .gitignore
- 符合 handoff 設計原意（交接檔案是臨時的）

**缺點**：
- 主 repo 和 worktree 間無法直接交接
- worktree 完成的任務無法在主 repo 中 resume
- 需要多次切換回主 repo 才能看到整體進度

**應用場景**：
- 主 repo 和 worktree 執行不同的任務（不交接）
- 每個 worktree 獨立執行並自我完成
- 臨時性 worktree（完成後直接刪除）

### 策略 B：全域共享（Handoff 中央儲存庫）

**定義**：所有 session（主 repo + 所有 worktrees）共享同一個 handoff 目錄。

**實作方式**：

**選項 B1：Git 追蹤的共享位置**
- 建立 `.claude/handoff/current/` 或 `docs/handoff/`（Git 追蹤）
- 所有 worktree 從同一位置讀寫
- 可能產生 merge conflict

**選項 B2：系統級共享位置**
- 使用 `~/.claude/handoff/` 或 `$XDG_DATA_HOME/ccsession-handoff/`
- 所有 session 共享系統級目錄
- 需要專案路徑隔離（防止不同專案衝突）

**選項 B3：主 repo 指向符號連結**
- 主 repo 的 `.claude/handoff/` 是符號連結
- 指向系統級共享位置
- Worktree 中的 `.claude/handoff/` 自動繼承

**優點**：
- 主 repo ↔ worktree 可直接交接
- 統一的 handoff 檢視
- 不需要重複切換 repo

**缺點**：
- **B1**：Git 追蹤 → merge conflicts
- **B2/B3**：系統配置複雜，跨專案管理困難
- 需要鎖定機制防止並發寫入
- Worktree 間可能產生 race conditions

**應用場景**：
- 複雜的多 worktree 工作流
- 需要跨 worktree 任務交接
- 中央化任務管理

## 建議方案

基於分析，**推薦採用策略 A（Session-Local）**，理由如下：

### 核心考量

| 考量 | 評估 | 優先級 |
|------|------|--------|
| **handoff 設計原意** | 臨時交接檔案，不版本控制 | 高 |
| **Git 相容性** | 不引入 gitignore 修改或 merge conflict | 高 |
| **實作複雜度** | 簡單易維護 | 中 |
| **跨 worktree 交接需求** | 實際工作流中罕見 | 低 |

### 為什麼不選 B？

**B1 缺點太多**：
- Git 追蹤 JSON 檔案會產生頻繁 commit
- Worktree 之間會產生 merge conflict
- 違反 handoff 設計意圖

**B2/B3 過度工程**：
- 增加系統配置複雜度
- 跨專案可能衝突
- 需要額外鎖定機制

**實際需求評估**：
- worktree 主要用途：並行開發不同功能
- 各 worktree 獨立完成任務，很少需要跨 worktree 交接
- 主 repo → worktree 交接：可使用 Ticket clone 或文件複製

## 策略 A 實作方案

### 方案概述

**目標**：讓 handoff 機制在各 worktree 中自動建立並運作，互不影響。

### 實作步驟

**Step 1：修改 get_project_root 邏輯（ticket_loader.py）**

```python
def get_project_root() -> Path:
    """
    獲取專案根目錄。
    
    優先返回 Git 的 worktree 根目錄，確保各 worktree 有獨立的檔案空間。
    如果不在 worktree 中，返回主 repo 根目錄。
    """
    # 1. 檢查環境變數（允許顯式指定）
    if os.environ.get("CCSESSION_PROJECT_ROOT"):
        return Path(os.environ["CCSESSION_PROJECT_ROOT"]).resolve()
    
    # 2. 從 Git 獲取 worktree 根目錄
    result = subprocess.run(
        ["git", "rev-parse", "--show-toplevel"],
        capture_output=True,
        text=True,
        timeout=5
    )
    if result.returncode == 0:
        return Path(result.stdout.strip()).resolve()
    
    # 3. Fallback：尋找 .git
    current = Path.cwd().resolve()
    for parent in [current] + list(current.parents):
        if (parent / ".git").exists():
            return parent
    
    raise RuntimeError("無法定位 Git 專案根目錄")
```

**結果**：
- 主 repo：返回 `/Users/mac-eric/project/ccsession`
- Worktree：返回 `/Users/mac-eric/project/worktree-name`（各自獨立）

**Step 2：初始化 Worktree 的 Handoff 目錄**

在 handoff.py 中確保 pending/ 目錄存在：

```python
def _create_handoff_file(ticket, direction):
    root = get_project_root()
    handoff_dir = root / HANDOFF_DIR / HANDOFF_PENDING_SUBDIR
    handoff_dir.mkdir(parents=True, exist_ok=True)  # ← 自動建立
    
    handoff_file = handoff_dir / f"{ticket.get('id')}.json"
    # ... 後續程式碼
```

**結果**：即使 pending/ 不存在，也會自動建立

**Step 3：在 resume.py 中進行相同操作**

```python
def _get_handoff_dir(subdir=HANDOFF_PENDING_SUBDIR):
    root = get_project_root()
    handoff_dir = root / HANDOFF_DIR / subdir
    handoff_dir.mkdir(parents=True, exist_ok=True)  # ← 自動建立
    return handoff_dir
```

**Step 4：文件說明（更新規則/指南）**

在 `.claude/rules/flows/ticket-lifecycle.md` 中新增「Worktree 中的 Handoff」章節：

```markdown
### Worktree 中的 Handoff 行為

**重要**：handoff 檔案存儲在各 worktree 的本地目錄中，不在 Git 版本控制下。

| 環境 | 路徑 | 特性 |
|------|------|------|
| 主 repo | `/project/.claude/handoff/pending/` | 本地，gitignored |
| Worktree | `/worktree/.claude/handoff/pending/` | 本地，gitignored |

**交接工作流**：
1. 在主 repo 中完成 Ticket → `ticket handoff`
2. 交接檔案存入主 repo 的 pending/
3. 如要在 worktree 中接手 → 返回主 repo，`ticket resume <id>`
4. Resume 後可在任意 worktree 中 claim

**跨 worktree 交接**：不建議直接進行。建議流程：
1. 主 repo：`ticket handoff` → 建立交接檔案
2. Worktree 1：完成任務後返回主 repo
3. 主 repo：`ticket resume` → 恢復任務
4. Worktree 2：可以 clone ticket 或從主 repo 中讀取交接檔案
```
