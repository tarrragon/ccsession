## 1. 測試策略規劃

### 1.1 分層測試決策

根據 hybrid-testing-strategy 方法論，本功能的測試分層如下：

| 層級 | 元件 | 測試方式 | 關鍵點 |
|------|------|---------|--------|
| **L3 (UseCase/CLI)** | `create.py` 的 CLI 指令流程 | 集成測試 (BDD style) | 測試完整命令執行和參數驗證 |
| **L4 (Logic/Function)** | `_build_decision_tree_path()` 決策邏輯 | 單元測試 | 測試所有參數組合和邊界 |
| **L4 (Logic/Function)** | `ticket-creation-validation-hook.py` 驗證邏輯 | 單元測試 | 測試 Hook 觸發條件和輸出 |
| **L2 (Behavior)** | `ticket_builder.py` frontmatter 輸出 | 單元測試 | 測試 YAML 結構正確性 |
| **L1 (Integration)** | 完整 CLI → Hook → 派發流程 | 整合測試 | 端對端驗證 |

### 1.2 Mock 策略（Sociable Unit Tests）

| 依賴 | Mock 策略 | 理由 |
|------|----------|------|
| 檔案系統 (`Path`, `write_file`) | Mock | 外部依賴，測試不關心實作 |
| YAML 序列化 (`yaml.dump`) | 不 Mock | 核心邏輯，直接測試 |
| sys.exit / print | Mock | 外部界面，測試關心返回值 |
| Ticket 模組內部函式 | 不 Mock | 同 module 邏輯，直接使用 |
| Logger / stderr | 捕獲 | 驗證訊息輸出 |

### 1.3 測試覆蓋率目標

| 覆蓋目標 | 期望值 |
|---------|-------|
| `create.py` 新增函式 | 100% |
| `_build_decision_tree_path()` 邏輯分支 | 100% |
| Hook 觸發條件分支 | 100% |
| frontmatter 輸出路徑 | 100% |
| 錯誤訊息格式 | 樣本覆蓋（每種錯誤至少 1 個） |

### 2.1 CLI 參數驗證測試（L3 - UseCase）

#### 測試組 A1：正常建立 — 完整參數

**標題**: TC-CLI-A1-001: 根任務正常建立（完整三參數）

```
Given: PM 已完成決策，準備建立 IMP 根任務
And: 決策樹路徑已明確（進入點：第五層 TDD 階段判斷）
When: 執行命令：
  ticket create \
    --action "實作" \
    --target "decision_tree_path 強制驗證" \
    --decision-tree-entry "第五層 TDD 階段判斷" \
    --decision-tree-decision "派發 Phase 3b 給 parsley" \
    --decision-tree-rationale "Phase 2 測試設計已完成，進入實作階段"
Then:
  1. CLI 返回 exit code 0
  2. Ticket 檔案成功建立
  3. frontmatter 含 decision_tree_path 三子欄位：
     - entry_point = "第五層 TDD 階段判斷"
     - final_decision = "派發 Phase 3b 給 parsley"
     - rationale = "Phase 2 測試設計已完成，進入實作階段"
  4. CLI 輸出成功訊息
  5. PostToolUse Hook 不輸出警告
```

**預期結果**: 通過（Ticket 建立成功，frontmatter 完整）

**驗證方式**:
- 檢查 exit code：`assert result.exit_code == 0`
- 讀取生成的 .md 檔，解析 YAML frontmatter
- 驗證三個子欄位存在且值相符
