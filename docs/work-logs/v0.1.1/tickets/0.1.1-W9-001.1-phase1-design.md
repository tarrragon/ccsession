# Phase 1 功能規格設計：get_project_root() 統一策略

## 一、功能需求分析

### 核心問題

目前專案中存在兩個各自獨立的 `get_project_root()` 定義：

| 位置 | 策略 | 問題 |
|------|------|------|
| `.claude/hooks/hook_utils/hook_base.py` | CLAUDE.md 向上搜尋（最多 5 層）| worktree 下 cwd 為子目錄，可能搜尋不到 CLAUDE.md |
| `.claude/skills/ticket/ticket_system/lib/paths.py` | CLAUDE.md / go.mod / pubspec.yaml 向上搜尋（無限層）| 同上，worktree 下可能回傳錯誤目錄 |
| `.claude/lib/git_utils.py` | git rev-parse --show-toplevel | 正確，git-native 不受 cwd 影響 |

**根本原因**：CLAUDE.md 搜尋策略在 worktree 環境下失效。git worktree add 建立的工作目錄可能位於 repo 根目錄外，cwd 不在任何含有 CLAUDE.md 的路徑上，導致 fallback 到 `cwd`，使所有後續路徑計算（Ticket 路徑、工作日誌路徑）均錯誤。

### 使用者場景

| 場景 | 使用者 | 操作 | 期望結果 |
|------|--------|------|---------|
| Hook 執行 | Hook 系統（22 個 hook 檔案） | 呼叫 `get_project_root()` | 回傳 git repo 根目錄，不受 worktree cwd 影響 |
| Ticket CLI 執行 | 開發者 | 在 worktree 子目錄執行 `/ticket create` | Ticket 寫入正確的 docs/work-logs/ 路徑 |
| 一般環境執行 | 開發者 | 在正常 git repo 中執行任何 hook/ticket 命令 | 行為與現有一致，無回歸 |
| 非 git repo 環境 | CI 系統 | 在無 git 的環境中執行 hook | 不崩潰，有合理 fallback |

## 二、功能規格設計

### 正常流程（git 可用）

```
呼叫 get_project_root()
    |
    v
[Step 1] 環境變數優先
    CLAUDE_PROJECT_DIR 是否設定?
    +-- 是 --> 直接回傳 Path(os.environ["CLAUDE_PROJECT_DIR"])
    +-- 否 --> 繼續
    |
    v
[Step 2] git rev-parse --show-toplevel
    執行 subprocess: git rev-parse --show-toplevel
    +-- 成功（returncode == 0）--> 回傳 Path(stdout.strip())
    +-- 失敗 --> 繼續
    |
    v
[Step 3] Fallback：向上搜尋 CLAUDE.md
    從 cwd 向上搜尋（最多 CLAUDE_MD_SEARCH_DEPTH 層）
    +-- 找到 --> 回傳找到的目錄 Path
    +-- 找不到 --> 繼續
    |
    v
[Step 4] 最終 Fallback
    回傳 Path.cwd()（永不失敗）
```

### 優先順序設計理由

| 優先級 | 策略 | 理由 |
|--------|------|------|
| 1 | 環境變數 CLAUDE_PROJECT_DIR | 明確的使用者配置，最高信任 |
| 2 | git rev-parse --show-toplevel | git-native 方式，不受 cwd 影響，worktree 環境下仍正確 |
| 3 | 向上搜尋 CLAUDE.md | git 不可用時的識別機制（向後相容） |
| 4 | Path.cwd() | 永不失敗，確保函式可呼叫性 |

### 異常情況處理

| 異常情況 | 處理方式 | 說明 |
|---------|---------|------|
| git 命令不存在 | 捕捉 FileNotFoundError，進入 Step 3 | CI 或非開發環境 |
| git 超時（timeout） | 捕捉 subprocess.TimeoutExpired，進入 Step 3 | 網路 git 掛載異常 |
| 非 git repo（git 回傳非 0） | returncode != 0，進入 Step 3 | 孤立目錄執行 |
| 所有策略均失敗 | 回傳 Path.cwd()，不拋出例外 | 確保 hook/ticket 不因此崩潰 |

### 邊界條件

| 邊界條件 | 預期行為 |
|---------|---------|
| worktree 根目錄之外（如 `/tmp` 中的 worktree） | git rev-parse 仍正確回傳 repo 根目錄 |
| git submodule 環境 | git rev-parse 回傳子模組目錄（與現有行為一致） |
| CLAUDE_PROJECT_DIR 設為不存在的路徑 | 直接回傳（呼叫端負責驗證路徑有效性） |
| 符號連結（symlink）目錄 | 依 git 行為，通常回傳真實路徑 |
| 搜尋深度邊界（CLAUDE_MD_SEARCH_DEPTH = 5） | Step 3 最多搜尋 5 層，超過後進入 Step 4 |

## 三、API 介面設計

### 統一函式規格

**hook_base.py 新版實作**：

```python
def get_project_root() -> Path:
    """取得專案根目錄

    優先順序：
    1. 環境變數 CLAUDE_PROJECT_DIR
    2. git rev-parse --show-toplevel（git-native，支援 worktree）
    3. 從 cwd 向上搜尋 CLAUDE.md（最多 CLAUDE_MD_SEARCH_DEPTH 層）
    4. Path.cwd() fallback（永不失敗）

    Returns:
        Path: 專案根目錄路徑

    Note:
        此函式不拋出例外。所有失敗情況均有 fallback。
        worktree 環境下 git rev-parse 策略確保路徑正確。
    """
```

**paths.py 新版實作（相同語意）**：

```python
def get_project_root() -> Path:
    """
    取得專案根目錄

    搜尋優先級：
    1. CLAUDE_PROJECT_DIR 環境變數
    2. git rev-parse --show-toplevel（git-native，支援 worktree 環境）
    3. 向上搜尋 CLAUDE.md（git 不可用時的 fallback，最多 5 層）
    4. fallback: Path.cwd()

    Returns:
        Path: 專案根目錄路徑

    Examples:
        >>> root = get_project_root()
        >>> (root / "CLAUDE.md").exists() or (root / ".git").exists()
        True
    """
```

### 參數規格

| 項目 | 規格 |
|------|------|
| 參數 | 無（零參數函式） |
| 回傳型別 | `Path`（pathlib.Path，**不是 str**） |
| 可能例外 | 無（函式保證不拋出例外） |
| 副作用 | 無（純查詢函式） |

### 內部輔助常數（hook_base.py）

| 常數 | 值 | 說明 |
|------|-----|------|
| `ENV_PROJECT_DIR` | `"CLAUDE_PROJECT_DIR"` | 環境變數名稱（已存在，不變） |
| `CLAUDE_MD_SEARCH_DEPTH` | `5` | CLAUDE.md 搜尋深度（已存在，不變） |
| `GIT_TOPLEVEL_TIMEOUT` | `5` | git rev-parse 超時秒數（新增） |

### 型別一致性說明

- `hook_base.py` 現有回傳型別已是 `Path`，維持不變
- `paths.py` 現有回傳型別已是 `Path`，維持不變
- `git_utils.py` 回傳 `str`（不在本次修改範圍，設計意圖不同）

### 模組依賴

**hook_base.py 新增依賴**：

```python
import subprocess  # 新增
```

**paths.py 新增依賴**：

```python
import subprocess  # 新增
```

兩個檔案均已有 `import os` 和 `from pathlib import Path`，無需重複引入。

## 四、行為場景提取（Given-When-Then）

### 場景 1：正常 git repo 環境（主要流程）

```
Given: 當前目錄位於 git repo 內（cwd = /project/some/subdir）
       git 命令可用
       CLAUDE_PROJECT_DIR 未設定
When: 呼叫 get_project_root()
Then: 執行 git rev-parse --show-toplevel
      回傳 Path("/project")（repo 根目錄）
      不受 cwd 的層級深度影響
```

### 場景 2：worktree 環境（核心修復目標）

```
Given: worktree 已建立於 /worktrees/feat-branch
       cwd = /worktrees/feat-branch（無 CLAUDE.md）
       git rev-parse --show-toplevel 回傳 /Users/dev/project
       CLAUDE_PROJECT_DIR 未設定
When: 呼叫 get_project_root()
Then: 回傳 Path("/Users/dev/project")（原始 repo 根目錄）
      不回傳 /worktrees/feat-branch 或 Path.cwd()
```

### 場景 3：CLAUDE_PROJECT_DIR 優先

```
Given: 環境變數 CLAUDE_PROJECT_DIR = /custom/project/path
When: 呼叫 get_project_root()
Then: 不執行 git 命令
      不搜尋 CLAUDE.md
      直接回傳 Path("/custom/project/path")
```

### 場景 4：git 不可用（fallback 流程）

```
Given: git 命令不存在（FileNotFoundError）
       CLAUDE_PROJECT_DIR 未設定
       cwd = /project，/project/CLAUDE.md 存在
When: 呼叫 get_project_root()
Then: 捕捉 FileNotFoundError，進入 CLAUDE.md 搜尋
      回傳 Path("/project")
      不拋出例外
```

### 場景 5：非 git repo 環境（fallback 流程）

```
Given: cwd = /tmp/test_dir（非 git repo）
       git rev-parse --show-toplevel 回傳 returncode != 0
       CLAUDE_PROJECT_DIR 未設定
       向上搜尋無 CLAUDE.md
When: 呼叫 get_project_root()
Then: git 失敗後進入 CLAUDE.md 搜尋
      搜尋不到後回傳 Path.cwd()
      不拋出例外
```

### 場景 6：現有 22 個 hook 無需修改

```
Given: hook 檔案包含 `from hook_utils import get_project_root`
When: get_project_root() 函式簽名和回傳型別不變（仍是 () -> Path）
Then: 所有 22 個 hook 無需任何修改
      向後相容
```

### 場景 7：現有 3 個 ticket 命令無需修改

```
Given: ticket 命令包含 `from ticket_system.lib.paths import get_project_root`
When: get_project_root() 函式簽名和回傳型別不變（仍是 () -> Path）
Then: 所有 3 個 ticket 命令無需任何修改
      向後相容
```

## 七、設計決策記錄

### 決策 1：回傳型別維持 Path（不改為 str）

**選項**：
- Option A：維持 `Path`（與現有 hook_base.py、paths.py 一致）
- Option B：改為 `str`（與 git_utils.py 一致）

**決定**：Option A（維持 Path）

**理由**：
- 所有 22 個 hook 和 3 個 ticket 命令的呼叫端均依賴 `Path` 型別（可直接做 `/` 路徑拼接）
- 改為 `str` 會需要修改所有呼叫端，範圍過大
- git_utils.py 的 `str` 回傳為其設計選擇，兩個函式服務不同模組，不強制統一

### 決策 2：不提取共用函式

**選項**：
- Option A：hook_base.py 和 paths.py 各自獨立實作 git rev-parse 邏輯
- Option B：提取共用函式（如 `git_utils.py` 或新的共用模組）

**決定**：Option A（各自獨立實作）

**理由**：
- hook_utils 和 ticket_system 是兩個獨立子系統，故意分開
- 若提取共用函式，需解決跨模組依賴問題（hook_utils 引用 ticket_system 或反之，均會造成循環依賴風險）
- 兩個實作邏輯簡單（< 20 行），重複是可接受的
- SA 審查確認只需修改這兩個定義點

### 決策 3：Fallback 保留 CLAUDE.md 搜尋（不直接跳 cwd）

**選項**：
- Option A：git 失敗後直接 fallback 到 cwd
- Option B：git 失敗後仍嘗試 CLAUDE.md 搜尋

**決定**：Option B（保留 CLAUDE.md 搜尋）

**理由**：
- git 不可用的場景下（CI 無 git、裸機環境），CLAUDE.md 搜尋仍可正確識別專案根目錄
- 向後相容：現有不使用 git 的環境行為不改變
- 多一層保障，降低 cwd fallback 的機率
