## Solution

### 測試設計策略

1. **分層測試決策**（5 層）：
   - Layer 5（Domain 邏輯）：純算法（ID 驗證、命名推導）→ 單元測試
   - Layer 4（Behavior）：業務轉換（branch 狀態計算）→ 單元測試
   - Layer 3（UseCase）：完整流程（create/status）→ 整合測試 (BDD)
   - Layer 2（Hook）：業務邏輯 + git 呼叫 → 單元 + 整合測試
   - Layer 1（Hook 入口）：完整 Hook 流程 → 整合測試

2. **Mock 策略**（Sociable Unit Tests）：
   - 外部依賴（git、檔案系統）→ Mock
   - 內層邏輯（Ticket ID、Branch Name）→ 真實物件
   - 測試間隔離（tmp_path、monkeypatch）

3. **測試案例設計**（38 個 GWT）：
   - 命名推導：6 個測試（正常、子任務、邊界）
   - create 命令：6 個測試（成功、dry-run、5 種錯誤）
   - status 命令：3 個測試（全部、單一、無）
   - 反推邏輯：5 個測試（合法、detached、ahead/behind、未 commit）
   - Hook 改造：12 個測試（verify-hook 4 個、remind-hook 4 個、路徑豁免 6 個）

4. **測試檔案結構**：
   - test_ticket_id_parsing.py：ID 驗證和命名推導
   - test_worktree_creation.py：create 子命令
   - test_worktree_status.py：status 子命令
   - test_branch_extraction.py：反推邏輯和 ahead/behind
   - test_git_utils_extensions.py：is_in_worktree 和路徑豁免
   - test_hook_integration.py：Hook 整合測試
