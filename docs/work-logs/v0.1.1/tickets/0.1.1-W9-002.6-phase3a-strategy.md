## 2. W9-002.1 實作策略：create 子命令

### 2.1 核心流程虛擬碼

```
函式：cmd_create(ticket_id: str, base: str = "main", dry_run: bool = False) -> int

步驟：
  1. 驗證票證 ID 格式
     validate_result = parse_ticket_id(ticket_id)
     if not validate_result:
       輸出「無效的 Ticket ID 格式」錯誤訊息 + 建議
       return 1

  2. 推導分支名和 worktree 路徑
     branch_name = derive_branch_name(ticket_id)           # feat/{ticket_id}
     worktree_path = derive_worktree_path(ticket_id)       # {parent}/{project}-{ticket_id}

  3. 驗證基礎分支存在
     base_exists = check_branch_exists(base)
     if not base_exists:
       輸出「基礎分支不存在」錯誤訊息 + 建議
       return 1

  4. 檢查分支已存在
     branch_exists = check_branch_exists(branch_name)
     if branch_exists:
       輸出「分支已存在」錯誤訊息 + 刪除建議
       return 1

  5. 檢查 worktree 路徑已存在
     path_exists = os.path.exists(worktree_path)
     if path_exists:
       輸出「目錄已存在」錯誤訊息
       return 1

  6. 構建 git 命令
     git_cmd = ["worktree", "add", "-b", branch_name, worktree_path, base]

  7. 如果是 dry-run
     if dry_run:
       輸出「[Dry Run] 將要執行的操作：」
       輸出重組後的 git 命令行
       return 0

  8. 執行 git worktree add
     result = run_git_command(git_cmd)
     if result.returncode != 0:
       輸出「建立 worktree 失敗」+ git 原始錯誤訊息
       return 1

  9. 成功輸出
     輸出「建立成功」訊息 + Ticket、分支、路徑、base 資訊
     輸出「下一步：cd {worktree_path}」
     return 0
```

### 2.3 核心函式實作虛擬碼

#### parse_ticket_id(ticket_id: str) -> bool

```
目的：驗證 ticket-id 符合 \d+\.\d+\.\d+-W\d+-\d+(\.\d+)* 格式

邏輯：
  pattern = r"^\d+\.\d+\.\d+-W\d+-\d+(\.\d+)*$"
  return re.match(pattern, ticket_id) is not None
```

#### derive_branch_name(ticket_id: str) -> str

```
目的：推導分支名稱

邏輯：
  return f"feat/{ticket_id}"
```

#### derive_worktree_path(ticket_id: str) -> str

```
目的：推導 worktree 絕對路徑

邏輯：
  project_root = get_project_root()                    # /Users/.../ccsession
  project_name = os.path.basename(project_root)      # ccsession
  parent_dir = os.path.dirname(project_root)         # /Users/.../project
  worktree_path = os.path.join(parent_dir, f"{project_name}-{ticket_id}")
  return worktree_path                                 # /Users/.../ccsession-{ticket_id}
```

#### check_branch_exists(branch_name: str) -> bool

```
目的：檢查分支是否存在（重用 git_utils 現有函式或封裝）

邏輯：
  result = run_git_command(["rev-parse", "--verify", branch_name])
  return result.returncode == 0
```

## 3. W9-002.2 實作策略：status 子命令

### 3.1 核心流程虛擬碼

```
函式：cmd_status(ticket_id: str | None = None) -> int

步驟：
  1. 取得全部 worktree 列表
     worktrees = get_worktree_list()  # 使用 git worktree list --porcelain

  2. 如果指定 ticket_id
     if ticket_id is not None:
       filtered = 篩選出對應的 worktree
       if not filtered:
         輸出「找不到 Ticket 對應的 worktree」錯誤 + 現有 worktree 清單
         return 1
       worktrees = filtered

  3. 如果無任何 worktree（除主倉庫外）
     if len(worktrees) == 1:  # 只有主倉庫
       輸出「目前沒有任何 worktree」提示
       return 0

  4. 遍歷每個 worktree，蒐集信息
     for worktree in worktrees:
       a. 取得路徑和分支
          path = worktree["path"]
          branch = worktree["branch"]

       b. 反推 Ticket ID
          ticket_id = extract_ticket_id_from_branch(branch)
          if ticket_id is None:
            ticket_label = "無法辨識" 或分支名

       c. 計算 ahead/behind
          if worktree is main:
            ahead, behind = 0, 0
          else:
            ahead, behind = get_worktree_ahead_behind(branch, "main")

       d. 計算未 commit 變更數
          uncommitted = get_worktree_uncommitted_count(path)

       e. 組裝輸出行
          display_info = {
            "path": path,
            "branch": branch,
            "ticket_id": ticket_id,
            "ahead": ahead,
            "behind": behind,
            "uncommitted": uncommitted
          }

  5. 格式化輸出
     輸出表頭（共 N 個 worktree）
     for each worktree_info in display_info:
       輸出分隔線（━）
       輸出 [主倉庫] 或 [Ticket ID]
       輸出路徑、分支、領先/落後、變更數

  6. 成功返回
     return 0
```

### 3.3 核心函式實作虛擬碼

#### extract_ticket_id_from_branch(branch: str) -> str | None

```
目的：從分支名反推 Ticket ID

邏輯：
  1. 檢查分支是否以 "feat/" 開頭
     if not branch.startswith("feat/"):
       return None

  2. 提取後半部分
     potential_ticket_id = branch[5:]  # 去掉 "feat/"

  3. 驗證格式
     if parse_ticket_id(potential_ticket_id):
       return potential_ticket_id
     else:
       return None
```

#### get_worktree_ahead_behind(branch: str, base: str = "main") -> tuple[int, int]

```
目的：計算分支相對 base 的 ahead/behind commit 數

邏輯：
  try:
    # 計算 base 有而 branch 沒有的 commit（branch 落後）
    ahead_result = run_git_command(["rev-list", "--count", f"{base}..{branch}"])
    ahead = int(ahead_result.stdout.strip())

    # 計算 branch 有而 base 沒有的 commit（branch 超前）
    behind_result = run_git_command(["rev-list", "--count", f"{branch}..{base}"])
    behind = int(behind_result.stdout.strip())

    return (ahead, behind)

  except Exception:
    return (0, 0)  # 或 return (None, None)，由實作決定
```

#### get_worktree_uncommitted_count(worktree_path: str) -> int

```
目的：計算未 commit 變更數

邏輯：
  try:
    status_result = run_git_command(
      ["status", "--porcelain"],
      cwd=worktree_path  # 在 worktree 目錄執行
    )
    lines = status_result.stdout.strip().split('\n')
    return len([line for line in lines if line])  # 空行不計

  except Exception:
    return 0  # 或 return -1 表示失敗
```

## 4. W9-002.3 實作策略：Hook 改造

### 4.1 git_utils.py 擴充：is_in_worktree()

#### 函式實作虛擬碼

```
函式：is_in_worktree() -> bool

目的：判斷當前工作目錄是否在 git worktree（非主倉庫）中

邏輯：
  try:
    # 取得主 .git 目錄路徑
    git_common_dir_result = run_git_command(["rev-parse", "--git-common-dir"])
    git_common_dir = git_common_dir_result.stdout.strip()

    # 取得當前 .git 目錄路徑
    git_dir_result = run_git_command(["rev-parse", "--git-dir"])
    git_dir = git_dir_result.stdout.strip()

    # 比較兩者
    # 在 worktree 中：git_dir 會是 /path/.git/worktrees/name（不同）
    # 在主倉庫中：git_dir 會是 /path/.git（相同）
    return git_common_dir != git_dir

  except Exception:
    # 錯誤時保守預設為主倉庫
    return False
```

#### 邊界條件處理

| 邊界條件 | 預期行為 | 實作策略 |
|---------|---------|---------|
| 非 git 目錄 | 返回 False | 捕獲異常，返回 False |
| git 命令超時 | 返回 False | 設定 timeout=10s，超時返回 False |
| git 目錄為相對路徑 | 正確判斷 | 使用 `os.path.abspath()` 正規化後比較 |

### 4.2 branch-verify-hook 改造

#### 函式實作虛擬碼

```
函式：branch_verify_hook(file_path: str, operation: str) -> str  # 返回 "allow" / "deny"

目的：判斷是否允許在當前分支上進行 Edit/Write 操作

邏輯：
  1. 檢查是否為 Edit/Write 工具
     if operation not in ["Edit", "Write"]:
       return "allow"  # 非目標工具，通過

  2. 取得當前分支
     current_branch = get_current_branch()
     if current_branch is None:
       return "allow"  # 保守預設

  3. 檢查是否在 worktree 中
     if is_in_worktree():
       # 在 worktree 中：檢查分支是否允許
       if is_allowed_branch(current_branch):
         return "allow"
       else:
         return "deny"

  4. 檢查是否為保護分支
     if not is_protected_branch(current_branch):
       return "allow"  # 非保護分支，通過

  5. 檢查路徑是否豁免
     if is_exempt_path_on_protected_branch(file_path):
       return "allow"

  6. 保護分支 + 非豁免路徑 -> deny
     return "deny"
```

#### is_exempt_path_on_protected_branch(file_path: str) -> bool

```
目的：判斷此路徑是否在保護分支上被豁免

邏輯：
  # 正規化路徑（移除開頭斜線）
  normalized_path = file_path.lstrip("/")

  # 豁免字首清單
  exempt_prefixes = [
    ".claude/",
    "docs/",
  ]

  # 豁免精確匹配清單
  exempt_exact = [
    "CLAUDE.md",
    "README.md",
  ]

  # 檢查字首
  for prefix in exempt_prefixes:
    if normalized_path.startswith(prefix):
      return True

  # 檢查精確匹配
  if normalized_path in exempt_exact:
    return True

  return False
```

```
[deny 訊息]

```

## 6. 資料結構設計

### 6.1 Ticket ID 資料模型

```
ticket_id: "0.1.1-W9-002.1"

分解結構（由 parse_ticket_id 驗證，由推導函式使用）：
{
  "version": "0.1.1",          # 版本號
  "wave": 9,                    # Wave 號
  "sequence": "002.1",          # 序列號（支援多層）
  "is_valid": True,             # 格式驗證結果
}

推導結果：
{
  "branch_name": "feat/0.1.1-W9-002.1",
  "worktree_path": "/Users/mac-eric/project/ccsession-0.1.1-W9-002.1",
  "parent_dir": "/Users/mac-eric/project",
  "project_name": "ccsession",
}
```

### 6.2 Worktree 資訊結構

```
worktree_info: 從 git worktree list --porcelain 解析

原始格式：
  /path/to/ccsession-0.1.1-W9-002.1 (branch feat/0.1.1-W9-002.1)

解析後結構：
{
  "path": "/Users/mac-eric/project/ccsession-0.1.1-W9-002.1",
  "branch": "feat/0.1.1-W9-002.1",
  "is_main": False,
  "ticket_id": "0.1.1-W9-002.1",  # 由 extract_ticket_id_from_branch 推導
  "ahead": 3,                      # commit 領先 main
  "behind": 0,                     # commit 落後 main
  "uncommitted": 2,                # 未 commit 變更數
}
```

### 6.3 Hook 決策流程結構

```
branch_verify_hook 判斷邏輯決策樹：

INPUT: (file_path, operation, current_branch)

決策流程：
  operation in ["Edit", "Write"]?
    ├─ 否 → ALLOW
    └─ 是 → 繼續

  current_branch = get_current_branch()?
    ├─ 失敗 → ALLOW（保守）
    └─ 成功 → 繼續

  is_in_worktree()?
    ├─ 是 → is_allowed_branch(current_branch)?
    │       ├─ 是 → ALLOW
    │       └─ 否 → DENY
    └─ 否 → 繼續

  is_protected_branch(current_branch)?
    ├─ 否 → ALLOW
    └─ 是 → is_exempt_path_on_protected_branch(file_path)?
            ├─ 是 → ALLOW
            └─ 否 → DENY
```

## 7. 控制流程圖

### 7.1 create 子命令流程

```
START
  ↓
驗證 Ticket ID 格式
  ├─ 無效 → 輸出錯誤 → RETURN 1
  └─ 有效 → 繼續
  ↓
推導分支名和 worktree 路徑
  ↓
驗證 base 分支存在
  ├─ 不存在 → 輸出錯誤 → RETURN 1
  └─ 存在 → 繼續
  ↓
檢查分支已存在
  ├─ 是 → 輸出錯誤 → RETURN 1
  └─ 否 → 繼續
  ↓
檢查 worktree 路徑已存在
  ├─ 是 → 輸出錯誤 → RETURN 1
  └─ 否 → 繼續
  ↓
構建 git worktree add 命令
  ↓
是 dry-run?
  ├─ 是 → 輸出命令 → RETURN 0
  └─ 否 → 繼續
  ↓
執行 git worktree add -b {branch} {path} {base}
  ├─ 失敗 → 輸出錯誤 → RETURN 1
  └─ 成功 → 繼續
  ↓
輸出成功訊息 + cd 建議
  ↓
RETURN 0
```

### 7.2 status 子命令流程

```
START
  ↓
取得全部 worktree 列表（git worktree list --porcelain）
  ↓
是否指定 ticket_id?
  ├─ 是 → 篩選該 worktree
  │        ├─ 找到 → 繼續
  │        └─ 未找到 → 輸出錯誤 + 現有清單 → RETURN 1
  └─ 否 → 不篩選
  ↓
worktree 清單是否為空（除主倉庫外）?
  ├─ 是 → 輸出「無任何 worktree」提示 → RETURN 0
  └─ 否 → 繼續
  ↓
FOR EACH worktree in 清單：
  ├─ 取得路徑和分支
  ├─ 反推 Ticket ID
  ├─ 計算 ahead/behind
  ├─ 計算未 commit 變更數
  └─ 組裝顯示資訊
  ↓
格式化輸出（表頭 + 分隔線 + 各 worktree 資訊）
  ↓
RETURN 0
```
