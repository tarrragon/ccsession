# Phase 1：功能規格設計

## 目標

消除 Hook（`.claude/hooks/package-version-sync-hook.py`）和 CLI（`.claude/skills/project-init/project_init/lib/package_manager.py`）之間的 pyproject.toml 掃描邏輯重複，提取共用模組實現代碼複用。

## 現狀分析

### Hook 端掃描邏輯（package-version-sync-hook.py）

**位置**：`.claude/hooks/package-version-sync-hook.py`

**核心函數**：

1. `scan_skill_packages()` (lines 266-334)
   - 掃描 `.claude/skills/*/pyproject.toml`
   - 返回 `Dict[str, Dict[str, str]]` 格式：`{"package_name": {"path": "...", "version": "..."}}`

2. `_load_pyproject_toml()` (lines 337-356)
   - 使用 tomllib/tomli 解析 pyproject.toml
   - 返回解析後的 TOML dict

3. 內聯提取邏輯（在 scan_skill_packages 內）
   - 提取 `[project].name` 和 `[project].version`

### CLI 端掃描邏輯（package_manager.py）

**位置**：`.claude/skills/project-init/project_init/lib/package_manager.py`

**核心函數**：

1. `scan_custom_packages()` (lines 61-97)
   - 掃描 `.claude/skills/*/pyproject.toml`
   - 返回 `list[PackageInfo]` 格式（自訂 dataclass）
   - 調用三個提取函數

2. `_parse_pyproject()` (lines 303-326)
   - 快取版本：避免重複解析同一檔案
   - 使用 tomllib 解析

3. 獨立提取函數：
   - `_extract_version_from_pyproject()` (lines 328-346)
   - `_extract_package_name_from_pyproject()` (lines 349-367)
   - `_extract_cli_name_from_pyproject()` (lines 370-391)

### 重複程度分析

| 邏輯單元 | Hook | CLI | 重複程度 |
|---------|------|-----|---------|
| pyproject.toml 解析 | `_load_pyproject_toml()` | `_parse_pyproject()` + cache | **完全重複** |
| 提取版本 | 內聯 | `_extract_version_from_pyproject()` | **完全重複** |
| 提取包名 | 內聯 | `_extract_package_name_from_pyproject()` | **完全重複** |
| 提取 CLI 名 | 無 | `_extract_cli_name_from_pyproject()` | 單邊功能 |
| 目錄遍歷 | `scan_skill_packages()` | `scan_custom_packages()` | **80% 重複**（邏輯相同，返回格式不同） |

**重複代碼統計**：
- pyproject.toml 解析：~20 行重複
- 提取邏輯：~50 行重複
- 目錄遍歷：~25 行重複
- **總計**：~95 行可提取的重複代碼

## 重構方案決定

### 選擇方案：B 提取共用模組（.claude/lib/pyproject_scanner.py）

**方案對比**：

| 方案 | 優點 | 缺點 | 選擇理由 |
|------|------|------|---------|
| **A：各自保留** | 零依賴 | 維護成本高，代碼重複 | 否 |
| **B：共用模組**（選擇） | 集中維護，跨環境可用 | 需要 sys.path.insert | 是 |
| **C：復制粘貼** | 簡單 | 永遠重複 | 否 |

**方案 B 實現**：

1. 在 `.claude/lib/pyproject_scanner.py` 建立共用模組
   - 包含 TOML 解析和提取邏輯
   - 無外部依賴（tomllib/tomli 標準）
   - 支援 Python 3.9+

2. Hook 修改（package-version-sync-hook.py）
   - 移除 `_load_pyproject_toml()`
   - 修改 `scan_skill_packages()` 使用共用模組
   - 新增 `sys.path.insert(0, str(Path(__file__).parent.parent.parent / '.claude' / 'lib'))` 匯入

3. CLI 修改（package_manager.py）
   - 移除 `_parse_pyproject()` 和三個提取函數
   - 修改 `scan_custom_packages()` 使用共用模組
   - 新增 import

### 新模組設計（.claude/lib/pyproject_scanner.py）

**提供的公開 API**：

| 函數 | 簽名 | 用途 |
|------|------|------|
| `load_pyproject_toml()` | `(Path) → Optional[Dict]` | 解析單一 pyproject.toml |
| `extract_version_from_pyproject()` | `(Path) → Optional[str]` | 提取版本 |
| `extract_package_name_from_pyproject()` | `(Path) → Optional[str]` | 提取包名 |
| `extract_cli_name_from_pyproject()` | `(Path) → Optional[str]` | 提取 CLI 名 |
| `scan_skills_directory()` | `(Path) → Dict[str, Dict[str, str]]` | 掃描 .claude/skills/ 並返回 Hook 格式 |

**設計決策**：

1. **返回格式統一**：統一為 Hook 格式 `Dict[str, Dict[str, str]]`
   - Hook 使用此格式
   - CLI 將此格式轉換為 `list[PackageInfo]`（在 scan_custom_packages 內轉換）

2. **快取處理**：不在共用模組內實施快取
   - Hook 有自己的 sync-cache.json 機制
   - CLI 可自行在 _parse_pyproject 層實施快取（如需要）

3. **錯誤處理**：靜默失敗（返回 None）
   - Hook 和 CLI 各自決定如何處理失敗

## 技術細節

### Hook 環境約束

- Python 3.9+（pyproject.toml 聲明的 requires-python）
- 無外部依賴（tomli 是 pyproject.toml 依賴）
- 獨立執行環境，不能 import project-init 包
- **解決方案**：在 Hook 中手動 sys.path.insert(0, ...) 導入 .claude/lib

### 共用模組相容性

- 支援 Python 3.9+ 的 tomllib/tomli
- 純文本函數，無副作用
- 返回標準 dict/Optional，易於轉換
