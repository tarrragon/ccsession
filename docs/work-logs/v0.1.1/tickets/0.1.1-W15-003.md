## 缺口盤點

### 缺口 1：決策樹第七層無 ANA 類型特殊處理
decision-tree.md 第七層（完成判斷）只有通用的「驗收方式確認 → 勾選驗收條件 → complete」流程，未區分任務類型。ANA Ticket 完成時應強制檢查「分析結論是否已轉化為後續 Ticket」。

### 缺口 2：ANA 驗收條件模板缺少「後續 Ticket」項目
ticket create 建立 ANA Ticket 時，預設驗收條件為通用的「任務實作完成 / 相關測試通過 / 無品質警告」，缺少 ANA 特有的「分析結論已建立修復 Ticket」和「根因已建立防護 Ticket」。

### 缺口 3：acceptance-gate-hook 無 ANA 特殊檢查
ANA Ticket complete 時，Hook 不檢查是否有 children 或 spawned_tickets。對 IMP/ADJ 這不是問題（產出是程式碼），但 ANA 的核心產出是「後續 Ticket」。

### 缺口 4：askuserquestion-rules 場景 #1 豁免 ANA
場景 #1（驗收方式確認）對 DOC/ANA 自動決定不觸發，但 ANA 其實應該觸發一個不同的確認：「分析結論是否已轉化為 Ticket？」

## 改進方案

### 方案 A：修改 ANA 驗收條件模板（最小改動，最高 ROI）
在 ticket create 的 ANA 類型預設驗收條件中加入：
- [ ] 分析結論已建立修復 Ticket（症狀修復）
- [ ] 根因已建立防護 Ticket（機制防護）
- [ ] 後續 Ticket 已記錄在 children 或 spawned_tickets

影響檔案：ticket_system/commands/create.py（ANA 預設 acceptance）

### 方案 B：acceptance-gate-hook 擴充 ANA 檢查
ANA 類型 Ticket 執行 complete 時，Hook 檢查 frontmatter 的 children + spawned_tickets 是否非空。
- 非空 → 通過
- 空 → WARNING 提醒「ANA Ticket 通常應有後續 Ticket，請確認分析結論已轉化」

影響檔案：.claude/hooks/acceptance-gate-hook.py

### 方案 C：決策樹第七層新增 ANA 分支
在「完成判斷流程」中新增 ANA 類型專屬步驟，complete 前強制確認後續 Ticket。

影響檔案：.claude/rules/core/decision-tree.md

### 建議優先級
A > B > C（A 是源頭防護，B 是自動提醒，C 是流程文件補充）
