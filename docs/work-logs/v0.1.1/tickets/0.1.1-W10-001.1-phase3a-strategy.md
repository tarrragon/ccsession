## 1. 實作策略設計

### 1.1 語言無關策略概述

merge 和 cleanup 子命令遵循**分層驗證 + 前置檢查鏈**的設計模式：

```
merge 命令流程：
┌─ 格式驗證 ─→ worktree 查詢 ─→ Ticket 狀態驗證 ─→ working tree 乾淨檢查
└─ ahead/behind 計算 ─→ 輸出指令（或警告/降級）

cleanup 命令流程：
┌─ 格式驗證 ─→ worktree 查詢 ─→ Level 1 閘門（未commit）
└─ Level 2 閘門（未push）─→ Level 3 閘門（未合併）─→ 執行清理
   （每層都可根據 --force 和前置條件決定是否繼續）
```

### 1.2 實作順序（依賴關係）

#### 第一階段：基礎輔助函式（無依賴）
1. **`_query_ticket_status(ticket_id) → Optional[str]`**
   - 透過 subprocess 呼叫 ticket CLI
   - 捕捉異常，降級失敗為 None（避免 merge 流程中斷）
   - 評估成本：低（單純 subprocess 包裝）

2. **`_is_branch_merged_to_base(branch, base="main") → bool`**
   - 執行 `git branch --merged <base>` 並檢查 branch 是否在結果中
   - 評估成本：低（單一 git 命令）

3. **`_is_branch_pushed(branch) → bool`**
   - 檢查 `origin/<branch>` 是否存在且與本地同步
   - 流程：先查 origin 分支是否存在 → 再比較 HEAD commit
   - 評估成本：低（兩步 git 命令）

#### 第二階段：merge 子命令邏輯
4. **`_merge_validate_ticket_status(ticket_id) → tuple[bool, str]`**
   - 呼叫 `_query_ticket_status()` 查詢
   - 若查詢成功，檢查狀態是否為 "completed"
   - 若查詢失敗，返回 (True, warning_message) 降級
   - 依賴：`_query_ticket_status()`

5. **`_merge_check_working_tree_clean(worktree_path) → tuple[bool, int]`**
   - 執行 `git status --porcelain` 計算未 commit 行數
   - 返回 (is_clean: bool, count: int)
   - 評估成本：低（單一 git 命令）

6. **`_merge_build_output(ticket_id, branch_name, ahead, behind, warnings)`**
   - 純輸出格式化邏輯，無副作用
   - 使用 MergeMessages 常數類別的訊息
   - 評估成本：低（純字串組合）

7. **`cmd_merge(ticket_id: str) → int`**
   - 主函式，依序執行驗證鏈：格式 → worktree 查詢 → Ticket 狀態 → working tree → ahead/behind
   - 任何驗證失敗則輸出錯誤並返回 1
   - 依賴：`_merge_validate_ticket_status()`, `_merge_check_working_tree_clean()`, `_merge_build_output()`

#### 第三階段：cleanup 子命令邏輯
8. **`_cleanup_check_level1(worktree_path) → tuple[bool, int]`**
   - 執行 `git status --porcelain` 計算未 commit 數
   - 返回 (passed: bool, count: int)
   - 評估成本：低（重用 merge 的邏輯，可抽象為共用函式）

9. **`_cleanup_single(worktree: dict, ticket_id: str, force: bool) → int`**
   - 核心清理邏輯，包含三層閘門檢查
   - 依序呼叫 `_cleanup_check_level1()` → `_is_branch_pushed()` → `_is_branch_merged_to_base()`
   - 若通過所有閘門，執行 `git worktree remove` 和 `git branch -d`
   - 依賴：`_cleanup_check_level1()`, `_is_branch_pushed()`, `_is_branch_merged_to_base()`

10. **`_cleanup_scan_all() → int`**
    - 遍歷 `get_worktree_list()` 的所有 worktree
    - 逐個評估每個 worktree 的狀態（已合併 / 未 push / 未合併 / 不安全）
    - 分類輸出建議
    - 依賴：`get_worktree_list()`, `_cleanup_check_level1()`, `_is_branch_pushed()`, `_is_branch_merged_to_base()`

11. **`cmd_cleanup(ticket_id: Optional[str] = None, force: bool = False) → int`**
    - 主函式，根據 ticket_id 分發到掃描模式或精確模式
    - 無參數 → 呼叫 `_cleanup_scan_all()`
    - 有 ticket_id → 呼叫 `_cleanup_single()`
    - 依賴：`_cleanup_scan_all()`, `_cleanup_single()`

#### 第四階段：main() 函式擴充
12. **新增 merge/cleanup subparser 至 main()**
    - 擴充現有 argparse 結構，保持與 create/status 一致
    - merge: `worktree merge <ticket-id>`
    - cleanup: `worktree cleanup [ticket-id] [--force]`

### 1.3 檔案修改清單

## 2. 資料結構選擇

### 2.1 merge 邏輯資料流

```
Input: ticket_id (string)
   ↓
驗證結果: {
    "format_valid": bool,
    "worktree_found": bool,
    "ticket_status": str | None,  # "completed", "in_progress", None(查詢失敗)
    "status_check_passed": bool,  # True = completed 或查詢失敗(降級)
    "working_tree_clean": bool,
    "uncommitted_count": int,
    "ahead": int,
    "behind": int,
    "warnings": list[str]
}
   ↓
輸出: git merge 指令 + 警告/提示 + exit code
```

### 2.2 cleanup 邏輯資料流

```
Input: ticket_id (Optional[str]), force (bool)
   ↓
掃描模式時的 worktree 狀態分類: {
    "safe_to_clean": list[worktree],    # uncommitted=0, ahead=0
    "warnings": list[{
        "worktree": dict,
        "level": int,  # 2 or 3
        "reason": str
    }],
    "unsafe": list[{
        "worktree": dict,
        "uncommitted_count": int
    }]
}
   ↓
輸出: 分類報告 + exit code
```

```
精確模式時的閘門檢查流程: {
    "level1_passed": bool,
    "level1_count": int,
    "level1_reason": str | None,

    "level2_passed": bool,
    "level2_reason": str | None,

    "level3_passed": bool,
    "level3_reason": str | None,

    "can_proceed": bool  # 根據 --force 和各層結果決定
}
   ↓
輸出: 清理結果或拒絕訊息 + exit code
```

## 3. 資料流程圖

### 3.1 merge 子命令資料流程

```
用戶輸入: /worktree merge 0.1.1-W9-002
  │
  ▼
[ 格式驗證 ]
  ├─ is_valid_ticket_id(ticket_id)
  └─ valid? ─YES→ 進行下一步
             └─NO → 輸出格式錯誤，exit 1

[ worktree 查詢 ]
  ├─ get_worktree_list()
  ├─ _find_worktree(ticket_id)
  └─ found? ─YES→ 進行下一步
           └─NO → 輸出找不到，exit 1

[ Ticket 狀態驗證 ]
  ├─ _query_ticket_status(ticket_id)
  ├─ status == "completed"?
  │  ├─ YES → 進行下一步
  │  ├─ NO → 輸出阻擋訊息，exit 1
  │  └─ TIMEOUT/ERROR → 降級警告，繼續

[ Working tree 乾淨檢查 ]
  ├─ _merge_check_working_tree_clean(path)
  ├─ uncommitted == 0?
  │  ├─ YES → 進行下一步
  │  └─ NO → 輸出阻擋訊息，exit 1

[ ahead/behind 計算 ]
  ├─ get_worktree_ahead_behind(branch)
  ├─ ahead == 0? ─YES→ 記錄警告「無新commit」
  ├─ behind > 0? ─YES→ 記錄提示「建議rebase」
  └─ 進行輸出

[ 輸出 git merge 指令 ]
  ├─ _merge_build_output(...) 格式化
  ├─ 輸出 git checkout main
  ├─ 輸出 git merge --no-ff feat/<branch>
  └─ exit 0
```

### 3.2 cleanup 子命令資料流程（掃描模式）

```
用戶輸入: /worktree cleanup
  │
  ▼
[ 取得 worktree 列表 ]
  ├─ get_worktree_list()
  └─ 篩選非主倉庫的 worktree

[ 逐一評估狀態 ]
  └─ FOR each worktree:
     ├─ _cleanup_check_level1(path) → uncommitted count
     ├─ _is_branch_pushed(branch) → bool
     ├─ _is_branch_merged_to_base(branch) → bool
     └─ 分類至：safe_to_clean / warnings / unsafe

[ 輸出分類報告 ]
  ├─ 「建議清理」區塊 + 清理指令
  ├─ 「需注意」區塊 + --force 提示
  ├─ 「不安全」區塊 + commit 提示
  └─ exit 0
```

### 3.3 cleanup 子命令資料流程（精確模式）

```
用戶輸入: /worktree cleanup 0.1.1-W9-002 [--force]
  │
  ▼
[ 格式驗證 + worktree 查詢 ]
  ├─ is_valid_ticket_id(ticket_id)
  └─ worktree 存在? ─NO→ 輸出錯誤，exit 1

[ Level 1 閘門：未commit檢查 ]
  ├─ _cleanup_check_level1(path)
  ├─ 有未commit? ─YES→ 輸出拒絕訊息，exit 1（--force 無效）

[ Level 2 閘門：未push檢查 ]
  ├─ _is_branch_pushed(branch)
  ├─ 未push? ─YES→
  │         ├─ --force? ─YES→ 略過，記錄警告訊息
  │         └─        ─NO → 輸出警告，exit 1

[ Level 3 閘門：未合併檢查 ]
  ├─ _is_branch_merged_to_base(branch)
  ├─ 未合併? ─YES→
  │         ├─ --force? ─YES→ 略過，記錄警告訊息
  │         └─        ─NO → 輸出警告，exit 1

[ 執行清理 ]
  ├─ _cleanup_execute(path, branch)
  ├─ git worktree remove <path> ─FAIL→ 輸出錯誤，exit 1
  ├─ git branch -d <branch>      ─FAIL→ 輸出部分成功，exit 0
  └─ 輸出清理完成，exit 0
```

## 4. 控制流程圖

### 4.1 merge 命令控制流程（簡化）

```
cmd_merge(ticket_id)
  │
  ├─ if not is_valid_ticket_id(ticket_id):
  │    └─ return 1  ← 格式錯誤
  │
  ├─ worktree = _find_worktree(ticket_id)
  │  └─ if not worktree:
  │      └─ return 1  ← 找不到
  │
  ├─ can_continue, msg = _merge_validate_ticket_status(ticket_id)
  │  └─ if not can_continue:
  │      └─ print(msg), return 1  ← Ticket 未完成
  │      (或 can_continue=True 但包含降級警告)
  │
  ├─ is_clean, uncommitted = _merge_check_working_tree_clean(path)
  │  └─ if not is_clean:
  │      └─ print(msg), return 1  ← working tree 不乾淨
  │
  ├─ ahead, behind = get_worktree_ahead_behind(branch)
  │
  ├─ warnings = []
  │  ├─ if ahead == 0:
  │  │   └─ warnings.append("沒有新commit")
  │  ├─ if behind > 0:
  │  │   └─ warnings.append("落後main")
  │  └─ if _merge_validate_ticket_status 返回警告:
  │      └─ warnings.append(...)
  │
  ├─ _merge_build_output(ticket_id, branch, ahead, behind, warnings)
  │  └─ print(輸出)
  │
  └─ return 0  ← 成功
```

### 4.2 cleanup 命令控制流程（精確模式）

```
cmd_cleanup(ticket_id, force)
  │
  ├─ if ticket_id is None:
  │    └─ return _cleanup_scan_all()  ← 掃描模式分支
  │
  ├─ if not is_valid_ticket_id(ticket_id):
  │    └─ return 1  ← 格式錯誤
  │
  ├─ worktree = _find_worktree(ticket_id)
  │  └─ if not worktree:
  │      └─ return 1  ← 找不到
  │
  ├─ return _cleanup_single(worktree, ticket_id, force)
  │  │
  │  ├─ passed, count = _cleanup_check_level1(path)
  │  │  └─ if not passed:
  │  │      └─ print(拒絕訊息), return 1  ← Level 1 永不可繞過
  │  │
  │  ├─ passed, msg = _cleanup_check_level2(branch)
  │  │  └─ if not passed and not force:
  │  │      └─ print(警告), return 1
  │  │  └─ elif not passed and force:
  │  │      └─ print(警告 + 略過提示), 繼續
  │  │
  │  ├─ passed, msg = _cleanup_check_level3(branch)
  │  │  └─ if not passed and not force:
  │  │      └─ print(警告), return 1
  │  │  └─ elif not passed and force:
  │  │      └─ print(警告 + 略過提示), 繼續
  │  │
  │  ├─ success, result_msg = _cleanup_execute(path, branch)
  │  │  ├─ if not success:
  │  │  │   └─ print(結果訊息), return 1 或 0（部分成功）
  │  │  └─ else:
  │  │      └─ print(成功訊息), return 0
  │  │
  │  └─ return exit_code
```

## 5. 關鍵實作指引

### 5.1 merge 命令實作優先順序

**目標測試**（對應 Phase 2）：
- 場景 1：正常流程（全驗證通過）→ **優先級 P0**
- 場景 2：Ticket 未完成阻擋 → **優先級 P0**
- 場景 3：working tree 不乾淨阻擋 → **優先級 P0**
- 場景 4：Ticket CLI 不可用降級 → **優先級 P1**
- 場景 5-8：邊界條件 → **優先級 P1-P2**

**實作步驟**：
1. **Step 1**：實作 `_merge_validate_ticket_status()` - 驗證 Ticket 狀態的核心
2. **Step 2**：實作 `_merge_check_working_tree_clean()` - 檢查 working tree 乾淨度
3. **Step 3**：實作 `_merge_build_output()` - 格式化輸出訊息
4. **Step 4**：實作 `cmd_merge()` - 主函式，組合上述三個函式的邏輯
5. **Step 5**：完成 `main()` 的 merge subparser 擴充

### 5.2 cleanup 命令實作優先順序

**目標測試**（對應 Phase 2）：
- 場景 9：精確模式三閘門全通過 → **優先級 P0**
- 場景 10：Level 1 拒絕永不可繞過 → **優先級 P0**
- 場景 11-14：Level 2/3 警告邏輯 → **優先級 P0-P1**
- 場景 15-18：掃描模式、邊界條件 → **優先級 P1-P2**

**實作步驟**：
1. **Step 1**：實作輔助閘門檢查函式
   - `_cleanup_check_level1()` - 直接複用 merge 中的未 commit 檢查邏輯
   - `_is_branch_pushed()` - 判斷分支是否已 push
   - `_is_branch_merged_to_base()` - 判斷分支是否已合併

2. **Step 2**：實作 `_cleanup_execute()` - 執行 git worktree remove 和 git branch -d

3. **Step 3**：實作 `_cleanup_single()` - 精確模式的核心邏輯（三閘門檢查 → 執行清理）

4. **Step 4**：實作 `_cleanup_scan_all()` - 掃描模式的報告生成邏輯

5. **Step 5**：實作 `cmd_cleanup()` - 主函式，分發到掃描或精確模式

6. **Step 6**：完成 `main()` 的 cleanup subparser 擴充

### 5.3 兩個命令的整合優先級

| 優先級 | 任務 | 判斷理由 |
|--------|------|---------|
| **P0** | merge 完整實作 + cleanup 三閘門邏輯 | 兩個命令的核心驗證邏輯，測試優先級最高 |
| **P1** | merge 降級邏輯 + cleanup 掃描模式 | 邊界條件和增強功能，重要但非阻擋 |
| **P2** | 完整的輸出格式化 + 所有警告訊息 | 用戶體驗相關，需要有訊息常數支援 |

## 6. 權宜方案與技術債務

### 6.1 最小可行實作策略

**merge 最小可行實作**：
- 實作基本的驗證鏈（格式 → worktree → Ticket 狀態 → working tree clean）
- 輸出簡單的 git merge 指令和基本訊息
- 不包含複雜的 ahead/behind 計算和警告邏輯（可後續添加）

**cleanup 最小可行實作**：
- 實作三層閘門檢查的邏輯骨架
- 精確模式優先實作，掃描模式其次
- Level 1 拒絕邏輯是必須的（安全相關），Level 2/3 警告可簡化為基本提示

### 6.2 已知限制

| 限制 | 影響範圍 | 後續改善方向 |
|------|---------|------------|
| Ticket CLI 超時時降級為警告 | merge 命令不驗證 Ticket 狀態 | Phase 4 可考慮增加重試機制或超時可配置 |
| git branch -d 失敗時只輸出提示不自動 -D | cleanup 可能留下分支孤立記錄 | Phase 4 可考慮自動探測失敗原因並建議更強的刪除策略 |
| 掃描模式無法辨識非 feat/ 前綴的 worktree | cleanup 掃描時會標記為「無法辨識」 | Phase 4 可擴充支援其他分支命名規則 |
| ahead/behind 計算依賴 main 分支名 | 不支援其他基礎分支名 | Phase 4 可增加 --base 參數選項 |

### 6.3 技術債務標記

**TDD-001: 訊息常數集中管理**
- 產生地點：scripts/messages.py 新建
- 類別：架構改善
- 優先級：中
- 說明：Python 專案應有 messages.py 集中管理使用者可見字串（良好實踐）
- 建議時機：Phase 3b 實作時同步進行

**TDD-002: worktree 資訊結構化**
- 產生地點：cleanup scan 模式中的 worktree 狀態分類
- 類別：代碼複用
- 優先級：低
- 說明：`get_worktree_list()` 回傳的 worktree dict 結構可在未來標準化為 Dataclass
- 建議時機：Phase 4 重構或後續版本

**TDD-003: 錯誤訊息的本地化支援**
- 產生地點：所有訊息輸出點
- 類別：增強功能
- 優先級：低
- 說明：目前所有訊息為繁體中文，未來可支援多語系（i18n）
- 建議時機：v0.2.0 或後續版本

## 7. 新增常數和訊息定義

### 7.1 constants.py 新增常數

```python
# ===== merge 子命令常數 =====

# ticket track 查詢超時秒數（避免 merge 流程卡住）
TICKET_QUERY_TIMEOUT = 5

# Ticket 已完成的狀態值
TICKET_COMPLETED_STATUS = "completed"

# ===== cleanup 子命令常數 =====

# cleanup 輸出寬度（與 status 一致）
```

## 8. 語言特定實作注意事項（Python）

### 8.1 Python 實作考量

**import 和 module 結構**：
- merge/cleanup 邏輯應保持在 worktree_manager.py 內（不拆分為子模組）
- 訊息常數需從新的 messages.py 引入：`from messages import MergeMessages, CleanupMessages`

**subprocess 和 exception 處理**：
- Ticket CLI 查詢使用 `subprocess.run()` 並捕捉 `subprocess.TimeoutExpired` 和 `subprocess.CalledProcessError`
- 超時應設為 TICKET_QUERY_TIMEOUT (5 秒)，避免 merge 命令卡住
- 異常捕捉後應列出 stderr/stdout 幫助除錯（但不中斷流程）

**字串格式化**：
- 所有訊息應使用 f-string（Python 3.10+）或 .format()
- 訊息從 messages.py 常數類別取得，不硬編碼字串
- 例：`print(MergeMessages.DIRTY_WORKING_TREE.format(count=uncommitted))`

**型別標註**：
- 公開函式應有完整型別標註：`def cmd_merge(ticket_id: str) -> int:`
- 返回值統一為 int（exit code）或 tuple[bool, str] (驗證結果)
- Optional 使用 `Optional[str]` 而非 `str | None`（保持向後相容）

**Guard Clause 優先**：
- 所有驗證失敗應在函式開頭 Guard Clause 形式返回，避免深層巢狀
- 例如 merge 命令應在開頭連續檢查：格式 → worktree → Ticket 狀態等

**函式長度控制**：
- 每個函式應 <= 30 行（理想 < 20 行）
- cmd_merge 和 cmd_cleanup 主函式可達 30-40 行（複雜邏輯，但流程清晰）
- 輔助函式應盡量控制在 10-15 行

### 8.2 效能最佳化建議

**subprocess 超時**：
- ticket 查詢設 TICKET_QUERY_TIMEOUT = 5 秒（不要等待過久）
- 其他 git 命令可使用 run_git_command 的預設超時 (10 秒)

**重複計算避免**：
- merge 中的 working tree clean 檢查和 cleanup Level 1 檢查邏輯相同
- 可抽象為共用的 `_get_worktree_uncommitted_count()` 內部函式（已存在）

**掃描模式的 worktree 遍歷**：
- 逐個 worktree 計算 ahead/behind/uncommitted 不會造成效能問題（通常 < 10 個 worktree）
- 若未來 worktree 數量增加，可考慮批量 git 命令

### 8.3 可能的技術挑戰

**Challenge 1：git branch -d vs -D 的自動決策**
- `-d` 要求分支已合併，否則失敗
- `-D` 強制刪除，但可能造成不可回復的資料遺失
- 本實作設計為失敗後提示用戶手動執行 `-D`（保守策略）
- Phase 4 可增強為自動偵測失敗原因，提供「分支未完全合併」的提示

**Challenge 2：origin 分支的動態檢查**
- `_is_branch_pushed()` 需檢查 `origin/<branch>` 是否存在
- 若使用者在本地刪除了 origin remote，邏輯可能失效
- 本實作假設 origin 始終存在（通常成立），如需更健壯可增加 remote 檢查

**Challenge 3：detached HEAD worktree 的處理**
- 部分 worktree 可能處於 detached HEAD 狀態（不在任何分支上）
- cleanup 應跳過或警告此類 worktree（Phase 1 設計未涵蓋，視為邊界）
- 本實作可簡化為：扣掉不是 feat/ 開頭的分支（無法清理）

### 11.1 merge 驗證邏輯虛擬碼

```pseudocode
function cmd_merge(ticket_id: string) → integer:
    // Step 1: 格式驗證
    if not is_valid_ticket_id(ticket_id):
        print("[錯誤] 無效的 Ticket ID 格式")
        return 1

    // Step 2: worktree 查詢
    worktree ← find_worktree_by_ticket_id(ticket_id)
    if worktree is null:
        print("[錯誤] 找不到 Ticket {ticket_id} 對應的 worktree")
        print("現有 worktree 列表：...")
        return 1

    // Step 3: Ticket 狀態驗證
    can_continue, warning_msg ← _merge_validate_ticket_status(ticket_id)
    if not can_continue:
        print(error_msg)
        return 1
    warnings ← []
    if warning_msg is not empty:
        warnings.append(warning_msg)

    // Step 4: working tree 乾淨檢查
    is_clean, uncommitted_count ← _merge_check_working_tree_clean(worktree.path)
    if not is_clean:
        print("[阻擋] Working tree 有 {uncommitted_count} 個未 commit 變更")
        return 1

    // Step 5: ahead/behind 計算
    ahead, behind ← get_worktree_ahead_behind(worktree.branch, "main")
    if ahead == 0:
        warnings.append("此分支沒有超前 main 的新 commit")
    if behind > 0:
        warnings.append("此分支落後 main {behind} 個 commit")

    // Step 6: 輸出
    _merge_build_output(ticket_id, worktree.branch, ahead, behind, warnings)
    return 0
```

### 11.2 cleanup 三層閘門虛擬碼

```pseudocode
function _cleanup_single(worktree: dict, ticket_id: string, force: bool) → integer:
    path ← worktree.path
    branch ← worktree.branch

    // Level 1: 未 commit 檢查（永不可繞過）
    passed, uncommitted_count ← _cleanup_check_level1(path)
    if not passed:
        print("[拒絕] Working tree 有 {uncommitted_count} 個未 commit 變更")
        print("此安全閘門無法繞過（--force 無效）")
        return 1

    // Level 2: 未 push 檢查（可被 --force 略過）
    passed, warning_msg ← _cleanup_check_level2(branch)
    if not passed:
        print(warning_msg)
        if not force:
            return 1
        else:
            print("[警告] 使用 --force 略過此警告，繼續清理")

    // Level 3: 未合併檢查（可被 --force 略過）
    passed, warning_msg ← _cleanup_check_level3(branch, "main")
    if not passed:
        print(warning_msg)
        if not force:
            return 1
        else:
            print("[警告] 使用 --force 略過此警告，繼續清理")

    // 執行清理
    success, result_msg ← _cleanup_execute(path, branch)
    print(result_msg)
    return (0 if success else 1)
```
