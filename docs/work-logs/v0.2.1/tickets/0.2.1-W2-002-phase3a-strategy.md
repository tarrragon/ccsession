## 2. 資料結構選擇

### SessionGroupUiState（不可變值物件）

```
SessionGroupUiState:
  currentPages: Map<SessionStatus, Integer>
    預設 {active: 0, idle: 0, completed: 0}
  expandedGroups: Map<SessionStatus, Boolean>
    預設 {active: true, idle: true, completed: false}
```

**選擇理由**：
- 使用 Map 而非 3 個獨立欄位，因為 SessionStatus 是 enum，Map 可用 enum 值做 key 統一存取
- 不可變 + Equatable，與 Riverpod state management 的重建機制一致
- copyWith 模式建立新實例，避免直接修改

### _ListItem sealed class 擴充

```
sealed _ListItem
  ├── _HeaderItem(status, count)      // 既有
  ├── _TileItem(session)              // 既有
  └── _PaginationItem(status, currentPage, totalPages)  // 新增
```

**選擇理由**：sealed class + pattern matching 在 itemBuilder 中消除 nullable 欄位，每個子型別自帶所需資料。

## 4. 控制流程圖

### _flattenGroups 虛擬碼

```
FUNCTION flattenGroups(grouped, uiState):
  items = []

  FOR EACH (status, sessions) IN grouped:
    count = sessions.length
    isExpanded = uiState.expandedGroups[status] ?? defaultExpanded(status)

    // 無論摺疊與否，Header 一律加入（顯示計數）
    items.ADD(HeaderItem(status, count, isExpanded))

    IF NOT isExpanded:
      CONTINUE  // 摺疊：跳過 tile 和 pagination

    // 展開：計算分頁
    pageSize = MAX_ITEMS_PER_PAGE  // 10
    totalPages = CEIL(count / pageSize)
    rawPage = uiState.currentPages[status] ?? 0
    safePage = CLAMP(rawPage, 0, MAX(totalPages - 1, 0))

    startIndex = safePage * pageSize
    endIndex = MIN(startIndex + pageSize, count)

    FOR i FROM startIndex TO endIndex - 1:
      items.ADD(TileItem(sessions[i]))

    // 超過一頁才加分頁控制
    IF totalPages > 1:
      items.ADD(PaginationItem(status, safePage, totalPages))

  RETURN items
```

### SessionGroupUiNotifier 虛擬碼

```
CLASS SessionGroupUiNotifier:

  FUNCTION build():
    RETURN SessionGroupUiState()  // 預設值

  FUNCTION setPage(status, pageIndex):
    clampedPage = MAX(pageIndex, 0)  // 只 clamp 下界，上界由 _flattenGroups 處理
    newPages = COPY(state.currentPages)
    newPages[status] = clampedPage
    state = state.copyWith(currentPages: newPages)

  FUNCTION toggleExpanded(status):
    newExpanded = COPY(state.expandedGroups)
    currentValue = newExpanded[status] ?? true
    newExpanded[status] = NOT currentValue
    state = state.copyWith(expandedGroups: newExpanded)

  FUNCTION resetAllPages():
    newPages = {active: 0, idle: 0, completed: 0}
    state = state.copyWith(currentPages: newPages)
```

### PaginationControls 虛擬碼

```
WIDGET PaginationControls(currentPage, totalPages, onPageChanged):
  // 顯示格式：「< 1 / 3 >」
  prevEnabled = currentPage > 0
  nextEnabled = currentPage < totalPages - 1
  displayPage = currentPage + 1  // 0-based 轉 1-based 顯示

  RENDER Row:
    IconButton(chevron_left, onPressed: prevEnabled ? onPageChanged(currentPage - 1) : null)
    Text("$displayPage / $totalPages")
    IconButton(chevron_right, onPressed: nextEnabled ? onPageChanged(currentPage + 1) : null)
```

### SessionGroupHeader 擴充虛擬碼

```
WIDGET SessionGroupHeader(status, count, isExpanded, onToggleExpand):
  icon = isExpanded ? expand_less : expand_more

  RENDER GestureDetector(onTap: onToggleExpand):
    Row:
      Icon(icon)
      Text("$displayName ($count)")
```

## 5. 關鍵實作指引

### _flattenGroups 存取策略決策

**決策：使用 @visibleForTesting 暴露**

理由：
- _flattenGroups 是純函式，9 個測試案例需精確驗證輸入→輸出
- 透過 Widget 間接測試無法精確控制 uiState 參數
- 將 _flattenGroups 從 file-private 改為 library-private，加上 @visibleForTesting 標注
- 具體做法：將 _flattenGroups 改名為 flattenGroupsForTesting 或保持名稱但改為非底線前綴（如 buildFlattenedList），加上 @visibleForTesting

**建議**：提取為頂層函式 `flattenGroups`（去掉底線前綴），加 @visibleForTesting，放在同一檔案。sealed class _ListItem 及其子類也需去掉底線前綴或另開檔案。

### _ListItem 可見性問題

TG-21 需要在測試中建構和比對 HeaderItem、TileItem、PaginationItem。因此：
- sealed class 和三個子類都必須對測試可見
- 選項 1：去掉底線前綴，維持在 session_list_page.dart
- 選項 2：提取到獨立檔案 `session_list_items.dart`（推薦，職責清晰）

**推薦選項 2**：建立 `ui/lib/features/session_list/presentation/session_list_items.dart`，將 sealed class 和 flattenGroups 一起放入。

### 搜尋重置整合方式

在 `_buildData` 或 `_SessionGroupListView`（改為 ConsumerWidget 後）中：

## 6. 權宜方案與技術債務

### 最小可行實作

- setPage 只 clamp 下界（>=0），上界由 _flattenGroups 的 safePage 處理，避免 Notifier 需要知道每組的 totalPages
- 摺疊狀態不持久化（App 重啟重置）—— 符合 Feature Spec 設計

### 已知限制

1. **分頁不支援鍵盤導航**：目前只有點擊互動，無 keyboard shortcut
2. **大量 session 時的效能**：每次 state 變化都重算整個 flattenGroups，未使用 select/memoize。對於目前預期的 session 數量（數十到數百筆）不成問題
3. **搜尋重置使用 ref.listen**：如果搜尋 debounce 期間多次觸發，resetAllPages 會被多次呼叫（幂等操作，無副作用）

### 技術債務標記

| 項目 | 優先級 | Phase 4 建議 |
|------|--------|-------------|
| _flattenGroups 每次全量重算 | 低 | 若 session 數量超過 1000，考慮 memoize |
| 搜尋重置與分頁重置的耦合 | 低 | 目前用 ref.listen 耦合在 View 層，可評估是否移到 Notifier 層 |

## 7. 語言特定實作注意事項

### Dart/Flutter 考量

- **Equatable**：SessionGroupUiState 繼承 Equatable，props 必須列出 currentPages 和 expandedGroups
- **Map 不可變性**：Dart Map 預設可變，copyWith 中需建立新 Map 實例（`Map.of()` 或展開運算子 `{...map}`）
- **@riverpod code generation**：SessionGroupUiNotifier 需要 part 宣告和 build_runner
- **@visibleForTesting**：來自 `package:flutter/foundation.dart` 或 `package:meta/meta.dart`
- **sealed class pattern matching**：itemBuilder 的 switch 表達式需處理新增的 PaginationItem 分支
- **Key 定位**：PaginationControls 的按鈕建議使用 `Key('pagination_prev_$status')` 等，方便測試定位。或直接用 Icons.chevron_left/right 配合 find.byIcon
