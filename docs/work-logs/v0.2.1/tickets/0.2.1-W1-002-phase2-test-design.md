## 1. 測試策略

### 分層決策

| 元件 | 層級 | 測試類型 | 理由 |
|------|------|---------|------|
| AssistantMessageBubble（Markdown 分支） | Layer 1 (UI) | Widget 測試 | UI 渲染條件分支，驗證 MarkdownBody 出現 |
| ThinkingBubble（Markdown 分支） | Layer 1 (UI) | Widget 測試 | UI 渲染條件分支，展開後驗證 MarkdownBody |

| ThemeData | 不 Mock | Flutter 內建，用 MaterialApp 提供 |

## 2. 測試案例設計

### TG-MD-01: AssistantMessageBubble Markdown 渲染

**功能職責**: 驗證 AssistantMessageBubble 在不同 highlightRanges 狀態下正確選擇 MarkdownBody 或 buildHighlightableText 渲染路徑。
**跨群組依賴**: 無。使用 createAssistantEvent 工廠，不依賴其他測試群組。

#### TC-MD-01-01: 基本 Markdown 格式 — 無搜尋高亮時使用 MarkdownBody

- **Given**: assistant 訊息內容為 `"**bold** and *italic*"`，highlightRanges 為 null
- **Then（前置驗證）**: AssistantMessageBubble Widget 存在
- **When**: Widget 渲染完成
- **Then**: 找到 MarkdownBody Widget（`find.byType(MarkdownBody)`）
- **Then**: 不存在 RichText 中包含高亮背景色的 span

**覆蓋場景**: 場景 1（基本 Markdown 格式）

#### TC-MD-01-02: 基本 Markdown 格式 — highlightRanges 為空列表時使用 MarkdownBody

- **Given**: assistant 訊息內容為 `"# Heading\n- item1\n- item2"`，highlightRanges 為 `[]`（空列表）
- **Then（前置驗證）**: AssistantMessageBubble Widget 存在
- **When**: Widget 渲染完成
- **Then**: 找到 MarkdownBody Widget

**覆蓋場景**: 場景 1（清單、標題）、降級策略 A 的「空列表」邊界

#### TC-MD-01-03: Markdown 表格 — 渲染為結構化表格

- **Given**: assistant 訊息內容為 Markdown 表格字串 `"| col1 | col2 |\n|------|------|\n| a | b |"`，highlightRanges 為 null
- **Then（前置驗證）**: MarkdownBody Widget 存在
- **When**: Widget 渲染完成
- **Then**: 找到 Table Widget（`find.byType(Table)`）

**覆蓋場景**: 場景 2（表格渲染）

#### TC-MD-01-04: 程式碼區塊 — 以視覺區分渲染

- **Given**: assistant 訊息內容為包含 fenced code block 的字串 ````"```dart\nfinal x = 1;\n```"````，highlightRanges 為 null
- **Then（前置驗證）**: MarkdownBody Widget 存在
- **When**: Widget 渲染完成
- **Then**: 渲染結果中存在程式碼區塊容器（找到帶有 `BoxDecoration` 的程式碼區塊區域）
- **Then**: Widget 樹中不 crash

**覆蓋場景**: 場景 3（程式碼區塊）

#### TC-MD-01-05: 搜尋高亮降級 — 有 highlightRanges 時不使用 MarkdownBody

- **Given**: assistant 訊息內容為 `"**bold** text"`，highlightRanges 為 `[(start: 0, end: 4, isCurrent: false, field: 'text')]`
- **Then（前置驗證）**: AssistantMessageBubble Widget 存在
- **When**: Widget 渲染完成
- **Then**: 不存在 MarkdownBody Widget（`find.byType(MarkdownBody)`, findsNothing）
- **Then**: 存在 RichText Widget（降級為純文字高亮）

**覆蓋場景**: 場景 5（搜尋高亮降級）

#### TC-MD-01-06: 搜尋高亮降級 — 不 crash

- **Given**: assistant 訊息內容為 `"# Title\n\n**bold** [link](url)"`，highlightRanges 為 `[(start: 2, end: 7, isCurrent: true, field: 'text')]`
- **Then（前置驗證）**: AssistantMessageBubble Widget 存在
- **When**: Widget 渲染完成
- **Then**: Widget 正常渲染不 crash（tester.pumpWidget 不拋出例外）
- **Then**: 不存在 MarkdownBody Widget

**覆蓋場景**: 場景 5（搜尋高亮不 crash）

#### TC-MD-01-07: 純文字 — 無退化

- **Given**: assistant 訊息內容為 `"Hello, this is plain text."`，highlightRanges 為 null
- **Then（前置驗證）**: AssistantMessageBubble Widget 存在
- **When**: Widget 渲染完成
- **Then**: 找到 MarkdownBody Widget
- **Then**: 文字 `"Hello, this is plain text."` 可在 Widget 樹中找到

**覆蓋場景**: 場景 6（純文字無退化）

#### TC-MD-01-08: 空內容 — 不 crash

#### TC-MD-01-09: 僅空白字元 — 不 crash

- **Given**: assistant 訊息內容為 `"   \n\n  "`（僅空白），highlightRanges 為 null
- **When**: Widget 渲染完成

**覆蓋場景**: 場景 7（極短/空白內容邊界）

#### TC-MD-01-10: 超長 Markdown 內容 — 不 crash

- **When**: Widget 渲染完成
- **Then**: Widget 正常渲染不 crash

**覆蓋場景**: 場景 8（超長內容）

#### TC-MD-01-11: 外層 Container 維持 bubbleMargin 和 bubbleContentPadding

- **Given**: assistant 訊息內容為 `"**test**"`，highlightRanges 為 null

**覆蓋驗收條件**: 外層 Container 仍使用 bubbleMargin、bubbleContentPadding（SA 結論 5）

#### TC-MD-01-12: 靠左對齊不變

- **Given**: assistant 訊息內容為 `"# Title"`，highlightRanges 為 null
- **When**: Widget 渲染完成
- **Then**: Align Widget 的 alignment 為 Alignment.centerLeft

**覆蓋**: 確保 Markdown 替換不改變對齊行為（回歸防護）

## 5. 測試環境設置

### 測試資料

- 使用現有 `createAssistantEvent(text)` 和 `createThinkingEvent(text)` 工廠
- HighlightRange 直接以 record literal 建構：`(start: N, end: M, isCurrent: false, field: 'text')`
- Markdown 測試字串定義為測試檔案頂部的常數

### 測試隔離

- 每個 testWidgets 使用獨立的 `MaterialApp(home: Scaffold(body: ...))` 包裝
- 無共享 mutable 狀態
- ThinkingBubble 測試需要 `tester.tap` + `tester.pumpAndSettle` 展開 ExpansionTile

### 測試清理

- Flutter Widget 測試自動管理 Widget 生命週期，無需手動清理
