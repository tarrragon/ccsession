## 1. Implementation Strategy Overview

Two independent test suites (Go backend, Flutter frontend) with no cross-dependency. Both can be implemented in parallel by separate agents.

### 1.1 Go Backend Strategy

**Core idea**: Build an `integrationHarness` that wires up all real components (FileWatcher, EventDispatcher, SessionRegistry, WebSocketServer) against a temporary directory, then drive tests by writing JSONL files and reading WebSocket messages.

### 1.2 Flutter Frontend Strategy

**Core idea**: Build a `FakeWebSocketService` that exposes `StreamController` inputs for message/connectionState, then verify Notifier state transitions through Riverpod `ProviderContainer`.

## 2. Go Backend Pseudocode

### 2.1 integrationHarness Structure

```
STRUCTURE integrationHarness:
  tmpDir         -- temporary directory (isolated file system)
  sessionEvCh    -- channel: FileWatcher -> EventDispatcher
  hookEvCh       -- channel: (unused, but required by EventDispatcher)
  dispatchCh     -- channel: EventDispatcher -> WebSocketServer
  registry       -- real SessionRegistry
  watcher        -- real FileWatcher (claudeHome = tmpDir)
  dispatcher     -- real EventDispatcher
  wsServer       -- real WebSocketServer
  httpServer     -- httptest.Server (wrapping wsServer.HandleWS)
  ctx            -- cancellable context
  cancel         -- cancel function
  timeProvider   -- injectable clock (for status scan tests)
```

### 2.2 Setup Pseudocode

```
FUNCTION setupIntegrationHarness():
  tmpDir = CREATE temporary directory
  CREATE projects subdirectory under tmpDir  // FileWatcher expects claudeHome/projects/

  sessionEvCh = MAKE channel(capacity = 256)
  hookEvCh    = MAKE channel(capacity = 16)
  dispatchCh  = MAKE channel(capacity = 256)

  timeProvider = controllable time function (default: real time.Now)
  registry   = NewSessionRegistry(timeProvider)
  watcher    = NewFileWatcher(tmpDir, sessionEvCh, registry)
  dispatcher = NewEventDispatcher(registry, sessionEvCh, hookEvCh, dispatchCh, timeProvider)
  wsServer   = NewWebSocketServer(registry, dispatchCh, timeProvider)

  ctx, cancel = CREATE cancellable context

  START goroutine: watcher.Start(ctx)
  START goroutine: dispatcher.Run(ctx)
  START goroutine: wsServer.Run(ctx)

  httpServer = httptest.NewServer(handler = wsServer.HandleWS)

  RETURN harness
```

### 2.3 Teardown Pseudocode

```
FUNCTION teardown(harness):
  cancel()                    // stop all goroutines
  httpServer.Close()          // stop HTTP server
  REMOVE tmpDir recursively   // cleanup filesystem
```

### 2.4 Helper: writeJSONL

```
FUNCTION writeJSONL(harness, sessionID, projectPath, jsonLine):
  // Encode project path as URL-safe directory name (matching FileWatcher logic)
  encodedPath = URL-encode(projectPath)
  dir = tmpDir / "projects" / encodedPath
  ENSURE dir exists

  filePath = dir / sessionID + ".jsonl"
  APPEND jsonLine + newline to filePath
```

**Key decision**: Must match FileWatcher's directory structure expectation. FileWatcher watches `claudeHome/projects/{encodedProjectPath}/*.jsonl`.

### 2.5 Helper: connectAndWaitInitial

```
FUNCTION connectAndWaitInitial(harness) -> wsConnection:
  conn = WebSocket dial to httpServer URL + "/ws"
  msg = READ message from conn (timeout 5s)
  ASSERT msg.type == "session_list"
  RETURN conn
```

### 2.6 Helper: readMessageWithTimeout

```
FUNCTION readMessageWithTimeout(conn, timeout) -> message OR timeout error:
  SET read deadline to now + timeout
  READ message from conn
  PARSE as ServerMessage (type + raw data)
  RETURN message
```

### 2.7 Helper: sendClientAction

```
FUNCTION sendClientAction(conn, action, payload):
  BUILD ClientMessage { action, data: payload }
  SERIALIZE to JSON
  WRITE to conn
```

### 2.8 Test Flow: TC-GO-01 (JSONL write triggers session_list)

```
FUNCTION TestJSONLWriteTriggersSessionList():
  h = setupIntegrationHarness()
  DEFER teardown(h)

  conn = connectAndWaitInitial(h)

  // Write a user message JSONL
  writeJSONL(h, "session-A", "/project/path", userMessageJSON)

  // Wait for session_list update
  msg = readMessageWithTimeout(conn, 5s)
  ASSERT msg.type == "session_list"
  PARSE msg.data as SessionListData
  ASSERT sessions contains entry with id == "session-A"
  ASSERT that entry's status == "active"
```

### 2.9 Test Flow: TC-GO-02 (Subscribe then receive session_event)

```
FUNCTION TestSubscribeReceivesSessionEvent():
  h = setupIntegrationHarness()
  DEFER teardown(h)

  conn = connectAndWaitInitial(h)

  // Create session
  writeJSONL(h, "session-1", "/project", userMessageJSON)
  msg = readMessageWithTimeout(conn, 5s)  // session_list update
  ASSERT contains "session-1"

  // Subscribe
  sendClientAction(conn, "subscribe_session", { sessionId: "session-1" })

  // Append assistant message
  writeJSONL(h, "session-1", "/project", assistantMessageJSON)

  // Read messages until session_event (may receive session_list first)
  LOOP:
    msg = readMessageWithTimeout(conn, 5s)
    IF msg.type == "session_event":
      ASSERT msg.data.sessionId == "session-1"
      ASSERT msg.data contains assistant content
      BREAK
    // else continue (skip session_list broadcasts)
```

### 2.10 Test Flow: TC-GO-05 (Status scan via timeProvider)

```
FUNCTION TestStatusChangeOnIdleTimeout():
  // Use controllable time
  currentTime = mutable reference to fixed timestamp
  timeProvider = FUNCTION() -> currentTime.value

  h = setupIntegrationHarness(timeProvider = timeProvider)
  DEFER teardown(h)

  conn = connectAndWaitInitial(h)

  // Create active session
  writeJSONL(h, "session-1", "/project", userMessageJSON)
  DRAIN messages until session_list with "session-1"

  // Advance time past idle threshold
  currentTime.value = currentTime.value + IdleThreshold + 1 minute

  // Wait for status scan tick to fire and produce status change
  msg = readMessageWithTimeout(conn, StatusScanInterval + 2s)
  // May need to loop — status scan is periodic
  ASSERT eventually receive type == "session_status_change"
  ASSERT msg.data.sessionId == "session-1"
  ASSERT msg.data.status == "idle"
```

**Design note**: The status scan is driven by a real `time.Ticker(StatusScanInterval)` inside EventDispatcher.Run(). We cannot inject the ticker, but we can control `timeProvider` so that when the ticker fires, `ScanAndUpdateStatus()` sees sessions as expired. This means the test must wait for one real ticker interval.

### 2.11 Test Flow: TC-GO-07 (Non-blocking drop)

```
FUNCTION TestNonBlockingDropWhenChannelFull():
  h = setupIntegrationHarness()
  // DO NOT start wsServer.Run() — dispatchCh has no consumer
  DEFER teardown(h)

  // Write many JSONL lines exceeding dispatchCh buffer
  FOR i = 0 TO DispatchChBufferSize + 10:
    writeJSONL(h, "session-flood", "/project", userMessageJSON_i)

  // Assert: completes within timeout (no deadlock)
  // The fact this function returns is the assertion
```

**Design note**: Need to modify harness setup to optionally skip starting `wsServer.Run()`. Or create a separate setup function for this specific test.

## 3. Flutter Frontend Pseudocode

### 3.1 FakeWebSocketService

```
STRUCTURE FakeWebSocketService IMPLEMENTS WebSocketService:
  messageController       -- StreamController<ServerMessage>.broadcast()
  connectionStateController -- StreamController<WsConnectionState>.broadcast()
  sentMessages            -- List of recorded outgoing messages

  PROPERTY messageStream -> messageController.stream
  PROPERTY connectionState -> connectionStateController.stream

  METHOD send(message):
    APPEND message to sentMessages

  // Convenience methods matching WebSocketService interface
  METHOD requestSessionList():     send(...)
  METHOD requestSessionHistory(id): send(...)
  METHOD subscribeSession(id):     send(...)
  METHOD unsubscribeSession(id):   send(...)

  METHOD dispose():
    CLOSE messageController
    CLOSE connectionStateController
```

**Design decision**: Check if `FakeWebSocketService` already exists in the codebase. If so, reuse it.

### 3.2 Test Container Setup

```
FUNCTION createTestContainer(fakeService) -> ProviderContainer:
  container = ProviderContainer(
    overrides: [
      webSocketServiceProvider.overrideWithValue(fakeService)
    ]
  )
  RETURN container
```

### 3.3 Helper: pushServerMessage

```
FUNCTION pushServerMessage(fakeService, type, data):
  fakeService.messageController.add(
    ServerMessage(type: type, data: data)
  )
  // Allow microtask queue to process
  AWAIT pump / future.delayed(Duration.zero)
```

### 3.4 Test Flow: TC-FL-01 (session_list drives SessionListNotifier)

```
FUNCTION testSessionListDrivesNotifier():
  fake = FakeWebSocketService()
  container = createTestContainer(fake)
  DEFER container.dispose()

  // Read notifier to trigger build
  notifier = container.read(sessionListNotifierProvider.notifier)
  AWAIT settle  // wait for build() to complete

  // Initial state
  state = container.read(sessionListNotifierProvider).value
  ASSERT state.sessions is empty

  // Push session_list
  pushServerMessage(fake, "session_list", {
    "sessions": [
      { "id": "s1", "status": "active", "projectPath": "/p1", ... },
      { "id": "s2", "status": "idle", "projectPath": "/p2", ... }
    ]
  })
  AWAIT settle

  state = container.read(sessionListNotifierProvider).value
  ASSERT state.sessions.length == 2
  ASSERT contains s1 (active) and s2 (idle)
```

### 3.5 Test Flow: TC-FL-02 (session_event drives ConversationNotifier)

```
FUNCTION testSessionEventDrivesConversation():
  fake = FakeWebSocketService()
  container = createTestContainer(fake)
  DEFER container.dispose()

  // Trigger ConversationNotifier build and loadSession
  notifier = container.read(conversationNotifierProvider("session-1").notifier)
  // loadSession triggers requestSessionHistory + subscribeSession
  AWAIT settle

  // Respond with empty history
  pushServerMessage(fake, "session_history", {
    "sessionId": "session-1", "events": [], "hasMore": false
  })
  AWAIT settle

  // Push session_event
  pushServerMessage(fake, "session_event", {
    "sessionId": "session-1",
    "type": "assistant",
    "content": { "text": "Hello" },
    "timestamp": "...",
    "messageId": "msg-1",
    "contentIndex": 0,
    "isLastContent": true
  })
  AWAIT settle

  state = container.read(conversationNotifierProvider("session-1")).value
  ASSERT state.events.length == 1
  ASSERT state.events.last.content.text == "Hello"
```

### 3.6 Test Flow: TC-FL-04 (Reconnect triggers resubscribe)

```
FUNCTION testReconnectResubscribes():
  fake = FakeWebSocketService()
  container = createTestContainer(fake)

  notifier = container.read(conversationNotifierProvider("s1").notifier)
  AWAIT settle

  // Clear sent messages
  fake.sentMessages.clear()

  // Simulate reconnect
  fake.connectionStateController.add(WsConnectionState.reconnecting)
  fake.connectionStateController.add(WsConnectionState.connected)
  AWAIT settle

  ASSERT fake.sentMessages contains subscribe_session("s1")
  ASSERT fake.sentMessages contains get_session_history("s1")
```

## 7. Key Implementation Guidelines

### Phase 3b Sub-task A: Go Backend (server/integration_test.go)

**Priority order**: TC-GO-01 -> TC-GO-02 -> TC-GO-03 -> TC-GO-04 -> TC-GO-06 -> TC-GO-05 -> TC-GO-07

Rationale: 01-04 build on the same harness incrementally. 05 needs timeProvider control (slightly more complex). 07 needs harness variant (no wsServer.Run).

**Key concerns**:
1. FileWatcher directory structure: Must create `tmpDir/projects/{urlEncodedPath}/` matching `file_watcher.go` line 63 expectations
2. Race conditions: Use `readMessageWithTimeout` with loops to handle non-deterministic message ordering (session_list may arrive before/after session_event)
3. TC-GO-05 (status scan): EventDispatcher uses real `time.Ticker`. Test must wait for actual ticker interval. Consider using short StatusScanInterval if configurable, or accept ~1s wait
4. TC-GO-07: Must NOT start `wsServer.Run()` goroutine to leave dispatchCh unconsumed

### Phase 3b Sub-task B: Flutter Frontend (ui/test/core/integration/websocket_to_provider_test.dart)

**Priority order**: TC-FL-01 -> TC-FL-03 -> TC-FL-02 -> TC-FL-05 -> TC-FL-06 -> TC-FL-04

Rationale: SessionListNotifier tests (01, 03) are simpler. ConversationNotifier (02, 05, 06) need loadSession flow. 04 (reconnect) needs connectionState injection.

**Key concerns**:
1. Check if `FakeWebSocketService` already exists in test utilities — reuse if so
2. ConversationNotifier is a family provider (parameterized by sessionId) — read with `conversationNotifierProvider("session-1")`
3. Async settling: Use `await Future.delayed(Duration.zero)` or pump to process microtasks after pushing messages
4. TC-FL-04: Need to verify how ConversationNotifier listens to connectionStateProvider — it may use `ref.listen` or `ref.watch`

## 8. Expedient Solutions and Technical Debt

### Minimal viable implementation notes:

| Item | Expedient approach | Technical debt | Phase 4 suggestion |
|------|-------------------|---------------|-------------------|
| Go: message ordering | Loop-and-filter in readMessageWithTimeout | Fragile if message types change | Consider typed message reader with filter predicate |
| Go: TC-GO-05 wait | Real wall-clock wait for ticker | Slow test (~1-2s) | Inject ticker interface to EventDispatcher for instant test control |
| Go: JSONL format | Hardcoded JSON strings in test | Duplicates knowledge of JSONL format | Extract test fixture builders |
| Flutter: async settle | `await Future.delayed(Duration.zero)` | May need multiple pumps for chained async | Consider `pumpEventQueue()` helper |
| Flutter: FakeWebSocketService | New implementation per test file | May duplicate existing test fakes | Consolidate into shared test utilities |

### Known limitations:

1. Go integration tests depend on fsnotify — may have platform-specific behavior on CI (Linux inotify vs macOS kqueue)
2. Status scan test (TC-GO-05) has inherent timing sensitivity due to real ticker
3. Flutter tests don't cover actual WebSocket wire protocol — that boundary is tested by Go side

## 9. Language-Specific Implementation Notes

### Go considerations:

- Use `t.Helper()` on all test helper functions
- Use `t.Cleanup()` for teardown instead of defer (cleaner with subtests)
- Channel buffer sizes: match production constants from `constants.go`
- URL encoding for project paths: use `url.PathEscape` matching FileWatcher implementation
- Build tag: consider `//go:build integration` if tests are slow, but Phase 2 did not specify this

### Dart/Flutter considerations:

- Riverpod `ProviderContainer` must be disposed in `addTearDown`
- `@riverpod` generated code: ConversationNotifier uses family (per sessionId)
- SessionListNotifier build() calls `service.requestSessionList()` — FakeWebSocketService will record this
- ServerMessage model: verify constructor matches test data shape (type + data as Map)
- Connection state: verify `WsConnectionState` enum values match what ConversationNotifier listens for
