**執行時間**: 2026-03-29
**執行代理人**: pepper-test-implementer

### 1. 實作策略設計

#### 核心問題

列表元件重建時，可展開容器的內部狀態被丟棄。原因：(a) 無穩定識別符導致框架無法復用元素，(b) 展開狀態僅存於容器內部，容器重建即歸零。

#### 解法：外部狀態管理 + 穩定識別符

```
虛擬碼 1: ExpansionStateNotifier

CLASS ExpansionStateNotifier(panelIndex: INT)
  STATE: MAP<STRING, BOOL> = {}

  FUNCTION setExpanded(eventKey: STRING, isExpanded: BOOL)
    state = COPY(state)
    state[eventKey] = isExpanded
    EMIT(state)

  FUNCTION isExpanded(eventKey: STRING) -> BOOL
    RETURN state[eventKey] OR false
```

```
虛擬碼 2: ToolUseBubble (改為讀取外部狀態)

BUILD(panelIndex, event, ...):
  eventKey = "${event.messageId}_${event.contentIndex}"
  notifier = READ_PROVIDER(expansionStateNotifier, panelIndex)
  currentlyExpanded = notifier.isExpanded(eventKey)

  RETURN Container(
    key = ValueKey(eventKey),
    child = ExpansionTile(
      initiallyExpanded = currentlyExpanded,
      onExpansionChanged = (expanded) => notifier.setExpanded(eventKey, expanded),
      ...
    )
  )
```

```
虛擬碼 3: MessageBubbleFactory.build (新增 panelIndex 參數)

FUNCTION build(event, panelIndex, highlightRanges?):
  SWITCH event.type:
    'tool_use'    -> ToolUseBubble(event, panelIndex, highlightRanges)
    'tool_result' -> ToolResultBubble(event, panelIndex, highlightRanges)
    其他           -> 不變
```

```
虛擬碼 4: conversation_view ListView.builder (傳入 panelIndex + ValueKey)

itemBuilder: (context, index) =>
  event = events[reversedIndex]
  MessageBubbleFactory.build(event, panelIndex, highlightRanges)
```

### 2. 資料結構選擇

| 結構 | 選擇 | 理由 |
|------|------|------|
| 展開狀態儲存 | MAP<STRING, BOOL> | O(1) 查詢，eventKey 為自然鍵 |
| eventKey 格式 | `${messageId}_${contentIndex}` | 利用現有欄位，無需新增識別符 |
| Provider 隔離 | family provider(panelIndex) | 多面板各自獨立，與現有 conversationNotifier 一致 |

**整合注意事項**:

- ValueKey 加在 Container 層級（bubble 最外層），不是 ExpansionTile 層級
- ExpansionTile 的 `initiallyExpanded` 只在首次建構時生效；ValueKey 確保同 key 的 element 被復用，所以 initiallyExpanded 只在首次出現時讀取

### 6. 權宜方案與技術債務

- **最小可行實作**: MAP 永不清理。長時間使用同一面板後，MAP 會累積大量 eventKey。對話切換時舊 key 不會被移除。
- **已知限制**: ExpansionTile 的 `initiallyExpanded` 在 element 復用時不會重新套用。這正是我們要的行為（保持狀態），但意味著外部 MAP 的值在 element 存活期間只是備份，真正控制的是 ExpansionTile 內部 State。
- **技術債務標記**:
  - [TD-1] MAP 清理機制：對話切換時應清空 MAP（Phase 4 評估）
  - [TD-2] 若未來需要程式化控制展開（如「全部展開/摺疊」按鈕），需改用 `ExpansionTileController`，目前架構不支援

### 7. 語言特定實作注意事項

**Dart/Flutter 考量**:
- `@riverpod` 標注的 family provider 需執行 `dart run build_runner build` 產生 `.g.dart`
- ConsumerWidget 的 `ref.watch` 會在 provider state 變更時觸發重建；但展開操作不需要重建（ExpansionTile 自行處理動畫），所以 `setExpanded` 後的 state emit 不會造成效能問題——因為 ValueKey 確保 element 復用，重建只更新 `initiallyExpanded` 屬性（且此屬性在復用時被忽略）
- ExpansionTile 沒有外部 `isExpanded` 屬性，只有 `initiallyExpanded`（初始值）和 `controller`（ExpansionTileController）。本方案使用 `initiallyExpanded` + ValueKey 復用，是最小改動方案
