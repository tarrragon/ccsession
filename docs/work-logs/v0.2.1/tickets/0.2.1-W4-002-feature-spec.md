# 0.2.1-W4-002 功能規格

## 1. Purpose（目的）

用戶反映 Session List 目前從上到下是舊到新排序，期望最新對話顯示在列表最上方。本功能確保所有專案頁籤中，每個狀態分組（Active / Idle / Completed）內的 session 按 `lastEventAt` 降序排列（最新在最上方）。

**背景調查**：現有程式碼 `groupSessionsByStatus` 已使用 `b.lastEventAt.compareTo(a.lastEventAt)` 做降序排列。若用戶仍感知為「舊到新」，可能原因包括：

1. Go Backend 傳送的 `lastEventAt` 未正確更新（session 有新事件但時間戳未變）
2. `session_status_change` 訊息更新 session 時未更新 `lastEventAt`，導致排序依據過時
3. UI 重建時排序未重新觸發

Phase 2 測試和 Phase 3 實作需優先排查上述根因，再決定修改範圍。

## 2. Scenarios（行為場景）

### 場景 1: 同一狀態組內按最新排序

- **Given**: 專案頁籤下有 3 個 Active session，lastEventAt 分別為 10:00、10:30、10:15
- **When**: 用戶查看 Session List
- **Then**: Active 組內排序為 10:30 -> 10:15 -> 10:00（最新在最上方）

### 場景 2: session 收到新事件後排序更新

- **Given**: Session A (lastEventAt=10:00) 排在 Session B (lastEventAt=10:30) 下方
- **When**: Session A 收到新事件，lastEventAt 更新為 10:45
- **Then**: Session A 排到 Session B 上方（10:45 > 10:30）

### 場景 3: 跨專案頁籤一致行為

- **Given**: 用戶有 2 個專案頁籤，每個頁籤各有多個 session
- **When**: 用戶切換專案頁籤
- **Then**: 每個頁籤的每個狀態組內，session 都按 lastEventAt 降序排列

### 場景 4: 搜尋結果保持排序

- **Given**: 用戶輸入搜尋關鍵字，篩選出多個 session
- **When**: 搜尋結果顯示
- **Then**: 搜尋結果中每個狀態組內仍按 lastEventAt 降序排列

### 場景 5: status 變更後排序正確

- **Given**: Session A 從 Active 變為 Completed
- **When**: UI 更新後
- **Then**: Session A 出現在 Completed 組中，依 lastEventAt 與該組其他 session 正確排序

### 場景 6: 空列表和單一 session

- **Given**: 狀態組只有 0 或 1 個 session
- **When**: 用戶查看 Session List
- **Then**: 正常顯示，無排序錯誤

## 3. Acceptance（驗收條件）

- [ ] 每個狀態分組（Active / Idle / Completed）內，session 按 `lastEventAt` 降序排列（最新在最上方）
- [ ] 排序行為在所有專案頁籤中一致
- [ ] 搜尋篩選後仍維持降序排列
- [ ] session 收到新事件更新 `lastEventAt` 後，排序即時反映變化
- [ ] `session_status_change` 處理不破壞排序（若有更新 lastEventAt 則重新排序）
- [ ] 全量 Flutter 測試通過
- [ ] 全量 Go 測試通過

## 根因調查指引（Phase 2/3 參考）

現有 `groupSessionsByStatus` 排序邏輯看起來正確（降序）。建議 Phase 2 測試階段優先驗證：

1. **Go Backend 排查**：`session_status_change` 訊息是否包含更新的 `lastEventAt`？若不包含，前端 `_handleStatusChange` 只更新 status 不更新時間戳，導致排序依據過時。
2. **前端排查**：`_handleStatusChange` 目前只更新 `session.status`，未更新 `lastEventAt`。這可能是根因 — session 狀態變了但時間戳沒變，排序位置不動。
3. **資料流排查**：`session_list` 全量更新時，Go backend 傳回的 session 列表是否已包含正確的 `lastEventAt`？
