## Phase 1 功能規格設計

### 1. 需求分析

**核心問題**：tool_use_bubble 目前使用 `formatJsonObject()` 將 toolInput 以 JSON pretty-print 顯示（大括號、逗號、引號、縮排），認知負擔高。改為 key-value 列表格式可大幅提升可讀性。

**現有程式碼**：
- `tool_use_bubble.dart` 第 45 行呼叫 `formatJsonObject(toolInput)` 產生 JSON 字串，以 `SelectableText` 顯示
- `json_format_helper.dart` 提供 `formatJsonObject()`（tool_use_bubble 用）和 `formatJsonContent()`（tool_result_bubble 用）
- `_unescapeForDisplay()` 為私有函式，處理 `\\n`, `\\t`, `\\"`, `\\\\` 跳脫字元還原

**toolInput 資料型別**：`Object?`，實際為 `Map<String, dynamic>`（JSON 解析後），值可能是 String、num、bool、List、巢狀 Map

### 2. 介面設計

#### 2.1 新增公開函式：`formatKeyValue`

**檔案**：`json_format_helper.dart`

```dart
/// 需求：[0.2.1-W7-001] 將 Map 格式化為 key-value 列表字串
/// 約束：僅處理頂層 key-value，巢狀物件以單行 JSON 表示
/// 維護：tool_use_bubble 使用此函式取代 formatJsonObject
String formatKeyValue(Object? value)
```

**輸入**：`Object? value` — 與現有 `formatJsonObject` 相同簽名，保持替換相容性
**輸出**：`String` — 格式化後的 key-value 文字

**格式規則**：
- 每個頂層 key 一行：`key: value`
- key 不加引號、不加大括號
- String 值：直接顯示（不加引號），套用 `_unescapeForDisplay` 還原跳脫字元
- num/bool 值：直接 toString
- null 值：顯示 `(empty)`
- 巢狀 Map/List 值：以單行 compact JSON 顯示（`json.encode`），套用 unescape
- 若 value 不是 Map（例如 String 或 List），fallback 為 `formatJsonObject` 行為

**範例**：

輸入 Map：
```json
{"file_path": "/src/main.dart", "command": "echo hello\nworld", "options": {"recursive": true}}
```

輸出：
```
file_path: /src/main.dart
command: echo hello
world
options: {"recursive": true}
```

將 `_unescapeForDisplay` 改為 `unescapeForDisplay`（移除底線前綴），供 `formatKeyValue` 和未來外部使用。現有 `formatJsonContent` 和 `formatJsonObject` 的內部呼叫同步更新。

#### 2.3 tool_use_bubble.dart 修改

第 45 行：`formatJsonObject(toolInput)` 改為 `formatKeyValue(toolInput)`

### 3. 巢狀物件渲染策略

**策略：頂層展開，巢狀保持 compact JSON**

| 層級 | 渲染方式 | 範例 |
|------|---------|------|
| 頂層 key | `key: value` 每行一個 | `file_path: /src/main.dart` |
| 巢狀 Map/List（深度 >= 1） | 單行 compact JSON | `options: {"recursive": true}` |

**理由**：
- Claude Code toolInput 實務上巢狀極少（常見 key 為 file_path, command, content 等扁平結構）
- 單行 compact JSON 在少數巢狀場景仍可讀
- 避免複雜遞迴渲染增加維護成本

### 4. 長文值處理策略

**策略：不截斷，自然換行**

- SelectableText 搭配 monospaceStyle 已支援自動換行（由 Flutter layout 處理）

### 1. 實作策略設計

核心函式 formatKeyValue(value) 虛擬碼：

```
FUNCTION formatKeyValue(value):
  IF value IS null THEN RETURN ""

  // 步驟 1：統一為物件
  IF value IS string THEN
    TRY decoded = JSON_DECODE(value)
    CATCH → RETURN formatJsonObject(value)  // fallback
    SET object = decoded
  ELSE
    SET object = value

  // 步驟 2：檢查是否為 Map
  IF object IS NOT Map THEN
    RETURN formatJsonObject(value)  // fallback（List、數值等）

  // 步驟 3：空 Map
  IF object IS empty THEN RETURN ""

  // 步驟 4：逐 key 格式化
  SET lines = []
  FOR EACH (key, val) IN object:
    IF val IS null THEN
      APPEND "{key}: (empty)"
    ELSE IF val IS Map OR val IS List THEN
      APPEND "{key}: {COMPACT_JSON(val)}"
    ELSE
      SET display = unescapeForDisplay(TO_STRING(val))
      APPEND "{key}: {display}"
  RETURN JOIN(lines, newline)
```

unescapeForDisplay — 僅需將現有 _unescapeForDisplay 改為公開（移除底線前綴）。

### 2. 資料結構選擇

| 結構 | 用途 | 理由 |
|------|------|------|
| Map（字典） | 頂層 key-value 迭代 | 輸入本身就是 Map |
| List（陣列） | 收集格式化行 | 最終 join 為字串 |
| String | 輸出 | 純文字，無需結構化 |

無需額外資料結構。所有操作為簡單的迭代和字串組合。

### 3. 資料流程圖

```

    v
[null 檢查] --null--> 回傳 ""
    |

    |                 |
    |                 +-- 成功 --> object
    |                 +-- 失敗 --> formatJsonObject (fallback)
    |
    +-- Map --> object
    |
    +-- 其他 --> formatJsonObject (fallback)

    |

```

