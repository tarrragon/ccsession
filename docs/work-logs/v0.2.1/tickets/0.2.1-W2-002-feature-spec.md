# 0.2.1-W2-002 功能規格

## 1. Purpose（目的）

Session List 隨使用時間增長，completed session 不斷累積，造成列表冗長、active/idle session 難以快速定位。本功能為三個分組（active/idle/completed）加入分頁機制，並讓 completed 分組預設摺疊，降低視覺雜訊。

目標用戶：所有使用 ccsession monitor 的開發者。
核心價值：在 session 數量增長時維持列表可用性。

## 2. API Signatures（介面定義）

### 2.1 新建：SessionGroupUiState（不可變狀態）

```dart
/// 需求：管理分頁索引和摺疊狀態的 UI 狀態
class SessionGroupUiState extends Equatable {
  const SessionGroupUiState({
    this.currentPages = const {
      SessionStatus.active: 0,
      SessionStatus.idle: 0,
      SessionStatus.completed: 0,
    },
    this.expandedGroups = const {
      SessionStatus.active: true,
      SessionStatus.idle: true,
      SessionStatus.completed: false, // completed 預設摺疊
    },
  });

  /// 每個分組的當前頁碼（從 0 開始）
  final Map<SessionStatus, int> currentPages;

  /// 每個分組的展開/摺疊狀態
  final Map<SessionStatus, bool> expandedGroups;
}
```

### 2.2 新建：SessionGroupUiNotifier（@riverpod Notifier）

```dart
@riverpod
class SessionGroupUiNotifier extends _$SessionGroupUiNotifier {
  @override
  SessionGroupUiState build();

  /// 需求：切換指定分組的頁碼
  /// 約束：pageIndex 必須在有效範圍內（0 <= pageIndex < totalPages）
  void setPage(SessionStatus status, int pageIndex);

  /// 需求：切換指定分組的展開/摺疊狀態
  void toggleExpanded(SessionStatus status);

  /// 需求：重置所有分組的頁碼到第 0 頁
  /// 觸發時機：搜尋條件變化、session 列表資料更新
  void resetAllPages();
}
```

### 2.8 搜尋整合

`SessionListSearchNotifier.updateQuery` 和 `closeSearch` 執行後，需觸發 `SessionGroupUiNotifier.resetAllPages()`。

## 3. GWT Scenarios（行為場景）

### 場景 1: Active 分組分頁顯示

- **Given**: active 分組有 15 筆 session
- **When**: 使用者進入 session list 頁面
- **Then**: active 分組展開，顯示前 10 筆 session 和分頁控制（第 1/2 頁）

### 場景 2: 分頁切換

- **Given**: active 分組有 15 筆 session，目前顯示第 1 頁
- **When**: 使用者點擊「下一頁」
- **Then**: active 分組顯示第 11-15 筆 session，分頁控制更新為第 2/2 頁

### 場景 3: Completed 預設摺疊

- **Given**: completed 分組有 20 筆 session
- **When**: 使用者進入 session list 頁面
- **Then**: completed 分組顯示 header「Completed (20)」但不顯示任何 session tile，header 顯示摺疊圖示

### 場景 4: Completed 展開後分頁

- **Given**: completed 分組有 20 筆 session，目前摺疊
- **When**: 使用者點擊 completed header 展開
- **Then**: completed 分組展開，顯示前 10 筆 session 和分頁控制（第 1/2 頁）

### 場景 5: 分頁切換不影響其他分組

- **Given**: active 分組在第 2 頁，idle 分組展開在第 1 頁
- **When**: 使用者切換 active 分組到第 1 頁
- **Then**: idle 分組仍在第 1 頁，展開狀態不變

### 場景 6: 摺疊/展開不影響其他分組

- **Given**: active 分組展開，completed 分組摺疊
- **When**: 使用者摺疊 active 分組
- **Then**: active 分組摺疊，completed 分組仍然摺疊

### 場景 7: 搜尋重置分頁

- **Given**: active 分組在第 2 頁
- **When**: 使用者輸入搜尋關鍵字
- **Then**: active 分組重置到第 1 頁，顯示篩選後的結果

### 場景 8: 不足一頁時不顯示分頁控制

- **Given**: idle 分組有 5 筆 session
- **When**: 使用者查看 idle 分組
- **Then**: idle 分組顯示全部 5 筆 session，不顯示分頁控制

### 場景 9: 空分組不顯示

- **Given**: idle 分組有 0 筆 session
- **When**: 使用者查看 session list
- **Then**: idle 分組的 header 和分頁控制都不顯示（與現有行為一致，groupSessionsByStatus 已排除空組）

### 場景 10: 資料更新後分頁頁碼安全回退

- **Given**: active 分組有 15 筆 session，使用者在第 2 頁（顯示 11-15 筆）
- **When**: WebSocket 推送更新，active 減少為 8 筆
- **Then**: active 分組頁碼重置到第 1 頁（因第 2 頁已不存在），顯示全部 8 筆

## 4. Error Handling（錯誤處理）

| 錯誤情境 | 處理策略 |
|---------|---------|
| `setPage` 傳入超出範圍的 pageIndex | clamp 到有效範圍 `[0, totalPages - 1]`，不拋出例外 |
| `expandedGroups` 缺少某個 SessionStatus key | 預設為展開（active/idle）或摺疊（completed） |
| `currentPages` 缺少某個 SessionStatus key | 預設為第 0 頁 |
| 資料更新後 currentPage 超出新的 totalPages | 在 `_flattenGroups` 中 clamp pageIndex，確保不越界 |

## 5. Dependencies（依賴）

| 依賴 | 說明 |
|------|------|
| `sessionListNotifierProvider` | 提供 session 資料，SessionGroupUiNotifier 需監聽其變化以重置分頁 |
| `sessionListSearchNotifierProvider` | 搜尋狀態變化時需重置分頁 |
| `groupSessionsByStatus()` | 現有分組邏輯，不修改 |
| Riverpod `@riverpod` code generation | 新 Notifier 需要 `build_runner` |

環境假設：
- 純前端分頁，不需修改 Go Backend
- 摺疊狀態不持久化（記憶體即可，重新開啟 App 會重置）

## 6. Acceptance（驗收條件）

- [ ] active/idle 分組預設展開，各自支援分頁顯示，每頁最多 10 筆
- [ ] completed 分組預設摺疊（header 可見，tile 隱藏）
- [ ] completed 展開後支援分頁顯示，每頁最多 10 筆
- [ ] 分頁切換不影響其他分組的頁碼和展開/摺疊狀態
- [ ] 不足一頁（<= 10 筆）時不顯示分頁控制
- [ ] 搜尋條件變化時所有分組頁碼重置到第 0 頁
- [ ] 資料更新導致 currentPage 超出範圍時安全回退
- [ ] SessionGroupUiNotifier 使用 @riverpod code generation
- [ ] 分頁常數 `maxItemsPerPage = 10` 定義在 SessionListConstants
- [ ] 新增/修改的所有 Widget 和 Notifier 有單元測試
