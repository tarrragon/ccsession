## 1. 實作策略設計

### 根因與修復方向

根因已確認：`session_status_change` 訊息不含 `lastEventAt`，前端 `_handleStatusChange` 只更新 status 不更新時間戳，排序依據過時。

修復方向：在 Go 端將 `lastEventAt` 加入狀態變更訊息，在 Dart 端解析並同步更新。

### 修改清單（4 個檔案）

| 編號 | 層級 | 檔案 | 修改內容 |
|------|------|------|---------|
| M1 | Go Model | `server/websocket_models.go` | `SessionStatusChangeData` 新增 `LastEventAt` 欄位 |
| M2 | Go Server | `server/websocket_server.go` | `broadcastStatusChange` 簽名加入 `lastEventAt`，填充欄位 |
| M3 | Dart Model | `ui/lib/core/models/server_message.dart` | `SessionStatusChangeData` 新增 `lastEventAt` optional 欄位 |
| M4 | Dart UseCase | `ui/lib/features/.../session_list_notifier.dart` | `_handleStatusChange` 同時更新 `lastEventAt` |

## 2. 資料結構選擇

### Go 端 SessionStatusChangeData

```
STRUCTURE SessionStatusChangeData:
  SessionID: string       (json: "sessionId")
  Status: SessionStatus   (json: "status")
  LastEventAt: time       (json: "lastEventAt")  // 新增
```

`LastEventAt` 使用 `time.Time` 非指標型別。Go 的 `time.Time` 零值序列化為 `"0001-01-01T00:00:00Z"`，不會是 null。這可接受，因為 broadcastStatusChange 總是能從 SessionInfo 取得有效時間。

### Dart 端 SessionStatusChangeData

```
STRUCTURE SessionStatusChangeData:
  sessionId: string       (required)
  status: SessionStatus   (required)
  lastEventAt: DateTime?  (optional, nullable)  // 新增
```

使用 nullable `DateTime?` 確保向後相容：舊版 backend 不傳此欄位時為 null，前端保留原值。

## 5. 關鍵實作指引

### 實作順序與並行策略

Go 和 Dart 修改**可並行派發**，理由：

1. 兩端修改互不依賴於對方的程式碼
2. 介面契約已在 Phase 2 明確定義（JSON 欄位名 `lastEventAt`，格式 RFC3339/ISO8601）
3. 各自有獨立的測試驗證（TG-E 驗 Go，TG-A/B/C/D 驗 Dart）
4. 整合驗證在兩端都完成後由 PM 執行 smoke test

### Go 端實作指引（fennel-go-developer）

**第一階段：Model + 序列化（TG-E01）**

1. `websocket_models.go`: `SessionStatusChangeData` 新增 `LastEventAt time.Time` 欄位，JSON tag `"lastEventAt"`
2. 撰寫 TC-E01 測試驗證序列化

**第二階段：Server 邏輯（TG-E03）**

1. `websocket_server.go`: `broadcastStatusChange` 簽名改為 `(sessionID string, status SessionStatus, lastEventAt time.Time)`
2. 呼叫端 (line 357) 改為 `s.broadcastStatusChange(event.Session.ID, event.Session.Status, event.Session.LastEventAt)`
3. 函式內 `SessionStatusChangeData` 建構式加入 `LastEventAt: lastEventAt`
4. 撰寫 TC-E03 測試驗證廣播訊息包含 lastEventAt

### Dart 端實作指引（parsley-flutter-developer）

**第一階段：Model 層（TG-A）**

1. `server_message.dart`: `SessionStatusChangeData` 新增 `final DateTime? lastEventAt` 欄位
2. `fromJson`: 解析 `json['lastEventAt']`，null 安全處理（若欄位不存在或為 null 則為 null）
3. `toJson`: lastEventAt 非 null 時輸出 ISO8601 字串
4. `props`: 加入 lastEventAt
5. 撰寫 TC-A01~A04

**第二階段：UseCase 層（TG-B）**

1. `session_list_notifier.dart`: `_handleStatusChange` 修改 copyWith 呼叫
2. 若 `data.lastEventAt != null`，同時更新 status 和 lastEventAt
3. 若 `data.lastEventAt == null`，只更新 status（保留原值）
4. 撰寫 TC-B01~B05

**第三階段：排序驗證（TG-C, TG-D）**

1. 補強 `groupSessionsByStatus` 測試（TC-C01~C04）— 排序邏輯本身不需修改
2. 補強搜尋結果排序測試（TC-D01~D02）— 篩選邏輯本身不需修改

## 7. 語言特定實作注意事項

### Go 考量

- `time.Time` JSON 序列化預設為 RFC3339 格式，與 Dart 的 `DateTime.parse` 相容
- `broadcastStatusChange` 簽名變更需同時更新唯一呼叫端（line 357）

### Dart 考量

- `DateTime.parse` 可解析 RFC3339/ISO8601，與 Go 端相容
- `copyWith` 需確認 `SessionInfo` 已支援 `lastEventAt` 參數（既有，無需新增）
- `Equatable` 的 `props` 需加入 `lastEventAt`，否則狀態比對可能失效
