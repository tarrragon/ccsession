## Problem Analysis

### 問題根因

**直接原因**：`server/jsonl_parser.go:28-33` 的 `conversationLineTypes` map 包含 `"human"` 但不包含 `"user"`。Claude Code JSONL 實際輸出的頂層 type 為 `"user"`（見 `docs/spec.md:107`）。

在 `jsonl_parser.go:61`，`if !conversationLineTypes[lineType]` 對 type="user" 的記錄回傳 `nil, nil`，導致所有使用者訊息被靜默丟棄。

`server/constants.go:7` 已定義 `EventTypeUser = "user"` 常數，但 `conversationLineTypes` 未使用此常數，硬編碼了過時的 `"human"` 字串。

**根因分類**：硬編碼字串與實際資料格式不一致（quality-common 1.3.1 違規）。

### 影響範圍

| 檔案 | 影響 | 修改需求 |
|------|------|---------|
| `server/jsonl_parser.go:28-33` | conversationLineTypes 缺少 "user" | 加入 `EventTypeUser: true`，評估是否保留 `"human"` 向後相容 |
| `server/jsonl_parser.go:28-33` | 硬編碼字串而非使用常數 | 改用 `constants.go` 常數 |
| `server/jsonl_parser_test.go` | 缺少 type="user" 測試案例 | 補充測試 |
| Flutter 前端 | **不受影響** | `MessageBubbleFactory` 已正確處理 "user" type |

### 相關 Error Pattern

無直接匹配。屬 quality-common.md 1.3.1 硬編碼字串問題。

### 調查過程

- `server/constants.go:7` — `EventTypeUser = "user"` 已定義但未被 conversationLineTypes 使用
- `server/jsonl_parser.go:28` — map 使用字面值 `"human"` 而非常數
- `server/jsonl_parser.go:61` — 過濾邏輯：type 不在 map 中回傳 nil
- `docs/spec.md:107` — 規格定義頂層 type 為 `"user|assistant"`
