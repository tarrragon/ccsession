# 0.2.1-W1-002 功能規格

## 1. Purpose（目的）

Claude Code 的 assistant 回覆大量使用 Markdown 格式（表格、程式碼區塊、清單、粗體等），目前 AssistantMessageBubble 和 ThinkingBubble 以純 Text Widget 顯示，導致格式資訊完全丟失，嚴重影響可讀性。本功能將這兩個 Bubble 的文字渲染從純文字替換為 flutter_markdown 渲染，讓 Markdown 內容以正確格式呈現。

---

## 2. Scenarios（行為場景）

### 場景 1: 基本 Markdown 格式渲染

- **Given**: assistant 訊息內容包含 Markdown 格式（粗體 `**text**`、斜體 `*text*`、標題 `# heading`、清單 `- item`、連結 `[text](url)`）
- **When**: ConversationView 顯示該訊息
- **Then**: 各 Markdown 元素以對應視覺樣式渲染（粗體加粗、斜體傾斜、標題放大、清單帶符號、連結可點擊或至少有視覺區分）

### 場景 2: Markdown 表格渲染

- **Given**: assistant 訊息內容包含 Markdown 表格（`| col1 | col2 |` 格式）
- **When**: ConversationView 顯示該訊息
- **Then**: 表格以結構化表格形式渲染，欄位對齊，表頭與內容有視覺區分

### 場景 3: 程式碼區塊渲染

- **Given**: assistant 訊息內容包含程式碼區塊（`` ```language ... ``` `` 或行內 `` `code` ``）
- **When**: ConversationView 顯示該訊息
- **Then**: 程式碼區塊以等寬字體（ConversationConstants.monospaceStyle）顯示，與周圍文字有視覺區分（背景色或邊框）；行內程式碼同樣以等寬字體顯示

### 場景 4: Thinking Bubble Markdown 渲染

- **Given**: thinking 事件的文字內容包含 Markdown 格式
- **When**: 使用者展開 ThinkingBubble
- **Then**: Markdown 內容以對應格式渲染，同時保持斜體基調風格

### 場景 5: 搜尋高亮啟用時 Markdown 訊息不 crash

- **Given**: 搜尋功能啟用，搜尋關鍵字匹配到某個 assistant Markdown 訊息
- **When**: 該訊息在 ConversationView 中顯示
- **Then**: 應用程式不 crash；Markdown 訊息中的搜尋高亮降級為不高亮（仍以 Markdown 格式渲染，但不標記匹配位置）

### 場景 6: 純文字 assistant 訊息

- **Given**: assistant 訊息內容為純文字，不含任何 Markdown 語法
- **When**: ConversationView 顯示該訊息
- **Then**: 顯示效果與改版前一致，無視覺退化

### 場景 7: 空內容或極短內容

- **Given**: assistant 訊息內容為空字串或僅含空白字元
- **When**: ConversationView 顯示該訊息
- **Then**: 不 crash，顯示空白或不顯示（與現有行為一致）

### 場景 8: 超長 Markdown 內容

- **Given**: assistant 訊息包含大量 Markdown 內容（例如數百行程式碼區塊或大型表格）
- **When**: ConversationView 顯示該訊息
- **Then**: 正常渲染不 crash，Bubble 高度隨內容自適應，列表可正常捲動

## 3. API / 介面變更定義

### 3.1 新增依賴

**檔案**: `ui/pubspec.yaml`

```yaml
dependencies:
  flutter_markdown: ^0.7.6  # 版本以實際最新穩定版為準
```

### 3.2 修改: AssistantMessageBubble

**檔案**: `ui/lib/features/conversation/presentation/widgets/assistant_message_bubble.dart`

**變更類型**: 修改（內部渲染邏輯替換）

**公開介面不變**：建構子簽名 `(event, highlightRanges, key)` 維持不動。

**內部變更**：

- `build()` 方法中，將 `buildHighlightableText(...)` 呼叫替換為條件分支：
  - 若 `highlightRanges` 為 null 或為空 → 使用 `MarkdownBody` Widget 渲染 `event.content.text`
  - 若 `highlightRanges` 非空 → 降級為現有純文字高亮渲染（即保留現有 `buildHighlightableText` 呼叫）
- `MarkdownBody` 配置：
  - `data`: `event.content.text`
  - `selectable`: `true`（允許複製）
  - `styleSheet`: 自訂 MarkdownStyleSheet，程式碼區塊引用 `ConversationConstants.monospaceStyle`
  - `shrinkWrap`: `true`（Bubble 內容自適應）

### 3.3 修改: ThinkingBubble

**檔案**: `ui/lib/features/conversation/presentation/widgets/thinking_bubble.dart`

**變更類型**: 修改（`_buildThinkingContent` 內部邏輯替換）

**公開介面不變**。

**內部變更**：

- `_buildThinkingContent()` 中：
  - 若無高亮範圍 → 使用 `MarkdownBody` 渲染，styleSheet 額外套用斜體基調
  - 若有高亮範圍 → 降級為現有 RichText 高亮渲染

### 3.4 不修改的檔案

| 檔案 | 原因 |
|------|------|
| MessageBubbleFactory | 只做 type → Widget 路由，不涉及渲染邏輯 |
| search_highlight_utils.dart | 高亮工具函式不變，降級時仍然使用 |
| UserMessageBubble | 使用者訊息不含 Markdown |
| ToolUseBubble / ToolResultBubble | 本次範圍外 |
| ConversationConstants | 現有 monospaceStyle 直接引用，無需新增常數 |

### 3.5 新增: MarkdownStyleSheet 建構輔助（建議）

可在 AssistantMessageBubble 或獨立工具檔案中建立一個輔助函式：

```dart
/// 建構 Bubble 用的 MarkdownStyleSheet，程式碼區塊使用 monospace 字體
MarkdownStyleSheet buildBubbleMarkdownStyleSheet(ThemeData theme) {
  return MarkdownStyleSheet.fromTheme(theme).copyWith(
    codeblockDecoration: BoxDecoration(
      color: theme.colorScheme.surfaceContainerHigh,
      borderRadius: BorderRadius.circular(4),
    ),
    code: ConversationConstants.monospaceStyle.copyWith(
      backgroundColor: theme.colorScheme.surfaceContainerHigh,
    ),
    // 表格邊框
    tableBorder: TableBorder.all(
      color: theme.colorScheme.outline.withValues(alpha: 0.3),
    ),
  );
}
```

是否獨立為檔案由 Phase 3b 實作者決定。此處定義行為契約，不規定檔案結構。

## 5. 搜尋高亮降級策略說明

**策略 A 行為定義**（SA 結論 2）：

| 狀態 | 渲染方式 | 搜尋高亮 |
|------|---------|---------|
| 無搜尋關鍵字 | MarkdownBody | 不適用 |
| 有搜尋關鍵字，此 Bubble 無匹配 | MarkdownBody | 不適用 |
| 有搜尋關鍵字，此 Bubble 有匹配 | 降級為純文字 + 高亮 | 使用現有 buildHighlightableText |

**判斷條件**：`highlightRanges != null && highlightRanges!.isNotEmpty`（過濾後的 field-specific ranges）

後續若需在 Markdown 內整合高亮，建立獨立 Ticket 處理。
