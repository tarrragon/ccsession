## Phase 1 功能規格設計

### 根因分析

#### 問題核心
ToolUseBubble 和 ToolResultBubble 都是 StatelessWidget，內部使用 ExpansionTile（自帶內部 StatefulWidget 狀態）。當 Riverpod conversationNotifierProvider 因新訊息觸發 state 變更時，ListView.builder 重建所有可見 item，ExpansionTile 的內部展開狀態隨之丟失。

#### 三層原因
1. 無穩定 Key：MessageBubbleFactory.build() 未給 bubble widget 設定 ValueKey，Flutter 無法識別已存在的 widget
2. StatelessWidget 無法保持狀態：ToolUseBubble/ToolResultBubble 是 StatelessWidget，ExpansionTile 的展開狀態完全依賴內部 State，widget 重建即狀態歸零
3. 列表反轉索引計算：conversation_view.dart L202 使用 events.length - 1 - index 反轉顯示順序，新訊息加入後同一 event 的 index 改變，進一步破壞 Flutter 的 element 復用

#### 可用唯一識別符
SessionEvent 具有 messageId (String) + contentIndex (int)，組合為穩定唯一 key

### 設計方案：ValueKey + 外部展開狀態管理

1. 為每個 bubble 加上穩定 ValueKey（messageId_contentIndex）
2. 新增 ExpansionStateNotifier（Riverpod family provider，key=panelIndex），維護 Map<String, bool>
3. ToolUseBubble/ToolResultBubble 改為 ConsumerWidget，從 provider 讀寫展開狀態
4. MessageBubbleFactory.build() 新增 panelIndex 參數
5. conversation_view.dart 傳入 panelIndex

### API 介面
- ExpansionStateNotifier: build(int panelIndex) => {}; setExpanded(String eventKey, bool isExpanded); bool isExpanded(String eventKey)
- ToolUseBubble: 新增 required int panelIndex
- ToolResultBubble: 新增 required int panelIndex
- MessageBubbleFactory.build: 新增 required int panelIndex

### 驗收場景（Given-When-Then）
1. 展開的氣泡在新訊息到達後保持展開
2. 手動摺疊的氣泡在刷新後維持摺疊
3. 新氣泡預設為摺疊
4. 非用戶操作的刷新不改變任何展開狀態
5. 多面板展開狀態互相隔離
6. flutter test 全部通過
