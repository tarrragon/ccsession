# 0.2.1-W4-002 Phase 2 測試設計

## 測試策略概述

### 根因確認

經程式碼分析確認根因：

1. **Go Backend** `broadcastStatusChange()` (websocket_server.go:418) 只傳送 `sessionId` + `status`，不含 `lastEventAt`
2. **Dart Frontend** `_handleStatusChange()` (session_list_notifier.dart:115) 只做 `session.copyWith(status: data.status)`，未更新 `lastEventAt`
3. **排序邏輯本身正確**：`groupSessionsByStatus` 已用 `b.lastEventAt.compareTo(a.lastEventAt)` 降序排列

### 修改範圍

| 層級 | 檔案 | 修改內容 |
|------|------|---------|
| Go Backend | `websocket_models.go` | `SessionStatusChangeData` 新增 `LastEventAt` 欄位 |
| Go Backend | `websocket_server.go` | `broadcastStatusChange` 傳入並填充 `lastEventAt` |
| Dart Frontend | `server_message.dart` | `SessionStatusChangeData` 新增 `lastEventAt` 欄位 |
| Dart Frontend | `session_list_notifier.dart` | `_handleStatusChange` 同時更新 `lastEventAt` |

### 測試分層決策

| 層級 | 測試類型 | 理由 |
|------|---------|------|
| `groupSessionsByStatus` (純函式) | 單元測試 | Layer 5 純邏輯，已有測試，補充排序驗證 |
| `SessionListNotifier._handleStatusChange` (UseCase) | BDD 測試 | Layer 3 UseCase，驗證狀態變更後排序行為 |
| `SessionStatusChangeData` (Model) | 單元測試 | 序列化/反序列化新增欄位 |
| Go `SessionStatusChangeData` (Model) | 單元測試 | JSON 序列化包含 lastEventAt |
| Go `broadcastStatusChange` (Server) | 整合測試 | 驗證廣播訊息包含 lastEventAt |

### Mock 策略

| 依賴 | 策略 | 理由 |
|------|------|------|
| `WebSocketService` | Mock | 外部依賴（網路層） |
| `SessionInfo` | 不 Mock | Domain Entity，使用 `createTestSession` 工廠 |
| `ServerMessage` | 不 Mock | Value Object |

### TG-W4-002-B: _handleStatusChange 同時更新 lastEventAt（BDD 測試）

**功能職責**：UseCase 層行為，核心修復邏輯。
**跨群組依賴**：依賴 TG-A（SessionStatusChangeData 格式）。
**測試檔案**：擴充 `session_list_notifier_test.dart`

#### TC-B01: status 變更同時更新 lastEventAt — 正常流程

```
Given: session 列表已載入，Session A (active, lastEventAt=10:00)、Session B (active, lastEventAt=10:30)
Then（前置驗證）: Session A 排在 Session B 下方（10:00 < 10:30）
When: 收到 session_status_change 訊息：sessionId=A, status=idle, lastEventAt=10:45
Then: Session A 的 status 更新為 idle
Then: Session A 的 lastEventAt 更新為 10:45
```

#### TC-B02: status 變更後排序即時反映 — 根因驗證場景（場景 2）

```
Given: session 列表已載入：
  - Session A (active, lastEventAt=10:00)
  - Session B (active, lastEventAt=10:30)
Then（前置驗證）: groupedSessions 中 Active 組排序為 [B, A]
When: 收到 session_status_change：sessionId=A, status=active, lastEventAt=10:45
Then: groupedSessions 中 Active 組排序變為 [A, B]（10:45 > 10:30）
```

#### TC-B03: status 變更不含 lastEventAt 時保留原值（向後相容）

```
Given: session 列表已載入，Session A (active, lastEventAt=10:00)
When: 收到 session_status_change：sessionId=A, status=idle, lastEventAt=null（舊版 backend）
Then: Session A 的 status 更新為 idle
Then: Session A 的 lastEventAt 仍為 10:00（不變）
```

#### TC-B04: 未知 sessionId 的 status 變更含 lastEventAt — 靜默忽略

```
Given: session 列表已載入，只有 Session A
When: 收到 session_status_change：sessionId=unknown, status=idle, lastEventAt=10:45
Then: session 列表不變，無錯誤
```

#### TC-B05: status 變更跨組後排序正確（場景 5）

```
Given: session 列表已載入：
  - Session A (active, lastEventAt=10:00)
  - Session C (completed, lastEventAt=09:00)
  - Session D (completed, lastEventAt=09:30)
Then（前置驗證）: Completed 組排序為 [D, C]
When: 收到 session_status_change：sessionId=A, status=completed, lastEventAt=10:45
Then: Session A 出現在 Completed 組
Then: Completed 組排序為 [A, D, C]（10:45 > 09:30 > 09:00）
Then: Active 組不含 Session A
```

## 行為鏈式推演

### 推演 1：status 變更後排序更新（核心修復鏈）

```
A: Go Backend 偵測到 session 狀態變更
  → B: broadcastStatusChange 發送包含 lastEventAt 的訊息
    → C: Dart _handleStatusChange 解析 lastEventAt
      → D: session.copyWith(status: ..., lastEventAt: ...) 更新兩個欄位
        → E: groupSessionsByStatus 重新排序，位置正確
```

**四維度分支**：

| 維度 | 場景 | 覆蓋測試 |
|------|------|---------|
| 正常流程 | lastEventAt 更新後排序變化 | TC-B01, TC-B02 |
| 異常流程 | 未知 sessionId | TC-B04 |
| 邊界條件 | lastEventAt 為 null（舊版 backend） | TC-B03 |
| 中斷操作 | 不適用（非互動式操作） | N/A |

### 推演 2：搜尋結果排序

```
A: 使用者輸入搜尋關鍵字
  → B: _filterByQuery 篩選匹配 session
    → C: groupSessionsByStatus 對篩選結果排序
```

**四維度分支**：

| 維度 | 場景 | 覆蓋測試 |
|------|------|---------|
| 正常流程 | 篩選結果內降序排列 | TC-D01 |
| 異常流程 | 不適用 |  |
| 邊界條件 | 搜尋結果為空 | TC-D02 |
| 中斷操作 | 不適用 | |

### 推演 3：跨組遷移排序

```
A: Session 從 Active 變為 Completed
  → B: _handleStatusChange 更新 status + lastEventAt
    → C: groupSessionsByStatus 將 session 分到新組
      → D: 新組內按 lastEventAt 降序排列
```

**四維度分支**：

| 維度 | 場景 | 覆蓋測試 |
|------|------|---------|
| 正常流程 | 遷移後在新組中正確排序 | TC-B05 |
| 異常流程 | 不適用 | |
| 邊界條件 | 目標組原本為空 | 已由 TC-10-09 覆蓋空組排除 |
| 中斷操作 | 不適用 | |
