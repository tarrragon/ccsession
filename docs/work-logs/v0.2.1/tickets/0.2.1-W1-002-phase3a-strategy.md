## 1. 實作策略設計

### 核心變更摘要

三個獨立修改點，無相互依賴：

| 修改點 | 目前行為 | 目標行為 |
|--------|---------|---------|
| AssistantMessageBubble.build() | 一律呼叫 buildHighlightableText | 條件分支：無高亮 → MarkdownBody；有高亮 → buildHighlightableText |
| ThinkingBubble._buildThinkingContent() | 無高亮 → Text；有高亮 → RichText | 無高亮 → MarkdownBody（斜體基調）；有高亮 → RichText（不變） |
| buildBubbleMarkdownStyleSheet() | 不存在 | 新增純函式：ThemeData → MarkdownStyleSheet |

### 虛擬碼

#### A. buildBubbleMarkdownStyleSheet（純函式）

```
FUNCTION buildBubbleMarkdownStyleSheet(theme):
    baseSheet = MarkdownStyleSheet.fromTheme(theme)
    RETURN baseSheet.copyWith(
        code = monospaceStyle + surfaceContainerHigh 背景,
        codeblockDecoration = BoxDecoration(surfaceContainerHigh 背景, 圓角 4),
        tableBorder = 全邊框(outline 色, alpha 0.3)
    )
```

#### B. AssistantMessageBubble.build() 修改

```
FUNCTION build(context):
    theme = 取得主題

    // 判斷是否需要搜尋高亮降級
    hasHighlight = (highlightRanges != null AND highlightRanges.isNotEmpty)

    IF hasHighlight:
        content = buildHighlightableText(原有邏輯不變)
    ELSE:
        content = MarkdownBody(
            data = event.content.text,
            selectable = true,
            shrinkWrap = true,
            styleSheet = buildBubbleMarkdownStyleSheet(theme)
        )

    RETURN Align(centerLeft,
        Container(
            margin = bubbleMargin,       // 不變
            padding = bubbleContentPadding, // 不變
            decoration = 原有裝飾不變,
            child = content
        )
    )
```

#### C. ThinkingBubble._buildThinkingContent() 修改

```
FUNCTION _buildThinkingContent():
    ranges = filterRangesByField(highlightRanges, fieldText)

    IF ranges == null OR ranges.isEmpty:
        // 原本是 Text(斜體)，改為 MarkdownBody(斜體基調)
        thinkingSheet = buildBubbleMarkdownStyleSheet(theme).copyWith(
            p = 斜體樣式  // 段落預設斜體
        )
        RETURN MarkdownBody(
            data = event.content.text,
            selectable = true,
            shrinkWrap = true,
            styleSheet = thinkingSheet
        )
    ELSE:
        // 降級路徑：完全不變
        RETURN RichText(原有邏輯)
```

## 2. 資料結構選擇

| 資料結構 | 選擇 | 理由 |
|---------|------|------|
| 降級判斷條件 | highlightRanges != null && isNotEmpty | 與功能規格第 5 節一致 |
| MarkdownStyleSheet | fromTheme + copyWith | 繼承主題樣式，只覆寫需要的屬性 |
| 斜體基調 | styleSheet.p 設定 fontStyle.italic | ThinkingBubble 的段落文字需保持斜體 |

無需新增資料模型。所有輸入輸出介面不變。

## 7. 語言特定實作注意事項

### Flutter/Dart 考量

- **ThinkingBubble context 傳遞**: `_buildThinkingContent()` 目前不接收 context/theme，改用 MarkdownBody 後需要 ThemeData 來建構 styleSheet。兩種方案：(a) 傳入 context/theme 作為參數；(b) 改為 Builder pattern 在 build() 中直接建構。Phase 3b 選擇。
- **MarkdownBody vs Markdown**: flutter_markdown 提供兩個 Widget：`Markdown`（含內建 scrolling）和 `MarkdownBody`（不含 scrolling，適合嵌入 ListView）。本案使用 MarkdownBody（shrinkWrap），因 Bubble 已在外層 ListView 中。
- **selectable 屬性**: MarkdownBody 的 selectable 參數啟用文字選取複製功能。
