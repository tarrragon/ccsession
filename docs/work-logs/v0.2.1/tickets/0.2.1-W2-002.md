## Problem Analysis

### 問題根因

completed session 隨使用時間不斷累積，全部顯示在 ListView 中造成列表冗長，active/idle session 難以快速定位。當任一分組 session 數量超過 10 筆時，缺乏分頁瀏覽機制。

### 影響範圍

- session_list_page.dart：修改 _flattenGroups 加入分頁/摺疊邏輯；sealed class 新增 _PaginationItem；_SessionGroupListView 改為 ConsumerWidget
- session_group_header.dart：新增 isExpanded + onToggleExpand 參數
- 新建 session_group_ui_notifier.dart：管理分頁索引和摺疊狀態的 Riverpod Notifier
- 新建 pagination_controls.dart：分頁控制 Widget
- session_list_constants.dart：新增 maxItemsPerPage = 10 常數
- session_list_search_notifier.dart：搜尋變化時觸發分頁重置

### 相關 Error Pattern

無直接相關的已知錯誤模式。需注意 IMP-035（多模式函式 Guard Clause 防護）—— _flattenGroups 將同時處理摺疊和展開兩種模式。

### Phase 1 功能規格

完整功能規格已產出至 0.2.1-W2-002-feature-spec.md（Full 模式 6 區段）。

### 設計決策摘要

1. 純前端分頁，不修改 Go Backend
2. 新建 SessionGroupUiNotifier（@riverpod Notifier）管理分頁索引 + 摺疊狀態
3. 狀態結構：Map<SessionStatus, int> currentPages + Map<SessionStatus, bool> expandedGroups
4. 預設值：active=展開, idle=展開, completed=摺疊
5. 摺疊狀態不持久化（記憶體即可）
6. 分頁常數 maxItemsPerPage = 10 定義在 SessionListConstants
7. 搜尋/資料更新時重置分頁到第 0 頁
8. _flattenGroups 擴充為接收 SessionGroupUiState，決定是否展開和分頁裁切
9. sealed class _ListItem 新增 _PaginationItem 子類
10. SessionGroupHeader 新增 isExpanded + onToggleExpand 參數
11. 新建 PaginationControls Widget 處理分頁 UI
