## 2. 測試案例設計

### TG-20: SessionGroupUiNotifier 單元測試

**功能職責**：管理分頁索引和摺疊狀態的純狀態邏輯。
**跨群組依賴**：無（獨立狀態管理，不依賴其他測試群組）。

#### TC-20-01: 初始狀態 — 預設值

- **Given**: SessionGroupUiNotifier 初始化完成
- **Then（前置驗證）**: state 不為 null
- **Then**: currentPages 為 {active: 0, idle: 0, completed: 0}
- **Then**: expandedGroups 為 {active: true, idle: true, completed: false}

#### TC-20-02: setPage — 正常設定頁碼

- **Given**: Notifier 已初始化，active 分組在第 0 頁
- **Then（前置驗證）**: state.currentPages[SessionStatus.active] == 0
- **When**: 呼叫 setPage(SessionStatus.active, 1)
- **Then**: state.currentPages[SessionStatus.active] == 1
- **Then**: idle 和 completed 的頁碼不變（仍為 0）

#### TC-20-03: setPage — 負數頁碼 clamp 到 0

- **Given**: Notifier 已初始化
- **When**: 呼叫 setPage(SessionStatus.active, -1)
- **Then**: state.currentPages[SessionStatus.active] == 0

#### TC-20-04: toggleExpanded — 展開變摺疊

- **Given**: Notifier 已初始化，active 分組為展開狀態
- **Then（前置驗證）**: state.expandedGroups[SessionStatus.active] == true
- **When**: 呼叫 toggleExpanded(SessionStatus.active)
- **Then**: state.expandedGroups[SessionStatus.active] == false

#### TC-20-05: toggleExpanded — 摺疊變展開

- **Given**: Notifier 已初始化，completed 分組為摺疊狀態
- **Then（前置驗證）**: state.expandedGroups[SessionStatus.completed] == false
- **When**: 呼叫 toggleExpanded(SessionStatus.completed)
- **Then**: state.expandedGroups[SessionStatus.completed] == true

#### TC-20-06: toggleExpanded — 不影響其他分組

- **Given**: Notifier 已初始化，active 展開，completed 摺疊
- **When**: 呼叫 toggleExpanded(SessionStatus.active)
- **Then**: active 變摺疊，completed 仍摺疊，idle 仍展開

#### TC-20-07: resetAllPages — 所有頁碼歸零

- **Given**: Notifier 已初始化，active 設定為第 2 頁，idle 設定為第 1 頁
- **Then（前置驗證）**: state.currentPages[SessionStatus.active] == 2
- **When**: 呼叫 resetAllPages()
- **Then**: 所有分組的 currentPages 值均為 0
- **Then**: expandedGroups 不受影響

#### TC-20-08: setPage — 不影響展開/摺疊狀態

- **Given**: Notifier 已初始化，completed 分組摺疊
- **When**: 呼叫 setPage(SessionStatus.completed, 1)
- **Then**: completed 頁碼變為 1，但 expandedGroups[completed] 仍為 false

### TG-21: _flattenGroups 分頁/摺疊邏輯 單元測試

**功能職責**：將分組資料根據 UI 狀態轉換為 _ListItem 列表（含分頁裁切和摺疊處理）。
**跨群組依賴**：依賴 SessionGroupUiState 結構（TG-20 的產出物），但透過直接建構 Value Object，不需要 TG-20 先執行。

> 注意：_flattenGroups 為 private 函式。測試策略選項：(1) 透過 Widget 測試間接驗證，或 (2) 使用 @visibleForTesting 標注。建議 Phase 3a 決定。

#### TC-21-01: 展開分組 — 不足一頁不產生 PaginationItem

- **Given**: active 分組有 5 筆 session，UI 狀態 active 展開、頁碼 0
- **Then（前置驗證）**: 輸入的 grouped map 中 active 有 5 筆
- **When**: 呼叫 _flattenGroups(grouped, uiState)
- **Then**: 結果包含 1 個 _HeaderItem(active, 5) + 5 個 _SessionItem
- **Then**: 結果不包含 _PaginationItem

#### TC-21-02: 展開分組 — 超過一頁產生 PaginationItem（第 1 頁）

- **Given**: active 分組有 15 筆 session，UI 狀態 active 展開、頁碼 0
- **When**: 呼叫 _flattenGroups(grouped, uiState)
- **Then**: 結果包含 1 個 _HeaderItem + 10 個 _SessionItem + 1 個 _PaginationItem(currentPage: 0, totalPages: 2)

#### TC-21-03: 展開分組 — 第 2 頁顯示剩餘項目

- **Given**: active 分組有 15 筆 session，UI 狀態 active 展開、頁碼 1
- **When**: 呼叫 _flattenGroups(grouped, uiState)
- **Then**: 結果包含 1 個 _HeaderItem + 5 個 _SessionItem + 1 個 _PaginationItem(currentPage: 1, totalPages: 2)

#### TC-21-04: 摺疊分組 — 只產生 Header，無 Session 和 Pagination

- **Given**: completed 分組有 20 筆 session，UI 狀態 completed 摺疊
- **When**: 呼叫 _flattenGroups(grouped, uiState)
- **Then**: completed 部分只有 1 個 _HeaderItem(completed, 20)
- **Then**: 無 _SessionItem 和 _PaginationItem

#### TC-21-05: 頁碼超出範圍 — clamp 到最後一頁

- **Given**: active 分組有 15 筆 session，UI 狀態 active 展開、頁碼 5（超出有效範圍）
- **When**: 呼叫 _flattenGroups(grouped, uiState)
- **Then**: 結果等同於頁碼 1（最後一頁），顯示第 11-15 筆

#### TC-21-06: 多分組混合 — 各分組獨立分頁

- **Given**: active 有 15 筆（頁碼 1）、idle 有 5 筆（頁碼 0）、completed 有 20 筆（摺疊）
- **When**: 呼叫 _flattenGroups(grouped, uiState)
- **Then**: active 部分顯示第 11-15 筆 + PaginationItem
- **Then**: idle 部分顯示全部 5 筆，無 PaginationItem
- **Then**: completed 部分只有 HeaderItem

#### TC-21-07: 恰好 10 筆 — 不產生 PaginationItem

- **Given**: active 分組恰好有 10 筆 session
- **When**: 呼叫 _flattenGroups(grouped, uiState)
- **Then**: 結果包含 10 個 _SessionItem，無 _PaginationItem

#### TC-21-08: 恰好 11 筆 — 產生 2 頁

- **Given**: active 分組有 11 筆 session，頁碼 0
- **When**: 呼叫 _flattenGroups(grouped, uiState)
- **Then**: 結果包含 10 個 _SessionItem + _PaginationItem(currentPage: 0, totalPages: 2)

#### TC-21-09: 恰好 20 筆 — 第 2 頁恰好滿頁

- **Given**: active 分組有 20 筆 session，頁碼 1
- **When**: 呼叫 _flattenGroups(grouped, uiState)
- **Then**: 結果包含 10 個 _SessionItem + _PaginationItem(currentPage: 1, totalPages: 2)

### TG-22: PaginationControls Widget 測試

**功能職責**：分頁控制 UI 渲染和互動回呼。
**跨群組依賴**：無（純 UI 元件，透過 callback 與外部溝通）。

#### TC-22-01: 顯示頁碼資訊

- **Given**: currentPage=0, totalPages=3
- **Then（前置驗證）**: Widget 已渲染
- **Then**: 顯示「1 / 3」頁碼文字

#### TC-22-02: 第一頁 — 上一頁按鈕禁用

- **Given**: currentPage=0, totalPages=3
- **Then（前置驗證）**: 上一頁按鈕存在
- **Then**: 上一頁按鈕禁用（onPressed 為 null）
- **Then**: 下一頁按鈕啟用

#### TC-22-03: 最後一頁 — 下一頁按鈕禁用

- **Given**: currentPage=2, totalPages=3
- **Then**: 下一頁按鈕禁用
- **Then**: 上一頁按鈕啟用

#### TC-22-04: 中間頁 — 兩個按鈕皆啟用

- **Given**: currentPage=1, totalPages=3
- **Then**: 上一頁和下一頁按鈕皆啟用

#### TC-22-05: 點擊下一頁 — 觸發 onPageChanged

- **Given**: currentPage=0, totalPages=3，onPageChanged 已註冊
- **Then（前置驗證）**: 下一頁按鈕存在且啟用
- **When**: 點擊下一頁按鈕
- **Then**: onPageChanged 被呼叫，參數為 1

#### TC-22-06: 點擊上一頁 — 觸發 onPageChanged

- **Given**: currentPage=2, totalPages=3，onPageChanged 已註冊
- **When**: 點擊上一頁按鈕
- **Then**: onPageChanged 被呼叫，參數為 1

#### TC-22-07: 僅一頁 — 不應被渲染

- **Given**: totalPages=1
- **Then**: PaginationControls 不應出現在 _flattenGroups 結果中（由 TG-21 保證）
- **備註**：此案例由 TG-21-01 覆蓋，PaginationControls 本身不需處理 totalPages=1

### TG-12（擴充）: SessionListPage 整合測試

**功能職責**：端對端使用者流程——分頁、摺疊、搜尋重置的完整互動。
**跨群組依賴**：間接依賴 TG-20（Notifier 行為）和 TG-22（PaginationControls 渲染），但透過真實 Widget 樹整合驗證，不需要其他測試群組先通過。

#### TC-12-10: Completed 預設摺疊 — 只顯示 Header

- **Given**: 透過 WebSocket 推送 session_list，包含 3 個 active + 5 個 completed
- **Then（前置驗證）**: 頁面已渲染，「Active (3)」Header 可見
- **Then**: 「Completed (5)」Header 可見
- **Then**: completed session 的 tile 不可見（被摺疊）

#### TC-12-11: 點擊 Completed Header — 展開顯示 session

- **Given**: 同 TC-12-10，completed 分組摺疊
- **Then（前置驗證）**: completed session tile 不可見
- **When**: 點擊「Completed (5)」Header
- **Then**: completed session 的 tile 全部可見（5 筆，不足一頁，無分頁控制）

#### TC-12-12: 分頁顯示 — 超過 10 筆顯示分頁控制

- **Given**: 透過 WebSocket 推送 15 筆 active session
- **Then（前置驗證）**: 「Active (15)」Header 可見
- **Then**: 顯示 10 筆 active session tile
- **Then**: 分頁控制可見，顯示「1 / 2」

#### TC-12-13: 分頁切換 — 點擊下一頁

- **Given**: 同 TC-12-12，顯示第 1 頁
- **Then（前置驗證）**: 分頁控制存在
- **When**: 點擊下一頁按鈕
- **Then**: 顯示第 11-15 筆 session tile
- **Then**: 分頁控制更新為「2 / 2」

#### TC-12-14: 搜尋重置分頁

- **Given**: active 分組有 15 筆 session，使用者在第 2 頁
- **Then（前置驗證）**: 分頁顯示「2 / 2」
- **When**: 使用者啟動搜尋並輸入關鍵字
- **Then**: 分頁重置到第 1 頁

#### TC-12-15: 分頁切換不影響其他分組

- **Given**: active 有 15 筆（第 1 頁），idle 有 12 筆（第 1 頁）
- **When**: 在 active 分組點擊下一頁
- **Then**: active 顯示第 2 頁
- **Then**: idle 仍顯示第 1 頁

#### TC-12-16: 摺疊不影響其他分組展開狀態

- **Given**: active 展開，idle 展開
- **When**: 點擊 active Header 摺疊
- **Then**: active session tile 消失
- **Then**: idle session tile 仍可見

## 3. 行為鏈式推演

### 鏈 1: 分頁瀏覽流程

```
初始載入 → 驗證 Header 可見 → 驗證 10 筆 tile 可見 → 驗證分頁控制可見
    → 點擊下一頁 → 驗證 tile 更新 → 驗證頁碼更新
    → 點擊上一頁 → 驗證回到第 1 頁
```

覆蓋案例：TC-12-12, TC-12-13, TC-22-05, TC-22-06

### 鏈 2: 摺疊展開流程

```
初始載入 → 驗證 completed Header 可見 → 驗證 completed tile 不可見
    → 點擊 Header → 驗證 tile 出現 → 驗證分頁控制（如超過 10 筆）
    → 再次點擊 Header → 驗證 tile 消失
```

覆蓋案例：TC-12-10, TC-12-11, TC-13-03~05, Feature Spec 場景 3/4

### 鏈 3: 搜尋重置流程

```
瀏覽到第 2 頁 → 驗證在第 2 頁 → 觸發搜尋 → 驗證分頁重置到第 1 頁
```

覆蓋案例：TC-12-14, TC-20-07, Feature Spec 場景 7

### 鏈 4: 資料更新安全回退

```
瀏覽到第 2 頁 → 資料更新減少到 8 筆 → 驗證頁碼 clamp 到第 1 頁
```

覆蓋案例：TC-21-05, Feature Spec 場景 10（此鏈由 TG-21 的單元測試覆蓋，因資料更新觸發 _flattenGroups 重算）

## 7. Phase 3a Handoff 注意事項

1. **_flattenGroups 是 private 函式**：Phase 3a 需決定測試方式（@visibleForTesting 或透過 Widget 間接測試）。建議使用 @visibleForTesting 以保持單元測試的精確性。
2. **Riverpod code generation**：SessionGroupUiNotifier 使用 @riverpod，測試前需確認 .g.dart 已生成。
3. **SessionGroupHeader 向下相容**：新增的 isExpanded 和 onToggleExpand 參數會破壞既有測試 TC-13-01/02 的建構方式，Phase 3b 需同步更新。
4. **PaginationControls 按鈕識別**：建議使用 Icon（Icons.chevron_left / chevron_right）或 Key 來定位按鈕，避免依賴文字。
