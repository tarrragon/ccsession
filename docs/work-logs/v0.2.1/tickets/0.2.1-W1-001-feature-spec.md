# 0.2.1-W1-001 功能規格

## 1. Purpose（目的）

v0.2.0 實機測試暴露「函式寫了但沒呼叫」的串接斷裂問題。現有測試皆為單元測試，無法偵測跨模組呼叫鏈斷裂。本 Ticket 建立端對端整合測試，驗證 Go 後端和 Flutter 前端各自的完整資料流管線，作為後續重構的安全網。

**核心價值**：確保每個模組的輸出確實被下游模組消費，防止呼叫鏈斷裂。

## 2. API Signatures（介面定義）

本 Ticket 不新增生產程式碼，僅新增測試檔案和測試輔助工具。

### 2.1 Go 端：整合測試 Harness

**檔案**：`server/integration_test.go`

```go
// TestIntegration_JSONL_to_WebSocket_SessionList
// 驗證完整鏈路：JSONL 寫入 → FileWatcher 偵測 → Parser 解析 → Registry 更新
//              → EventDispatcher 融合 → WebSocketServer 推送 session_list

// TestIntegration_JSONL_to_WebSocket_SessionEvent
// 驗證完整鏈路：JSONL 寫入 → ... → WebSocketServer 推送 session_event（給已訂閱的 client）

// TestIntegration_JSONL_to_WebSocket_SessionHistory
// 驗證完整鏈路：JSONL 寫入 → ... → client 請求 get_session_history → 回傳歷史事件
```

**測試 Harness 結構**：

```go
// integrationHarness 封裝一個完整的 Go 後端管線，
// 含 channels、registry、dispatcher、wsServer，
// 以及 httptest.Server 提供真實 WebSocket 端點。
type integrationHarness struct {
    tmpDir      string           // 模擬 claudeHome
    sessionEvCh chan SessionEvent
    hookEvCh    chan HookEvent
    dispatchCh  chan DispatchedEvent
    registry    *SessionRegistry
    watcher     *FileWatcher
    dispatcher  *EventDispatcher
    wsServer    *WebSocketServer
    httpServer  *httptest.Server
    ctx         context.Context
    cancel      context.CancelFunc
}

// newIntegrationHarness 建構完整管線，啟動所有 goroutine。
func newIntegrationHarness(t *testing.T) *integrationHarness

// writeJSONL 在 tmpDir 中模擬 JSONL 檔案寫入。
// 建立 projects/{encodedPath}/{sessionID}.jsonl 並寫入一行 JSON。
func (h *integrationHarness) writeJSONL(sessionID, projectPath string, line []byte) error

// connectWS 建立 WebSocket 連線到 httpServer。
func (h *integrationHarness) connectWS(t *testing.T) *websocket.Conn

// readMessage 從 WebSocket 讀取一則 ServerMessage（帶 timeout）。
func (h *integrationHarness) readMessage(t *testing.T, conn *websocket.Conn, timeout time.Duration) ServerMessage

// sendAction 透過 WebSocket 送出 ClientMessage。
func (h *integrationHarness) sendAction(t *testing.T, conn *websocket.Conn, msg ClientMessage)

// teardown 關閉所有資源。
func (h *integrationHarness) teardown()
```

### 2.2 Flutter 端：整合測試 Harness

**檔案**：`ui/test/core/integration/websocket_to_provider_test.dart`

```dart
/// 測試 Harness：模擬 WebSocket channel，驗證從訊息接收到 provider 狀態更新。
/// 使用 StreamController<String> 模擬 WebSocket 輸入，
/// 透過 Riverpod ProviderContainer 驗證 notifier 狀態變化。

// test: WebSocket 訊息 → ServerMessage 解析 → SessionListNotifier 更新 sessions
// test: WebSocket 訊息 → ServerMessage 解析 → ConversationNotifier 更新 events
// test: WebSocket 連線狀態變更 → connectionStateProvider 更新
// test: session_status_change → SessionListNotifier 更新對應 session 的 status
```

**測試 Helper**：

```dart
/// FakeWebSocketService 實作 WebSocketService，
/// 暴露 StreamController 讓測試直接注入 ServerMessage。
class FakeWebSocketService implements WebSocketService {
  final messageController = StreamController<ServerMessage>.broadcast();
  final connectionStateController = StreamController<WsConnectionState>.broadcast();
  final List<ClientMessage> sentMessages = []; // 記錄發送的訊息

  @override
  Stream<ServerMessage> get messageStream => messageController.stream;

  @override
  Stream<WsConnectionState> get connectionStateStream => connectionStateController.stream;

  @override
  void send(ClientMessage message) => sentMessages.add(message);

  // ... 其餘方法
}
```

## 3. GWT Scenarios（行為場景）

### Go 端整合測試

#### 場景 1: JSONL 寫入觸發 session_list 推送

- **Given**: 整合 harness 已啟動，WebSocket client 已連線（連線時會自動收到初始 session_list）
- **When**: 在 tmpDir 中建立 `projects/{path}/{sessionID}.jsonl` 並寫入一行 user message JSON
- **Then**: WebSocket client 收到 `session_list` 訊息，且 sessions 陣列包含該 sessionID

#### 場景 2: 已訂閱 client 收到 session_event

- **Given**: 整合 harness 已啟動，WebSocket client 已連線且已訂閱 sessionID "test-session-1"
- **When**: 在對應 JSONL 檔案中 append 一行 assistant message JSON
- **Then**: WebSocket client 收到 `session_event` 訊息，且 sessionId 為 "test-session-1"，content 包含該 assistant 回應文字

#### 場景 3: client 請求 session_history 取得歷史事件

- **Given**: 整合 harness 已啟動，JSONL 檔案已寫入 3 行 conversation events
- **When**: WebSocket client 送出 `get_session_history` action（sessionId = "test-session-1"）
- **Then**: WebSocket client 收到 `session_history` 訊息，events 陣列長度 >= 3

#### 場景 4: 未訂閱 client 不收到 session_event

- **Given**: 整合 harness 已啟動，WebSocket client 已連線但未訂閱任何 session
- **When**: 在某 JSONL 檔案中 append 一行 message
- **Then**: WebSocket client 不收到 `session_event`（僅收到 `session_list` 廣播）

#### 場景 5: session_status_change 在狀態變更時廣播

- **Given**: 整合 harness 已啟動，WebSocket client 已連線，session "test-session-1" 已存在且為 active
- **When**: EventDispatcher 的 status scan 偵測到該 session 超時變為 idle
- **Then**: WebSocket client 收到 `session_status_change` 訊息，status 為 "idle"

### Flutter 端整合測試

#### 場景 6: session_list 訊息驅動 SessionListNotifier 狀態更新

- **Given**: ProviderContainer 已建立，FakeWebSocketService 已注入
- **When**: 透過 FakeWebSocketService 推入 `session_list` 類型的 ServerMessage（含 2 個 session）
- **Then**: sessionListNotifierProvider 的 state 包含 2 個 SessionInfo，且欄位正確

#### 場景 7: session_event 驅動 ConversationNotifier 事件追加

- **Given**: ProviderContainer 已建立，ConversationNotifier 已 loadSession("session-1")
- **When**: 透過 FakeWebSocketService 推入 `session_event` 類型的 ServerMessage（sessionId = "session-1"）
- **Then**: conversationNotifierProvider 的 state.events 長度增加 1，新事件內容正確

#### 場景 8: session_status_change 驅動 SessionListNotifier 狀態欄位更新

- **Given**: SessionListNotifier 已持有 session "s1"（status = active）
- **When**: 透過 FakeWebSocketService 推入 `session_status_change`（sessionId = "s1", status = "idle"）
- **Then**: SessionListNotifier 中 session "s1" 的 status 變為 idle

#### 場景 9: WebSocket 重連後 ConversationNotifier 自動重新訂閱

- **Given**: ConversationNotifier 正在查看 session "s1"
- **When**: connectionStateProvider 從 reconnecting 變為 connected
- **Then**: FakeWebSocketService.sentMessages 包含 subscribeSession("s1") 和 requestSessionHistory("s1")

#### 場景 10: loadSession 時發送正確的 WebSocket 命令序列

- **Given**: ProviderContainer 已建立，FakeWebSocketService 已注入
- **When**: ConversationNotifier.loadSession("new-session") 被呼叫
- **Then**: FakeWebSocketService.sentMessages 依序包含 requestSessionHistory("new-session") 和 subscribeSession("new-session")

## 4. Error Handling（錯誤處理）

| 錯誤情境 | Go 端行為 | Flutter 端行為 |
|---------|----------|---------------|
| JSONL 檔案格式錯誤（非 JSON） | parser 回傳 error，FileWatcher log warning，跳過該行，不中斷監控 | N/A |
| WebSocket 連線中斷 | server 從 clients map 移除 client | service 觸發 reconnect，provider 狀態變為 reconnecting |
| 請求不存在的 session history | server 回傳 error message（code: session_not_found） | ConversationNotifier 設定 errorMessage |
| client 送出無效 action | server 回傳 error message（code: invalid_action） | N/A（前端不送無效 action） |
| EventDispatcher 輸出通道滿 | non-blocking drop，log warning | N/A |

## 6. Acceptance（驗收條件）

### Go 端串接點覆蓋

- [ ] FileWatcher.readNewLinesForReader 呼叫 ParseLine 並將結果送入 eventCh — 場景 1 驗證
- [ ] EventDispatcher.processSessionEvent 從 sessionEvCh 讀取事件，呼叫 registry.UpsertFromSessionEvent 和 registry.AppendEvent — 場景 1, 2 驗證
- [ ] EventDispatcher.dispatchAfterUpdate 將 DispatchedEvent 送入 outCh — 場景 1, 2 驗證
- [ ] WebSocketServer.processDispatchedEvent 從 dispatchCh 讀取，呼叫 broadcastSessionList 或 pushToSubscribers — 場景 1, 2, 4 驗證
- [ ] WebSocketServer.handleGetSessionHistory 呼叫 querier.GetHistory 並回傳結果 — 場景 3 驗證
- [ ] WebSocketServer.broadcastStatusChange 在狀態變更時推送給所有 client — 場景 5 驗證

### Flutter 端串接點覆蓋

- [ ] WebSocketService.messageStream → SessionListNotifier._handleMessage → _handleSessionList — 場景 6 驗證
- [ ] WebSocketService.messageStream → ConversationNotifier._handleMessage → _handleSessionEvent — 場景 7 驗證
- [ ] WebSocketService.messageStream → SessionListNotifier._handleStatusChange — 場景 8 驗證
- [ ] connectionStateProvider 變更 → ConversationNotifier._resubscribeCurrentSession — 場景 9 驗證
- [ ] ConversationNotifier.loadSession → WebSocketService.requestSessionHistory + subscribeSession — 場景 10 驗證

### 自動化要求

- [ ] Go 整合測試透過 `(cd server && go test ./...)` 自動執行
- [ ] Flutter 整合測試透過 `(cd ui && flutter test)` 自動執行
- [ ] 所有整合測試在 CI 環境中可獨立執行，無外部依賴

### 不在範圍內

- 跨程序測試（Go server + Flutter client 同時執行）：因 CI 複雜度過高，不在本 Ticket 範圍
- 重複已有單元測試的邏輯（如 JSON 解析細節、reconnect 策略細節）
