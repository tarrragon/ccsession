# Execution Log

## Task Summary

基於 v0.2.0 最小實現驗證結果，建立端對端整合測試套件，作為後續程式重構的驗證保護

---

## Problem Analysis

### 問題根因

v0.2.0 各模組有完整單元測試，但沒有跨模組呼叫鏈驗證。函式 A 可能回傳正確結果，但函式 B 從未呼叫函式 A，導致資料流在中間斷裂。單元測試無法偵測此類「存在但未串接」問題。

### 影響範圍

- Go 後端：FileWatcher → Parser → Registry → EventDispatcher → WebSocketServer 完整管線
- Flutter 前端：WebSocketService → ServerMessage → SessionListNotifier / ConversationNotifier 完整管線

### 相關 Error Pattern

參考 feedback_e2e_integration_test_gaps.md — 整合測試必須覆蓋端到端呼叫鏈

---

## Solution

### Phase 1 設計完成

詳見功能規格文件：`0.2.1-W1-001-feature-spec.md`

**設計摘要**：

1. **Go 端**：建立 `server/integration_test.go`，使用 integrationHarness 封裝完整管線（FileWatcher + EventDispatcher + WebSocketServer + httptest.Server），驗證 5 個端對端場景
2. **Flutter 端**：建立 `ui/test/core/integration/websocket_to_provider_test.dart`，使用 FakeWebSocketService 注入 Riverpod ProviderContainer，驗證 5 個訊息流場景
3. **串接點覆蓋**：Go 端 6 個、Flutter 端 5 個，共 11 個跨模組呼叫點

**關鍵設計決策**：
- Go 端使用 httptest + 真實 WebSocket 連線，而非 mock，確保 HTTP upgrade 路徑也被測試
- Flutter 端不啟動真實 WebSocket，使用 FakeWebSocketService 控制輸入，聚焦 provider 狀態轉換
- 不做跨程序整合測試（Go + Flutter 同時啟動），CI 複雜度不值得

## Phase 2: Test Case Design

詳見測試設計文件：`0.2.1-W1-001-phase2-test-design.md`

**設計摘要**：

1. **Go 端**：7 個測試案例（TC-GO-01 ~ TC-GO-07），含 5 個正常場景 + 2 個異常/邊界場景，覆蓋全部 6 個串接點
2. **Flutter 端**：6 個測試案例（TC-FL-01 ~ TC-FL-06），含 5 個正常場景 + 1 個異常場景，覆蓋全部 5 個串接點，另含 5 個邊界條件子場景
3. **Mock 策略**：Go 端使用真實物件 + tmpDir + httptest（Sociable Unit Tests）；Flutter 端使用 FakeWebSocketService + 真實 ProviderContainer
4. **四維度覆蓋**：正常流程、異常流程、邊界條件、中斷操作皆有案例

**測試策略決策**：整合測試層級，只 Mock 外部邊界，驗證跨模組呼叫鏈串接
