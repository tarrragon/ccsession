### 1.2 各 API 虛擬碼

#### groupSessionsByProject(sessions)

```
FUNCTION groupSessionsByProject(sessions):
  result = empty map<string, list>
  FOR EACH session IN sessions:
    key = session.projectPath   // 空字串直接作為 key
    IF key NOT IN result:
      result[key] = empty list
    APPEND session TO result[key]
  RETURN result
```

#### sortedProjectPaths(grouped)

```
FUNCTION sortedProjectPaths(grouped):
  keys = grouped.keys as list

  // 分離空 key 和非空 key
  emptyKeys = FILTER keys WHERE key == ""
  nonEmptyKeys = FILTER keys WHERE key != ""

  // 非空 key 按 extractProjectName 結果做 case-insensitive 排序
  SORT nonEmptyKeys BY extractProjectName(key).lowercase()

  RETURN nonEmptyKeys + emptyKeys
```

#### filteredGroupedSessions 增加 projectPath

```
FUNCTION filteredGroupedSessions(projectPath):
  sessions = 從 provider 讀取全部 sessions
  IF sessions == null: RETURN empty map

  // 新增：先按 projectPath 過濾
  filtered = FILTER sessions WHERE session.projectPath == projectPath

  // 原有搜尋邏輯
  query = state.query.trim()
  IF query NOT empty:
    filtered = FILTER filtered WHERE matchesQuery(session, query)

  RETURN groupSessionsByStatus(filtered)
```

#### _ProjectTabbedView Widget

```
WIDGET _ProjectTabbedView(sessions, selectedSessionId, onSelectSession):
  // 計算分組
  projectGroups = groupSessionsByProject(sessions)
  sortedPaths = sortedProjectPaths(projectGroups)
  tabCount = sortedPaths.length

  // 需要 TickerProviderStateMixin → ConsumerStatefulWidget
  BUILD:
    DefaultTabController(length: tabCount)
      Column:
        TabBar(isScrollable: true):
          FOR EACH path IN sortedPaths:
            label = IF path == "" THEN "Other"
                    ELSE extractProjectName(path)
            count = projectGroups[path].length
            Tab(text: "{label} ({count})")
        Expanded:
          TabBarView:
            FOR EACH path IN sortedPaths:
              _SessionGroupListView(
                grouped: filteredGroupedSessions(projectPath: path),
                // 傳入 per-project 的 uiState
              )

  // 監聽 tabCount 變化 → 重建 TabController
  // 監聽 tab 索引變化 → clamp 到有效範圍
```

## 2. 資料結構選擇

| 結構 | 選擇 | 理由 |
|------|------|------|
| project 分組 | Map<string, list<SessionInfo>> | key 為 projectPath，O(n) 一次走訪 |
| 排序路徑 | List<string> | 排序後線性結構，直接對應 Tab 索引 |
| Tab 索引 | integer | 簡單狀態，Riverpod Notifier 管理 |
| per-project UI state | family provider(projectPath) | 利用 Riverpod family 機制天然隔離 |

## 6. 權宜方案與技術債務

- **最小可行實作**: TabController 在 sessions 變化時整個重建（而非 incremental update），可能有短暫閃爍
- **已知限制**: Tab 切換動畫期間若 sessions 更新導致 tabCount 變化，可能有瞬間錯位
- **技術債務標記**:
  - TD-1: Tab 標籤的 session count badge 未做即時動畫更新（Phase 4 評估是否需要 AnimatedSwitcher）
  - TD-2: 搜尋過濾後某些 Tab 內容為空但 Tab 仍顯示（Phase 1 規格明確要求此行為，非 debt）

## 7. 語言特定實作注意事項

**Dart/Flutter 考量**:
- `DefaultTabController` 需要 `TickerProviderStateMixin`，因此 `_ProjectTabbedView` 必須是 `ConsumerStatefulWidget`
- Riverpod family provider 需要 `@Riverpod` annotation 的 `build` 方法加參數，然後重跑 `build_runner`
- `TabController.length` 不可動態修改，`length` 變化時必須建新的 `TabController`
- `extractProjectName` 已存在於 `session_list_helpers.dart`，直接引用
