## 多視角審核結論（二次深度驗證）

### 第一次分析的重大誤判

| 原判斷 | 修正結果 | 原因 |
|--------|---------|------|
| Flutter ref.listen 累積 P0（10-20GB） | **誤判 -- 無問題** | Riverpod AutoDispose 自動清理 ref.listen |
| Flutter ListView 全量渲染（5-10GB） | **誤判 -- 實際 5-50MB** | ListView.builder 本身就是虛擬化 |
| Flutter Markdown 快取（3-8GB） | **誤判 -- 實際 <5MB** | 只渲染可見區域 |
| Go broadcastSessionList（20-30GB） | **誤判 -- 實際數十 MB** | data []byte 是 client 間共享的 |
| Go session history（30-50GB） | **高估 -- 實際 2-3GB** | 每 event 約 5KB，500 events/session |
| Go dedup table（1-5GB） | **誤判 -- 實際 <1MB** | 已有安全閥 MaxDedupTableSize=10000 |

### 確認的真實問題（修正後優先級）

**Go 後端（83GB 主要來源）：**

| 優先級 | 問題 | 修復方式 |
|--------|------|---------|
| P0 | tool output 無上限（唯一能造成 GB 級膨脹） | 加 MaxToolOutputLength 常數截斷 |
| P1 | slice 截斷未釋放底層陣列（Go append 機制） | 截斷後 copy 到新 slice |
| P1 | session/history map 永不 evict completed entries | 加 TTL eviction（completed 2h 後移除） |
| P1 | FileWatcher.readers map 永不清理 | session completed 時清除 reader |
| P2 | 無 pprof endpoint | 加 /debug/pprof/ 便於診斷 |

**Flutter 前端（非記憶體主因，但有功能 bug）：**

| 優先級 | 問題 | 修復方式 |
|--------|------|---------|
| P1 | 關閉面板不向後端 unsubscribe | ref.onDispose 中加 unsubscribeSession |
| P1 | ref.read(webSocketService) 重連後 stream 斷裂 | 改為 ref.watch 或重建訂閱邏輯 |
| P2 | List 複製 GC 壓力 | 考慮 ring buffer 或 batch 更新 |

### 架構層面結論

**根本問題**：後端把自己當「記憶體資料庫」，應該是「事件路由器」。

| 資料 | 目前所有者 | 應該的所有者 |
|------|-----------|------------|
| Session 元資料 | 記憶體 | 記憶體（正確） |
| Session 事件歷史 | 記憶體 history map | 磁碟 JSONL 檔案 |
| 活躍事件 | 記憶體+推送 | 推送即丟 |

**長期方案**：移除 history map，改為按需從 JSONL 讀取。session list 改增量更新。加全域記憶體預算。

### 修復策略

**Phase 1（立即 - 解決 83GB）：**
1. Go: 加 MaxToolOutputLength 截斷 output
2. Go: slice 截斷改 copy-to-new-slice
3. Go: session map 加 TTL eviction

**Phase 2（本版本 - 架構改善）：**
4. Go: history map 改磁碟讀取（事件路由器模式）
5. Go: session list 增量更新
6. Flutter: unsubscribe + ref.watch 修復
7. Go: 加 pprof endpoint

**Phase 3（下版本 - 防護網）：**
8. 全域記憶體預算和降級策略

## 第三輪診斷結論（最終）

### 83GB 是 Virtual Memory Size，非實際物理記憶體

macOS「強制結束」視窗顯示 Virtual Size，包含：
- Flutter Metal IOSurface 虛擬映射（數十 GB）— Skia GPU texture/glyph cache 映射到進程虛擬位址空間
- Go madvise(MADV_FREE) 未歸還頁面（數 GB）— 已釋放但 OS 未主動回收
- Tool output 未截斷（數 GB）— 唯一的真實記憶體問題

### 驗證方式
ps -o pid,rss,vsz,comm | grep ccsession
預期 RSS 遠小於 VSZ（如 RSS=500MB, VSZ=83GB）

### 確認需修復的真實問題
1. Go tool output 無截斷（extractToolResultOutput 無長度限制）
2. Go 未設定 debug.SetMemoryLimit
3. session/history map 無 eviction（長期運行累積）
4. slice 截斷未 copy-to-new-slice（底層陣列未釋放）
5. Flutter 面板關閉未向後端 unsubscribe
