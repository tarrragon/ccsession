### 1. 實作策略設計

#### 1.1 核心模組分析

WebSocket Server 是一個事件驅動的多 Client 管道，核心職責：

1. **連線管理**：register/unregister Client，並發安全的 clients 集合
2. **請求路由**：解析 Client 訊息，路由到對應 handler
3. **事件消費**：從 dispatchCh 讀取 DispatchedEvent，依 ChangeType 路由推送
4. **心跳維持**：writePump 定期 ping，readPump 設定 pong deadline

#### 1.2 前置需求

Phase 3b 實作前必須完成的擴充：

1. **SessionQuerier interface 抽取**：從 SessionRegistry 抽出查詢介面，WebSocketServer 依賴 interface
2. **SessionRegistry.GetHistory() 方法**：新增歷史事件查詢（分頁）
3. **SessionRegistry.AppendEvent() 方法**：新增歷史事件儲存
4. **gorilla/websocket 依賴**：`go get github.com/gorilla/websocket`

#### 1.3 虛擬碼：核心函式

**NewWebSocketServer(querier, dispatchCh)**

```
FUNCTION NewWebSocketServer(querier: SessionQuerier, dispatchCh: Channel<DispatchedEvent>)
    server = new WebSocketServer
    server.registry = querier
    server.dispatchCh = dispatchCh
    server.clients = empty map
    server.upgrader = WebSocket upgrader with default config
    RETURN server
```

**HandleWS(responseWriter, request)**

```
FUNCTION HandleWS(w, r)
    conn = upgrader.Upgrade(w, r)
    IF error THEN log ERROR, RETURN

    client = new Client{
        conn: conn,
        send: buffered channel(ClientSendBufferSize),
        subscriptions: empty map
    }

    registerClient(client)
    sendInitialSessionList(client)

    START goroutine readPump(client)
    START goroutine writePump(client)
```

**Run(ctx)**

```
FUNCTION Run(ctx)
    log INFO "websocket server started"
    LOOP
        SELECT
        CASE ctx.Done:
            closeAllClients()
            log INFO "websocket server stopped"
            RETURN
        CASE event FROM dispatchCh:
            IF channel closed THEN RETURN
            processDispatchedEvent(event)
```

**processDispatchedEvent(event)**

```
FUNCTION processDispatchedEvent(event)
    SWITCH event.ChangeType
    CASE "new":
        broadcastSessionList()
        pushToSubscribers(event.Session.ID, buildSessionEvent(event))
    CASE "updated":
        pushToSubscribers(event.Session.ID, buildSessionEvent(event))
    CASE "status_changed":
        broadcastStatusChange(event.Session.ID, event.Session.Status, event.Timestamp)
```

**readPump(client)**

```
FUNCTION readPump(client)
    DEFER unregisterClient(client)
    set MaxMessageSize on conn
    set ReadDeadline = now + PongWaitTimeout
    set PongHandler = reset ReadDeadline

    LOOP
        messageType, data = conn.ReadMessage()
        IF error THEN RETURN (triggers defer unregister)

        msg = JSON.parse(data) as ClientMessage
        IF parse error THEN
            sendToClient(client, error: INVALID_JSON)
            CONTINUE

        SWITCH msg.Action
        CASE "subscribe_session":    handleSubscribeSession(client, msg)
        CASE "unsubscribe_session":  handleUnsubscribeSession(client, msg)
        CASE "get_session_list":     handleGetSessionList(client)
        CASE "get_session_history":  handleGetSessionHistory(client, msg)
        DEFAULT:                     sendToClient(client, error: INVALID_ACTION)
```

**writePump(client)**

```
FUNCTION writePump(client)
    ticker = new Ticker(HeartbeatInterval)
    DEFER ticker.Stop()
    DEFER client.conn.Close()

    LOOP
        SELECT
        CASE message FROM client.send:
            IF channel closed THEN RETURN
            set WriteDeadline = now + WriteWaitTimeout
            write message to conn
            IF error THEN RETURN
        CASE ticker.Tick:
            set WriteDeadline = now + WriteWaitTimeout
            write Ping to conn
            IF error THEN RETURN
```

**handleSubscribeSession(client, msg)**

```
FUNCTION handleSubscribeSession(client, msg)
    IF msg.SessionID is empty THEN
        sendToClient(client, error: INVALID_PARAMS)
        RETURN

    session = registry.Get(msg.SessionID)
    IF session is nil THEN
        sendToClient(client, error: SESSION_NOT_FOUND)
        RETURN

    client.mu.Lock()
    client.subscriptions[msg.SessionID] = true
    client.mu.Unlock()
    log INFO "subscribed"
```

**handleGetSessionHistory(client, msg)**

```
FUNCTION handleGetSessionHistory(client, msg)
    IF msg.SessionID is empty THEN
        sendToClient(client, error: INVALID_PARAMS)
        RETURN

    session = registry.Get(msg.SessionID)
    IF session is nil THEN
        sendToClient(client, error: SESSION_NOT_FOUND)
        RETURN

    limit = msg.Limit
    IF limit <= 0 THEN limit = DefaultHistoryLimit
    IF limit > MaxHistoryLimit THEN limit = MaxHistoryLimit

    before = parse msg.Before as time
    IF parse error THEN before = zero time (ignore invalid)

    events, hasMore, err = registry.GetHistory(msg.SessionID, limit, before)
    IF err THEN sendToClient(client, error: SESSION_NOT_FOUND); RETURN

    sendToClient(client, session_history: {sessionId, events, hasMore})
```

**sendToClient(client, msg)**

```
FUNCTION sendToClient(client, msg)
    data = JSON.serialize(msg)
    SELECT
    CASE client.send <- data:
        // success
    DEFAULT:
        // buffer full - slow consumer
        log WARN "send buffer full"
        close(client.send)
        // writePump will detect closed channel and close conn
```

**broadcastSessionList()**

```
FUNCTION broadcastSessionList()
    sessions = registry.List()
    msg = ServerMessage{Type: "session_list", Data: {Sessions: sessions}}
    mu.RLock()
    FOR each client in clients
        sendToClient(client, msg)
    mu.RUnlock()
```

**pushToSubscribers(sessionID, msg)**

```
FUNCTION pushToSubscribers(sessionID, msg)
    mu.RLock()
    FOR each client in clients
        client.mu.RLock()
        IF sessionID in client.subscriptions THEN
            sendToClient(client, msg)
        client.mu.RUnlock()
    mu.RUnlock()
```

### 2. 資料結構選擇

| 結構 | 選擇 | 理由 |
|------|------|------|
| clients 集合 | map[*Client]struct{} | O(1) 註冊/移除，遍歷效率足夠（Client 數通常 < 50） |
| client.subscriptions | map[string]struct{} | O(1) 查詢訂閱狀態，天然冪等 |
| client.send | buffered channel | 解耦推送和寫入，writePump 序列化存取 conn |
| 歷史事件儲存 | map[string][]*SessionEvent | 記憶體中，按 sessionID 分組，slice 支援分頁 |
| 並發保護 | sync.RWMutex | 讀多寫少場景（broadcast 頻繁讀，register/unregister 較少寫） |

### 3. 資料流程圖

```
[EventDispatcher.outCh]
        |
        v
[WebSocketServer.Run() select loop]
        |
        +-- ChangeType == "new"
        |     +-- broadcastSessionList() --> ALL clients
        |     +-- pushToSubscribers()    --> subscribed clients only
        |
        +-- ChangeType == "updated"
        |     +-- pushToSubscribers()    --> subscribed clients only
        |
        +-- ChangeType == "status_changed"
              +-- broadcastStatusChange() --> ALL clients


[Client WebSocket]
        |
        v
[readPump] --> parse JSON --> route by action
        |
        +-- subscribe_session    --> validate --> add to subscriptions
        +-- unsubscribe_session  --> remove from subscriptions
        +-- get_session_list     --> registry.List() --> sendToClient
        +-- get_session_history  --> registry.GetHistory() --> sendToClient
        +-- unknown              --> sendToClient(error)


[writePump]
        |
        +-- client.send channel --> write to WebSocket
        +-- ticker (30s)        --> send Ping frame
```

### 4. 控制流程圖

```
HandleWS 請求到達
    |
    v
Upgrade to WebSocket
    |-- fail --> HTTP 400, RETURN
    |-- ok   --> 建立 Client
                    |
                    +-- registerClient (Lock clients map)
                    +-- send initial session_list
                    +-- go readPump (獨立 goroutine)
                    +-- go writePump (獨立 goroutine)

readPump 迴圈:
    ReadMessage --> parse --> route --> handler --> sendToClient
    |-- read error --> unregisterClient --> RETURN

writePump 迴圈:
    SELECT
    |-- client.send --> write to conn
    |   |-- write error --> close conn, RETURN
    |   |-- channel closed --> RETURN
    |-- ticker --> send Ping
        |-- write error --> close conn, RETURN

Run() 迴圈:
    SELECT
    |-- ctx.Done --> closeAllClients, RETURN
    |-- dispatchCh --> processDispatchedEvent
    |   |-- channel closed --> RETURN
```

### 6. 權宜方案與技術債務

- **最小可行實作**: 心跳測試使用方案 C（測試專用較短的 HeartbeatInterval），而非注入 ticker factory（方案 A）。若測試穩定性不足再升級為方案 A。
- **已知限制**:
  - SessionRegistry.GetHistory() 為記憶體實作，大量歷史事件時記憶體消耗高（v0.3 可改用 LRU 或持久化）
  - broadcastSessionList 推送完整快照而非差異（Phase 1 TDR-003 已記錄，v0.3 可最佳化）
  - AppendEvent 無上限保護的風險已由 Phase 1 定義 MaxHistoryLimit 覆蓋
- **技術債務標記**:
  - TD-1: SessionRegistry 直接持有歷史事件的 slice，無 LRU 淘汰（低風險，v0.3）
  - TD-2: 心跳若使用方案 C，測試依賴真實 timer，CI 環境可能因排程延遲導致 flaky test（中風險）

### 7. 語言特定實作注意事項

**Go 考量**:
- gorilla/websocket 的 `Conn` 不支援並發寫入，必須透過 writePump 序列化
- `select` 在 `case event, ok := <-ch` 中，channel 為 nil 時永遠不會被選中（可用於停止消費已關閉的 channel）
- `httptest.NewServer` + gorilla `websocket.Dialer` 是測試 WebSocket 的標準模式
- `go test -race` 必須通過所有並發測試
- `t.Cleanup` 確保 httptest.Server 和 WebSocket 連線在測試結束時正確關閉
