## 1. 測試策略

### 分層決策

| 層級 | 測試對象 | 策略 | 理由 |
|------|---------|------|------|
| Layer 3 (UseCase) | SessionListSearchNotifier 篩選邏輯 | BDD 單元測試 | 核心業務邏輯，Given-When-Then |
| Layer 3 (UseCase) | SessionListSearchState 衍生屬性 | 單元測試 | 純計算，無副作用 |
| Layer 1 (UI) | SessionListSearchBar Widget | 整合測試 | UI 互動驗證 |

### Sociable Unit Tests 原則

| 依賴 | Mock 策略 | 理由 |
|------|----------|------|
| WebSocketService | Mock | 外部依賴（網路） |
| SessionListNotifier (上游資料) | 透過 WebSocket mock 間接控制 | Sociable — 使用真實 Notifier |
| SessionInfo (Domain Entity) | 不 Mock | 內層邏輯，使用真實物件 |
| SessionListSearchState (Value Object) | 不 Mock | 直接使用真實物件 |
| Timer (debounce) | 透過 fakeAsync 控制 | 外部時間依賴 |

### 測試檔案結構

| 檔案 | 測試群組 | 功能職責 |
|------|---------|---------|
| `session_list_search_notifier_test.dart` | TG-FILTER-01 ~ TG-FILTER-04 | Notifier 純邏輯（篩選、狀態管理、debounce、即時更新） |
| `session_list_search_bar_test.dart` | TG-FILTER-05 | Widget 互動（輸入、按鈕、鍵盤） |

## 3. Notifier 測試案例（session_list_search_notifier_test.dart）

### TG-FILTER-01: 搜尋 UI 狀態管理

**功能職責**: openSearch / closeSearch 狀態切換
**跨群組依賴**: 無

#### TC-FILTER-01: openSearch 設定 isSearchVisible 為 true

```
Given: Notifier 已初始化，isSearchVisible 為 false
Then（前置驗證）: state.isSearchVisible == false
Then（前置驗證）: state.query == ''
When: 呼叫 openSearch()
Then: state.isSearchVisible == true
Then: state.query == ''（維持空字串）
```

#### TC-FILTER-02: closeSearch 重置所有搜尋狀態

```
Given: 搜尋列已開啟且有篩選文字 "auth"
Then（前置驗證）: state.isSearchVisible == true
Then（前置驗證）: state.query == 'auth'
When: 呼叫 closeSearch()
Then: state.isSearchVisible == false
Then: state.query == ''
Then: filteredGroupedSessions 回傳完整列表（無篩選）
```

#### TC-FILTER-03: hasActiveFilter 衍生屬性

```
Given: state.query == ''
Then: state.hasActiveFilter == false

Given: state.query == 'auth'
Then: state.hasActiveFilter == true
```

---

### TG-FILTER-02: 篩選邏輯核心

**功能職責**: updateQuery 觸發的篩選行為、多欄位匹配、case-insensitive
**跨群組依賴**: 無

#### TC-FILTER-10: 基本文字篩選 — summary 匹配（場景 1）

```
Given: Session 列表含 A("refactor auth"), B("add payment"), C("fix login bug")
Then（前置驗證）: filteredGroupedSessions 包含 3 個 session
When: updateQuery("pay") 並等待 debounce
Then: filteredGroupedSessions 僅包含 Session B
```

#### TC-FILTER-11: Case-insensitive 篩選（場景 2）

```
Given: Session 列表含 A(summary="Refactor Auth Module")
Then（前置驗證）: Session A 存在於列表中
When: updateQuery("refactor") 並等待 debounce
Then: Session A 出現在篩選結果中

When: updateQuery("REFACTOR") 並等待 debounce
Then: Session A 出現在篩選結果中
```

#### TC-FILTER-12: 多欄位匹配 — projectPath（場景 3）

```
Given: Session A(summary="fix bug", projectPath="/Users/dev/payment-service")
Then（前置驗證）: Session A 存在
When: updateQuery("payment") 並等待 debounce
Then: Session A 出現在篩選結果中（匹配 projectPath）
```

#### TC-FILTER-13: 多欄位匹配 — agentName

```
Given: Session A(agentName="opus"), Session B(agentName="claude")
When: updateQuery("opus") 並等待 debounce
Then: 僅 Session A 出現
```

#### TC-FILTER-14: 多欄位匹配 — lastMessage

```
Given: Session A(lastMessage="implementing checkout"), Session B(lastMessage="fixed null check")
When: updateQuery("checkout") 並等待 debounce
Then: 僅 Session A 出現
```

#### TC-FILTER-15: 任一欄位匹配即顯示（OR 邏輯）

```
Given: Session A(summary="fix bug", projectPath="/Users/dev/auth-service")
When: updateQuery("auth") 並等待 debounce
Then: Session A 出現（匹配 projectPath，即使 summary 不匹配）
```

#### TC-FILTER-16: 無匹配結果（場景 8）

```
Given: Session 列表含多個 session
When: updateQuery("zzzznotexist") 並等待 debounce
Then: filteredGroupedSessions 為空 Map
```

#### TC-FILTER-17: 清空篩選恢復完整列表（場景 4）

```
Given: 已輸入 "auth" 且列表已篩選，結果為部分 session
Then（前置驗證）: filteredGroupedSessions 不含所有 session
When: updateQuery('') 並等待 debounce
Then: filteredGroupedSessions 包含所有 session
```

#### TC-FILTER-18: 空查詢顯示全部（場景 9）

```
Given: 搜尋列已開啟，query 為空
Then: filteredGroupedSessions 與完整列表相同
```

#### TC-FILTER-19: 篩選結果保持分組排序（場景 12）

```
Given: 3 個 active session（lastEventAt 分別為 T+3h, T+1h, T+2h）
       2 個 idle session（lastEventAt 分別為 T+4h, T+0h）
       所有 session summary 都包含 "test"
When: updateQuery("test") 並等待 debounce
Then: 結果按 active → idle 分組
Then: active 組內按 lastEventAt 降序排列（T+3h, T+2h, T+1h）
Then: idle 組內按 lastEventAt 降序排列（T+4h, T+0h）
```

### TG-FILTER-03: Debounce 與時間控制

**功能職責**: debounce 300ms 行為
**跨群組依賴**: 無（使用 fakeAsync 獨立控制時間）

#### TC-FILTER-20: debounce 只在最後一次輸入後 300ms 執行篩選（場景 10）

```
Given: 搜尋列已開啟，Session 列表已載入
When: 快速連續呼叫 updateQuery("a"), updateQuery("au"), updateQuery("aut"), updateQuery("auth")（每次間隔 100ms < 300ms）
Then: 在最後一次 updateQuery 後 300ms 內，state.query 更新為 "auth"
Then: 中間值 "a", "au", "aut" 不觸發篩選計算
```

**實作注意**: 使用 `fakeAsync` 精確控制時間，參照 TC-SEARCH-26 模式。

---

### TG-FILTER-04: 即時事件串流與篩選互動

**功能職責**: WebSocket 推送新 session 時，自動套用現有篩選
**跨群組依賴**: 依賴 SessionListNotifier 的 session_list 訊息處理（Sociable）

#### TC-FILTER-30: 新匹配 session 自動加入篩選結果（場景 6）

```
Given: 已輸入 "auth" 篩選，filteredGroupedSessions 含 2 個匹配 session
Then（前置驗證）: filteredGroupedSessions 的 session 總數 == 2
When: WebSocket 推送 session_list 訊息，新增一個 summary="auth migration" 的 session
Then: filteredGroupedSessions 含 3 個 session
Then: state.query 仍為 "auth"（篩選條件不變）
```

#### TC-FILTER-31: 不匹配的新 session 不出現（場景 7）

```
Given: 已輸入 "auth" 篩選
Then（前置驗證）: 記錄當前 filteredGroupedSessions session 總數
When: WebSocket 推送 session_list 訊息，新增一個 summary="add logging" 的 session
Then: filteredGroupedSessions session 總數不變
```

#### TC-FILTER-32: 無篩選時新 session 直接出現

```
Given: 搜尋列未開啟（或 query 為空），列表含 3 個 session
When: WebSocket 推送 session_list 訊息，新增一個 session
Then: filteredGroupedSessions 含 4 個 session
```

## 4. Widget 測試案例（session_list_search_bar_test.dart）

### TG-FILTER-05: SessionListSearchBar Widget 互動

**功能職責**: UI 元素渲染、使用者輸入轉發、鍵盤快捷鍵
**跨群組依賴**: 無（使用 FakeNotifier 隔離）

**Widget 測試策略**: 使用 FakeSessionListSearchNotifier（記錄方法呼叫），透過 ProviderScope overrides 注入，參照 ConversationSearchBar 測試模式。

#### TC-FILTER-50: 搜尋列可見時渲染 TextField 和關閉按鈕

```
Given: FakeNotifier state = (isSearchVisible: true, query: '')
Then（前置驗證）: SessionListSearchBar widget 存在
Then: 找到一個 TextField
Then: 找到 close 按鈕（Icons.close）
Then: 不存在上/下導航按鈕（與 ConversationSearchBar 不同）
```

#### TC-FILTER-51: 搜尋列隱藏時不渲染

```
Given: FakeNotifier state = (isSearchVisible: false)
Then: 找不到 TextField
```

#### TC-FILTER-52: 文字輸入觸發 updateQuery

```
Given: 搜尋列可見
When: 在 TextField 輸入 "auth"
Then: FakeNotifier.calls 包含 'updateQuery:auth'
```

#### TC-FILTER-53: 關閉按鈕觸發 closeSearch

```
Given: 搜尋列可見
When: 點擊 close 按鈕
Then: FakeNotifier.calls 包含 'closeSearch'
```

#### TC-FILTER-54: Escape 鍵觸發 closeSearch（場景 5）

```
Given: 搜尋列可見
When: 按下 Escape 鍵
Then: FakeNotifier.calls 包含 'closeSearch'
```

#### TC-FILTER-55: TextField 開啟時自動聚焦（AC-11）

```
Given: FakeNotifier state = (isSearchVisible: true)
When: Widget 完成渲染
Then: TextField 擁有焦點（autofocus 屬性）
```

#### TC-FILTER-56: hint 文字顯示正確

```
Given: 搜尋列可見，query 為空
Then: TextField 顯示 hint 文字 'Filter sessions...'
```

## 5. 邊界條件測試案例

以下邊界條件分散於對應的測試群組中：

### 在 TG-FILTER-02 中

#### TC-FILTER-40: 特殊字元當純文字處理（B3 / 場景 11）

```
Given: Session 列表含 projectPath="/Users/dev/my-project (v2)"
When: updateQuery("(v2)") 並等待 debounce
Then: 該 session 出現在篩選結果中（正則元字元不被解析）
```

#### TC-FILTER-41: 超長輸入字串正常處理（B4）

```
Given: Session 列表已載入
When: updateQuery("a" * 1000) 並等待 debounce
Then: 篩選正常執行，不拋出異常
Then: 因無匹配，filteredGroupedSessions 為空
```

#### TC-FILTER-42: query 前後空白 trim（B8）

```
Given: Session 列表含 summary="auth module"
When: updateQuery("  auth  ") 並等待 debounce
Then: 該 session 出現在篩選結果中（query 已 trim）
```

#### TC-FILTER-43: 所有欄位為空字串的 session（B7）

```
Given: Session E(summary="", projectPath="/Users/dev/empty", agentName="", lastMessage="")
       Session A(summary="auth", ...)
When: updateQuery("auth") 並等待 debounce
Then: Session E 不出現（無欄位匹配）

When: updateQuery("") 並等待 debounce
Then: Session E 出現（空 query 顯示全部）
```

#### TC-FILTER-44: 篩選中已選中 session 被篩掉（B6）

```
Given: Session A 已被選中（selectedSessionId == A.id），列表已篩選排除 Session A
Then: selectedSessionId 不變（仍為 A.id）
Then: Session A 不在 filteredGroupedSessions 中
```

**設計決策說明**: 此測試驗證 SearchNotifier 不干預 selectedSessionId。選中狀態由 SessionListNotifier 管理，SearchNotifier 僅負責篩選顯示。

## 6. 行為鏈式推演總結

### 主要行為鏈

```
openSearch() → [isSearchVisible=true] → updateQuery(q) → [debounce 300ms] → [篩選計算] → [filteredGroupedSessions 更新]
                                                                                              |
closeSearch() ← [Escape 鍵 / close 按鈕] ← ────────────────────────────────────────────────────┘
```

### 四個維度覆蓋

| 維度 | 測試案例 |
|------|---------|
| 正常流程 | TC-FILTER-01/02/10/11/12/13/14/15/17/18/19/30/50/52/53/54 |
| 異常流程 | TC-FILTER-16（無匹配）、TC-FILTER-44（選中被篩掉） |
| 邊界條件 | TC-FILTER-03/40/41/42/43 |
| 中斷操作 | TC-FILTER-02（搜尋中關閉）、TC-FILTER-20（快速輸入 debounce） |

### 完成標準確認

- 所有 12 個 Phase 1 GWT 場景均有對應測試案例
- 所有 8 個邊界條件（B1-B8）均已覆蓋
- 四個維度均有至少一個測試案例
- 無法再提出新的「如果...那麼...」行為分支
