## 測試群組：TestAutoDirectionHandling

### 場景 1：auto direction 未完成 Ticket 歸入 recent_tasks（正常流程）

```
Given: pending 目錄有一個 JSON 檔案，direction="auto"，resumed_at=None
       對應 Ticket 未完成（is_ticket_completed 回傳 False）
Then（前置驗證）: pending 目錄存在且包含該 JSON 檔案
When: 呼叫 scan_pending_handoff_tasks()
Then: pending_tasks 為空（長度 0）
      recent_tasks 包含該 ticket_id（長度 1）
      recent_tasks[0]["direction"] == "auto"
```

**驗證方式**: 直接呼叫 `scan_pending_handoff_tasks()`，檢查回傳 tuple 的兩個 list。

### 場景 2：auto:TARGET_ID 格式同樣不阻塞（正常流程）

```
Given: pending 目錄有一個 JSON 檔案，direction="auto:0.2.0-W3-009"，resumed_at=None
       對應 Ticket 未完成
Then（前置驗證）: JSON 檔案的 direction 欄位包含 ":"
When: 呼叫 scan_pending_handoff_tasks()
Then: pending_tasks 為空
      recent_tasks 包含該 ticket_id
      recent_tasks[0]["direction"] == "auto:0.2.0-W3-009"
```

### 場景 3：auto direction 超過 30 分鐘仍不阻塞（邊界條件）

```
Given: pending 目錄有一個 JSON 檔案，direction="auto"，resumed_at=None
       對應 Ticket 未完成
       is_ticket_recently_started() 回傳 False（模擬超過 30 分鐘）
Then（前置驗證）: Ticket 未完成且超時
When: 呼叫 scan_pending_handoff_tasks()
Then: pending_tasks 為空（auto 永遠不進 pending_tasks）
      recent_tasks 包含該 ticket_id
```

**關鍵驗證點**: 修改後的邏輯在 `direction_type == "auto"` 時直接歸入 recent_tasks，不再進入 `is_ticket_recently_started()` 的判斷分支。因此即使超過 30 分鐘，auto 仍歸入 recent_tasks。

### 場景 4：非 auto direction 遺留任務仍阻塞（行為不變驗證）

```
Given: pending 目錄有一個 JSON 檔案，direction="context-refresh"，resumed_at=None
       對應 Ticket 未完成
       is_ticket_recently_started() 回傳 False（超過 30 分鐘）
Then（前置驗證）: direction 不是 "auto" 開頭
When: 呼叫 scan_pending_handoff_tasks()
Then: pending_tasks 包含該 ticket_id（長度 1）
      recent_tasks 為空
```

### 場景 5：非 auto direction 最近任務歸入 recent_tasks（行為不變驗證）

```
Given: pending 目錄有一個 JSON 檔案，direction="context-refresh"，resumed_at=None
       對應 Ticket 未完成
       is_ticket_recently_started() 回傳 True（最近 30 分鐘內）
When: 呼叫 scan_pending_handoff_tasks()
Then: recent_tasks 包含該 ticket_id
      pending_tasks 為空
```

### 場景 6：auto + 已完成 Ticket 被 GC 刪除（邊界條件）

```
Given: pending 目錄有一個 JSON 檔案，direction="auto"，resumed_at=None
       對應 Ticket 已完成（is_ticket_completed 回傳 True）
Then（前置驗證）: Ticket 狀態為 completed
When: 呼叫 scan_pending_handoff_tasks()
Then: pending_tasks 為空
      recent_tasks 為空
      該 JSON 檔案已被刪除（GC）
```

**說明**: auto 不在 `chain_directions` 集合中，`should_preserve_pending_json("auto")` 回傳 False，因此 GC 正常刪除。此場景驗證 GC 路徑不受修改影響。

### 場景 7：混合場景 - auto 和非 auto 同時存在（整合驗證）

```
Given: pending 目錄有兩個 JSON 檔案：
       - ticket A: direction="auto"，resumed_at=None，Ticket 未完成
       - ticket B: direction="context-refresh"，resumed_at=None，Ticket 未完成，超過 30 分鐘
Then（前置驗證）: 兩個檔案都存在
When: 呼叫 scan_pending_handoff_tasks()
Then: pending_tasks 只包含 ticket B（長度 1）
      recent_tasks 只包含 ticket A（長度 1）
```

### 場景 8：auto direction 的 logger.info 驗證（輸出驗證）

```
Given: pending 目錄有一個 JSON 檔案，direction="auto"，resumed_at=None
       對應 Ticket 未完成
When: 呼叫 scan_pending_handoff_tasks()
Then: logger.info 被呼叫，訊息包含 "auto handoff" 和 "不阻塞"
```

## 測試環境設置

### Mock 物件設計

每個測試需要：

1. **tmp_project_root**（conftest fixture）: 臨時目錄，含 `.claude/handoff/pending/`
2. **pending JSON 檔案**: 手動建立，包含 `ticket_id`、`title`、`direction`、`resumed_at` 欄位
3. **Mock `is_ticket_completed`**: `patch.object(hook_module, "is_ticket_completed", return_value=...)`
4. **Mock `is_ticket_recently_started`**: `patch.object(hook_module, "is_ticket_recently_started", return_value=...)`（僅非 auto 場景需要）
5. **Mock logger**: `MagicMock()` 用於驗證日誌輸出
