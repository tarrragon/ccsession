# Execution Log

## Task Summary

CLI 呼叫失敗時主動偵測是否為引導不足導致的新使用情境，提示需要補充 SKILL 說明

---

## Problem Analysis

### 問題根因

SKILL 系統無法預先列舉所有可能的使用情境，當用戶嘗試使用 SKILL 文檔未明確說明的參數或子命令時，會遇到 CLI 錯誤。這種錯誤往往反映「SKILL 引導不足」而非使用者操作錯誤，但目前缺乏機制自動偵測並回饋。

### 影響範圍

- 涉及所有 ticket/skill 相關 CLI 命令的使用
- 當新使用情境出現時（如新增參數、新子命令），無法主動提示更新 SKILL 文檔
- 影響使用者的學習曲線和文檔完整性

### 相關 Error Pattern

- 參數不存在：`unrecognized arguments`、`argument not recognized`
- 參數格式錯誤：`error: argument`、`invalid argument`
- 未知子命令：`invalid choice`、`unknown command`

---

## Solution

### 設計方案

實作 PostToolUse Hook `skill-cli-error-feedback-hook.py`，在 Bash 命令執行後自動偵測是否為 SKILL 引導缺陷類型的錯誤。

#### 核心邏輯

1. **命令過濾**：檢查命令是否包含 `ticket` 或 `skill` 前綴
2. **錯誤類型分析**：使用正則表達式識別：
   - `unrecognized arguments[:]?` → 參數不存在
   - `error: argument` → 參數格式錯誤
   - `invalid choice:` → 未知子命令
3. **業務邏輯排除**：排除已知的非 SKILL 引導問題：
   - `ticket not found` → Ticket 不存在
   - `not in progress` → 狀態不符
   - `permission denied` → 權限問題
4. **回饋輸出**：使用 additionalContext 輸出友好的引導不足警告，包含：
   - 錯誤類型分類
   - 失敗命令摘要
   - 補充文檔的建議動作
   - 參考文檔連結

#### 技術實現

- Hook 類型：PostToolUse（Bash 工具執行後）
- Exit Code：0（不阻止操作）
- 日誌記錄：`.claude/hook-logs/skill-cli-error-feedback/`
- 配置位置：`.claude/settings.json` 的 PostToolUse -> Bash 區段

### 檔案清單

1. `.claude/hooks/skill-cli-error-feedback-hook.py` - Hook 實作（273 行）
   - 使用 hook_utils 的 `setup_hook_logging` 和 `run_hook_safely`
   - 支援 PEP 723 inline metadata（uv run --quiet --script）
   - 完整的錯誤模式偵測和排除邏輯

2. `.claude/settings.json` - Hook 註冊配置
   - 在 PostToolUse -> Bash hooks 中添加新 hook
   - 設定 timeout: 5000ms
