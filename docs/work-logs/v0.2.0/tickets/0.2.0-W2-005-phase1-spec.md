# 0.2.0-W2-005 Phase 1：Conversation View 全文搜尋功能設計規格

## 1. Purpose

### 核心問題

使用者在監控 Claude Code session 時，對話內容可能很長（數百條訊息）。目前無法在對話中快速定位特定關鍵字（錯誤訊息、檔案名稱、函式名稱等），必須手動捲動尋找。

### 需求來源

- spec 4.2 搜尋章節：支援對話內容全文搜尋、搜尋結果高亮顯示、上/下導航搜尋結果

### 使用者場景

| 場景 | 描述 |
|------|------|
| 錯誤追蹤 | 使用者搜尋 "Error" 或 "failed" 定位工具執行失敗的位置 |
| 檔案定位 | 搜尋特定檔案名稱（如 "main.dart"）查看相關操作 |
| 回顧決策 | 搜尋關鍵字回顧 agent 的推理和決策 |

## 2. 搜尋行為定義

### 2.1 搜尋觸發方式

| 方式 | 觸發條件 | 行為 |
|------|---------|------|
| 鍵盤快捷鍵 | Ctrl+F (Windows/Linux) / Cmd+F (macOS) | 開啟搜尋列 |
| 搜尋按鈕 | 點擊 AppBar 搜尋圖示 | 開啟搜尋列 |
| Escape 鍵 | 搜尋列開啟時按 Escape | 關閉搜尋列並清除高亮 |

### 2.2 搜尋演算法

| 項目 | 規格 |
|------|------|
| 大小寫敏感度 | 預設不敏感（case-insensitive） |
| 匹配方式 | 子字串匹配（非正則） |
| 搜尋時機 | 輸入即搜（debounce 300ms） |
| 最小搜尋長度 | 1 字元（空字串清除結果） |

### 2.3 搜尋範圍

搜尋目標為 `ConversationState.events` 中所有事件的可搜尋文字：

| event.type | 搜尋欄位 | 說明 |
|------------|---------|------|
| `user` | `content.text` | 使用者輸入文字 |
| `assistant` | `content.text` | 助手回應文字 |
| `thinking` | `content.text` | 思考內容（非空時） |
| `tool_use` | `content.toolName` + `content.text` | 工具名稱和參數摘要 |
| `tool_result` | `content.output` + `content.text` | 工具輸出結果 |

### 2.4 搜尋結果排序

- 按 events 陣列順序（即 timestamp 升序）
- 同一 event 內多個匹配按文字位置排序

## 3. 狀態模型設計

### 3.1 SearchMatch 模型

```dart
/// 單一搜尋匹配項
class SearchMatch extends Equatable {
  const SearchMatch({
    required this.eventIndex,
    required this.startOffset,
    required this.endOffset,
    required this.field,
  });

  /// 在 ConversationState.events 中的索引
  final int eventIndex;

  /// 匹配文字在該欄位中的起始偏移量
  final int startOffset;

  /// 匹配文字在該欄位中的結束偏移量
  final int endOffset;

  /// 匹配發生的欄位名稱（"text", "output", "toolName"）
  final String field;
}
```

### 3.2 ConversationSearchState 模型

```dart
/// 搜尋功能的完整 UI 狀態
class ConversationSearchState extends Equatable {
  const ConversationSearchState({
    this.isSearchVisible = false,
    this.query = '',
    this.matches = const [],
    this.currentMatchIndex = -1,
  });

  /// 搜尋列是否可見
  final bool isSearchVisible;

  /// 當前搜尋字串
  final String query;

  /// 所有匹配結果（按 event 順序 + 位置順序）
  final List<SearchMatch> matches;

  /// 當前聚焦的匹配項索引（-1 表示無聚焦）
  final int currentMatchIndex;

  /// 衍生屬性：是否有匹配結果
  bool get hasMatches => matches.isNotEmpty;

  /// 衍生屬性：顯示用計數文字（如 "3/15"）
  String get matchCountDisplay {
    if (query.isEmpty) return '';
    if (matches.isEmpty) return '0/0';
    return '${currentMatchIndex + 1}/${matches.length}';
  }

  /// 衍生屬性：當前聚焦的匹配項
  SearchMatch? get currentMatch {
    if (currentMatchIndex < 0 || currentMatchIndex >= matches.length) {
      return null;
    }
    return matches[currentMatchIndex];
  }
}
```

### 3.3 狀態轉換流程

```
[搜尋關閉] --(Ctrl+F / 按鈕)--> [搜尋開啟, query="", matches=[]]
    |                                   |
    |                              (輸入文字, debounce 300ms)
    |                                   |
    |                                   v
    |                           [搜尋中, query="xxx"]
    |                                   |
    |                              (執行匹配)
    |                                   |
    |                                   v
    |                           [有結果, currentMatchIndex=0]
    |                           [無結果, currentMatchIndex=-1]
    |                                   |
    |                          (上/下導航, Enter)
    |                                   |
    |                                   v
    |                           [currentMatchIndex 更新, 捲動到該 event]
    |                                   |
    |<----------(Escape / 關閉按鈕)------+
```

## 4. API 介面定義

### 4.1 ConversationSearchNotifier

```dart
@riverpod
class ConversationSearchNotifier extends _$ConversationSearchNotifier {

  @override
  ConversationSearchState build();

  /// 需求：開啟搜尋列
  /// 約束：開啟時自動 focus 輸入框
  void openSearch();

  /// 需求：關閉搜尋列並清除所有搜尋狀態
  void closeSearch();

  /// 需求：更新搜尋字串並觸發匹配
  /// 約束：由 TextField.onChanged 呼叫，Notifier 內部 debounce
  void updateQuery(String query);

  /// 需求：導航到下一個匹配項
  /// 約束：到最後一個時循環回第一個
  void nextMatch();

  /// 需求：導航到上一個匹配項
  /// 約束：到第一個時循環回最後一個
  void previousMatch();
}
```

### 4.2 Provider 依賴關係

```
conversationSearchNotifierProvider
    |
    +-- ref.watch(conversationNotifierProvider)  // 讀取 events 列表
    |
    v
ConversationSearchNotifier
    |-- build(): 監聽 conversationNotifierProvider，events 變化時重新搜尋
    |-- _performSearch(): 遍歷 events 執行子字串匹配
```

**互動機制**：

- `ConversationSearchNotifier` 透過 `ref.watch` 監聽 `conversationNotifierProvider`
- 當 events 列表變化（新訊息加入）且搜尋開啟中，自動重新執行搜尋
- 搜尋結果透過 `conversationSearchNotifierProvider` 傳遞給 Widget 層

### 4.3 搜尋輔助函式

```dart
/// 需求：從 SessionEvent 提取可搜尋文字
/// 約束：根據 event.type 決定搜尋哪些欄位
List<({String field, String text})> extractSearchableText(SessionEvent event);

/// 需求：在文字中找出所有匹配位置
/// 約束：case-insensitive 子字串匹配
List<({int start, int end})> findAllMatches(String text, String query);
```

## 5. Widget 設計

### 5.1 ConversationSearchBar

**位置**：ConversationView 頂部，搜尋開啟時以 overlay 或 column 方式顯示。

**組成**：

| 元件 | 說明 |
|------|------|
| TextField | 搜尋輸入框，自動 focus |
| 匹配計數 | 顯示 "3/15" 格式的計數文字 |
| 上一個按鈕 | Icons.keyboard_arrow_up，呼叫 previousMatch() |
| 下一個按鈕 | Icons.keyboard_arrow_down，呼叫 nextMatch() |
| 關閉按鈕 | Icons.close，呼叫 closeSearch() |

**鍵盤行為**：

| 按鍵 | 行為 |
|------|------|
| Enter | 導航到下一個匹配（等同下一個按鈕） |
| Shift+Enter | 導航到上一個匹配 |
| Escape | 關閉搜尋 |

### 5.2 Message Bubble 高亮機制

**方案**：各 Bubble Widget 接收 `highlightRanges` 參數。

```dart
/// 需求：需要支援高亮的 Bubble 共用參數
/// 約束：由各 Bubble Widget 自行決定如何渲染高亮
typedef HighlightRange = ({int start, int end, bool isCurrent});
```

**修改範圍**：

| Widget | 修改內容 |
|--------|---------|
| MessageBubbleFactory.build() | 新增 `highlightRanges` 參數傳入 |
| AssistantMessageBubble | Text 改為 RichText，匹配段落套用高亮背景色 |
| UserMessageBubble | 同上 |
| ThinkingBubble | 同上 |
| ToolUseBubble | toolName 和 text 區域分別處理高亮 |
| ToolResultBubble | output 和 text 區域分別處理高亮 |

**高亮樣式**：

| 類型 | 背景色 |
|------|--------|
| 普通匹配 | 黃色半透明（Colors.yellow.withOpacity(0.4)） |
| 當前聚焦匹配 | 橘色半透明（Colors.orange.withOpacity(0.6)） |

```dart
  String text,
  List<HighlightRange> ranges,
  TextStyle baseStyle,

```

### 5.3 搜尋結果導航捲動

- 當 `currentMatchIndex` 變化時，自動捲動 ListView 到對應 event 的位置
- 使用 `ScrollController.animateTo()` 或 `Scrollable.ensureVisible()`
- 暫停 autoScroll（設 `isAutoScrollEnabled = false`）直到使用者手動關閉搜尋

## 6. 邊界條件與錯誤處理

### 6.1 邊界條件

| 條件 | 預期行為 |
|------|---------|
| 空 events 列表 | matches 為空，顯示 "0/0" |
| query 為空字串 | 清除所有匹配，不顯示計數 |
| query 為 1 字元 | 正常搜尋 |
| 搜尋中有新 event 加入 | 自動重新搜尋，保持 currentMatchIndex 指向同一 match |
| 搜尋中 event 被清空（切換 session） | 自動關閉搜尋列 |
| 搜尋字串含特殊字元 | 視為字面字串搜尋（非正則） |
| 超長搜尋字串 | 正常處理，不限制長度 |
| 單一 event 內多個匹配 | 每個匹配獨立列入 matches 列表 |
| 搜尋中 loadMoreHistory | 重新搜尋，新歷史事件的匹配 prepend 到結果前 |

### 6.2 效能考量

| 策略 | 說明 |
|------|------|
| debounce 300ms | 避免每個按鍵都觸發搜尋 |
| 純同步搜尋 | events 在記憶體中，子字串匹配效能足夠 |
| 延遲高亮計算 | 只計算可見 Bubble 的 highlightRanges |

## 7. 驗收標準（Given-When-Then）

### 場景 1：開啟搜尋列

```
Given: ConversationView 顯示對話內容
When: 使用者按下 Ctrl+F（或 Cmd+F）
Then: 搜尋列出現在頂部，輸入框自動獲得焦點
```

### 場景 2：輸入搜尋關鍵字並顯示匹配

```
Given: 搜尋列已開啟，對話中有包含 "error" 的訊息
When: 使用者輸入 "error"
Then: 所有包含 "error" 的文字段落以黃色背景高亮，第一個匹配以橘色高亮，計數顯示 "1/N"
```

### 場景 3：大小寫不敏感匹配

```
Given: 對話中有 "Error"、"ERROR"、"error" 三個訊息
When: 使用者搜尋 "error"
Then: 三個都匹配，計數顯示正確
```

### 場景 4：下一個/上一個導航

```
Given: 搜尋到 5 個匹配，當前在第 1 個
When: 使用者點擊下一個按鈕 5 次
Then: 依序跳到 2, 3, 4, 5, 1（循環），每次自動捲動到對應 event
```

### 場景 5：上一個導航循環

```
Given: 搜尋到 3 個匹配，當前在第 1 個
When: 使用者點擊上一個按鈕
Then: 跳到第 3 個匹配（循環到最後）
```

### 場景 6：Enter 鍵導航

```
Given: 搜尋列有焦點，有匹配結果
When: 使用者按 Enter
Then: 跳到下一個匹配
When: 使用者按 Shift+Enter
Then: 跳到上一個匹配
```

### 場景 7：關閉搜尋

```
Given: 搜尋列開啟，有高亮結果
When: 使用者按 Escape
Then: 搜尋列消失，所有高亮清除，搜尋狀態重置
```

### 場景 8：無匹配結果

```
Given: 搜尋列開啟
When: 使用者輸入一個對話中不存在的字串
Then: 計數顯示 "0/0"，無高亮，上/下按鈕禁用
```

### 場景 9：空 query 清除結果

```
Given: 搜尋列有匹配結果
When: 使用者清空輸入框
Then: 所有高亮清除，計數文字消失
```

### 場景 10：搜尋中新訊息到達

```
Given: 搜尋 "test" 已有 3 個匹配
When: 新的包含 "test" 的 assistant 訊息到達
Then: 匹配更新為 4 個，計數更新
```

### 場景 11：tool_use/tool_result 搜尋

```
Given: 對話包含 tool_use（toolName="Read"）和 tool_result（output 含 "main.dart"）
When: 使用者搜尋 "Read"
Then: tool_use bubble 的 toolName 高亮
When: 使用者搜尋 "main.dart"
Then: tool_result bubble 的 output 區域高亮
```

### 場景 12：切換 session 時搜尋重置

```
Given: 搜尋列開啟，有匹配結果
When: 使用者切換到另一個 session
Then: 搜尋列自動關閉，狀態重置
```
