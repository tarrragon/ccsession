**Test Files**:
- `server/session_registry_test.go` - Session Registry 單元測試（13 個函式）
- `server/event_dispatcher_test.go` - Event Dispatcher 整合/單元測試（12 個函式）

## 測試設計總體策略

### 分層測試決策

| 模組 | 層級 | 測試策略 | 優先級 |
|------|------|---------|--------|
| **SessionRegistry** | Domain（Layer 5） | 單元測試（Table-driven） | P0 |
| **EventDispatcher** | UseCase（Layer 3） | 單元測試 + 整合測試 | P0 |
| **去重機制** | 業務邏輯 | 單元測試（邊界值） | P1 |
| **狀態機轉換** | Domain | 單元測試（狀態轉換表） | P1 |

### Sociable Unit Tests 原則應用

- **Mock 策略**：Mock channel（實現細節），直接使用 Registry（Domain 邏輯）
- **測試邊界**：SessionRegistry 和 EventDispatcher 各自測試其 public API
- **測試穩定性**：測試驗證行為（狀態轉換、事件發送），不依賴內部實作結構
- **Time 控制**：注入 `now func() time.Time` 以控制時間推進，確保定時掃描測試確定性

### 6. EventDispatcher 去重機制測試

#### 6.1 測試 HTTP 優先去重（相同事件，HTTP 先到）
**測試名稱**: `TestEventDispatcher_Deduplication_HTTPFirst_JSONLIgnored`

**前置條件**:
- SessionRegistry 為空
- Dispatcher 執行中
- 去重表已設置

**執行步驟**:
1. 向 hookCh 發送 HookEvent: `{Type:"SubagentStart", SessionID:"abc", AgentID:"agent1", Timestamp:"2026-03-25T12:00:00Z"}`
2. 等待 50ms（確保 HTTP 先處理）
3. 向 sessionCh 發送 SessionEvent: `{SessionID:"abc", Type:"assistant", Timestamp:"2026-03-25T12:00:01Z", MessageID:"msg-same"}`
   - 構造該 JSONL 事件使其被視為 HTTP 事件的重複（同 key）
4. 讀取 outCh（應只有 HTTP 事件）
5. 驗證 Registry 中 EventCount

**預期結果**:
- outCh 收到 1 個 DispatchedEvent（HTTP 事件）
- 第二個 JSONL 事件被去重，不發送到 outCh
- Registry EventCount 仍為 1（JSONL 被忽略）

**覆蓋驗收條件**: AC-7（去重 5 秒窗口），AC-8（HTTP 優先）

---

#### 6.2 測試去重鍵組合（AgentID + EventType + Timestamp window）
**測試名稱**: `TestEventDispatcher_Deduplication_KeyComponents_SameKey`

**前置條件**:
- Dispatcher 執行中，去重表為空

**執行步驟**:
1. 向 hookCh 發送 `HookEvent{Type:"SubagentStart", AgentID:"agent1", SessionID:"abc", Timestamp:"2026-03-25T12:00:00Z"}`
2. 向 hookCh 發送相同事件，但 Timestamp 改為 "12:00:03Z"（同 5 秒窗口內）
3. 向 hookCh 發送相同事件，但 Timestamp 改為 "12:00:06Z"（超出 5 秒窗口）
4. 讀取 outCh
5. 驗證收到的事件數

**預期結果**:
- 事件 1（12:00:00）：outCh 發送（新）
- 事件 2（12:00:03）：outCh 忽略（重複，5 秒內）
- 事件 3（12:00:06）：outCh 發送（新，窗口外）
- 總共 2 個 DispatchedEvent

**覆蓋驗收條件**: AC-7（去重鍵規則）

---

#### 6.3 測試不同 AgentID 的事件不去重

### 7. EventDispatcher 容錯測試

#### 7.1 測試 outCh 滿時的容錯
**測試名稱**: `TestEventDispatcher_Run_OutChFull_DropsEvent_RegistryUpdated`

**前置條件**:

- Registry 為空

**執行步驟**:
1. 向 sessionCh 發送 3 個 SessionEvent（快速發送）
2. outCh 緩衝區滿後，觀察第 3 個事件處理
3. 讀取能成功接收的事件
4. Get Registry，驗證所有 session 是否都已更新

**預期結果**:
- outCh 丟棄第 3 個事件（容錯，避免 block）
- Registry 已更新所有 3 個 session（Registry 更新不受 outCh 滿的影響）
- 日誌記錄 "dropped event to prevent blocking" 警告

**覆蓋驗收條件**: 設計中場景 7（容錯邊界）

#### 7.2 測試 channel 關閉後的安全終止
**測試名稱**: `TestEventDispatcher_Run_ClosedChannels_GracefulShutdown`

**前置條件**:
- Dispatcher 執行中

**執行步驟**:
1. 向 sessionCh 和 hookCh 發送數個事件
2. 關閉 sessionCh 和 hookCh
3. 讓 Dispatcher 執行 50ms 以完成 cleanup
4. 驗證 Dispatcher 已終止且無 panic

**預期結果**:
- Dispatcher.Run() 無 panic 退出（檢測 channel 關閉）
- Registry 中存在所有已發送事件對應的 session
- 沒有 goroutine leak（可用 pprof 驗證）

**覆蓋驗收條件**: 邊界條件，容錯設計

### 8. EventDispatcher 融合測試（雙源混合）

**前置條件**:
- Dispatcher 執行中
- Registry 為空

**執行步驟**:
1. 發送事件序列：
   - sessionCh: SessionEvent(ID="abc", Type="user", Timestamp=12:00:00)
   - hookCh: HookEvent(Type="SubagentStart", SessionID="abc", AgentID="xyz", Timestamp=12:00:01)
   - sessionCh: SessionEvent(ID="abc", Type="assistant", Timestamp=12:00:02)
2. 讀取所有 DispatchedEvent
3. 驗證 Registry 最終狀態

**預期結果**:
- Registry session "abc"：
  - EventCount=2（user + assistant）
  - AgentID="xyz"（來自 HTTP）
  - Status="active"（沒有觸發轉換）
  - LastEventAt=12:00:02
- outCh 發送順序：創建事件 → agent 更新事件 → 內容事件

**覆蓋驗收條件**: AC-6（融合無衝突）

#### 8.2 測試 JSONL 先於 HTTP 的 Agent 填充（場景 5）
**測試名稱**: `TestEventDispatcher_Run_JSONLFirst_HTTPFills_AgentID`

**前置條件**:
- Dispatcher 執行中

**執行步驟**:
1. 向 sessionCh 發送 SessionEvent(ID="abc", Type="user") → 建立 session，AgentID=""
2. 等待 100ms
3. 向 hookCh 發送 HookEvent(Type="SubagentStart", SessionID="abc", AgentID="xyz")
4. 驗證 Registry

**預期結果**:
- Session "abc"：AgentID 從空填補為 "xyz"
- 輸出 2 個 DispatchedEvent：
  1. session_created（JSONL 事件）
  2. agent_filled（HTTP 事件，ChangeType="agent_info_updated"）

**覆蓋驗收條件**: 設計中場景 5（AgentID 遞補）

#### 8.3 測試 HTTP 子代理 Stop 即時完成（核心路徑）
**測試名稱**: `TestEventDispatcher_Run_SubagentStopHTTPEvent_ImmediateCompleted`

**前置條件**:
- SessionRegistry 已有 session "abc"（Status="active", LastEventAt=12:00:00）
- 當前時間=12:00:05（距建立 5 秒，未超時）
- Dispatcher 執行中

**執行步驟**:
1. 向 hookCh 發送 HookEvent(Type="SubagentStop", SessionID="abc", LastMessage="Task done")
2. 讀取 DispatchedEvent
3. Get Registry session "abc"
4. 驗證 Status 和時間

**預期結果**:
- Registry session "abc"：Status="completed"（即時，不等 30 分鐘 idle timeout）
- DispatchedEvent: `{SessionID:"abc", ChangeType:"status_changed", NewStatus:"completed"}`
- 無需 ScanAndUpdateStatus 介入

**覆蓋驗收條件**: AC-5（HTTP SubagentStop 即時觸發）

### 9. EventDispatcher 時間推進綜合測試

#### 9.1 測試狀態機完整轉換鏈（active → idle → completed）
**測試名稱**: `TestEventDispatcher_Run_StateTransitionChain_ActiveIdleCompleted`

**前置條件**:
- Dispatcher 執行中，scanTicker=100ms（快速掃描）
- Time 提供者可控制

**執行步驟**:
1. 向 sessionCh 發送 SessionEvent(ID="abc", Timestamp=12:00:00) → Status="active"
2. 推進時間至 12:02:30（2.5 分鐘 > 2 min threshold）
3. 觸發掃描 → Status 轉 "idle"
4. 推進時間至 12:32:30（30 分鐘 > 30 min threshold）
5. 觸發掃描 → Status 轉 "completed"
6. 讀取所有 DispatchedEvent

**預期結果**:
- DispatchedEvent 序列：
  1. session_created
  2. status_changed (active→idle)
  3. status_changed (idle→completed)
- Registry 最終 Status="completed"

**覆蓋驗收條件**: AC-4（狀態機轉換）
