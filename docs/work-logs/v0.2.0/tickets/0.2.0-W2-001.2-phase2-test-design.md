# Phase 2 測試設計：HTTP Hooks Handler

## 1. 測試策略

### 1.1 測試層級與工具選擇

**測試層級**：單元測試（HTTP Handler 級別）

**測試框架**：Go 標準庫 `testing` 包 + `net/http/httptest`

**測試方法**：Table-driven tests（表驅動測試）

**理由**：
- HTTP Hooks Handler 是純粹的 HTTP 端點，職責明確且邊界清晰
- `httptest` 提供隔離的測試環境，無需啟動真實 HTTP 伺服器
- Table-driven 模式便於組織多個測試場景，特別是邊界條件和異常情況
- 使用帶緩衝的 channel 作為 mock，驗證事件傳遞邏輯

### 1.2 測試覆蓋範圍

| 項目 | 覆蓋率目標 | 說明 |
|------|---------|------|
| HTTP 端點回傳碼 | 100% | 200 / 400 |
| 事件類型識別 | 100% | SubagentStart/Stop/TaskCompleted/TeammateIdle + 未知類型 |
| JSON 解析邏輯 | 100% | 正常 / 格式錯誤 / 必填欄位缺失 |
| Channel 傳遞 | 100% | 成功傳入 / Channel 已滿情況 |
| Log 記錄 | 100% | INFO / WARN / ERROR 各場景 |
| v0.3 預留欄位 | 100% | ParentAgentID 有值 / 無值 |

### 1.3 Mock 設計

**Mock eventCh**：使用帶緩衝 channel（容量為 1）
- 便於驗證事件是否成功傳入
- 驗證 non-blocking send 邏輯（channel 已滿時的行為）
- 避免測試中的 goroutine 死鎖

**Mock Logger**：使用 Go 標準庫 `log/slog` 的記憶體適配器（或簡單的全局變數記錄）
- 驗證 log 層級（INFO / WARN / ERROR）
- 驗證 log 欄位完整性（layer, type 等）

### 案例 TC-001：SubagentStart 事件正常接收

```
案例 ID: TC-001
優先級: P0
場景名稱: SubagentStart 事件正常接收

Given（前置條件）:
  1. HTTP Hooks Handler 已啟動
  2. eventCh 為帶緩衝 channel（容量 100），當前為空
  3. Logger 已配置（捕獲 log 輸出）

When（動作）:
  1. 發送 HTTP POST 請求至 /hooks/agent-event
  2. Request Body:
     {
       "type": "SubagentStart",
       "agent_id": "a1b2c3d4-1234-5678-9abc-def012345678",
       "agent_type": "subagent",
       "session_id": "f635f2ad-9e19-4fca-ba65-4f836ab7b737",
       "timestamp": "2026-03-25T10:30:00.000Z"
     }

Then（預期結果）:
  1. 回傳 HTTP 狀態碼 200 OK
  2. Response Body 為空或包含成功訊息（spec 未定義，實作決定）
  3. eventCh 成功接收一個 HookEvent：
     - Type: "SubagentStart"
     - AgentID: "a1b2c3d4-1234-5678-9abc-def012345678"
     - AgentType: "subagent"
     - SessionID: "f635f2ad-9e19-4fca-ba65-4f836ab7b737"
     - Timestamp: "2026-03-25T10:30:00.000Z"
  4. 記錄 INFO log：
     - layer: "hooks_handler"
     - type: "SubagentStart"
     - agent_id: "a1b2c3d4-1234-5678-9abc-def012345678"
     - session_id: "f635f2ad-9e19-4fca-ba65-4f836ab7b737"

測試驗證步驟:
  1. 發送 HTTP 請求，驗證回傳碼為 200
  2. 非阻塞讀取 eventCh（設定超時 100ms），驗證事件被傳入
  3. 驗證事件欄位值與預期一致
  4. 驗證 log 輸出包含預期的層級和欄位
```

### 案例 TC-009：eventCh 已滿

```
案例 ID: TC-009
優先級: P1
場景名稱: eventCh 已滿（Channel buffer overflow）

Given:
  1. HTTP Hooks Handler 已啟動
  2. eventCh 為帶緩衝 channel（容量 1）
  3. eventCh 的緩衝區已填滿（使用者代碼未消費事件）
  4. Logger 已配置

When:
  1. 發送 HTTP POST 至 /hooks/agent-event
  2. Request Body: 已知的有效事件（SubagentStart）

Then:
  1. 回傳 HTTP 狀態碼 200 OK（不阻塞 Claude Code 請求）
  2. 記錄 WARN log：
     - layer: "hooks_handler"
     - type: "SubagentStart"
     - message: "hook event channel full, dropping event" 或類似
  3. 事件被丟棄（不傳入 eventCh）
  4. Handler 執行時間不應因 channel 滿而延長（non-blocking send）

測試驗證步驟:
  1. 預先向 eventCh 發送一個 dummy event，填滿緩衝（容量 1）
  2. 發送 HTTP 請求，驗證回傳碼為 200
  3. 驗證 eventCh 仍只包含原 dummy event，新事件未被傳入
  4. 驗證 WARN log 被記錄
  5. 使用計時測量，驗證 Handler 回應時間不受 channel 滿的影響（< 100ms）
```

## 6. Log 驗證設計

### 6.1 Log 格式規範（遵循 spec §3.4 + quality-go.md）

每條 log 必須包含 `layer` 欄位：

| 情境 | Log 層級 | 欄位 | 範例 |
|------|---------|------|------|
| 成功接收已知事件 | INFO | layer, type, agent_id, session_id | `logger.Info("hook event received", "layer", "hooks_handler", "type", "SubagentStart", "agent_id", "...", "session_id", "...")` |
| 未知事件類型 | WARN | layer, type, hint | `logger.Warn("unknown hook event type", "layer", "hooks_handler", "type", "WorktreeCreate", "hint", "may be a new event type...")` |
| JSON 解析失敗 | ERROR | layer, error | `logger.Error("failed to parse hook event", "layer", "hooks_handler", "error", err)` |
| Channel 已滿 | WARN | layer, type, message | `logger.Warn("hook event channel full, dropping event", "layer", "hooks_handler", "type", "SubagentStart")` |

### 6.2 Log 驗證策略

使用 `log/slog` 的測試適配器或記憶體 logger 捕獲輸出，驗證：
1. 日誌層級正確（INFO / WARN / ERROR）
2. 必填欄位存在（layer）
3. 事件相關資訊完整（type, agent_id, session_id）

## 7. 邊界條件與異常場景測試

### 7.1 必填欄位缺失

| 缺失欄位 | HTTP 狀態碼 | 預期行為 |
|---------|-----------|--------|
| `type` | 400 | JSON 解析成功，但若無 type 則 handler 無法判斷事件類型；實作可選擇拒絕（400）或視為未知事件（200 + WARN） |
| `session_id`（SubagentStart） | 400 | 視同 JSON 格式錯誤 |
| `timestamp` | 400 | 視同 JSON 格式錯誤 |

**設計決策**：根據 Phase 1 spec，「必填欄位為空」視同格式錯誤，回傳 400。實作時應在結構體中使用 `omitempty` 只對可選欄位，必填欄位如缺失應導致解析失敗。

### 7.2 邊界值測試

| 邊界條件 | 測試資料 | 預期結果 |
|---------|--------|--------|
| 超長 agent_id | 1000 字元 UUID | 正常接收，傳入 eventCh |
| 超長 last_message | 10KB 文本 | 正常接收 |
| 空字符串 last_message | `"last_assistant_message": ""` | 視為有效（omitempty，可空） |
| 極早的 timestamp | `"1970-01-01T00:00:00.000Z"` | 正常接收（無時間驗證） |
| 未來的 timestamp | `"2099-12-31T23:59:59.999Z"` | 正常接收 |

### 7.3 HTTP 方法與內容類型

| 測試場景 | HTTP 方法 | Content-Type | 預期行為 |
|---------|---------|-----------|--------|
| 正常請求 | POST | application/json | 200 |
| 非 POST 方法 | GET | application/json | 405 Method Not Allowed（HTTP 層級，非 handler 責任） |
| 空 Content-Type | POST | （無） | Body 仍按 JSON 解析，成功時正常，格式錯誤時 400 |
| text/plain | POST | text/plain | Body 按 JSON 解析，成功時正常，格式錯誤時 400 |

## 8. 測試環境與隔離設計

### 8.1 Channel 隔離

```go
// 每個測試用例單獨建立 channel，避免交叉污染
func TestCase(t *testing.T) {
    eventCh := make(chan HookEvent, 1)  // 容量為 1，便於驗證 non-blocking send
    defer close(eventCh)

    handler := NewHooksHandler(eventCh)
    // ... 測試邏輯
}
```

### 8.2 Logger 隔離

```go
// 方案 A：使用全局 logger，清空每個測試前的輸出
// 方案 B：使用記憶體適配器，每個測試單獨初始化
func TestCase(t *testing.T) {
    buf := &bytes.Buffer{}
```

### 9.1 Table-Driven 模式規範

```go
func TestNewHooksHandler(t *testing.T) {
    tests := []struct {

        wantEvent     *HookEvent       // 預期事件（nil = 不傳入）

    }{
        {
            name: "SubagentStart event received successfully",
            eventBody: `{"type":"SubagentStart","agent_id":"abc","..."}`,
            wantStatusCode: 200,
            wantEvent: &HookEvent{Type: "SubagentStart", ...},
            wantLogLevel: "INFO",
        },
        // ... 更多 case
    }

    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            // 測試邏輯
        })
    }
}
```
