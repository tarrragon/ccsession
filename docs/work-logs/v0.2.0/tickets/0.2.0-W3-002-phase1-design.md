# 0.2.0-W3-002 Phase 1 功能規格設計

## 版本檢測與 HTTP Hooks Fallback 降級機制

---

## 1. 功能需求分析

### 1.1 核心問題

HTTP Hooks 功能依賴 Claude Code 特定版本：

- `v2.1.30+`：SubagentStart / SubagentStop 基礎事件
- `v2.1.63+`：HTTP Hooks 功能整體可用（含路由 POST 端點）
- `v2.1.69+`：完整 agent 欄位（`agent_id`、`agent_type`、`parent_agent_id`）

系統啟動時若不檢測版本，直接啟用 HTTP Hooks Handler，會在舊版 Claude Code 環境中：
- 接收不到任何 HTTP 事件（但 handler 仍佔用 port）
- 缺少 `agent_id` 等欄位導致 SessionRegistry 資料不完整
- 無法對 UI 呈現準確的 session 狀態

### 1.2 使用者場景

**場景 A（降級模式）**：用戶使用 Claude Code v2.1.50
- 啟動 ccsession-monitor
- 系統自動偵測版本不足，禁用 HTTP Hooks
- 純 JSONL watching 模式正常運作
- 用戶看到 INFO log 提示：需升級到 v2.1.63+ 以啟用 HTTP Hooks

**場景 B（基礎模式）**：用戶使用 Claude Code v2.1.65
- 啟動 ccsession-monitor
- 系統偵測版本在 [v2.1.63, v2.1.69) 區間
- 啟用 HTTP Hooks，但只處理基礎事件（SubagentStart/Stop）
- INFO log 提示：部分欄位功能受限（agent_id/agent_type 可能不完整）

**場景 C（完整模式）**：用戶使用 Claude Code v2.1.69+
- 啟動 ccsession-monitor
- 系統偵測版本 >= v2.1.69
- 啟用完整 HTTP Hooks 功能
- 所有 agent 欄位完整可用

**場景 D（命令不存在）**：claude CLI 未安裝或不在 PATH
- 系統嘗試執行 `claude --version` 失敗
- 安全降級為 JSONL-only 模式
- ERROR log 記錄無法偵測版本

## 2. API 介面定義

### 2.1 公開結構體

```go
// VersionConfig 記錄版本檢測結果，決定各功能是否啟用。
// 由 DetectClaudeVersion() 產生，傳入啟動流程作為路由依據。
type VersionConfig struct {
    // DetectedVersion 是 claude --version 解析後的版本號。
    // 格式為 "MAJOR.MINOR.PATCH"（如 "2.1.69"）。
    // 若命令不存在或解析失敗，值為空字串 ""。
    DetectedVersion string

    // HTTPHooksEnabled 表示是否啟用 HTTP Hooks Handler（/hooks/agent-event 路由）。
    // 條件：DetectedVersion >= MinVersionHTTPHooks（v2.1.63）
    HTTPHooksEnabled bool

    // FullFeaturesAvailable 表示是否可使用完整 agent 欄位。
    // 條件：DetectedVersion >= MinVersionFullFeatures（v2.1.69）
    // 影響：agent_id、agent_type、parent_agent_id 欄位是否可靠
    FullFeaturesAvailable bool
}
```

### 2.2 公開函式

```go
// DetectClaudeVersion 執行 claude --version 並解析版本號，
// 回傳 VersionConfig 決定各功能的啟用狀態。
//
// 版本判定規則：
//   - 命令不存在或執行失敗 → HTTPHooksEnabled=false, FullFeaturesAvailable=false
//   - 版本 < v2.1.63       → HTTPHooksEnabled=false, FullFeaturesAvailable=false
//   - v2.1.63 <= 版本 < v2.1.69 → HTTPHooksEnabled=true, FullFeaturesAvailable=false
//   - 版本 >= v2.1.69      → HTTPHooksEnabled=true, FullFeaturesAvailable=true
//
// 此函式不回傳 error；所有失敗情境均安全降級，並透過 logger 記錄原因。
func DetectClaudeVersion(logger *slog.Logger) VersionConfig
```

```go
// ParseClaudeVersion 從 `claude --version` 的輸出中提取語義版本號字串。
//
// 輸入範例：
//   "Claude Code 2.1.69\n"  → "2.1.69", nil
//   "claude v2.1.63-beta"    → "2.1.63", nil
//   "unknown format"         → "", ErrVersionParseFailure
//
// 回傳格式保證為 "MAJOR.MINOR.PATCH"，不含 v 前綴。
func ParseClaudeVersion(output string) (string, error)
```

```go
// CompareVersions 比較兩個語義版本字串的大小關係。
//
// 回傳值：
//   -1 = a < b
//    0 = a == b
//    1 = a > b
//
// 輸入格式為 "MAJOR.MINOR.PATCH"（無前綴，無後綴）。
// 若輸入格式不合法，回傳 0 並記錄 WARN log（安全降級）。
func CompareVersions(a, b string) int
```

### 2.3 常數定義（version_detect_constants.go）

```go
// 版本功能閾值常數
const (
    // MinVersionHTTPHooks 是啟用 HTTP Hooks 功能的最低版本（含）。
    // 對應 spec.md §6.4：HTTP Hooks 功能需要 Claude Code v2.1.63+
    MinVersionHTTPHooks = "2.1.63"

    // MinVersionFullFeatures 是啟用完整 agent 欄位的最低版本（含）。
    // 對應 spec.md §6.4：完整 agent_id/agent_type 欄位需 v2.1.69+
    MinVersionFullFeatures = "2.1.69"
)

// claude CLI 相關常數
const (
    // ClaudeCLICommand 是執行版本檢測的指令名稱。
    ClaudeCLICommand = "claude"

    // ClaudeCLIVersionFlag 是取得版本號的旗標。
    ClaudeCLIVersionFlag = "--version"

    // VersionCmdTimeoutSecs 是版本命令執行逾時（秒）。
    VersionCmdTimeoutSecs = 5

    // VersionPattern 是從輸出中提取版本號的正則表達式。
    // 匹配格式：可選的 "v" 前綴 + MAJOR.MINOR.PATCH
    VersionPattern = `(\d+\.\d+\.\d+)`
)
```

### 2.4 錯誤定義

```go
var (
    // ErrVersionParseFailure 表示無法從輸出中提取版本號。
    ErrVersionParseFailure = errors.New("version: cannot parse version from output")

    // ErrVersionCmdFailed 表示 claude --version 命令執行失敗。
    ErrVersionCmdFailed = errors.New("version: claude command failed")

    // ErrVersionCmdNotFound 表示 claude 命令不存在（未安裝或不在 PATH）。
    ErrVersionCmdNotFound = errors.New("version: claude command not found")

    // ErrVersionCmdTimeout 表示命令執行逾時。
    ErrVersionCmdTimeout = errors.New("version: command timed out")
)
```

## 3. 行為規格（Given-When-Then）

### 場景 1：完整模式（版本 >= v2.1.69）

```
Given: claude --version 輸出 "Claude Code 2.1.69"
When:  DetectClaudeVersion() 被呼叫
Then:
  - VersionConfig.DetectedVersion == "2.1.69"
  - VersionConfig.HTTPHooksEnabled == true
  - VersionConfig.FullFeaturesAvailable == true
  - INFO log：LogVersionDetected（含版本號和啟用模式）
  - INFO log：LogHTTPHooksEnabled（含版本號）
  - INFO log：LogFullFeaturesEnabled（含版本號）
```

### 場景 2：基礎模式（v2.1.63 <= 版本 < v2.1.69）

```
Given: claude --version 輸出 "Claude Code 2.1.65"
When:  DetectClaudeVersion() 被呼叫
Then:
  - VersionConfig.DetectedVersion == "2.1.65"
  - VersionConfig.HTTPHooksEnabled == true
  - VersionConfig.FullFeaturesAvailable == false
  - INFO log：LogVersionDetected（含版本號）
  - INFO log：LogHTTPHooksEnabled（含版本號）
  - INFO log：LogFullFeaturesPartial（提示 agent_id/agent_type 欄位可能不完整）
```

### 場景 3：降級模式（版本 < v2.1.63）

```
Given: claude --version 輸出 "Claude Code 2.1.50"
When:  DetectClaudeVersion() 被呼叫
Then:
  - VersionConfig.DetectedVersion == "2.1.50"
  - VersionConfig.HTTPHooksEnabled == false
  - VersionConfig.FullFeaturesAvailable == false
  - INFO log：LogVersionDetected（含版本號）
  - INFO log：LogHTTPHooksDisabled（提示需升級到 v2.1.63+）
```

### 場景 4：命令不存在

```
Given: PATH 中不存在 claude 命令
When:  DetectClaudeVersion() 被呼叫
Then:
  - VersionConfig.DetectedVersion == ""
  - VersionConfig.HTTPHooksEnabled == false
  - VersionConfig.FullFeaturesAvailable == false
  - ERROR log：LogVersionCmdNotFound（含建議安裝路徑提示）
```

### 場景 5：命令執行失敗（非零退出碼）

```
Given: claude 命令存在但執行回傳非零退出碼
When:  DetectClaudeVersion() 被呼叫
Then:
  - VersionConfig.DetectedVersion == ""
  - VersionConfig.HTTPHooksEnabled == false
  - VersionConfig.FullFeaturesAvailable == false
  - ERROR log：LogVersionCmdFailed（含 exit code 和 stderr 輸出）
```

### 場景 6：輸出格式異常（無法解析版本號）

```
Given: claude --version 輸出不含可識別的版本號（如 "unknown"）
When:  DetectClaudeVersion() 被呼叫
Then:
  - VersionConfig.DetectedVersion == ""
  - VersionConfig.HTTPHooksEnabled == false
  - VersionConfig.FullFeaturesAvailable == false
  - WARN log：LogVersionParseFailed（含原始輸出、提示格式可能已變更）
```

### 場景 7：命令執行逾時（> 5 秒）

```
Given: claude --version 命令超過 VersionCmdTimeoutSecs 秒未回應
When:  DetectClaudeVersion() 被呼叫
Then:
  - VersionConfig.DetectedVersion == ""
  - VersionConfig.HTTPHooksEnabled == false
  - VersionConfig.FullFeaturesAvailable == false
  - ERROR log：LogVersionCmdTimeout
```

### 場景 8：降級模式下 HTTP Hooks Handler 路由行為

```
Given: VersionConfig.HTTPHooksEnabled == false
When:  POST /hooks/agent-event 收到請求
Then:  回傳 HTTP 501 Not Implemented
       Body: {"error": "HTTP Hooks not available: requires Claude Code v2.1.63+"}
       INFO log：LogHTTPHooksNotAvailable（含請求來源）
```

### 場景 9：CompareVersions 版本比較

```
Given: 兩個有效版本字串
When:  CompareVersions("2.1.63", "2.1.69") 被呼叫
Then:  回傳 -1（a < b）

When:  CompareVersions("2.1.69", "2.1.69") 被呼叫
Then:  回傳 0（a == b）

When:  CompareVersions("2.2.0", "2.1.69") 被呼叫
Then:  回傳 1（a > b）
```

## 4. 錯誤處理策略

### 4.1 失敗矩陣

| 失敗情境 | 偵測方式 | 處理方式 | Log 等級 |
|---------|---------|---------|---------|
| claude 命令不存在 | `exec.LookPath` 回傳 error | 安全降級，繼續啟動 | ERROR |
| 命令執行非零退出碼 | `cmd.Run()` 回傳 ExitError | 安全降級，繼續啟動 | ERROR |
| 輸出無法解析版本號 | `ParseClaudeVersion` 回傳 error | 安全降級，繼續啟動 | WARN |
| 命令執行逾時 | context deadline exceeded | 安全降級，繼續啟動 | ERROR |
| 版本比較格式錯誤 | `strconv.Atoi` 回傳 error | 安全降級（視為 0.0.0），繼續 | WARN |

### 4.2 設計原則

**安全降級優先**：所有失敗情境均視為「版本不足」，不阻斷啟動流程。
系統在無法確認版本時，選擇最保守的運作模式（JSONL-only）。

**錯誤不上浮**：`DetectClaudeVersion` 不回傳 error，所有錯誤透過 logger 記錄後靜默降級。
這符合「版本檢測失敗不應導致系統無法啟動」的設計原則。

**逾時保護**：執行 `claude --version` 使用 context with timeout（`VersionCmdTimeoutSecs`）防止 CLI hang 住阻塞啟動。

## 5. 整合點設計

### 5.1 與 main.go 的整合

```go
// main.go 啟動流程（概念設計）

func main() {
    // Step 1: 初始化 logger
    logger := slog.New(...)

    // Step 2: 版本檢測（在所有其他初始化之前）
    versionCfg := DetectClaudeVersion(logger)

    // Step 3: 根據版本條件路由初始化
    if versionCfg.HTTPHooksEnabled {
        hooksCh := make(chan HookEvent, HookEventChanBufferSize)
        http.Handle("/hooks/agent-event", NewHooksHandler(hooksCh))
        // ... 啟動 event dispatcher with hooksCh
    } else {
        // 降級：/hooks/agent-event 回傳 501
        http.HandleFunc("/hooks/agent-event", newDisabledHooksHandler(logger))
    }

    // Step 4: JSONL watching 始終啟動（不受版本影響）
    // fileWatcher := NewFileWatcher(...)

    // Step 5: FullFeaturesAvailable 傳入 EventDispatcher 或 SessionRegistry
    // 用於調整 agent_id 欄位的使用策略
}
```

### 5.2 與 HooksHandler 的整合

**正常路由**（`HTTPHooksEnabled == true`）：
- `NewHooksHandler(hooksCh)` 正常建立，掛載到 `/hooks/agent-event`
- `FullFeaturesAvailable` 作為 `HooksHandler` 的配置參數，
  決定是否信任 `agent_id`/`agent_type` 欄位

**降級路由**（`HTTPHooksEnabled == false`）：
- `/hooks/agent-event` 掛載 `newDisabledHooksHandler`
- 收到請求回傳 HTTP 501，記錄 INFO log
- 現有 `HooksHandler` 程式碼不受影響

### 5.3 與 FileWatcher 的整合

FileWatcher 啟動**不受版本檢測影響**，始終正常啟動。
版本降級只影響 HTTP Hooks 路由，不影響 JSONL file watching 路徑。

### 5.4 FullFeaturesAvailable 的傳遞

`VersionConfig` 在 `main()` 初始化後透過參數傳遞，不使用全域變數：

```
main()
  └─ DetectClaudeVersion() → VersionConfig
       └─ 傳入 NewHooksHandler(hooksCh, versionCfg)（或作為條件路由依據）
```

若 `FullFeaturesAvailable == false`，`HooksHandler` 在 WARN log 中標記
`agent_id`/`agent_type` 欄位可能不可靠，Session Registry 降低對這些欄位的依賴。

```go
// Version detection layer log messages
const (
    // 成功偵測到版本
    LogVersionDetected = "Claude Code version detected"

    // HTTP Hooks 已啟用（v2.1.63+）
    LogHTTPHooksEnabled = "HTTP Hooks enabled"

    // 完整 agent 欄位可用（v2.1.69+）
    LogFullFeaturesEnabled = "full agent fields available"

    // 版本在 [v2.1.63, v2.1.69)，部分欄位受限

    // claude 命令執行失敗
    LogVersionCmdFailed = "claude --version command failed, falling back to JSONL-only mode"

    // 版本號解析失敗

    // 命令逾時
    LogVersionCmdTimeout = "claude --version timed out, falling back to JSONL-only mode"

    // HTTP Hooks 端點收到請求但功能未啟用
    LogHTTPHooksNotAvailable = "HTTP Hooks request received but feature is disabled"
)
```

## 7. 單元測試需求（供 Phase 2 參考）

### 7.1 需要 Mock 的外部依賴

`DetectClaudeVersion` 依賴 `exec.Command` 執行 `claude --version`。
為使單元測試不依賴實際 claude CLI，需要注入命令執行介面：

**建議方案**：定義 `CommandRunner` 介面（或使用函式注入）

```go
// CommandRunner 抽象命令執行，便於測試時注入 mock。
type CommandRunner interface {
    Run(name string, args ...string) (output []byte, err error)
}
```

`DetectClaudeVersion` 簽名調整為：

```go
func DetectClaudeVersion(logger *slog.Logger, runner CommandRunner) VersionConfig
```

生產程式碼提供 `defaultCommandRunner`（實際執行 `exec.Command`），
測試程式碼提供 `mockCommandRunner`（回傳預設輸出或錯誤）。

### 7.2 測試案例分類

| 測試群組 | 測試場景 | 涉及函式 |
|---------|---------|---------|
| ParseClaudeVersion | 標準格式、v 前綴、beta 後綴、無版本號、空字串 | ParseClaudeVersion |
| CompareVersions | a<b、a==b、a>b、跨 minor、跨 major、格式錯誤 | CompareVersions |
| DetectClaudeVersion | 完整模式、基礎模式、降級模式、命令不存在、執行失敗、逾時、輸出格式異常 | DetectClaudeVersion（mock runner） |
| 501 降級 handler | HTTPHooksEnabled=false 時路由 501、正確 body | newDisabledHooksHandler |

### 7.3 版本邊界值測試

| 輸入版本 | 預期 HTTPHooksEnabled | 預期 FullFeaturesAvailable |
|---------|----------------------|--------------------------|
| "2.1.62" | false | false |
| "2.1.63" | true | false |
| "2.1.68" | true | false |
| "2.1.69" | true | true |
| "2.1.70" | true | true |
| "2.2.0"  | true | true |
| ""       | false | false |

### 特別注意事項

1. **CommandRunner 介面是測試可行性的關鍵**：`exec.Command` 必須透過介面注入，否則版本相關測試無法在 CI 環境中穩定執行。

2. **版本比較不使用 semver 套件**：三段式版本（MAJOR.MINOR.PATCH）僅需整數比較，無需引入外部依賴。`CompareVersions` 自訂實作即可。

3. **安全降級優先**：所有失敗情境均降級到 JSONL-only 模式，測試必須驗證降級後系統仍可正常提供 WebSocket 服務。

4. **邊界值 v2.1.63 和 v2.1.69 為閉區間起點**：分別測試 `.62`、`.63`、`.68`、`.69` 確保 >= 邏輯正確。
