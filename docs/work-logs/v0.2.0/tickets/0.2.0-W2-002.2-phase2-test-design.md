## 1. 測試策略

### 1.1 分層測試決策

| 層級 | 測試對象 | 測試類型 | 理由 |
|------|---------|---------|------|
| 純函式 | `extractProjectName` | 單元測試 | 無依賴，輸入輸出可完全控制 |
| 狀態管理 | `SessionListNotifier` | BDD 單元測試（Given-When-Then） | Layer 3 UseCase 邏輯，核心業務行為 |
| Widget | `SessionListPage`, `SessionGroupHeader`, `SessionListTile`, `StatusIndicator` | Widget 測試（整合測試） | Layer 1 UI 關鍵流程 |

### 1.2 Sociable Unit Tests 原則

| 依賴 | Mock 策略 | 理由 |
|------|----------|------|
| `serverMessageProvider` (Stream) | Mock（ProviderScope override） | 外部依賴（WebSocket） |
| `webSocketServiceProvider` | Mock | 外部依賴（網路） |
| `SessionInfo` | 不 Mock，使用真實物件 | Domain Entity |
| `SessionListState` | 不 Mock，使用真實物件 | Value Object |
| `SessionStatus` | 不 Mock | Enum |

### 1.3 測試檔案結構

```
ui/test/features/session_list/
├── presentation/
│   ├── session_list_notifier_test.dart   # TG-10: Notifier 行為測試
```

## 2. 測試群組和測試案例

### TG-10: SessionListNotifier 行為測試

**檔案**: `session_list_notifier_test.dart`
**Mock 需求**: `serverMessageProvider` override 為 `StreamController<ServerMessage>`，`webSocketServiceProvider` override 為 Mock

#### TC-10-01: 初始載入 — 成功（場景 1）

```
Given: WebSocket 已連線，serverMessageProvider 可用
Then（前置驗證）: Notifier 狀態為 AsyncLoading
When: serverMessageProvider 發出 session_list 訊息，包含 3 個 session（1 active, 1 idle, 1 completed）
Then: Notifier 狀態為 AsyncData
Then: state.sessions 長度為 3
Then: groupedSessions 包含 3 個 key（active, idle, completed）
```

#### TC-10-02: 初始載入 — 空列表（場景 2）

```
Given: WebSocket 已連線
When: serverMessageProvider 發出 session_list 訊息，sessions 為空陣列
Then: Notifier 狀態為 AsyncData
Then: state.sessions 為空
Then: groupedSessions 為空 Map
```

#### TC-10-03: 即時狀態更新 — session 從 active 變 idle（場景 3）

```
Given: Notifier 已載入 session 列表，session-A 狀態為 active
Then（前置驗證）: groupedSessions[active] 包含 session-A
When: serverMessageProvider 發出 session_status_change，sessionId='session-A', status=idle
Then: groupedSessions[active] 不包含 session-A
Then: groupedSessions[idle] 包含 session-A
Then: session-A 的 status 為 SessionStatus.idle
```

#### TC-10-04: 選擇 session（場景 4）

```
Given: Notifier 已載入 session 列表（至少 1 個 session）
Then（前置驗證）: state.selectedSessionId 為 null
When: 呼叫 selectSession('session-A')
Then: state.selectedSessionId 為 'session-A'
```

#### TC-10-05: 切換選擇 session（場景 5）

```
Given: Notifier 已載入，selectedSessionId 為 'session-A'
Then（前置驗證）: state.selectedSessionId 為 'session-A'
When: 呼叫 selectSession('session-B')
Then: state.selectedSessionId 為 'session-B'
```

#### TC-10-06: 分組排序 — 組間順序固定，組內按 lastEventAt 降序（場景 6）

```
Given: Notifier 收到 session_list，包含：
  - session-1: active, lastEventAt=T+3
  - session-2: active, lastEventAt=T+1
  - session-3: idle, lastEventAt=T+2
  - session-4: completed, lastEventAt=T+0
Then: groupedSessions.keys 順序為 [active, idle, completed]
Then: groupedSessions[active] 順序為 [session-1, session-2]（T+3 在前）
```

#### TC-10-07: 未知 sessionId 狀態變更 — 靜默忽略（場景 8）

```
Given: Notifier 已載入 session 列表（不含 'unknown-id'）
Then（前置驗證）: state.sessions 中無 id 為 'unknown-id' 的項目
When: serverMessageProvider 發出 session_status_change，sessionId='unknown-id', status=completed
Then: state.sessions 長度不變
Then: 不拋出例外
```

#### TC-10-08: session_list 訊息替換整個列表

```
Given: Notifier 已載入 2 個 session
Then（前置驗證）: state.sessions.length == 2
When: serverMessageProvider 再次發出 session_list 訊息，包含 5 個 session
Then: state.sessions.length == 5（完全替換，非附加）
```

#### TC-10-09: 空分組不出現在 groupedSessions（場景 10）

```
Given: Notifier 收到 session_list，所有 session 狀態為 active
Then: groupedSessions.keys 僅包含 SessionStatus.active
Then: groupedSessions 不包含 idle 和 completed key
```

#### TC-10-10: 斷線重連後重新請求列表（場景 9）

```
Given: Notifier 已初始化並載入列表
When: WebSocket 斷線後重新連線（模擬 serverMessageProvider 重新建立）
Then: 自動發送 get_session_list 請求
Then: 收到新的 session_list 訊息後更新列表
```

## 3. 行為鏈式推演

### 3.1 使用者操作鏈：啟動 -> 查看列表 -> 選擇 session

```
A: App 啟動，WebSocket 連線建立
  -> B: Notifier build()，發送 get_session_list
    -> C: 收到 session_list 回應，列表渲染
      -> D: 使用者看到分組列表（前置：列表非空且分組正確）
        -> E: 使用者點擊某個 session
          -> F: selectedSessionId 更新，視覺反饋
```

**每步前置條件和對應測試**：

| 步驟 | 前置條件 | 驗證測試 |
|------|---------|---------|
| A -> B | WebSocket 已連線 | TC-10-01 |
| B -> C | serverMessageProvider 有回應 | TC-10-01, TC-10-02 |
| C -> D | sessions 非空、分組正確 | TC-10-06, TC-12-02 |
| D -> E | SessionListTile 存在且可點擊 | TC-12-05 |
| E -> F | selectSession 正確更新狀態 | TC-10-04, TC-12-06 |

### 3.2 即時更新鏈：Server 推送 -> 列表更新

```
A: 列表已載入
  -> B: Server 推送 session_status_change
    -> C: Notifier 處理訊息，更新 session 狀態
      -> D: groupedSessions 重新計算，session 移動到新分組
```

**四維度覆蓋**：

| 維度 | 場景 | 測試 |
|------|------|------|
| 正常流程 | 狀態從 active 變 idle | TC-10-03 |
| 異常流程 | 未知 sessionId 的變更 | TC-10-07 |
| 邊界條件 | 所有 session 同一狀態 | TC-10-09 |
| 中斷操作 | 斷線重連 | TC-10-10 |

### 3.3 摘要顯示鏈：資料 -> 顯示文字

| 維度 | 場景 | 測試 |
|------|------|------|
| 正常流程 | summary 有值 | TC-14-01 |
| 邊界條件 | summary 空，lastMessage 有值 | TC-14-02 |
| 邊界條件 | summary 和 lastMessage 都空 | TC-14-03 |
| 邊界條件 | projectPath 各種格式 | TC-11-01 ~ TC-11-06 |

### 4.1 SessionInfo 工廠方法

測試中建議建立 helper 函式，避免每個測試重複建構：

```
createTestSession({
  String id = 'session-1',
  String projectPath = '/Users/test/project',
  String summary = 'Test summary',
  SessionStatus status = SessionStatus.active,
  DateTime? lastEventAt,  // 預設 DateTime.now()
  String lastMessage = '',
  String agentName = 'claude',
})
```

```
createSessionListMessage(List<SessionInfo> sessions)

createStatusChangeMessage(String sessionId, SessionStatus newStatus)
  -> ServerMessage(type: 'session_status_change', data: {'sessionId': ..., 'status': ...})
```
