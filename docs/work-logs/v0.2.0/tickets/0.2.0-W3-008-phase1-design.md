# 0.2.0-W3-008 Phase 1 設計：Stop Hook auto direction 修正

## 問題摘要

`scan_pending_handoff_tasks()` 將 `direction=auto` 的 pending JSON 與其他 direction 同等處理。當 Ticket 未完成且 `started_at` 超過 30 分鐘時，auto handoff 會被歸入 `pending_tasks`（阻塞性），導致無關 Session 退出被劫持。

auto handoff 是 `ticket track complete` 後自動建立的建議性任務，語義上不應阻塞任何 Session。

## 修改範圍

**檔案**：`.claude/hooks/handoff-auto-resume-stop-hook.py`

### 修改點 1：`scan_pending_handoff_tasks()` 第 506 行附近

**現有邏輯**（第 506-523 行）：

```python
else:
    # Ticket 未完成，檢查是否在最近開始執行
    if is_ticket_recently_started(project_root, ticket_id, logger):
        recent_tasks.append(...)
    else:
        pending_tasks.append(...)
```

**修改後邏輯**：

```python
else:
    # 新增：direction=auto 的 handoff 是建議性的，永遠歸入 recent_tasks
    direction_type = direction.split(":")[0]
    if direction_type == "auto":
        recent_tasks.append({
            "ticket_id": ticket_id,
            "title": title,
            "direction": direction
        })
        logger.info(
            f"auto handoff 為建議性任務，不阻塞退出: {ticket_id}"
        )
    # Ticket 未完成，檢查是否在最近開始執行
    elif is_ticket_recently_started(project_root, ticket_id, logger):
        recent_tasks.append(...)
    else:
        pending_tasks.append(...)
```

**插入位置**：第 506 行 `else:` 之後、`is_ticket_recently_started` 判斷之前。

### 修改點 2：docstring 更新

`scan_pending_handoff_tasks()` 的 docstring（第 438-465 行）新增一條 GC 機制說明：

```
- direction 為 auto → 歸入「最近任務」（建議性，不阻塞）
```

### 無需修改的部分

- `should_preserve_pending_json()`：auto direction 不在 chain_directions 集合中，GC 行為正確（auto + completed = 正常刪除）
- `generate_hook_output()`：不需改動，recent_tasks 已有 INFO 輸出 + 不阻塞的處理路徑
- `format_pending_tasks_list()`：不需改動，只用於 pending_tasks

## 邊界條件

| 場景 | direction | Ticket 狀態 | 預期行為 |
|------|-----------|------------|---------|
| auto + 未完成 + 最近 | auto | in_progress (< 30min) | recent_tasks (INFO) |
| auto + 未完成 + 遺留 | auto | in_progress (> 30min) | recent_tasks (INFO)，不阻塞 |
| auto + 已完成 | auto | completed | GC 刪除（現有邏輯已正確） |
| auto:TARGET_ID | auto:0.2.0-W3-009 | in_progress | recent_tasks (INFO) |
| context-refresh + 遺留 | context-refresh | in_progress (> 30min) | pending_tasks (block)，行為不變 |
| to-sibling + 已完成 | to-sibling | completed | 保留（現有邏輯已正確） |

## API 變更

無。`scan_pending_handoff_tasks()` 的回傳型別 `tuple(list, list)` 不變，只是分類邏輯調整。
