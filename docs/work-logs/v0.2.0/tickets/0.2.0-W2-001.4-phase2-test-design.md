## 1. 測試策略

### 1.1 測試分層決策

| 層級 | 策略 | 理由 |
|------|------|------|
| WebSocket Server 核心邏輯 | 單元測試（Sociable Unit Test） | UseCase 層級，驗證行為而非結構 |
| Client 請求處理 | 單元測試 | 每個 action handler 獨立可測 |
| 事件推送路由 | 單元測試 | DispatchedEvent → Client 推送的路由邏輯 |
| 心跳機制 | 單元測試（時間注入） | 需要 mock time 控制 30 秒間隔 |
| 多 Client 並發 | 單元測試 + `-race` | 驗證並發安全性 |

### 1.2 Mock 策略

| 依賴 | Mock 方式 | 理由 |
|------|----------|------|
| SessionRegistry | Mock interface | 外部依賴，隔離查詢邏輯 |
| dispatchCh | 真實 channel | Go channel 是語言原語，直接使用 |
| WebSocket 連線 | httptest.NewServer + gorilla/websocket Dialer | 使用真實 HTTP Server 測試完整升級流程 |
| time（心跳） | timeProvider 注入 | 避免真實等待 30 秒 |

**Sociable Unit Tests 原則**：WebSocketServer、Client、ServerMessage、ClientMessage 等 Domain 物件使用真實實例，不 mock。只 mock 外部介面（SessionRegistry）。

### 1.3 測試基礎設施

```
server/websocket_server_test.go    # 所有 WebSocket Server 測試
```

**測試輔助函式**（在測試檔案內部定義）：

| 輔助函式 | 用途 |
|---------|------|
| `setupTestServer(registry)` | 建立 httptest.Server + WebSocketServer，回傳 server URL |
| `dialWS(url)` | 建立 gorilla/websocket 連線，回傳 *websocket.Conn |
| `readServerMessage(conn)` | 從 WebSocket 讀取並解析 ServerMessage |
| `sendClientMessage(conn, msg)` | 序列化 ClientMessage 並寫入 WebSocket |
| `mockRegistry(sessions)` | 建立帶有預設 session 資料的 mock SessionRegistry |

### 1.4 測試環境清理策略

- 每個測試函式使用獨立的 httptest.Server（`t.Cleanup` 自動關閉）
- 每個 WebSocket 連線在測試結束時 `defer conn.Close()`
- dispatchCh 使用 buffered channel，測試結束時 close
- 使用 `context.WithCancel` 控制 `Run()` goroutine 生命週期

// mockSessionRegistry 實作 SessionRegistry 的查詢介面

## 6. 設計過程發現的問題

### 6.1 SessionRegistry 需要 interface 抽象

Phase 1 設計中 WebSocketServer 直接依賴 `*SessionRegistry`（具體 struct）。為了測試可 mock，建議抽出 `SessionQuerier` interface：

```go
type SessionQuerier interface {
    List() []*SessionInfo
    Get(sessionID string) *SessionInfo
    GetHistory(sessionID string, limit int, before time.Time) ([]*SessionEvent, bool, error)
}
```

**影響**：Phase 3b 實作時需要修改 `NewWebSocketServer` 的參數類型。

### 6.2 心跳測試的時間注入

Phase 1 設計未定義 timeProvider 注入機制。心跳測試（TC-18, TC-19）需要控制時間流逝。建議：

- 方案 A：注入 `ticker` factory 到 WebSocketServer（推薦）
- 方案 B：使用較短的測試超時值（如 100ms）替代 30 秒
- 方案 C：使用真實 timer 但設定較短的 HeartbeatInterval（測試專用常數）

**建議 Phase 3b 優先考慮方案 A 或 C。**
