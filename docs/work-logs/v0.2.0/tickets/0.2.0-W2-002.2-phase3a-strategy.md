### 1. 實作策略設計

#### 1.1 實作順序和依賴關係

```
Layer 0: 常數和工具函式（無依賴）
  - SessionListConstants（常數定義）
  - extractProjectName（純函式）

Layer 1: 狀態模型（依賴 Layer 0）
```

**Layer 0 和 Layer 1 是 Layer 2 和 Layer 3 的共同前置條件，但 Layer 2 和 Layer 3 之間無實作依賴（Widget 測試 Mock Notifier）。**

#### 1.2 核心虛擬碼

##### extractProjectName

```
FUNCTION extractProjectName(projectPath):
  IF projectPath is empty:
    RETURN empty string

  // 移除尾部斜線
  path = projectPath
  WHILE path ends with '/' AND length > 1:
    path = remove last character

  IF path == '/':
    RETURN empty string

  // 取最後一段
  lastSlashIndex = last index of '/' in path
  IF lastSlashIndex < 0:
    RETURN path  // 無斜線，回傳原字串
  RETURN substring of path from (lastSlashIndex + 1)
```

##### SessionListNotifier.build

```
FUNCTION build():
  // 訂閱 serverMessageProvider stream
  subscription = listen to serverMessageProvider
    ON each message:
      CALL _handleMessage(message)

  // 發送初始請求
  webSocketService = get webSocketServiceProvider
  webSocketService.requestSessionList()

  // 回傳初始狀態（空列表，等待 WebSocket 回應填充）
  RETURN SessionListState(sessions: [], selectedSessionId: null)
```

##### SessionListNotifier._handleMessage

```
FUNCTION _handleMessage(serverMessage):
  SWITCH serverMessage.type:
    CASE 'session_list':
      data = parse serverMessage.data as SessionListData
      state = AsyncData(currentState.copyWith(sessions: data.sessions))

    CASE 'session_status_change':
      data = parse serverMessage.data as SessionStatusChangeData
      updatedSessions = currentState.sessions.map(session =>
        IF session.id == data.sessionId:
          session.copyWith(status: data.status)
        ELSE:
          session
      ).toList()
      state = AsyncData(currentState.copyWith(sessions: updatedSessions))
```

##### SessionListNotifier.groupedSessions

```
GETTER groupedSessions -> Map<SessionStatus, List<SessionInfo>>:
  IF state is not AsyncData:
    RETURN empty map

  sessions = state.value.sessions
  result = empty ordered map

  FOR EACH status IN [active, idle, completed]:  // 固定順序
    group = sessions WHERE session.status == status
    IF group is not empty:
      // 按 lastEventAt 降序排列
      sort group by lastEventAt descending
      result[status] = group

  RETURN result
```

##### SessionListNotifier.selectSession

```
FUNCTION selectSession(sessionId):
  IF state is AsyncData:
    state = AsyncData(currentState.copyWith(selectedSessionId: sessionId))
```

##### SessionListTile 摘要顯示邏輯

```
FUNCTION getDisplaySummary(session):
  IF session.summary is not empty:
    RETURN session.summary
  IF session.lastMessage is not empty:
    RETURN first SUMMARY_FALLBACK_MAX_LENGTH characters of session.lastMessage
  RETURN first 8 characters of session.id
```

##### SessionListPage 渲染邏輯

```
FUNCTION build(context, ref):
  asyncState = watch sessionListNotifierProvider
  MATCH asyncState:
    CASE Loading:
      RETURN centered loading indicator
    CASE Error:
      RETURN centered error message
    CASE Data:
      groupedSessions = notifier.groupedSessions
      IF groupedSessions is empty:
        RETURN centered empty state message
      RETURN scrollable list:
        FOR EACH (status, sessions) IN groupedSessions:
          RENDER SessionGroupHeader(status, sessions.length)
          FOR EACH session IN sessions:
            isSelected = session.id == state.selectedSessionId
            RENDER SessionListTile(session, isSelected)
              ON tap: notifier.selectSession(session.id)
```

### 2. 資料結構選擇

| 結構 | 選擇 | 理由 |
|------|------|------|
| SessionListState | freezed immutable value object | Riverpod 狀態管理需要不可變狀態 |
| groupedSessions | 有序 Map（key=enum, value=sorted list） | 保證分組順序固定（active/idle/completed） |
| sessions 列表 | 不可變 List | 每次更新建立新 List，不原地修改 |
| selectedSessionId | nullable String | null 表示未選中，簡單明確 |

### 6. 測試實作策略

#### 6.1 Notifier 測試 Mock 配置

```
// Notifier 測試的 ProviderScope.overrides 設計

1. 建立 StreamController<ServerMessage> 作為訊息來源
2. override serverMessageProvider 為該 stream
3. override webSocketServiceProvider 為 Mock（驗證 requestSessionList 呼叫）
4. 每個測試透過 controller.add() 模擬 Server 推送

虛擬碼：
  controller = new StreamController<ServerMessage>()
  mockWebSocketService = Mock of WebSocketService

  providerOverrides = [
    serverMessageProvider.overrideWith(() => controller.stream),
    webSocketServiceProvider.overrideWithValue(mockWebSocketService),
  ]

  container = ProviderContainer(overrides: providerOverrides)
  notifier = container.read(sessionListNotifierProvider.notifier)

  // 模擬 session_list 訊息
  controller.add(ServerMessage(type: 'session_list', data: {...}))
  await pump  // 等待 async 處理
  ASSERT state == expected
```

### 9. 架構決策記錄

| 決策 | 選擇 | 理由 | 替代方案 |
|------|------|------|---------|
| groupedSessions 實作方式 | getter（每次重新計算） | 簡單直接，session 數量 < 100 效能無問題 | 快取 Map + 髒標記（過度設計） |
| SessionListState 位置 | 與 Notifier 同檔案 | 減少檔案數，State 和 Notifier 緊密耦合 | 獨立檔案（增加複雜度無收益） |
| 摘要 fallback 邏輯位置 | SessionListTile Widget 內部 | 純顯示邏輯，不屬於業務層 | Notifier 或 utils（過度分離） |
| i18n 暫時方案 | 常數字串 | l10n 系統未建立，避免阻塞 | 等 l10n 就緒才實作（阻塞進度） |
| 分組排序保證 | 以固定 enum 順序迭代，非依賴 Map 排序 | 明確控制順序，不依賴隱含行為 | 使用 LinkedHashMap（依賴插入順序，較隱晦） |

### 10. Dart/Flutter 特定實作注意事項

| 考量 | 說明 |
|------|------|
| freezed code generation | SessionListState 需要 `build_runner` 產生 `.freezed.dart` 和 `.g.dart` |
| riverpod code generation | SessionListNotifier 需要 `@riverpod` annotation 和 code gen |
| AsyncNotifier vs Notifier | 使用 AsyncNotifier（build 回傳 Future），因為初始狀態需要等待 WebSocket 回應 |
| Stream 訂閱生命週期 | ref.listen 自動在 Provider dispose 時取消訂閱，無需手動管理 |
| Widget 測試 pump | AsyncNotifier 測試需要 `await Future.delayed(Duration.zero)` 或 `container.pump()` 讓 async 完成 |
| ProviderContainer 清理 | 測試中 addTearDown(container.dispose) 確保資源釋放 |
