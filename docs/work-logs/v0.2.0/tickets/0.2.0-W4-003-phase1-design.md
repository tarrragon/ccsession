# Phase 1 功能規格：Session 列表文字篩選

**Ticket**: 0.2.0-W4-003
**日期**: 2026-03-27
**範圍**: Session 列表即時文字篩選（UC-005 剩餘部分）

---

## 1. 功能需求分析

### 核心問題

使用者同時監控多個 Claude Code session 時，session 數量增多後需要快速定位特定 session。需要在 sidebar session 列表提供即時文字篩選功能。

### 使用者場景

- 使用者記得專案名稱，想快速找到對應 session
- 使用者想篩選特定 git branch 的 session
- 使用者想透過 session summary 關鍵字找到目標 session

### 設計決策

- **僅篩選（顯示/隱藏）**，不需高亮匹配文字（與對話搜尋不同）
- **本地篩選**，不需後端參與，對已載入的 session 列表做 client-side filter
- **參考 ConversationSearchBar 的 UI 模式**，保持 UX 一致性
- **不需上/下導航按鈕和計數顯示**（篩選結果直接可見於列表中）

## 2. API 介面定義

### 2.1 SessionListSearchState

**檔案位置**: `ui/lib/features/session_list/presentation/session_list_search_state.dart`

```dart
class SessionListSearchState extends Equatable {
  const SessionListSearchState({
    this.isSearchVisible = false,
    this.query = '',
  });

  /// 搜尋列是否可見
  final bool isSearchVisible;

  /// 當前篩選字串
  final String query;

  /// 需求：是否有有效篩選條件（非空 query）
  bool get hasActiveFilter => query.isNotEmpty;

  SessionListSearchState copyWith({
    bool? isSearchVisible,
    String? query,
  });

  @override
  List<Object?> get props => [isSearchVisible, query];
}
```

**設計說明**：
- 不含 `filteredSessions` 欄位 — 篩選結果由 Notifier 的計算屬性提供，避免狀態重複
- 比 ConversationSearchState 更簡單：不需 matches、currentMatchIndex（篩選 vs 搜尋導航）

### 2.2 SessionListSearchNotifier

**檔案位置**: `ui/lib/features/session_list/presentation/session_list_search_notifier.dart`

```dart
@riverpod
class SessionListSearchNotifier extends _$SessionListSearchNotifier {
  Timer? _debounceTimer;

  @override
  SessionListSearchState build();

  /// 需求：開啟搜尋列
  void openSearch();

  /// 需求：關閉搜尋列並清除篩選狀態
  void closeSearch();

  /// 需求：更新篩選字串（由 TextField.onChanged 呼叫）
  /// 約束：內部 debounce 使用 SearchConstants.searchDebounceMilliseconds (300ms)
  void updateQuery(String query);

  /// 需求：取得篩選後的分組 session 列表
  /// 約束：監聽 sessionListNotifierProvider，query 變化時重新篩選
  /// 約束：篩選邏輯對 SessionInfo 的 summary、projectName、gitBranch 做 case-insensitive contains
  /// 約束：空 query 回傳完整列表（不篩選）
  Map<SessionStatus, List<SessionInfo>> get filteredGroupedSessions;
}
```

**篩選欄位**（對 SessionInfo）：

| 欄位 | 型別 | 說明 |
|------|------|------|
| `summary` | String | Session 摘要 |
| `projectPath` | String | 專案路徑（含專案名稱） |
| `agentName` | String | Agent 名稱 |

**注意**：SA 建議篩選 `projectName` 和 `gitBranch`，但 SessionInfo model 中無此欄位。實際可用欄位為 `projectPath`（包含專案名稱資訊）和 `agentName`。`summary` 和 `lastMessage` 也是有意義的搜尋目標。

**最終篩選欄位決策**：`summary`、`projectPath`、`agentName`、`lastMessage`

### 2.3 與 SessionListNotifier 的互動方式

```
SessionListNotifier (sessions 資料來源)
        |
        | ref.watch(sessionListNotifierProvider)
        v
SessionListSearchNotifier (篩選邏輯 + 搜尋 UI 狀態)
        |
        | filteredGroupedSessions (計算屬性)
        v
SessionListPage (消費篩選結果)
```

- `SessionListSearchNotifier.build()` 中 `ref.watch(sessionListNotifierProvider)` 監聽 session 列表變化
- 當 WebSocket 推送新 session 資料時，`build()` 重新執行，自動對新資料套用現有 query 篩選
- `SessionListPage` 改為消費 `SessionListSearchNotifier` 的 `filteredGroupedSessions` 而非直接消費 `SessionListNotifier.groupedSessions`

## 3. 邊界條件分析

| 編號 | 邊界條件 | 預期行為 |
|------|---------|---------|
| B1 | 空查詢字串 | 顯示完整列表（不篩選） |
| B2 | 無匹配結果 | 列表顯示空狀態提示（如「No matching sessions」） |
| B3 | 特殊字元輸入（正則元字元等） | 當純文字處理，不做正則解析 |
| B4 | 超長輸入字串 | 正常處理，String.contains 無長度限制 |
| B5 | 篩選中有新 session 進入（WebSocket 推送） | 新 session 自動套用現有篩選條件 |
| B6 | 篩選中已選中的 session 被篩掉 | 選中狀態維持（selectedSessionId 不變），但視覺上不可見 |
| B7 | 所有欄位都是空字串的 session | 只有空 query 時才會顯示 |
| B8 | query 前後有空白 | trim 後再比對 |

## 4. 行為場景（Given-When-Then）

### 場景 1: 基本文字篩選

```
Given: Session 列表包含 3 個 session（summary 分別為 "refactor auth", "add payment", "fix bug"）
When: 使用者開啟搜尋列並輸入 "pay"
Then: 列表僅顯示 "add payment" session
```

### 場景 2: Case-insensitive 篩選

```
Given: Session 列表包含 summary 為 "Refactor Auth Module" 的 session
When: 使用者輸入 "refactor"
Then: 該 session 顯示在篩選結果中
```

### 場景 3: 多欄位匹配

```
Given: Session A 的 summary 為 "fix bug"，projectPath 為 "/Users/dev/payment-service"
When: 使用者輸入 "payment"
Then: Session A 顯示在篩選結果中（匹配 projectPath）
```

### 場景 4: 清空篩選

```
Given: 使用者已輸入 "auth" 且列表已篩選
When: 使用者清空輸入框（或按關閉按鈕）
Then: 列表恢復顯示所有 session
```

### 場景 5: 關閉搜尋列

```
Given: 搜尋列已開啟且有篩選文字
When: 使用者按 Escape 鍵
Then: 搜尋列隱藏，篩選條件清除，列表恢復完整顯示
```

### 場景 6: 即時事件串流進入時的篩選狀態維持

```
Given: 使用者已輸入 "auth" 篩選，列表顯示 2 個匹配 session
When: WebSocket 推送新 session（summary 為 "auth migration"）
Then: 新 session 自動出現在篩選結果中（共 3 個），篩選條件不變
```

### 場景 7: 即時事件串流 — 不匹配的新 session

```
Given: 使用者已輸入 "auth" 篩選
When: WebSocket 推送新 session（summary 為 "add logging"）
Then: 新 session 不出現在篩選結果中
```

### 場景 8: 無匹配結果

```
Given: Session 列表包含多個 session
When: 使用者輸入 "zzzznotexist"
Then: 列表顯示空狀態提示文字
```

### 場景 9: 空查詢顯示全部

```
Given: 搜尋列已開啟
When: 使用者未輸入任何文字（query 為空）
Then: 列表顯示所有 session（與搜尋列未開啟時相同）
```

### 場景 10: Debounce 行為

```
Given: 搜尋列已開啟
When: 使用者快速連續輸入 "a", "au", "aut", "auth"（間隔 < 300ms）
Then: 僅在最後一次輸入後 300ms 執行一次篩選
```

### 場景 11: 特殊字元處理

```
Given: Session 列表包含 projectPath 為 "/Users/dev/my-project (v2)" 的 session
When: 使用者輸入 "(v2)"
Then: 該 session 正確匹配並顯示
```

### 場景 12: 篩選結果保持分組排序

```
Given: 3 個 active session 和 2 個 idle session 匹配篩選條件
When: 篩選結果顯示
Then: 仍按 active/idle/completed 分組，每組內按 lastEventAt 降序排列
```

## 5. 驗收標準

### 功能性

- [ ] AC-1: 文字輸入對 summary、projectPath、agentName、lastMessage 做 case-insensitive contains 篩選
- [ ] AC-2: 篩選結果即時更新（debounce 300ms 後）
- [ ] AC-3: 空 query 顯示完整列表
- [ ] AC-4: 關閉搜尋列清除所有篩選狀態
- [ ] AC-5: WebSocket 推送新 session 時自動套用現有篩選條件
- [ ] AC-6: 篩選結果保持狀態分組和排序
- [ ] AC-7: 無匹配時顯示空狀態提示

### 效能

- [ ] AC-8: 篩選回應時間 < 200ms（已載入資料，本地 String.contains）
- [ ] AC-9: 篩選不影響 WebSocket 即時事件串流

### UX

- [ ] AC-10: Escape 鍵關閉搜尋列
- [ ] AC-11: 搜尋列開啟時 TextField 自動聚焦
- [ ] AC-12: 提供清除/關閉按鈕
