## 3. 資料流程圖

### 3.1 歷史載入流程

```
loadSession(sessionId)
    |
    +--[1] 取消前 session 訂閱 → send(unsubscribe_session, oldId)
    +--[2] 重置 state → events=[], isLoadingHistory=true, sessionId=newId
    +--[3] 請求歷史 → send(get_session_history, sessionId)
    +--[4] 訂閱即時事件 → send(subscribe_session, sessionId)
    |
    v
messageStream 收到 session_history 回應
    |
    +-- 解析 SessionHistoryData(sessionId, events, hasMore)
    +-- state = state.copyWith(events: data.events, hasMore, isLoadingHistory=false)
```

### 3.2 即時事件流程

```
messageStream 收到 session_event
    |
    +-- 解析 SessionEvent.fromJson(message.data)
    +-- event.sessionId == state.sessionId ?
        +-- YES → state = state.copyWith(events: [...events, event])
        +-- NO  → 忽略
```

### 3.3 分頁載入流程

```
loadMoreHistory()
    |
    +-- hasMore == false OR isLoadingHistory == true ?
        +-- YES → 直接返回
        +-- NO  → isLoadingHistory = true
                   before = events.first.timestamp
                   send(get_session_history, sessionId, before)
    |
    v
收到 session_history 回應
    +-- state = state.copyWith(
           events: [...newEvents, ...oldEvents],
           hasMore: data.hasMore,
           isLoadingHistory: false)
```

## 4. 控制流程圖

### 4.1 ConversationNotifier._handleMessage

```
FUNCTION _handleMessage(message):
    TRY:
        SWITCH message.type:
            CASE 'session_history':
                data = SessionHistoryData.fromJson(message.data)
                IF data.sessionId != state.sessionId: RETURN
                IF state.events 非空 AND 這是分頁載入:
                    events = [...data.events, ...state.events]   // prepend
                ELSE:
                    events = data.events                          // 首次載入
                更新 state(events, hasMore=data.hasMore, isLoadingHistory=false)

            CASE 'session_event':
                event = SessionEvent.fromJson(message.data)
                IF event.sessionId == state.sessionId:
                    更新 state(events: [...state.events, event])

            CASE 'error':
                data = ErrorData.fromJson(message.data)
                更新 state(errorMessage=data.code, isLoadingHistory=false)

            DEFAULT:
                忽略（或 log）
    CATCH:
        log ERROR，不中斷 stream
```

### 4.2 MessageBubbleFactory

```
FUNCTION buildBubble(event):
    SWITCH event.type:
        CASE 'user':       RETURN UserMessageBubble(event)
        CASE 'assistant':  RETURN AssistantMessageBubble(event)
        CASE 'tool_use':   RETURN ToolUseBubble(event)
        CASE 'tool_result': RETURN ToolResultBubble(event)
        CASE 'thinking':
            IF event.content.text 為空: RETURN 空 Widget
            RETURN ThinkingBubble(event)
        DEFAULT:           RETURN fallback Widget 或 SizedBox.shrink
```

### 4.3 ConversationView 捲動邏輯

```
初始化:
    scrollController = ScrollController()
    scrollController.addListener(onScrollChanged)

FUNCTION onScrollChanged():
    distanceFromBottom = maxScrollExtent - offset
    IF distanceFromBottom > THRESHOLD:
        notifier.setAutoScroll(false)
    ELSE:
        notifier.setAutoScroll(true)

當 events 列表變化 AND isAutoScrollEnabled:
    WidgetsBinding.addPostFrameCallback:
        scrollController.jumpTo(maxScrollExtent)

跳到最新按鈕 onPressed:
    scrollController.animateTo(maxScrollExtent)
    notifier.setAutoScroll(true)
```

## 8. 3b 拆分評估

### 指標分析

| 指標 | 值 | 觸發拆分? |
|------|---|----------|
| 測試群組數 | 3 個（TG-20/21/22），無交叉依賴 | 是（> 3 但恰好 3 個） |
| 認知負擔指數 | ~12（3 群組 + State/Notifier/Widget 三層 + mock 設定 + 捲動邏輯） | 是（> 10） |
| 跨架構層級數 | 2（Notifier 邏輯層 + Widget UI 層） | 否（<= 2） |
| 預估 context 消耗 | ~25K tokens（Phase 1/2/3a 文件讀取 ~8K + 實作 ~10K + 測試執行 ~7K） | 是（> 20K） |

### 拆分建議：拆為 2 個子任務

認知負擔 > 10 且 context 預估 > 20K，建議拆分。但因 TG-21（ConversationView）依賴 TG-20（Notifier）和 TG-22（Bubble），不能完全並行。

**建議拆分方案**：

| 子任務 | 測試群組 | 測試數 | 修改檔案 | 可並行? |
|--------|---------|--------|---------|--------|
| 3b-A | TG-20（Notifier）+ TG-22（Bubbles） | 15 + 9 = 24 | conversation_notifier.dart, message_bubble_factory.dart, 5 個 bubble widget, test_conversation_factory.dart | 獨立 |
| 3b-B | TG-21（ConversationView） | 8 | conversation_view.dart | 依賴 3b-A 完成 |

**理由**：
- TG-20 和 TG-22 之間無依賴（Notifier 不依賴 Bubble，Bubble 不依賴 Notifier），可合併為一個子任務
- TG-21 的 Widget test 需要 override ConversationNotifier provider，但只需要固定 state（mock），不依賴 Notifier 實作檔案
- 實際上 3b-B 可以在 3b-A **之後**序列執行（因為 ConversationView 需要 import Notifier provider 和 Bubble widgets）
- 但也可並行：3b-B 只需知道 provider 名稱和 state 結構（Phase 1 已定義），mock 掉 Notifier 即可

**最終建議**：**序列執行 2 個子任務**（3b-A 先，3b-B 後）。原因：3b-B 需要 import 3b-A 產出的 Notifier provider 和 Bubble widgets，並行會因檔案不存在而編譯失敗。每個子任務的認知負擔分別為 ~8 和 ~6，均在可管理範圍。
