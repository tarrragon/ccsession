## 1. 測試策略

### 1.1 測試金字塔層次分配

| 層次 | 對應子任務 | 測試目標 | 數量佔比 |
|------|-----------|---------|---------|
| 單元測試 | A（狀態管理）、B（family 化） | Notifier 行為、State 不可變性、Storage 讀寫 | 60% |
| Widget 測試 | C（Widget 層） | UI 渲染、互動手勢、面板佈局 | 30% |
| 整合測試 | D（DashboardPage 整合） | 端對端流程、sidebar 聯動、持久化恢復 | 10% |

### 1.2 分層決策樹

| 被測元件 | 層級 | 測試策略 | 理由 |
|---------|------|---------|------|
| SplitViewNotifier | Layer 3 (UseCase) | BDD 單元測試 (GWT) | 核心業務邏輯 |
| SplitViewStorage | Layer 5 (Data) | 單元測試 | 外部依賴隔離 |
| SplitViewState / PanelState | Layer 5 (Domain) | 單元測試 | 值物件 |
| ConversationNotifier (family) | Layer 3 (UseCase) | BDD 單元測試 | 行為變更驗證 |
| SplitViewContainer | Layer 1 (UI) | Widget 測試 | 佈局渲染 |
| SessionPanel / PanelHeader | Layer 1 (UI) | Widget 測試 | UI 互動 |
| ResizableDivider | Layer 1 (UI) | Widget 測試 | 手勢互動 |
| DashboardPage 整合 | Layer 1 (UI) | 整合測試 | 端對端流程 |

### 1.3 Sociable Unit Tests 原則應用

| 依賴類型 | Mock 策略 | 理由 |
|---------|----------|------|
| SplitViewStorage (Interface) | Mock/Fake | 外部依賴（SharedPreferences） |
| SharedPreferences | Mock | 外部依賴（平台儲存） |
| SplitViewState / PanelState / LayoutMode | 不 Mock | Domain 值物件，使用真實物件 |
| ConversationNotifier（Widget 測試中） | Override | 隔離 WebSocket 等外部依賴 |
| WebSocketService | Mock | 外部依賴（網路） |

## 2. Fake/Mock 設計

### 2.1 FakeSplitViewStorage

記憶體實作 `SplitViewStorage` 介面，用於 SplitViewNotifier 單元測試。

- `save()`: 存入記憶體 Map
- `load()`: 從記憶體讀取
- `clear()`: 清除記憶體
- 可設定 `shouldThrow` 旗標模擬儲存失敗
- 可設定 `loadResult` 直接指定回傳值（用於損壞/不存在場景）

### 2.2 MockSharedPreferences

用於 `SharedPrefsSplitViewStorage` 單元測試，驗證 JSON 序列化/反序列化。

### 2.3 FakeConversationNotifier

用於 Widget 測試中，Override `conversationNotifierProvider(panelIndex)` 以避免 WebSocket 依賴。提供固定的 ConversationState。

##### switchLayout 轉換路徑（6 路徑）

**A-N01: single -> splitHorizontal**（對應場景 1）

```
Given: 當前為 single 模式，panel[0].sessionId = "session-A"
Then（前置驗證）: state.layoutMode == LayoutMode.single
  And: state.panels.length == 1
When: 呼叫 switchLayout(LayoutMode.splitHorizontal)
Then: state.layoutMode == LayoutMode.splitHorizontal
  And: state.panels.length == 2
  And: panels[0].sessionId == "session-A"（保留）
  And: panels[1].sessionId == null（新面板為空）
  And: FakeSplitViewStorage.save 被呼叫（持久化）
```

**A-N02: single -> grid2x2**（對應場景 2）

```
Given: 當前為 single 模式，panel[0].sessionId = "session-A"
Then（前置驗證）: state.panels.length == 1
When: 呼叫 switchLayout(LayoutMode.grid2x2)
Then: state.layoutMode == LayoutMode.grid2x2
  And: state.panels.length == 4
  And: panels[0].sessionId == "session-A"
  And: panels[1].sessionId == null
  And: panels[2].sessionId == null
  And: panels[3].sessionId == null
```

**A-N03: splitHorizontal -> single**（對應場景 3 之變體）

```
Given: splitHorizontal 模式，activePanelIndex = 1，P0=session-A，P1=session-B
Then（前置驗證）: state.panels.length == 2
When: 呼叫 switchLayout(LayoutMode.single)
Then: state.layoutMode == LayoutMode.single
  And: state.panels.length == 1
  And: panels[0].sessionId == "session-B"（保留 activePanel）
```

**A-N04: grid2x2 -> single**（對應場景 3）

```
Given: grid2x2 模式，activePanelIndex = 2
When: 呼叫 switchLayout(LayoutMode.single)
Then: state.panels.length == 1
  And: panels[0].sessionId == 原 P2 的 sessionId
```

**A-N05: grid2x2 -> splitHorizontal**

```
Given: grid2x2 模式，P0=A, P1=B, P2=C, P3=D
When: 呼叫 switchLayout(LayoutMode.splitHorizontal)
Then: state.panels.length == 2
  And: panels[0].sessionId == "A"（保留前 2 個）
  And: panels[1].sessionId == "B"
```

**A-N06: splitHorizontal -> grid2x2**

```
Given: splitHorizontal 模式，P0=A, P1=B
When: 呼叫 switchLayout(LayoutMode.grid2x2)
Then: state.panels.length == 4
  And: panels[0].sessionId == "A"
  And: panels[1].sessionId == "B"
  And: panels[2].sessionId == null
  And: panels[3].sessionId == null
```

**A-N07: 切換到相同模式（邊界 — 無操作）**

```
Given: splitHorizontal 模式
When: 呼叫 switchLayout(LayoutMode.splitHorizontal)
Then: state 不變
```

**A-N08: splitVertical -> splitHorizontal（同面板數切換）**

```
Given: splitVertical 模式，P0=A, P1=B
When: 呼叫 switchLayout(LayoutMode.splitHorizontal)

  And: panels 保留不變（P0=A, P1=B）
```

## 6. 設計決策記錄

### 6.1 場景 12（sessionId 不存在）的測試策略

Phase 1 規格指出 sessionId 存在性驗證在 ConversationNotifier 層處理（server 回傳 error 時面板顯示空狀態），而非 SplitViewNotifier 層。因此：

- SplitViewNotifier 的測試只驗證持久化的 sessionId 被正確載入
- ConversationNotifier 的測試（既有）應已覆蓋 session 不存在時的錯誤處理
- 不在 SplitViewNotifier 層新增 sessionId 驗證測試

### 6.2 grid2x2 關閉面板的行為

Phase 1 規格的 closePanel 約束描述「若剩餘 1 個面板，自動切換到 single 模式」，但未明確定義 grid2x2 關閉 1 個面板（剩餘 3 個）時的 layoutMode 行為。A-N32 標記為需確認。

### 6.3 拖拉調整面板比例的測試範圍

Phase 1 明確聲明面板比例由 Widget 本地 State 管理，不經過 Notifier。因此拖拉測試只驗證 ResizableDivider 的 onDrag callback 是否正確觸發，不測試比例持久化。
