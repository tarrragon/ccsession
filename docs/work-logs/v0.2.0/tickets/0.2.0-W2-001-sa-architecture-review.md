# SA 前置審查報告：v0.2.0 架構重設計

## 執行摘要

### 審查結論
**建議採用混合架構**，整合原有 JSONL file watching 方案與新的 HTTP Hooks 事件驅動架構。

- **評估結果**：現有 5 個 Ticket 需要**架構調整**，但**基本範圍和 Wave 規劃保持不變**
- **新增 Ticket**：建議新增 3 個前置基礎設施 Ticket
- **風險等級**：中（HTTP Hooks 依賴 Claude Code 版本，需降級策略）
- **實作優先順序**：W2 保持不變，W3-W4 依新架構調整

### 核心決策
1. HTTP Hooks 作為**即時事件源**（SubagentStart/Stop、TaskCompleted）
2. JSONL watching 保留**完整對話內容存儲**（Boundary 信號、Tool chain）
3. Go Backend 作為**雙源聚合層**（HTTP endpoint + File watcher）
4. 數據流分離：**事件驅動**（系統狀態變化）vs **內容拉取**（對話詳情）

## 1. 新的 Claude Code 功能分析

### 1.1 Agent 生命週期 Hook 事件

| 事件 | 版本 | 觸發時機 | 關鍵欄位 | 用途 |
|------|------|---------|---------|------|
| `SubagentStart` | v2.1.30+ | subagent 生成時 | `agent_id`, `agent_type` | 追蹤 agent 啟動 |
| `SubagentStop` | v2.1.30+ | subagent 完成時 | `agent_transcript_path`, `last_assistant_message` | 追蹤 agent 生命週期 |
| `TaskCompleted` | v2.1.33+ | 任務完成時 | `task_id`, `status`, `duration` | 標記任務終點 |
| `TeammateIdle` | v2.1.33+ | Agent Team 隊友閒置 | `teammate_id`, `idle_duration` | 協作監控 |
| `WorktreeCreate` | v2.1.50+ | Worktree 建立時 | `worktree_path`, `branch` | 開發環境追蹤 |
| `WorktreeRemove` | v2.1.50+ | Worktree 刪除時 | `worktree_path` | 清理追蹤 |

### 1.2 HTTP Hooks 架構

**變革點**：Hook 可直接 POST JSON 到 URL，無需透過 shell command 中轉。

```
Claude Code
    |
    +-- JSONL append → [File Watcher 實時拉取]
    |
    +-- Agent Event → [HTTP POST] → Go Backend:8765/hooks
                                     ↓
                                  Event Handler
                                     ↓
                                  Session Manager
```

**與現有方案的差異**：
- **現有**：poll-based，定期檢查 JSONL 檔案變更（延遲可能 100ms-1s）
- **新方案**：event-driven，Claude Code 主動推送事件（延遲 < 10ms）

### 1.3 版本依賴

| 功能 | 最低版本 | 說明 |
|------|---------|------|
| 基礎 Hooks 系統 | v2.1.10+ | Hook 本身支援 |
| SubagentStart/Stop | v2.1.30+ | **建議最低版本** |
| HTTP 端點支援 | v2.1.63+ | **關鍵新功能** |
| 完整 Agent 欄位 | v2.1.69+ | `agent_id`, `agent_type` 標準化 |

**現狀**：Claude Code 目前已經推出 v2.1.69+，支援所有功能。但需要注意降級相容性。

### 2.2 數據流詳解

#### 數據流 1：會話初始化（HTTP 事件）
```
Claude Code SubagentStart Event
  ↓
POST /hooks/agent-event
{
  "type": "SubagentStart",
  "agent_id": "abc-123",
  "agent_type": "parsley-flutter-developer",
  "timestamp": "2026-03-25T10:00:00Z"
}
  ↓
Go Backend HTTP Handler
  ↓ (enrichment: 查詢對應 JSONL 檔案)
  ↓
Event Dispatcher → Session Registry
  ↓
WebSocket Server → Frontend: session_list update
```

#### 數據流 2：對話內容流（JSONL + Boundary 信號）
```
Claude Code JSONL append
{
  "type": "assistant",
  "message": { ... },
  "timestamp": "2026-03-25T10:00:10Z",
  "uuid": "msg-456"
}
  ↓
File Watcher (fsnotify)
  ↓
Incremental Read (offset-based)
  ↓
JSONL Parser
  ↓ (展開 content array)
  ↓
SessionEvent (with IsLastContent = true)
  ↓
Event Dispatcher → WebSocket Server
  ↓
Frontend: session_event stream
  ↓
Real-time rendering
```

#### 數據流 3：會話終止（HTTP 事件）
```
Claude Code SubagentStop Event
  ↓
POST /hooks/agent-event
{
  "type": "SubagentStop",
  "agent_id": "abc-123",
  "last_assistant_message": "完成分析",
  "agent_transcript_path": "~/.claude/projects/.../session-uuid.jsonl"
}
  ↓
Go Backend HTTP Handler
  ↓
Event Dispatcher → Session Registry (status: idle → completed)
  ↓
WebSocket Server → Frontend: session_status_change
```

### 2.3 數據源優先級

| 數據類型 | 來源 | 優先級 | 說明 |
|---------|------|--------|------|
| 系統狀態變化 | HTTP Hooks | 主 | SubagentStart/Stop/TaskCompleted，即時準確 |
| 備用系統狀態 | JSONL 檔案存在/消失 | 備 | 如果 HTTP 事件遺失，fallback 到檔案監控 |
| 對話內容 | JSONL 逐行內容 | 唯一 | 完整的訊息、Tool chain、邊界信號，無備選 |
| 會話元數據 | sessions-index.json + HTTP 欄位 | 融合 | 兩者合並，HTTP 優先 |

### 3.2 0.2.0-W2-001 詳細調整

#### 受影響的元件

| 元件 | 原設計 | 新設計 | 變更說明 |
|------|--------|--------|---------|
| File Watcher | 單一職責：fsnotify → SessionEvent | 保留不變 | 繼續作為內容源 |
| JSONL Parser | 保留不變 | 保留不變 | 無變更 |
| Session Registry | 狀態來源：JSONL 檔案生命週期推論 | 新增：HTTP 事件直接更新 | **新增 HTTP event handler** |
| WebSocket Server | 推送 JSONL event | **新增**：推送 HTTP 事件（status change） | 新增 session_status_change type |

#### 新增 HTTP Handler 元件規格

**新增元件**：`HTTPHooksHandler`

```go
type HTTPHooksHandler struct {
    eventDispatcher EventDispatcher
    sessionRegistry SessionRegistry
    logger          *slog.Logger
}

type HookEvent struct {
    Type           string            `json:"type"`     // SubagentStart, SubagentStop, TaskCompleted
    AgentID        string            `json:"agent_id"`
    AgentType      string            `json:"agent_type"`
    Timestamp      string            `json:"timestamp"` // ISO 8601
    TranscriptPath string            `json:"agent_transcript_path,omitempty"`
    LastMessage    string            `json:"last_assistant_message,omitempty"`
    Extra          map[string]string `json:"extra"`
}
```

**職責**：
1. POST `/hooks/agent-event` 端點
2. 驗證 webhook 簽名（可選，後續版本）
3. 解析 HookEvent 並轉換為 SessionEvent
4. 更新 Session Registry 狀態
5. 分發給 Event Dispatcher

**容錯處理**：
- 忽略無法映射到 session 的 HTTP 事件（agent_id → session 映射不存在）
- 記錄 WARN log
- 不中斷主流程

#### 0.2.0-W2-001 驗收條件補充

原驗收條件保持，新增：
- [ ] HTTP `/hooks/agent-event` 端點實現，支援 SubagentStart/Stop 事件
- [ ] HTTP 事件正確觸發 session 狀態轉換（active → idle → completed）
- [ ] HTTP 事件與 JSONL 事件在 Session Registry 中協調無衝突
- [ ] Webhook 事件解析失敗時記錄 WARN log，不中斷服務

## 4. 新增前置基礎設施 Ticket

### 4.1 建議新增 3 個 Ticket

基於 HTTP Hooks 和版本相容性考量，建議新增以下 Ticket：

#### Ticket A：HTTP Hooks 配置與驗證框架

**編號**：0.2.0-W2-001-A（子任務）
**標題**：實作 HTTP Hooks 接收端點與事件驗證框架
**優先級**：P0（0.2.0-W2-001 的前置依賴）
**Wave**：W2
**涵蓋範圍**：
- Go Backend HTTP 端點實現 (`/hooks/agent-event`)
- 事件簽名驗證（如果有）
- HookEvent 數據結構定義
- 與 Session Registry 的整合介面

**依賴**：無
**何時執行**：W2 開始前，作為 0.2.0-W2-001 的先行任務

**風險**：HTTP Hooks 版本依賴，需要 Claude Code v2.1.63+

#### Ticket B：HTTP Hooks 與 JSONL 事件協調機制

**編號**：0.2.0-W2-001-B（子任務）
**標題**：實作 HTTP Hooks 與 JSONL 事件的融合聚合層
**優先級**：P0（0.2.0-W2-001 的核心邏輯）
**Wave**：W2
**涵蓋範圍**：
- Event Dispatcher 增強，支援融合聚合
- 狀態衝突解決（HTTP 事件優先 vs JSONL 事件優先 的決策）
- Deduplication 機制（同一事件不重複推送）
- 事件時序保證（timestamp 排序）

**依賴**：Ticket A 完成
**何時執行**：Ticket A 完成後

**關鍵設計決策**：
- **優先級規則**：HTTP SubagentStop 事件優先設定 `status = completed`，不再等待 30 分鐘 idle timeout
- **Deduplication**：同一 agent_id + timestamp 的事件只推送一次

#### Ticket C：HTTP Hooks 版本相容性與降級策略

**編號**：0.2.0-W2-001-C（子任務）
**標題**：實作 HTTP Hooks 版本檢測與 fallback 機制
**優先級**：P1（降級保障，非核心）
**Wave**：W3 或後續版本
**涵蓋範圍**：
- 系統啟動時檢測 Claude Code 版本
- 版本 < v2.1.63 時，禁用 HTTP Hooks，完全回退 JSONL file watching
- 版本 >= v2.1.63 時，啟用 HTTP Hooks + JSONL 混合方案
- 日誌輸出版本檢測結果

**依賴**：Ticket A 完成
**何時執行**：W3 或之後（低優先級，保障項）

**容錯場景**：
1. Claude Code 版本過舊 → 自動降級，只用 JSONL watching
2. HTTP 端點連線失敗 → 持續重試，JSONL watching 作為備選
3. Hook 簽名驗證失敗 → 拒絕事件，記錄安全告警

## 6. 架構一致性檢查

### 6.1 命名規範

✓ **通過**

- Go 元件命名：`HTTPHooksHandler`, `HookEvent` 遵循 PascalCase（Go convention）
- WebSocket message type：`session_status_change` 保持小寫蛇形（現有規範）

### 6.2 架構模式

✓ **通過，設計目的合理**

新增的 HTTP Hooks Handler 遵循現有架構：
- 單一職責：只負責 HTTP 事件解析和分發

- 事件驅動：與現有 JSONL parser 一樣，都是事件源

```
JSONL Parser → Event
HTTP Handler → Event
                ↓ (融合)
            Event Dispatcher
                ↓

```

### 6.3 依賴方向

✓ **正確**

```
HTTP Handler ───┐
                ├─→ Event Dispatcher
JSONL Parser ───┤
                ├─→ WebSocket Server
Session Registry┘
```

無循環依賴，方向正確（source → dispatcher → output）

### 6.4 事件系統一致性

✓ **保持一致**

HTTP Hooks 事件最終也轉換為統一的 SessionEvent 或 status_change 事件，符合現有事件驅動架構。
