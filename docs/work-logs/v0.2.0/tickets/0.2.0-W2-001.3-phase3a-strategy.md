## 2. 實作策略與虛擬碼

### 2.1 SessionRegistry 核心邏輯

#### 2.1.1 數據結構與初始化

**虛擬碼**：
```
型別 SessionRegistry:
  欄位:
    sessions: Map[SessionID] -> SessionInfo
    mu: Mutex（讀寫鎖）
    now: 函式 () -> 時間戳（可注入，預設 time.Now）

函式 NewSessionRegistry(timeProvider):
  建立新 registry
  返回 SessionRegistry {
    sessions: 空 Map,
    mu: 新 Mutex,
    now: timeProvider 或 time.Now
  }
```

**設計考量**：
- `now` 函式必須可注入，以便測試控制時間
- 使用 RWMutex（讀寫鎖）以支援並發讀
- sessions map 內部使用 SessionID 作為唯一 key

#### 2.1.2 UpsertFromSessionEvent 方法

**虛擬碼**：
```
函式 UpsertFromSessionEvent(sessionEvent SessionEvent):
  獲得寫鎖 mu.Lock()
  延遲解鎖 defer mu.Unlock()

  取 session = sessions[sessionEvent.SessionID]

  如果 session 不存在:
    // 新建 session
    session = SessionInfo {
      ID: sessionEvent.SessionID,
      ProjectPath: sessionEvent.ProjectPath,
      Status: "active",
      FirstEventAt: now(),
      LastEventAt: now(),
      EventCount: 0,
      Summary: "" （先不提取，預留給 Phase 2）
    }
    sessions[sessionEvent.SessionID] = session

  // 更新現有 session
  session.EventCount += 1
  session.LastEventAt = now()

  // 記錄首個 user 事件時戳
  如果 sessionEvent.Type == "user" 且 session.FirstUserMessageAt 為零值:
    session.FirstUserMessageAt = now()

  sessions[sessionEvent.SessionID] = session

  返回 nil
```

**邊界條件**：
- SessionID 為空 → 記錄警告，返回（不插入）
- EventCount 溢出 → Go 的 int 足夠大，非問題
- 時間戳為零值 → 使用 now()

#### 2.1.3 UpsertFromHookEvent 方法

**虛擬碼**：
```
函式 UpsertFromHookEvent(hookEvent HookEvent):
  取 session = sessions[hookEvent.SessionID]

  如果 session 不存在:
    // Hook 事件未找到對應 session → 記錄警告，返回
    log.Warn("hook event for unknown session", sessionID=hookEvent.SessionID)
    返回

  獲得寫鎖

  根據 hookEvent.Type 分支:

  情況 "SubagentStart":
    session.AgentID = hookEvent.AgentID
    session.AgentType = hookEvent.AgentType
    // 不更新 Status 和 EventCount（Hook 事件不算事件）
    session.LastEventAt = now()

  情況 "SubagentStop":
    session.Status = "completed"
    session.LastMessage = hookEvent.LastMessage
    session.LastEventAt = now()
    // 即時轉換，無需等待掃描

  情況 "TeammateIdle":
    // 強制轉 idle（稍後由 computeStatus 邏輯處理）
    session.Status = "idle"
    session.LastEventAt = now()

  情況 "TaskCompleted":
    // 暫時 no-op（v0.2 未定義行為）
    session.LastEventAt = now()

  預設:
    // 未知類型，忽略
    返回

  sessions[hookEvent.SessionID] = session
  解鎖
```

**關鍵點**：
- Hook 事件不增加 EventCount
- SubagentStop 立即設定 "completed"，無需等待定時掃描
- TeammateIdle 強制轉 "idle"
- 所有 Hook 事件都更新 LastEventAt

#### 2.1.4 ScanAndUpdateStatus 定時掃描方法

**虛擬碼**：
```
函式 ScanAndUpdateStatus():
  現在時間 = now()

  獲得寫鎖 mu.Lock()
  延遲解鎖 defer mu.Unlock()

  對於每個 session ∈ sessions:
    新狀態 = computeStatus(session, 現在時間)

    如果 新狀態 != session.Status:
      session.Status = 新狀態
      log.Info("session status changed",
               sessionID=session.ID,
               oldStatus=舊狀態,
               newStatus=新狀態)

  返回 nil
```

**特點**：
- 原子操作（全程持有寫鎖）
- 只比較狀態變化，避免日誌噪音
- 掃描應定期執行（每 30 秒一次，由 EventDispatcher 驅動）

#### 2.1.5 computeStatus 狀態轉換邏輯

**虛擬碼**：
```
函式 computeStatus(session SessionInfo, 現在時間 Time) -> SessionStatus:
  時間差 = 現在時間 - session.LastEventAt

  // 優先級 1：SubagentStop 事件已觸發
  如果 session.Status == "completed":
    返回 "completed"（永遠不轉換）

  // 優先級 2：定時掃描阈值
  如果 時間差 >= 30 分鐘:
    返回 "completed"

  如果 時間差 >= 2 分鐘 且 時間差 < 30 分鐘:
    返回 "idle"

  // 預設
  返回 "active"
```

**狀態轉換表**：

| 當前狀態 | 條件 | 下一狀態 | 備註 |
|---------|------|---------|------|
| active | LastEventAt > 2 min 前 | idle | 自動超時 |
| active | LastEventAt > 30 min 前 | completed | 自動超時 |
| idle | 新 JSONL 事件 | active | 事件觸發（由 Dispatcher 觸發狀態轉換） |
| idle | 新 SubagentStart Hook | active | （Hook 事件，暫不處理） |
| [任意] | SubagentStop Hook | completed | 即時，無需掃描 |
| [任意] | TeammateIdle Hook | idle | 即時，無需掃描 |

#### 2.1.6 Get, List, Count 查詢方法

**虛擬碼**：
```
函式 Get(sessionID String) -> SessionInfo?, 錯誤:
  獲得讀鎖 mu.RLock()
  延遲解鎖 defer mu.RUnlock()

  session, 存在 = sessions[sessionID]
  如果 不存在:
    返回 nil, ErrNotFound

  深度複製 session（避免外部修改）
  返回 複本, nil

函式 List() -> []SessionInfo:
  獲得讀鎖 mu.RLock()
  延遲解鎖 defer mu.RUnlock()

  結果 = []SessionInfo{}
  對於每個 session ∈ sessions:
    深度複製 session
    結果.append(複本)

  返回 結果

函式 Count() -> int:
  獲得讀鎖 mu.RLock()
  延遲解鎖 defer mu.RUnlock()

  返回 len(sessions)
```

**深度複製策略**：
- 複製所有欄位（包括字串和時間戳，Go 中為值類型，自動複製）
- 確保外部修改不影響內部狀態

### 2.2 EventDispatcher 核心邏輯

#### 2.2.1 UnifiedEvent 內部表示

**虛擬碼**：
```
型別 UnifiedEvent:
  // 標準化所有來源的事件為統一格式

  欄位:
    SessionID: 字串
    Source: 列舉值 ("JSONL" | "HTTP_HOOK")
    Type: 事件類型（"user", "assistant", "SubagentStop" 等）
    Timestamp: 時間戳
    Data: 任意結構（可為 SessionEvent 或 HookEvent）
    DedupKey: 字串（source + sessionID + type + timestamp 的組合）

函式 ComputeDedupKey(unified UnifiedEvent) -> 字串:
  返回格式化字串: "{source}#{sessionID}#{type}#{timestamp}"

  // 例子：
  // "JSONL#abc123#user#2026-03-25T12:00:00Z"
  // "HTTP#abc123#SubagentStop#2026-03-25T12:00:05Z"
```

**設計考量**：
- DedupKey 必須包含 timestamp 以支援同一 session 的多個相同類型事件
- timestamp 格式必須統一（RFC3339）
- Source 必須區分（JSONL vs HTTP Hook）

#### 2.2.2 EventDispatcher 結構體與初始化

**虛擬碼**：
```
型別 EventDispatcher:
  欄位:
    registry: SessionRegistry（指標）
    sessionEventCh: 只讀 chan<- SessionEvent
    hookEventCh: 只讀 chan<- HookEvent
    outCh: 只寫 chan<- WebSocketMessage（推送至前端）
    dedupTable: Map[DedupKey] -> bool（最近 5 秒的事件記錄）
    dedupWindow: 時間間隔（5 秒）
    cleanupTicker: 定時器（30 秒一次清理）
    now: 時間提供者函式
    done: chan<- struct{}（停止訊號）

函式 NewEventDispatcher(
    registry SessionRegistry,
    sessionEventCh chan SessionEvent,
    hookEventCh chan HookEvent,
    outCh chan WebSocketMessage,
    timeProvider func() -> Time
) -> EventDispatcher:

  返回 EventDispatcher{
    registry: registry,
    sessionEventCh: sessionEventCh,
    hookEventCh: hookEventCh,
    outCh: outCh,
    dedupTable: 空 Map,
    dedupWindow: 5 秒,
    cleanupTicker: 每 30 秒觸發,
    now: timeProvider,
    done: make(chan struct{})
  }
```

#### 2.2.3 Run 主事件循環

**虛擬碼**：
```
函式 EventDispatcher.Run(ctx Context):
  // 關鍵：使用 select 同時監聽多個 channel

  cleanupTicker = 每 30 秒觸發一次

  for {
    select {

    情況 sessionEvent := <- dispatcher.sessionEventCh:
      // 處理 JSONL 事件
      dispatcher.processSessionEvent(sessionEvent)

    情況 hookEvent := <- dispatcher.hookEventCh:
      // 處理 HTTP Hook 事件
      dispatcher.processHookEvent(hookEvent)

    情況 <- cleanupTicker.C:
      // 定期清理舊去重項
      dispatcher.cleanupDedupTable()
      // 定期掃描狀態轉換
      dispatcher.registry.ScanAndUpdateStatus()

    情況 <- ctx.Done():
      // 優雅關閉
      cleanupTicker.Stop()
      返回

    情況 <- dispatcher.done:
      // 內部停止信號
      cleanupTicker.Stop()
      返回
    }
  }
```

**設計考量**：
- select 同時監聽所有來源，無優先級（Go scheduler 平衡）
- cleanupTicker 觸發兩個動作：清理去重表 + 掃描狀態
- 優雅關閉支援 context cancel 或內部 done 信號
- 所有操作都非阻塞（channel 要麼有資料要麼超時）

#### 2.2.4 processSessionEvent 方法

**虛擬碼**：
```
函式 EventDispatcher.processSessionEvent(evt SessionEvent):
  // Step 1: 建立統一事件格式
  unified = UnifiedEvent{
    SessionID: evt.SessionID,
    Source: "JSONL",
    Type: evt.Type,
    Timestamp: evt.Timestamp,
    Data: evt,
    DedupKey: ComputeDedupKey(...)
  }

  // Step 2: 檢查去重
  如果 dispatcher.shouldDeduplicate(unified.DedupKey):
    log.Debug("dropping duplicate JSONL event", dedupKey=unified.DedupKey)
    返回

  // Step 3: 記錄到去重表
  dispatcher.dedupTable[unified.DedupKey] = true

  // Step 4: 呼叫 Registry 更新狀態
  err = dispatcher.registry.UpsertFromSessionEvent(evt)
  如果 err != nil:
    log.Error("failed to upsert session event", err=err, sessionID=evt.SessionID)
    返回

  // Step 5: 推送到 WebSocket
  dispatcher.pushToWebSocket(unified)

  log.Debug("processed JSONL event", sessionID=evt.SessionID, type=evt.Type)
```

**邊界條件**：
- SessionID 為空 → Registry 會警告，Dispatcher 繼續
- Timestamp 無效 → 使用 now() 替代
- WebSocket 推送失敗 → 記錄但繼續（不阻塞事件流）

#### 2.2.5 processHookEvent 方法

**虛擬碼**：
```
函式 EventDispatcher.processHookEvent(evt HookEvent):
  // Step 1: 建立統一事件格式
  unified = UnifiedEvent{
    SessionID: evt.SessionID,
    Source: "HTTP_HOOK",
    Type: evt.Type,
    Timestamp: ParseTimestamp(evt.Timestamp),（RFC3339）
    Data: evt,
    DedupKey: ComputeDedupKey(...)
  }

  // Step 2: HTTP 事件不進行去重（每次都處理）
  // 原因：Hook 事件的語義是「狀態變化通知」，不可丟棄

  // Step 3: 呼叫 Registry 更新狀態
  // HTTP 事件有優先級：SubagentStop 立即設定 completed
  err = dispatcher.registry.UpsertFromHookEvent(evt)
  如果 err != nil:
    log.Error("failed to upsert hook event", err=err, sessionID=evt.SessionID)
    返回

  // Step 4: 推送到 WebSocket
  dispatcher.pushToWebSocket(unified)

  log.Info("processed HTTP hook event",
           sessionID=evt.SessionID,
           type=evt.Type,
           agentID=evt.AgentID)
```

**為什麼 HTTP 事件不去重**：
- Hook 事件代表狀態變化（SubagentStart/Stop），不可丟棄
- JSONL 重複來自同一檔案反覆觀察
- Hook 重複來自網路重試（應由應用層確保冪等，不由 Dispatcher 去重）

#### 2.2.6 shouldDeduplicate 去重判定

**虛擬碼**：
```
函式 EventDispatcher.shouldDeduplicate(dedupKey 字串) -> bool:
  _, 已存在 = dispatcher.dedupTable[dedupKey]

  如果 已存在:
    返回 true

  返回 false
```

**簡化版本**：
- 查表即可，無需時間檢查（由 cleanupDedupTable 定期清理）

#### 2.2.7 cleanupDedupTable 定期清理

**虛擬碼**：
```
函式 EventDispatcher.cleanupDedupTable():
  現在時間 = dispatcher.now()

  移除項目列表 = []DedupKey{}

  對於每個 (key, 記錄時間) ∈ dispatcher.dedupTable:
    時間差 = 現在時間 - 記錄時間

    // 注意：dedupTable 實現應保留事件的記錄時間
    // 簡化：只保留最近 5 秒的事件，超過則刪除

    如果 時間差 > 5 秒:
      移除項目列表.append(key)

  對於每個 key ∈ 移除項目列表:
    delete(dispatcher.dedupTable, key)

  log.Debug("cleaned up dedup table", removedCount=len(移除項目列表))
```

**實作建議**：
- dedupTable 應存儲 `Map[DedupKey]time.Time`（記錄插入時間）
- 每 30 秒執行一次清理
- 清理成本 O(n)，n 通常很小（5 秒窗口內的重複事件數）

#### 2.2.8 pushToWebSocket 輔助方法

**虛擬碼**：
```
函式 EventDispatcher.pushToWebSocket(unified UnifiedEvent):
  // 轉換為 WebSocket 訊息格式
  msg = WebSocketMessage{
    Type: unified.Type,
    SessionID: unified.SessionID,
    Source: unified.Source,
    Timestamp: unified.Timestamp,
    Payload: unified.Data
  }

  // 非阻塞發送
  select {
  情況 dispatcher.outCh <- msg:
    // 成功推送
    log.Debug("pushed message to websocket", sessionID=unified.SessionID)

  預設:
    // Channel 滿，丟棄
    log.Warn("websocket channel full, dropping message",
             sessionID=unified.SessionID)
  }
```

### 3.2 Red-Green-Refactor 迭代模板

**單個測試的迴圈**：

```
1. 紅燈：寫測試，執行 → FAIL
   - 測試驗證尚未實作的行為

2. 綠燈：最小實作
   - 不考慮優雅性，只讓測試通過
   - 例：hardcode 返回值、簡單 if-else

3. 重構：改進實作
   - 消除重複程式碼
   - 提取輔助函式
   - 改進錯誤處理
   - 確保測試仍通過

4. 提交：git commit
   - 訊息格式：`feat(0.2.0-W2-001.3): {功能} - {測試名稱}`
```

**每批次的迴圈**：
1. 執行該批次的所有測試 → 全紅
2. 實作該批次的所有功能 → 全綠
3. 重構程式碼品質 → 保持綠
4. 提交該批次 → 準備下一批

## 4. Mock 策略與時間控制

### 4.1 時間提供者注入（Time Provider）

**策略**：
```
型別 TimeProvider func() -> Time

在所有需要「現在時間」的地方使用 TimeProvider，而非直接呼叫 time.Now()。

SessionRegistry 初始化：
  registry = NewSessionRegistry(func() -> Time {
    return time.Now()  // 生產環境
  })

測試中注入固定時間：
  fixedTime := time.Date(2026, 3, 25, 12, 0, 0, 0, time.UTC)
  registry = NewSessionRegistry(func() -> Time {
    return fixedTime  // 或使用 mockClock.Now()
  })
```

**優勢**：
- 測試中完全控制時間，確保確定性
- 無需使用 sleeptest
- 可快速模擬時間推進

### 4.2 Channel 模擬策略

**設計**：
```
型別 MockChannels struct {
  SessionEventCh: chan SessionEvent
  HookEventCh: chan HookEvent
  OutCh: chan WebSocketMessage

測試 Step 1: 建立 mock channels
  sessionEventCh := make(chan SessionEvent, 100)
  hookEventCh := make(chan HookEvent, 100)

測試 Step 4: 發送事件
  sessionEventCh <- SessionEvent{...}

測試 Step 5: 驗證輸出（select 超時 1 秒）

  case <- time.After(1 * time.Second):
    fail("no message received")
  }

測試 Step 6: 停止 Dispatcher
  dispatcher.Stop()  // 或 cancel(ctx)
```

|-----|------|------|

### 5.3 潛在風險

| 風險 | 概率 | 影響 | 緩解 |
|-----|------|------|------|
| Channel 阻塞 | 中 | 事件丟失 | 使用 buffer 和非阻塞 select |
| 時間戳不一致 | 低 | 去重失效 | RFC3339 標準化，測試驗證 |
| 並發修改 panic | 低 | 程序崩潰 | 完整的 mutex 保護，並發測試 |
| goroutine 洩漏 | 低 | 記憶體洩漏 | 優雅關閉 + context cancel |

## 10. 核心設計決策理由

### 決策 1：為何選擇 RWMutex？
**替代方案**：全局 Mutex / 無鎖設計（CAS）
**選擇理由**：
- 讀操作（Get, List）遠多於寫操作
- RWMutex 允許多讀者並發，提高吞吐量
- 實作簡單，Go 標準庫支援
**權衡**：寫入時仍需串行

### 決策 2：為何 5 秒去重窗口？
**替代方案**：1 秒 / 30 秒
**選擇理由**：
- FileWatcher 掃描頻率通常 1-5 秒（watchdog 預設 4 秒）
- 5 秒足以覆蓋 JSONL 重複讀，避免冗餘
- 超過 5 秒的重複來自新事件，應計入
**驗證**：測試覆蓋邊界情況

### 決策 3：為何 HTTP 事件不去重？
**替代方案**：HTTP 事件也去重
**選擇理由**：
- HTTP Hook 來自外部系統（Claude Code），不可靠
- SubagentStop 是狀態變化通知，丟棄會導致狀態不同步
- 應用層（SessionRegistry）已實現冪等（同事件多次處理無副作用）
**風險**：若 HTTP 推送方有 bug，可能導致重複處理

### 決策 4：為何 SubagentStop 立即生效？
**替代方案**：等待 ScanAndUpdateStatus（30 秒延遲）
**選擇理由**：
- HTTP Hook 是即時通知，不能延遲
- Phase 1 設計明確要求「即時」
- 避免前端顯示過期狀態
**權衡**：增加代碼複雜性（特殊處理一個事件類型）
