# 0.2.0-W5-012 分析報告：Subagent Context 過大根因分析

## 2. Claude Code Rules 載入機制驗證

### 2.1 實驗結果

| 測試 | 結果 |
|------|------|
| 子目錄遞迴載入？ | 是（core/, flows/, guides/, forbidden/ 全部載入） |
| Session 中新建檔案是否即時載入？ | 否（test-subdir/test-autoload.md 未被 subagent 看到） |
| Subagent 繼承主線程 rules？ | 是（31 個檔案完全一致） |

### 2.2 載入行為結論

- Claude Code 在 session 啟動時掃描 `.claude/rules/` **遞迴**載入所有 `.md` 檔案
- 所有 subagent（Agent tool）繼承相同的 rules context
- **沒有機制**可選擇性載入（無 `.claudeignore`、無 rules include/exclude 設定）

## 3. 可行方案評估

### 方案 A：PM 規則移出 auto-load 路徑

| 項目 | 說明 |
|------|------|
| 做法 | 12 個 PM 檔案移至 `.claude/pm-rules/`（不在 rules/ 下，不自動載入） |
| 效果 | rules/ 從 195KB 降至 104KB（-47%，-45K tokens） |
| 優點 | 最直接，立即見效，subagent 可用空間增加一倍 |
| 缺點 | PM 主線程也不自動載入，需在 session 啟動時手動 Read |
| 風險 | PM 忘記載入規則時可能違反流程 |
| 緩解 | 建立 SessionStart hook 自動提醒 PM 載入 pm-rules |

### 方案 C：Progressive Disclosure 壓縮規則

| 項目 | 說明 |
|------|------|
| 做法 | 每個 rules 檔案只保留 summary（30-50%），詳細內容移到 references/ |
| 效果 | rules/ 從 195KB 降至約 60-100KB（-30~50%） |
| 優點 | 不改目錄結構，PM 體驗不變 |
| 缺點 | 大量改寫工作，壓縮後可能遺失關鍵細節 |
| 風險 | 壓縮過度導致規則執行不完整 |

### 方案 D：A + C 混合（推薦）

| 項目 | 說明 |
|------|------|
| 做法 | PM 規則移出（-91KB） + 剩餘規則壓縮 30%（-31KB） |
| 效果 | rules/ 從 195KB 降至約 73KB（-63%，-61K tokens） |
| 預估 subagent auto-load | 從 ~123K tokens 降至 ~72K tokens |
| 預估 subagent 可用空間 | 從 ~50K tokens 增至 ~100K tokens |

---

## 4. 推薦方案

**推薦方案 D（混合）**，分兩步執行：

**Phase 1（立即，高 ROI）**：方案 A — 移出 PM 專用規則
- 12 個檔案移至 `.claude/pm-rules/`
- 更新 CLAUDE.md 和 README.md 引用路徑
- 建立 SessionStart hook 提醒 PM 載入
- 預期效果：-91KB（-47%）

**Phase 2（後續，中 ROI）**：方案 C — 壓縮剩餘規則
- 針對 quality-common.md（15KB）、ticket-id-conventions.md（13.5KB）等大檔案
- 保留 summary，詳細移到 references/
- 預期效果：額外 -31KB（-16%）
