## 1. 實作概述

### 1.1 模組職責邊界

本 Ticket 實作兩個相互配合的模組：

| 模組 | 職責 | 對應 spec | 輸出 |
|------|------|-----------|------|
| **FileWatcher** | 監控 `~/.claude/projects/` 下所有 `.jsonl` 檔案變更；offset-based 增量讀取；動態偵測新 session | §3.1 | `chan SessionEvent` |
| **JSONLParser** | 逐行解析 JSONL；展開 assistant content array 為多個 `SessionEvent`；設定 ContentIndex 和 IsLastContent Boundary 信號 | §3.2 | `[]SessionEvent` |

### 1.2 核心設計原則

1. **Test-Driven Implementation**：先實作解析器測試（無外部依賴），再實作監控器測試（fsnotify mock）
2. **Offset-Based Incremental Read**：追蹤檔案讀取位置，避免重複讀取或遺漏
3. **Single Event Loop**：使用單一 goroutine 處理 fsnotify 事件，序列處理確保邏輯簡潔
4. **Graceful Degradation**：遇錯不停機，記錄警告後繼續運作
5. **Boundary Signalling**：透過 `ContentIndex` 和 `IsLastContent` 標記訊息邊界

```
  Step 1: 反序列化原始行
    row := parseJSONLRow(line)
    if error:
      return nil, errorWithContext

  Step 2: 初步驗證
    if row.Type is unknown:
      if row.Type in [progress, queue-operation, file-history-snapshot]:
        return nil, nil    // 忽略輔助事件，無 error
      else:
        log.Debug("Unknown type")
        return nil, nil

  Step 3: 提取共同欄位
    timestamp := parseISO8601(row.Timestamp)  // 失敗用 time.Time{} + WARN

      // ~/projects/{encoded-path}/session.jsonl -> {encoded-path}
      // 反轉義："-" -> "/"

  Step 4: 解析 message 欄位
    message := parseRawMessage(row.Message)
    if error:
      return nil, errorWithContext

  Step 5: 依 type 分流

    case row.Type == "assistant":
      return expandAssistantContent(row, message, sessionID, projectPath)
      // content 可能是 string 或 array
      // 若是 array，解包為多個 SessionEvent
      // 若是 string，產生一個 SessionEvent

    case row.Type == "user":
      // message.Content 是 string
      events := [SessionEvent{
        SessionID: sessionID,
        Type: "user",
        ContentIndex: -1,

        Content: EventContent{Text: message.Content},
        ...
      }]
      return events, nil

    case row.Type == "tool_result":
      // 從 message 提取 tool_use_id、content、is_error
      event := SessionEvent{
        Type: "tool_result",
        ContentIndex: -1,
        Content: EventContent{
          ToolUseID: extractToolUseID(message),
          Output: extractOutput(message),
          IsError: extractIsError(message),
        },
        ...
      }
      return [event], nil

    default:
      log.Debug("Unknown type")
      return nil, nil


function expandAssistantContent(row, message, sessionID, projectPath) -> []SessionEvent:

  Step 1: 檢查 content 型別
    if message.Content is string:
      // 單一文字 content，不展開
      event := SessionEvent{
        Type: "assistant",
        ContentIndex: -1,
        IsLastContent: false,
        Content: EventContent{Text: message.Content},
        ...
      }
      return [event]

    if message.Content is not array:
      // 異常情況（既不是 string 也不是 array）
      log.Warn("Invalid content format")
      return nil

  Step 2: 解析 content array
    contentArray := parseContentArray(message.Content)
    if len(contentArray) == 0:
      return []  // 空 array，無事件產生

  Step 3: 展開為多個 SessionEvent
    events := []SessionEvent{}
    for i, item := range contentArray:

      event := SessionEvent{
        SessionID: sessionID,
        Type: item.Type,  // "text", "tool_use", "thinking"
        ContentIndex: i,  // 0-based，關鍵邊界指標
        IsLastContent: (i == len(contentArray) - 1),  // 最後一個為 true
        MessageID: row.UUID,  // 所有子事件共享
        Content: buildEventContent(item),
      }

      events.append(event)

    return events


function buildEventContent(contentItem) -> EventContent:

  switch contentItem.Type:
    case "text":
      return EventContent{Text: contentItem.Text}

    case "tool_use":
      return EventContent{
        ToolName: contentItem.Name,
        ToolInput: contentItem.Input,  // json.RawMessage
        ToolUseID: contentItem.ID,
      }

    case "thinking":
      return EventContent{Text: contentItem.Thinking}

    default:
      log.Warn("Unknown content type")
      return EventContent{}
```

```
struct FileWatcher:
  claudeHome: string                        // ~/.claude 路徑
  watchers: map[string]*SessionFileReader   // 檔案路徑 -> reader
  parser: *JSONLParser                      // 解析器實例
  eventCh: chan SessionEvent                // 輸出通道（buffered）
  watcher: *fsnotify.Watcher                // fsnotify 實例
  mu: sync.RWMutex                          // 保護 watchers map
  ctx: context.Context                      // Stop 訊號
  cancel: context.CancelFunc                // 取消函式


function NewFileWatcher(claudeHome string, bufferSize int) -> (*FileWatcher, error):

  Step 1: 驗證輸入
    if claudeHome is empty:
      return nil, error("claudeHome required")

    if bufferSize <= 0:
      bufferSize = DefaultEventChannelBuffer

  Step 2: 初始化 fsnotify
    watcher, err := fsnotify.NewWatcher()
    if err:
      return nil, errorWithContext("fsnotify init failed")

  Step 3: 建立 FileWatcher 實例
    fw := FileWatcher{
      claudeHome: claudeHome,
      watchers: make(map[string]*SessionFileReader),
      parser: NewJSONLParser(),
      eventCh: make(chan SessionEvent, bufferSize),
      watcher: watcher,
      mu: sync.RWMutex{},
    }

    return &fw, nil


function (fw *FileWatcher) Start(ctx context.Context) -> error:

  Step 1: 儲存 context（用於 Stop 訊號）
    fw.ctx = ctx

  Step 2: 掃描現有檔案
    err := fw.scanExistingFiles()
    if err:
      fw.watcher.Close()
      return errorWithContext("scan existing files failed")

  Step 3: 監控目錄（projects 子目錄）
    projectDir := filepath.Join(fw.claudeHome, SessionProjectsDir)
    if !directoryExists(projectDir):
      fw.watcher.Close()
      return error("projects directory not found")

    err = fw.watcher.Add(projectDir)
    if err:
      fw.watcher.Close()
      return errorWithContext("add directory to watcher failed")

  Step 4: 事件循環（阻塞）
    defer fw.watcher.Close()
    defer close(fw.eventCh)

    for {
      select {
        case <-ctx.Done():
          // 收到停止訊號
          return ctx.Err()

        case event := <-fw.watcher.Events:
          fw.handleFsEvent(event)

        case err := <-fw.watcher.Errors:
          log.Warn("FileWatcher fsnotify error", "error", err)
      }
    }


function (fw *FileWatcher) Events() -> <-chan SessionEvent:
  // 回傳只讀通道
  return fw.eventCh
```

```
function (fw *FileWatcher) scanExistingFiles() -> error:

  Step 1: 建立 projects 目錄路徑
    projectDir := filepath.Join(fw.claudeHome, SessionProjectsDir)

  Step 2: 遞迴掃描目錄
    // projects/ 下有子目錄，每個子目錄代表一個 project
    // 每個 project 下可能有多個 *.jsonl 檔案
    entries := readdir(projectDir)  // 遞迴或 filepath.Walk

    for each entry in entries:
      if entry.IsDir:
        // 掃描子目錄下的 .jsonl 檔案
        subDir := filepath.Join(projectDir, entry.Name)
        subEntries := readdir(subDir)
        for each subEntry in subEntries:
          if subEntry.Name ends with ".jsonl":
            err := fw.addFile(filepath.Join(subDir, subEntry.Name))
            if err:
              log.Warn("add file failed", "path", subEntry.Name)
      else:
        // projects/ 根目錄下不應有檔案，忽略

  Step 3: 回傳
    return nil  // 掃描過程中的錯誤已記錄，不中斷


function (fw *FileWatcher) addFile(filePath string) -> error:

  Step 1: 驗證副檔名
    if !strings.HasSuffix(filePath, JSONLFileExt):
      return nil  // 非 .jsonl，靜默忽略

  Step 2: 加鎖檢查
    fw.mu.Lock()
    defer fw.mu.Unlock()

    if fw.watchers[filePath] != nil:
      return nil  // 已存在，冪等

  Step 3: 建立 SessionFileReader
    reader := SessionFileReader{
      filePath: filePath,
      offset: 0,  // 從頭讀起
      sessionID: extractSessionID(filePath),  // 從路徑提取 session ID
    }

  Step 4: 加入監控
    fw.watchers[filePath] = &reader

    // 同時加入 fsnotify（監控此檔案的變更）
    err := fw.watcher.Add(filePath)
    if err:
      delete(fw.watchers, filePath)
      return errorWithContext("add file to watcher failed")

  Step 5: 回傳
    return nil


function (fw *FileWatcher) handleFsEvent(event fsnotify.Event) -> void:

  Step 1: 過濾非 .jsonl 事件
    if !strings.HasSuffix(event.Name, JSONLFileExt):
      return

  Step 2: 依 event.Op 分流

    case event.Op == fsnotify.Create:
      // 新檔案建立
      fw.addFile(event.Name)

    case event.Op == fsnotify.Write:
      // 檔案被寫入，讀取新行
      fw.mu.RLock()
      reader := fw.watchers[event.Name]
      fw.mu.RUnlock()

      if reader == nil:
        return  // 檔案剛被新增，可能尚未加入 watchers

      err := reader.ReadNewLines(fw.parser, fw.eventCh)
      if err:
        log.Warn("read new lines failed", "path", event.Name, "error", err)

    case event.Op == fsnotify.Remove:
      // 檔案被刪除
      fw.mu.Lock()
      delete(fw.watchers, event.Name)
      fw.mu.Unlock()

      // 發送 session_completed 事件
      event := SessionEvent{
        SessionID: extractSessionID(event.Name),
        Type: "session_completed",
        Timestamp: time.Now(),
      }

      select {
        case fw.eventCh <- event:
          // 成功送出
        case <-fw.ctx.Done():
          // 已停止，忽略
      }

    default:
      // Rename 等其他事件，忽略
```

**Step 10: SessionFileReader 增量讀取**

虛擬碼：

```
struct SessionFileReader:
  filePath: string    // 檔案絕對路徑
  offset: int64       // 已讀取到的位元組位置
  sessionID: string   // 從檔案路徑或 JSONL 欄位提取


function (r *SessionFileReader) ReadNewLines(parser *JSONLParser, eventCh chan<- SessionEvent) -> error:

  Step 1: 開啟檔案
    file, err := os.Open(r.filePath)
    if err:
      if isPermissionError(err):
        log.Warn("permission denied", "path", r.filePath)
        return err  // 回傳 error，caller 記錄並跳過
      return errorWithContext("open file failed")

    defer file.Close()

  Step 2: 尋位到上次讀取位置
    _, err = file.Seek(r.offset, io.SeekStart)
    if err:
      // 可能是檔案被截斷（offset > 檔案大小）
      if isOffsetOutOfBounds(r.filePath, r.offset):
        log.Warn("file truncated, resetting offset", "path", r.filePath)
        r.offset = 0
        return nil  // 下次呼叫時重新讀取
      return errorWithContext("seek failed")

  Step 3: 讀取內容
    content, err := io.ReadAll(file)
    if err:
      return errorWithContext("read file failed")

  Step 4: 按行分割
    lines := bytes.Split(content, []byte{'\n'})

    // 檢查最後一行是否完整（應以換行符結尾）
    // lines[-1] 為空或不為空：
    //   - 若為空：content 以 \n 結尾，所有行完整
    //   - 若非空：最後一行無換行符，表示不完整

  Step 5: 處理行
    lastCompleteLineIndex := len(lines) - 1

    if len(lines[lastCompleteLineIndex]) > 0:
      // 最後一行不完整
      lastCompleteLineIndex -= 1

    for i := 0; i <= lastCompleteLineIndex; i++:
      line := lines[i]

      if len(line) == 0:
        // 空行，跳過
        continue

      // 解析
      events, err := parser.ParseLine(string(line), r.filePath)

      if err:
        // JSON 格式錯誤、缺欄位等
        log.Warn("parse line failed", "path", r.filePath, "error", err)
        continue  // 忽略此行，繼續下一行

      // 送出所有事件
      for _, event := range events:
        select {
          case eventCh <- event:
            // 成功
          case <-ctx.Done():
            // Channel 被關閉，停止
            return ctx.Err()
        }

  Step 6: 更新 offset
    // offset 應指向最後一個完整行結尾（含換行符）之後
    newOffset := r.offset + int64(bytesReadUpToLastCompleteLine())
    r.offset = newOffset

  Step 7: 回傳
    return nil
```

```text
struct SessionEvent:
  SessionID: string              # 從 JSONL 或檔案路徑提取
  ProjectPath: string            # 從檔案路徑反轉義提取
  Type: string                   # user, assistant, tool_use, tool_result, thinking, session_completed

  MessageID: string              # JSONL 行的 UUID，用於去重和 thread 識別
  ContentIndex: int              # Content array 中的 0-based 索引；非 array 訊息為 -1
  IsLastContent: bool            # 該 MessageID 下最後一個子事件時為 true
  Content: EventContent          # 依 Type 的不同有效欄位
  ToolName: string               # tool_result 時的工具名稱
```

## 5. 實作技術細節和 Go 特有考量

### 5.1 Goroutine 和 Channel 生命週期

**核心設計**：

- **單一事件循環 goroutine**：Start() 阻塞執行，fsnotify 事件在主 loop 中序列處理
- **SessionFileReader 讀取是同步的**：不創建額外 goroutine，避免競態
- **eventCh 生命週期**：Start() 開始時建立（NewFileWatcher），Start() 結束時關閉（defer close）
- **Context 傳播**：使用 context.Done() 檢測停止訊號，優雅退出

```text
Main Thread:
  fw.Start(ctx)  ← 阻塞呼叫，在 goroutine 中執行
    |
    +-- 掃描現有檔案
    |
    +-- 事件循環
    |   select {
    |     case <-ctx.Done():  ← 偵測停止訊號
    |       close(fw.eventCh)
    |       return
    |     case event := <-fw.watcher.Events:
    |       handleFsEvent(...)  ← 同步處理，不需 goroutine
    |   }
    |
    v

Caller:
  go fw.Start(ctx)  ← 在 goroutine 中啟動

  for event := range fw.Events() {  ← 消費
    dispatcher.Process(event)
  }
```

### 5.2 Mutex 和競態防護

**watchers map 並發保護**：

```text
操作：讀取 watcher (查詢、處理事件)
  fw.mu.RLock()
  reader := fw.watchers[filePath]
  fw.mu.RUnlock()

  // 釋放鎖後再執行 ReadNewLines，避免持鎖過久

操作：寫入 watcher (新增、刪除)
  fw.mu.Lock()
  fw.watchers[filePath] = reader  // 或 delete(fw.watchers, filePath)
  fw.mu.Unlock()

設計保證：
  ✓ 持鎖期間不呼叫 ReadNewLines（無死鎖風險）
  ✓ SessionFileReader.offset 無鎖，因為單一 goroutine 呼叫
  ✓ eventCh 無鎖（channel 本身是線程安全的）
```

### 5.3 錯誤處理和上下文保留

**Go 1.21+ fmt.Errorf 慣例**：

```text
正確做法：使用 %w 保留錯誤鏈
  return fmt.Errorf("read file %s at offset %d: %w", r.filePath, r.offset, err)

錯誤做法：丟棄上下文
  return errors.New("read failed")

日誌記錄：slog with 結構化欄位
  logger.Warn(msg, "path", filePath, "offset", offset, "error", err)
```

### 5.4 常數管理和魔法數字消除

**constants.go 設計**：

```go
const (
    SessionProjectsDir = "projects"
    JSONLFileExt = ".jsonl"
    DefaultEventChannelBuffer = 100
    FileReadTimeout = 5 * time.Second
)

var (
    // 或使用 const，取決於類型
    MaxRetries = 3
)
```

**禁止硬編碼**：

```text
❌ 錯誤：
  if !strings.HasSuffix(filePath, ".jsonl")
  make(chan SessionEvent, 100)

✅ 正確：
  if !strings.HasSuffix(filePath, JSONLFileExt)
  make(chan SessionEvent, DefaultEventChannelBuffer)
```

### 5.5 Offset 管理細節

**關鍵：offset 應指向已讀內容之後的位元組位置**

```text
檔案內容：
  byte: 0...50        51...100       101...120
  content: "...line1\n"  "...line2\n"  "...incomplete"

初始狀態：
  offset = 0

讀取第一次：
  讀取 0 到 EOF，得到所有內容
  按 \n 分割：[line1, line2, ...incomplete]
  last complete line: line2
  新 offset = 101  (byte 100 的 \n 符後)

讀取第二次：
  Seek(offset=101)
  讀取 101 到 EOF，得到 "...incomplete"
  無完整行（無 \n）
  offset 不變 = 101

讀取第三次（寫入完整）：
  新增 "...incomplete content\n"
  Seek(offset=101)
  讀取 101 到 EOF，得到 "...incomplete content\n"
  解析該行
  新 offset = 121 (or 字節計數)
```

## 8. 技術債務和已知限制

### 最小可行實作的簡化決策

1. **fsnotify Polling 模式**：未來可在 Phase 4 改為 OS 原生機制的最佳化
2. **順序事件處理**：單一 goroutine 事件循環確保簡潔性；未來若性能成瓶頸可升級為 goroutine pool
3. **Error Handling**：容錯傾向於記錄 WARN 並繼續；嚴重錯誤（fsnotify init fail）才會停機
4. **SessionID 提取**：簡化版本直接從路徑提取；未來可考慮從 JSONL 欄位驗證

### Phase 4 建議重構

| 項目 | 現狀 | Phase 4 改善 |
|------|------|-----------|
| 單一事件循環性能 | 可處理 50+ session，頻率 < 100ms | 考慮 goroutine pool 或非同步設計 |
| Offset 管理複雜度 | 手動更新，易出錯 | 封裝成 offset manager struct |
| Error Recovery | 簡單記錄 | 可加入 retry logic 或 circuit breaker |
| JSON 解析效率 | 使用標準 encoding/json | 考慮 fastjson 或 stream parser |

## 9. 與其他模組的整合點

### 與 Event Dispatcher (§3.7) 的契約

**FileWatcher 提供**：

```text
Interface: FileWatcher.Events() <-chan SessionEvent

Properties:
  - Channel 為 buffered (100)
  - 只讀通道，Event Dispatcher 無法寫入
  - Channel 在 Start() 終止時自動關閉（close(fw.eventCh)）

Events Produced:
  - 正常 SessionEvent：user、assistant、tool_result、thinking
  - 特殊 SessionEvent：session_completed

Contract:
  - Event Dispatcher 應能匹配上 eventCh 的生產速度
  - 遇到 session_completed 應通知 Session Registry
```
