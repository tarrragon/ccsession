## Problem Analysis

HTTP Hooks Handler 是 v0.2 新增的事件源之一，與 JSONL file watching 一起構成雙事件源架構。需要實作：
1. HookEvent 結構體定義（含核心欄位和 v0.3 預留欄位）
2. HTTP POST /hooks/agent-event 端點
3. JSON 解析和事件類型路由
4. Non-blocking channel send（避免 Claude Code 請求阻塞）
5. 容錯處理（未知事件類型、JSON 解析失敗）
6. 結構化日誌記錄（layer 欄位必填）

### 實作成果

**建立檔案**：
- `server/hooks_constants.go`：Hook 事件類型常數（SubagentStart/Stop/TaskCompleted/TeammateIdle）+ channel 緩衝大小
- `server/hooks_models.go`：HookEvent struct（核心欄位 + omitempty 欄位 + v0.3 預留）、errorResponse struct
- `server/hooks_messages.go`：Log 訊息常數、提示訊息常數、錯誤訊息常數

- `server/hooks_handler_test.go`：16 個測試案例（table-driven 模式）

**實作細節**：
1. Handler 邏輯遵循 Phase 3a 虛擬碼：讀取 Body → 解析 JSON → 驗證必填欄位 → 檢查事件類型 → non-blocking send → 回傳 200
2. 4 種已知事件類型（SubagentStart/Stop/TaskCompleted/TeammateIdle）的路由和日誌記錄
3. 未知事件類型回傳 200 + WARN log（無訊息體，避免中斷 Claude Code）
4. JSON 解析失敗或必填欄位缺失回傳 400 + ERROR log + errorResponse body
5. Channel 已滿時使用 select + default 實現 non-blocking send，記錄 WARN log 但仍回傳 200
6. 所有 log 使用 log/slog 結構化格式，含 "layer": "hooks_handler" 欄位
7. 常數和訊息集中管理，遵循 quality-go.md 規範
