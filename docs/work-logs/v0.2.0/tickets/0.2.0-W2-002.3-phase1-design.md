# 0.2.0-W2-002.3 Phase 1: Session Conversation View 功能規格設計

---

## 1. 功能需求分析

### 1.1 核心問題

使用者選擇一個 session 後，需要即時查看該 session 的對話內容，包含 5 種訊息類型的渲染和自動捲動行為。

### 1.2 使用者場景

| 場景 | 描述 |
|------|------|
| 首次載入 | 使用者點擊 sidebar session，載入最近 100 筆歷史事件並顯示對話 |
| 即時監控 | session 持續產生新事件，UI 自動 append 並捲動到底部 |
| 回顧歷史 | 使用者手動上捲查看歷史訊息，此時暫停自動捲動 |
| 跳回最新 | 使用者點擊「跳到最新」按鈕，恢復自動捲動 |
| 切換 session | 使用者切換到另一個 session，取消前一個的訂閱並載入新的歷史 |

## 2. 資料模型

### 2.1 現有模型（無需修改）

`SessionEvent` 和 `EventContent` 已完整對應 Go Backend 的 5 種類型：

| type 值 | EventContent 使用欄位 | 說明 |
|---------|----------------------|------|
| `user` | `text` | 使用者輸入文字 |
| `assistant` | `text` | 助手文字回應 |
| `tool_use` | `toolName`, `toolInput`, `toolUseId` | 工具呼叫 |
| `tool_result` | `toolUseId`, `output`, `isError` | 工具執行結果 |
| `thinking` | `text` | 模型思考過程 |

**thinking 類型區分**：spec 3.2 定義 `type: "thinking"` 為獨立的頂層類型（與 `user`、`assistant` 同級），`SessionEvent.type` 值即為 `"thinking"`，不需要額外欄位區分。現有 model 已足夠。

### 2.2 Model 缺陷：SessionEventData 需修正

現有 `SessionEventData` 只有 `sessionId` + `agentId`，缺少實際事件內容。依據 spec 3.3，`session_event` 的 data 就是一個完整的 `SessionEvent`。

**修正方案**：`session_event` 訊息的 `data` 直接用 `SessionEvent.fromJson()` 解析，不需要 `SessionEventData` 中間層。或者擴充 `SessionEventData` 包含完整的 `SessionEvent` 欄位。

**建議**：在 ConversationNotifier 中直接 `SessionEvent.fromJson(message.data)` 解析，繞過不完整的 `SessionEventData`。後續可建技術債 Ticket 統一修正 `SessionEventData`。

### 2.3 新增 State：ConversationState

```dart
@freezed
abstract class ConversationState with _$ConversationState {
  const factory ConversationState({
    /// 當前載入的 session ID
    String? sessionId,

    /// 對話事件列表（按 timestamp 升序）
    @Default([]) List<SessionEvent> events,

    /// 是否正在載入歷史事件
    @Default(false) bool isLoadingHistory,

    /// 是否還有更早的歷史事件可載入
    @Default(false) bool hasMore,

    /// 是否處於自動捲動模式（使用者未手動上捲）
    @Default(true) bool isAutoScrollEnabled,

    /// 錯誤訊息（載入失敗時）
    String? errorMessage,
  }) = _ConversationState;
}
```

## 3. API 介面定義

### 3.1 ConversationNotifier

```dart
@riverpod
class ConversationNotifier extends _$ConversationNotifier {
  /// 初始建構：訂閱 WebSocket messageStream
  @override
  Future<ConversationState> build();

  /// 載入指定 session 的對話
  /// 1. 取消前一個 session 的訂閱
  /// 2. 清空 events
  /// 3. 發送 get_session_history 請求
  /// 4. 發送 subscribe_session 請求
  void loadSession(String sessionId);

  /// 離開 session（取消訂閱）
  void leaveSession();

  /// 設定自動捲動狀態
  void setAutoScroll(bool enabled);

  /// 載入更早的歷史事件（向前分頁）
  void loadMoreHistory();
}
```

**內部訊息處理邏輯**：

| ServerMessage.type | 處理邏輯 |
|--------------------|---------|
| `session_history` | 解析 `SessionHistoryData`，設定 `events`（首次載入）或 prepend（分頁載入），設定 `hasMore` |
| `session_event` | 解析 `SessionEvent.fromJson(message.data)`，若 `sessionId` 匹配則 append 到 `events` |

## 4. 流程設計

### 4.1 載入 session 流程

```
使用者點擊 sidebar session
    |
    v
SessionListNotifier.selectSession(sessionId)
    |
    v
ConversationNotifier.loadSession(sessionId)
    |
    ├── 1. 取消前 session 訂閱（unsubscribeSession）
    ├── 2. 重置 state（events=[], isLoadingHistory=true, hasMore=false）
    ├── 3. 發送 get_session_history(sessionId)
    └── 4. 發送 subscribe_session(sessionId)
    |
    v
收到 session_history 回應
    |
    ├── 設定 events = historyData.events
    ├── 設定 hasMore = historyData.hasMore
    ├── 設定 isLoadingHistory = false
    └── 自動捲動到底部
```

### 4.2 即時事件接收流程

```
Backend 推送 session_event
    |
    v
ConversationNotifier._handleSessionEvent()
    |
    ├── 檢查 event.sessionId == state.sessionId ?
    │   ├── 否 → 忽略
    │   └── 是 → append event 到 events 列表
    |
    v
UI 偵測 events 列表變化
    |
    ├── isAutoScrollEnabled == true → 自動捲動到底部
    └── isAutoScrollEnabled == false → 不捲動，「跳到最新」按鈕保持顯示
```

### 4.3 分頁載入流程

```
使用者點擊「載入更早的訊息」
    |
    v
ConversationNotifier.loadMoreHistory()
    |
    ├── 檢查 hasMore == true && isLoadingHistory == false ?
    │   ├── 否 → 忽略
    │   └── 是 → 設定 isLoadingHistory = true
    │           → 取 events.first.timestamp 作為 before
    │           → 發送 get_session_history(sessionId, before: before)
    |
    v
收到 session_history 回應
    |
    ├── prepend 歷史事件到 events 前面
    ├── 更新 hasMore
    └── 設定 isLoadingHistory = false
```

### 4.4 切換 session 流程

```
使用者點擊另一個 session
    |
    v
ConversationNotifier.loadSession(newSessionId)
    |
    ├── unsubscribeSession(oldSessionId)  // 取消前一個
    ├── 重置 state
    └── 執行 4.1 載入流程
```

## 5. 邊界條件與異常處理

### 5.1 邊界條件

| 條件 | 預期行為 |
|------|---------|
| session 無任何事件 | 顯示空狀態提示文字（如「尚無對話內容」） |
| events 為空且 isLoadingHistory 為 true | 顯示載入指示器 |
| 同一 messageId 的多個子事件（contentIndex） | 各自獨立渲染為不同 Bubble，不做合併 |
| toolInput 為 null 或空 | ToolUseBubble 顯示工具名稱，參數區域顯示「無參數」 |
| toolResult.output 非常長 | 可摺疊區塊預設收合，展開後顯示完整內容 |
| thinking.text 為空字串 | 不渲染該 ThinkingBubble |
| 快速連續切換 session | loadSession 內先取消訂閱再重新載入，確保無競態 |
| WebSocket 斷線重連後 | 重新 subscribe_session + 可選擇重新載入歷史 |

### 5.2 錯誤處理

| 錯誤情境 | 處理方式 |
|---------|---------|
| get_session_history 回傳 error | 設定 errorMessage，UI 顯示錯誤提示 |
| session_event JSON 解析失敗 | log ERROR，忽略該事件，不中斷 stream |
| SESSION_NOT_FOUND | 顯示「Session 不存在或已結束」，清空 events |

## 7. 行為場景提取（Given-When-Then）

### 場景 1: 載入 session 歷史 — 成功

```
Given: 使用者已連線到 WebSocket，sidebar 顯示 session 列表
When: 使用者點擊某個 session
Then: 發送 get_session_history 請求，收到回應後顯示歷史訊息列表
```

### 場景 2: 即時事件接收 — 自動捲動

```
Given: 使用者正在查看某 session，自動捲動開啟
When: Backend 推送新的 session_event
Then: 事件 append 到對話流底部，UI 自動捲動到最新訊息
```

### 場景 3: 手動上捲 — 暫停自動捲動

```
Given: 使用者正在查看某 session，自動捲動開啟
When: 使用者手動向上捲動超過閾值
Then: 自動捲動暫停，底部顯示「跳到最新」按鈕
```

### 場景 4: 跳到最新 — 恢復自動捲動

```
Given: 使用者已手動上捲，「跳到最新」按鈕顯示中
When: 使用者點擊「跳到最新」按鈕
Then: UI 捲動到底部，自動捲動恢復，按鈕消失
```

### 場景 5: 切換 session — 正確清理

```
Given: 使用者正在查看 session-A
When: 使用者點擊 session-B
Then: 取消 session-A 訂閱，清空事件列表，載入 session-B 歷史並訂閱
```

### 場景 6: 5 種訊息類型渲染 — 正確樣式

```
Given: session 歷史包含 user/assistant/tool_use/tool_result/thinking 事件
When: 對話列表渲染完成
Then: 各類型顯示對應樣式（user 靠右藍色、assistant 靠左灰色 Markdown、tool_use/tool_result/thinking 可摺疊）
```

### 場景 7: 空 session — 空狀態

```
Given: 使用者點擊一個尚無任何事件的 session
When: get_session_history 回傳空列表
Then: 顯示空狀態提示文字
```

### 場景 8: 分頁載入 — 載入更早訊息

```
Given: 已載入最近 100 筆事件，hasMore 為 true
When: 使用者觸發載入更多
Then: 以最早事件的 timestamp 作為 before，載入前一批歷史事件並 prepend 到列表前方
```

### 場景 9: session_event JSON 解析失敗 — 容錯

```
Given: 使用者正在查看某 session
When: 收到一個格式異常的 session_event
Then: log ERROR，忽略該事件，不中斷後續事件接收
```
