## 4. 虛擬碼：SessionListSearchNotifier

```
結構 SessionListSearchNotifier:
  私有:
    _debounceTimer: 計時器（可空）
    _currentSearch: SessionListSearchState（跨 build 保留）

  build():
    監聽 sessionListNotifierProvider（觸發自動重建）
    註冊 dispose 回呼（取消 _debounceTimer）
    回傳 _currentSearch

  openSearch():
    _currentSearch = _currentSearch.copyWith(isSearchVisible: true)
    更新狀態

  closeSearch():
    取消 _debounceTimer
    _currentSearch = 預設初始狀態
    更新狀態

  updateQuery(query):
    _currentSearch = _currentSearch.copyWith(query: query)
    更新狀態（立即反映 query 字串到 UI）
    取消前一個 _debounceTimer
    啟動新計時器（300ms 後觸發 _applyFilter）

  _applyFilter():
    // 實際上不需要額外動作 — query 已在 state 中
    // debounce 的目的是延遲 state 更新，避免頻繁重算
    // 修正：updateQuery 應分兩階段 —
    //   立即：更新 _currentSearch.query（供 UI 顯示輸入）
    //   延遲：觸發 state 更新（觸發 filteredGroupedSessions 重算）

  filteredGroupedSessions (計算屬性):
    sessions = 從 sessionListNotifierProvider 讀取完整列表
    IF query 為空（trim 後）:
      回傳 groupByStatus(sessions)
    normalizedQuery = query.trim().toLowerCase()
    filtered = sessions.filter(session =>
      matchesQuery(session, normalizedQuery)
    )
    回傳 groupByStatus(filtered)

  matchesQuery(session, normalizedQuery):
    FOR field IN [summary, projectPath, agentName, lastMessage]:
      IF field.toLowerCase().contains(normalizedQuery):
        回傳 true
    回傳 false

  groupByStatus(sessions):
    result = 空有序映射
    FOR status IN [active, idle, completed]:
      group = sessions.filter(s => s.status == status)
      排序 group 按 lastEventAt 降序
      IF group 非空:
        result[status] = group
    回傳 result
```

### Debounce 策略設計決策

**問題**：ConversationSearchNotifier 的 debounce 只延遲搜尋計算，但立即更新 query 到 state。Session 篩選場景中，`filteredGroupedSessions` 是計算屬性，每次 state 變化都會被消費端重算。

**方案**：與 ConversationSearchNotifier 相同模式 — `updateQuery` 立即更新 `_currentSearch.query` 和 `state`，debounce 計時器到期後再次觸發 state 更新。但因 `filteredGroupedSessions` 是同步計算屬性，實際上每次 state 更新都會觸發 UI 重建和重算。

**最終決策**：debounce 控制的是 `state` 的更新頻率。`updateQuery` 只更新 `_currentSearch`（內部快取），不立即更新 `state`。計時器到期後，才將 `_currentSearch` 寫入 `state`，觸發 UI 重建。

修正虛擬碼：

```
  updateQuery(query):
    取消前一個 _debounceTimer
    _currentSearch = _currentSearch.copyWith(query: query)
    // 注意：不立即更新 state
    啟動新計時器（300ms 後）:
      state = _currentSearch  // 延遲更新，觸發 UI 重建
```

**權衡**：使用者輸入期間 TextField 的文字由 TextEditingController 管理（非 state），所以延遲 state 更新不影響輸入體驗。

## 9. 架構決策記錄

| 決策 | 選擇 | 理由 |
|------|------|------|
| filteredGroupedSessions 放在哪裡 | SearchNotifier 的計算屬性 | 與現有 groupedSessions 模式一致，集中篩選邏輯 |
| groupByStatus 邏輯重複 | SearchNotifier 複製 SessionListNotifier 的分組邏輯 | Phase 4 可提取為共用函式；目前最小可行實作 |
| debounce 延遲 state 還是立即更新 | 延遲更新 state | TextField 由 controller 管理輸入顯示，state 延遲不影響 UX |
| _currentSearch 跨 build 保留 | 與 ConversationSearchNotifier 相同模式 | Riverpod build() 重建會覆寫 state，需額外欄位保留 |
| SearchNotifier 是否接 panelIndex 參數 | 否（無參數） | Session list 全域唯一，不像 ConversationSearch 有多面板 |
