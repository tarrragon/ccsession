# Phase 1 功能規格設計：HTTP Hooks Handler

## 1. 模組概述

### 1.1 職責定義

HTTP Hooks Handler 是 Go Backend 的**系統事件源**，負責接收 Claude Code 透過 HTTP POST 推送的 agent 生命週期事件，將其解析並轉換為系統統一格式，再交由 Event Dispatcher 分發。

此模組在雙源架構中扮演的角色：

```
Claude Code (v2.1.33+)
       |
       | HTTP POST /hooks/agent-event
       v
+---------------------------+
| HTTP Hooks Handler (§3.6) |  <- 本模組
|  - 接收並驗證請求          |
|  - 解析 JSON Body          |
|  - 路由至對應事件處理邏輯   |
|  - 回傳 HTTP 狀態碼        |
+------------+--------------+
             |
             | chan HookEvent
             v
+---------------------------+
| Event Dispatcher (§3.7)   |  <- 下游模組（.3 子任務）
+---------------------------+
```

### 1.2 在雙源架構中的定位

| 事件源 | 模組 | 資料類型 | 延遲特性 |
|--------|------|---------|---------|
| JSONL file watching | File Watcher + JSONL Parser (.1) | 完整對話內容 | fsnotify，< 100ms |
| HTTP Hooks | **本模組 (.2)** | agent 生命週期事件 | 即時推送，< 10ms |

本模組與 .1 子任務**可並行實作**，兩者均向 Event Dispatcher (.3) 提供資料，互不依賴。

## 2. 公開 API 定義

### 2.1 HookEvent 結構體

```go
// HookEvent 表示來自 Claude Code HTTP Hooks 的 agent 生命週期事件。
// 欄位對應 Claude Code HTTP Hooks 的 JSON 推送格式。
//
// 版本依賴：
//   - type/agent_id/agent_type/session_id：v2.1.30+
//   - timestamp 完整欄位：v2.1.69+
//   - agent_transcript_path：v2.1.50+
type HookEvent struct {
    // 核心識別欄位（v2.1.30+）
    Type      string `json:"type"`
    AgentID   string `json:"agent_id"`
    AgentType string `json:"agent_type"`
    SessionID string `json:"session_id"`
    Timestamp string `json:"timestamp"`

    // SubagentStop 專用欄位（omitempty）
    TranscriptPath string `json:"agent_transcript_path,omitempty"`
    LastMessage    string `json:"last_assistant_message,omitempty"`

    // [v0.3 預留] agent 父子關係追蹤
    // 用途：v0.3 AgentNode 拓撲建立時，識別 subagent 的上層 agent
    // 填充時機：SubagentStart 事件中由 Claude Code 提供
    // 若 Claude Code 版本不提供此欄位，值為空字串，不影響 v0.2 功能
    ParentAgentID string `json:"parent_agent_id,omitempty"`
}
```

**欄位說明**：

| 欄位 | 型別 | 必填 | 說明 |
|------|------|------|------|
| `Type` | string | 是 | 事件類型，詳見事件類型常數 |
| `AgentID` | string | 是（SubagentStart/Stop） | agent 的唯一識別符 |
| `AgentType` | string | 否 | agent 類型（如 "subagent", "orchestrator"） |
| `SessionID` | string | 是 | 對應的 session UUID |
| `Timestamp` | string | 是 | ISO 8601 UTC 時間戳 |
| `TranscriptPath` | string | 否 | SubagentStop 時的對話記錄路徑 |
| `LastMessage` | string | 否 | SubagentStop 時的最後回應摘要 |
| `ParentAgentID` | string | 否 | [v0.3 預留] 父 agent 識別符 |

### 2.2 事件類型常數

```go
// HookEventType 定義系統支援的 Hook 事件類型。
// v0.2 必要支援：SubagentStart/Stop/TaskCompleted/TeammateIdle
// v0.2 擴充記錄（不需實作）：WorktreeCreate/WorktreeRemove
const (
    HookEventSubagentStart  = "SubagentStart"   // subagent 生成時（v2.1.30+）
    HookEventSubagentStop   = "SubagentStop"    // subagent 完成時（v2.1.50+）
    HookEventTaskCompleted  = "TaskCompleted"   // 任務完成時（v2.1.33+）
    HookEventTeammateIdle   = "TeammateIdle"    // Agent Team 隊友閒置（v2.1.33+）

    // 下列事件類型為 v2.1.50+ 擴充，v0.2 收到時以「未知事件」邏輯處理（記錄 WARN，回傳 200）
    // v0.3 實作時應新增對應常數與處理邏輯
    // HookEventWorktreeCreate = "WorktreeCreate"
    // HookEventWorktreeRemove = "WorktreeRemove"
)
```

### 2.3 Handler 函式簽名

```go
// HooksHandler 處理 POST /hooks/agent-event 請求。
// 依賴注入 eventCh，將解析完成的 HookEvent 傳入下游 Event Dispatcher。
//
// 回傳：
//   - 200 OK：事件已接收並處理（包含已知/未知事件類型）
//   - 400 Bad Request：JSON 解析失敗
func HooksHandler(eventCh chan<- HookEvent) http.HandlerFunc

// NewHooksHandler 為依賴注入的建構函式，回傳已綁定 channel 的 HandlerFunc。
// 在 main.go 中透過此函式建立 Handler 並注冊路由。
func NewHooksHandler(eventCh chan<- HookEvent) http.HandlerFunc
```

### 2.4 HTTP 端點規格

| 屬性 | 值 |
|------|-----|
| 路徑 | `/hooks/agent-event` |
| 方法 | POST |
| Content-Type | `application/json` |
| 回傳 200 | 事件接收成功（含未知事件類型） |
| 回傳 400 | JSON 解析失敗，Body 包含錯誤訊息 |

**請求 Body 範例（SubagentStart）**：

```json
{
    "type": "SubagentStart",
    "agent_id": "a1b2c3d4-...",
    "agent_type": "subagent",
    "session_id": "f635f2ad-...",
    "timestamp": "2026-03-25T10:30:00.000Z"
}
```

**請求 Body 範例（SubagentStop）**：

```json
{
    "type": "SubagentStop",
    "agent_id": "a1b2c3d4-...",
    "agent_type": "subagent",
    "session_id": "f635f2ad-...",
    "timestamp": "2026-03-25T10:45:00.000Z",
    "agent_transcript_path": "/path/to/transcript.jsonl",
    "last_assistant_message": "任務已完成"
}
```

## 3. 事件類型路由設計

### 3.1 路由邏輯

HTTP Hooks Handler 採用**輕量路由**策略：Handler 本身不執行業務邏輯，僅負責解析和分發；所有狀態更新由 Event Dispatcher 和 Session Registry 處理。

```
POST /hooks/agent-event
       |
       v
[1] 讀取並解析 JSON Body
       |
       +-- 解析失敗 --> 回傳 400 + ERROR log
       |
       v
[2] 識別 event.Type
       |
       +-- SubagentStart  --> 傳入 eventCh，回傳 200
       +-- SubagentStop   --> 傳入 eventCh，回傳 200
       +-- TaskCompleted  --> 傳入 eventCh，回傳 200
       +-- TeammateIdle   --> 傳入 eventCh，回傳 200
       +-- 未知類型        --> WARN log，回傳 200（不傳入 eventCh）
```

### 3.2 各事件的關鍵欄位與語義

| 事件類型 | 關鍵欄位 | 語義 | 觸發的下游動作（Event Dispatcher 職責） |
|---------|---------|------|----------------------------------------|
| `SubagentStart` | `agent_id`, `agent_type`, `session_id` | subagent 開始執行 | Session 狀態轉換為 `active` |
| `SubagentStop` | `agent_id`, `transcript_path`, `last_message` | subagent 執行完成 | Session 狀態轉換為 `completed` |
| `TaskCompleted` | `session_id` | 整體任務完成 | 觸發 `session_status_change` WebSocket 推送 |
| `TeammateIdle` | `session_id` | Agent Team 隊友閒置 | Session 狀態轉換為 `idle` |

注意：事件分發至 Event Dispatcher 後，Handler 即完成職責，不等待下游處理結果。

### 3.3 未知事件類型設計原則

收到不在已知清單中的事件類型時：
1. 記錄 WARN log，包含收到的 type 值（便於偵測 Claude Code 新版本新增的事件）
2. 回傳 200（不回傳 4xx，避免 Claude Code 誤判為錯誤並停止推送）
3. **不傳入** eventCh（避免下游模組收到無法處理的事件）

## 4. 錯誤處理策略

### 4.1 錯誤分類表

| 情境 | HTTP 狀態碼 | Log 層級 | 傳入 eventCh | 說明 |
|------|-----------|---------|------------|------|
| JSON 解析失敗 | 400 | ERROR | 否 | Body 格式錯誤，Claude Code 應修正請求 |
| 未知事件類型 | 200 | WARN | 否 | 可能是新版本事件，安全忽略 |
| 無法映射到已知 session | 200 | WARN | 否 | session_id 不在 Registry 中，Event Dispatcher 處理 |
| 必填欄位為空（如 Type） | 400 | ERROR | 否 | 視同格式錯誤 |

注意：「無法映射到已知 session」的檢查由 Event Dispatcher 執行，Handler 本身不查詢 Session Registry，保持職責單一。

### 4.2 JSON 解析失敗的回應格式

```go
// 400 回應 Body
type errorResponse struct {
    Error string `json:"error"`
}

// 範例：{"error": "invalid JSON: unexpected end of JSON input"}
```

### 4.3 Log 格式要求

遵循 spec §3.4 和 quality-go.md 規範，每條 log 必須包含 `layer` 欄位：

```go
// INFO：成功接收已知事件
logger.Info("hook event received",
    "layer", "hooks_handler",
    "type", event.Type,
    "agent_id", event.AgentID,
    "session_id", event.SessionID)

// WARN：未知事件類型
logger.Warn("unknown hook event type",
    "layer", "hooks_handler",
    "type", event.Type,
    "hint", "may be a new event type from newer Claude Code version")

// ERROR：JSON 解析失敗
logger.Error("failed to parse hook event",
    "layer", "hooks_handler",
    "error", err)
```

## 5. 與其他模組的介面

### 5.1 與 Event Dispatcher (.3) 的介面

HTTP Hooks Handler 透過**有緩衝 channel** 向 Event Dispatcher 傳遞事件，實現非同步解耦。

```go
// channel 型別定義（在 main.go 或共用 types 中宣告）
type HookEventChan chan HookEvent

// 建議 channel 緩衝大小
const HookEventChanBufferSize = 100
```

**Channel 使用規則**：
- Handler 使用 **non-blocking send**（`select` + `default`）避免 Claude Code 請求被阻塞
- 若 channel 已滿，記錄 WARN log 並回傳 200（不丟失 HTTP 回應，但事件可能被丟棄）
- Event Dispatcher 是 channel 的唯一消費者

```go
// non-blocking send 範例
select {
case eventCh <- event:
    // 成功傳入
default:
    logger.Warn("hook event channel full, dropping event",
        "layer", "hooks_handler",
        "type", event.Type)
}
```

### 5.2 與 main.go 的整合

```go
// main.go 中的路由注冊
hookEventCh := make(chan HookEvent, HookEventChanBufferSize)

http.Handle("/hooks/agent-event", NewHooksHandler(hookEventCh))

// 啟動 Event Dispatcher goroutine（.3 子任務負責）
go eventDispatcher.Run(hookEventCh, jsonlEventCh)
```

### 5.3 模組邊界

| 職責 | 模組 | 說明 |
|------|------|------|
| 接收 HTTP 請求、解析 JSON | HTTP Hooks Handler（本模組） | |
| session_id 有效性驗證 | Event Dispatcher (.3) | Handler 不直接查詢 Registry |
| Session 狀態更新 | Session Registry (.3/.4) | Handler 透過 Dispatcher 間接觸發 |
| 事件去重（5 秒窗口） | Event Dispatcher (.3) | 依 agent_id+event_type+timestamp |

## 6. v0.3 預留欄位設計

### 6.1 ParentAgentID 欄位

**預留位置**：`HookEvent.ParentAgentID`

```go
// [v0.3 預留]
ParentAgentID string `json:"parent_agent_id,omitempty"`
```

**預留理由**：
v0.3 計劃實作 AgentNode 拓撲視圖，需要追蹤 subagent 的上層 agent。根據 spec §8 的分析，`SubagentStart` 事件預計會包含 `parent_agent_id` 欄位。提前在 HookEvent struct 中預留此欄位，可讓 v0.3 實作時只需在 Event Dispatcher 中新增處理邏輯，無需修改 HookEvent 定義。

**v0.2 行為**：
- JSON 反序列化時，若 Claude Code 推送了此欄位，會自動填入（不影響 v0.2 功能）
- 若 Claude Code 未推送，值為空字串
- Event Dispatcher 在 v0.2 中不使用此欄位

**已知不確定點**（spec §8.6 記錄）**：
Claude Code 目前實際推送的 `parent_agent_id` 欄位名稱尚未確認。v0.3 實作前應先驗證實際欄位名稱，必要時調整 JSON tag。

### 6.2 v0.2 不實作的事件類型（擴充點）

| 事件類型 | 最低版本 | v0.3 預計用途 |
|---------|---------|--------------|
| `WorktreeCreate` | v2.1.50+ | 追蹤 Worktree 建立，對應 Git branch 資訊 |
| `WorktreeRemove` | v2.1.50+ | 追蹤 Worktree 刪除 |

v0.2 收到上述事件時以「未知事件」處理（記錄 WARN，回傳 200）。v0.3 實作時在常數定義中新增對應常數並加入路由即可，Handler 主體邏輯無需修改。

## 7. 行為場景（Given-When-Then）

### 場景 1：成功接收已知事件（正常流程）

```
Given: HTTP Hooks Handler 已啟動，eventCh 有緩衝空間
When: Claude Code 發送 POST /hooks/agent-event
      Body: {"type":"SubagentStart","agent_id":"abc","session_id":"xyz","timestamp":"2026-03-25T10:00:00.000Z"}
Then: 回傳 HTTP 200
      HookEvent{Type:"SubagentStart", AgentID:"abc", SessionID:"xyz"} 傳入 eventCh
      記錄 INFO log（layer=hooks_handler, type=SubagentStart）
```

### 場景 2：JSON 解析失敗（異常流程）

```
Given: HTTP Hooks Handler 已啟動
When: 接收到格式錯誤的 JSON Body（如截斷的字串）
Then: 回傳 HTTP 400
      Body: {"error": "invalid JSON: ..."}
      記錄 ERROR log（layer=hooks_handler）
      eventCh 不接收任何事件
```

### 場景 3：未知事件類型（邊界條件）

```
Given: HTTP Hooks Handler 已啟動
When: 接收到已知類型以外的事件（如 type="WorktreeCreate"）
Then: 回傳 HTTP 200（不回傳錯誤，避免 Claude Code 停止推送）
      記錄 WARN log（layer=hooks_handler, type=WorktreeCreate, hint=...)
      eventCh 不接收此事件
```

### 場景 4：eventCh 已滿（邊界條件）

```
Given: HTTP Hooks Handler 已啟動，eventCh 緩衝區已滿（Event Dispatcher 暫停消費）
When: Claude Code 發送 POST /hooks/agent-event（已知事件類型）
Then: 回傳 HTTP 200（不阻塞 Claude Code 請求）
      記錄 WARN log（event dropped due to full channel）
      事件被丟棄（可接受，JSONL watching 為備用事件源）
```

### 場景 5：SubagentStop 含 omitempty 欄位（正常流程）

```
Given: HTTP Hooks Handler 已啟動
When: 接收 SubagentStop 事件，Body 包含 agent_transcript_path 和 last_assistant_message
Then: 回傳 HTTP 200
      HookEvent.TranscriptPath 和 LastMessage 正確填入
      HookEvent 傳入 eventCh
```

### 場景 6：v0.3 預留欄位自動填充（預留行為）

```
Given: HTTP Hooks Handler 已啟動（v0.2 版本）
When: 接收到包含 parent_agent_id 欄位的 SubagentStart 事件
Then: 回傳 HTTP 200
      HookEvent.ParentAgentID 正確填入（非空字串）
      Event Dispatcher 在 v0.2 中不使用此欄位，正常分發
```
