# Execution Log

## Task Summary

修正 EventDispatcher 去重鍵語義不匹配（MessageID vs AgentID）

---

## Problem Analysis

### 問題根因

EventDispatcher 去重機制使用 `deduplicationKey` 時，鍵的語義不一致：
- **JSONL 事件**（processSessionEvent）：使用 `event.MessageID` 作為 AgentID（消息級識別符）
- **HTTP Hook 事件**（processHookEvent）：使用 `event.AgentID` 作為 AgentID（代理人級識別符）

這兩個欄位代表**完全不同的概念**，導致同一個 session 的相同事件如果同時從兩個事件源進入，去重鍵會不同，靜默失效。

### 影響範圍

**受影響檔案**：
- `server/event_dispatcher.go`：去重鍵構建邏輯（processSessionEvent、processHookEvent）
- `server/event_dispatcher_test.go`：測試覆蓋

**生產環境場景**：
當 Claude Code 同時產生 JSONL 檔案寫入和 HTTP Hook 事件時，同一個狀態變更可能被推送兩次，導致 Frontend 收到重複事件。

### 相關 Error Pattern

DES-001（Phase 4a code-reviewer 發現）：EventDispatcher 去重鍵語義不匹配，MessageID 和 AgentID 混用。

---

## Solution

### 修復策略

統一去重鍵語義，使 JSONL 和 HTTP Hook 事件使用相同的 AgentID 定義：

#### 1. processSessionEvent（JSONL 事件）
- **修正前**：使用 `event.MessageID`（消息級識別符）
- **修正後**：
  - 優先使用 `session.AgentID`（若 session 已存在）
  - 回退至 `event.SessionID`（若 session 不存在或 AgentID 未設置）
  - 確保語義與 HTTP Hook 事件一致

#### 2. processHookEvent（HTTP Hook 事件）
- **修正前**：直接使用 `event.AgentID`
- **修正後**：
  - 優先使用 `event.AgentID`
  - 回退至 `event.SessionID`（若 AgentID 為空）
  - 確保回退行為與 JSONL 事件一致

### 核心改變

去重鍵從 `{MessageID, Type, TimeWindow}` 改為 `{AgentID（或SessionID), Type, TimeWindow}`，確保同一 session 的事件無論來自哪個事件源，都使用相同的識別符去重。

### Claude Code JSONL 格式調查結論

JSONL SessionEvent 中：
- `MessageID`：來自 `uuid` 欄位，代表 Claude 對話中的單個消息
- **無 AgentID 欄位**：因此從 SessionInfo.AgentID（由 HTTP Hook SubagentStart 設置）回退至 SessionID

這是符合設計的，因為 JSONL 只記錄對話內容，不知道執行的是哪個 agent。
