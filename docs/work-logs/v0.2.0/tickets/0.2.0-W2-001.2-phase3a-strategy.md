## 1. 實作策略設計

### 1.1 核心目標

實作 HTTP Hooks 接收端點，將 Claude Code agent 生命週期事件轉換為統一的 HookEvent 格式，並經由 channel 分發給 Event Dispatcher。

**測試驅動開發順序**：先寫測試（hooks_handler_test.go），再寫實作（hooks_handler.go）

### 1.2 實作順序

#### 第一步：定義資料結構與常數（無需測試）
1. 在 `server/` 目錄下建立 `hooks_handler.go`
2. 定義 `HookEvent` struct，包含：
   - 核心欄位：Type, AgentID, AgentType, SessionID, Timestamp
   - omitempty 欄位：TranscriptPath, LastMessage, ParentAgentID（v0.3 預留）
3. 定義事件類型常數：
   - HookEventSubagentStart = "SubagentStart"
   - HookEventSubagentStop = "SubagentStop"
   - HookEventTaskCompleted = "TaskCompleted"
   - HookEventTeammateIdle = "TeammateIdle"
4. 定義 HTTP 回應的 errorResponse struct
5. 定義常數：HookEventChanBufferSize = 100

#### 第二步：撰寫完整的測試檔案（hooks_handler_test.go）
1. 建立表驅動測試框架
2. 實作 16 個測試案例（對應 Phase 2 的 TC-001 到 TC-016）
3. 使用 httptest 隔離 HTTP 層
4. 實作輔助函式：
   - `sendHookRequest(handler, body)` — 發送 HTTP 請求
   - `expectEventInChannel(eventCh, timeout)` — 驗證 channel 中是否有事件
   - `expectNoEventInChannel(eventCh, timeout)` — 驗證 channel 無事件
5. 所有測試應當失敗（RED 狀態，等待實作）

#### 第三步：實作 Handler（hooks_handler.go）
1. 實作 `NewHooksHandler(eventCh chan<- HookEvent) http.HandlerFunc` 函式
2. 實作 Handler 內部邏輯
3. 執行測試，逐一修正至綠燈（GREEN 狀態）

## 2. 虛擬碼設計

### 2.1 HookEvent 結構體定義

```
struct HookEvent
    Type: string              // 事件類型（SubagentStart 等）
    AgentID: string           // agent 識別符（可選，SubagentStart/Stop 有）
    AgentType: string         // agent 類型（可選）
    SessionID: string         // session UUID（必填）
    Timestamp: string         // ISO 8601 時間戳（必填）

    // omitempty 欄位
    TranscriptPath: string    // SubagentStop 時的對話記錄路徑
    LastMessage: string       // SubagentStop 時的最後回應摘要
    ParentAgentID: string     // [v0.3 預留] 父 agent 識別符
```

### 2.2 Handler 邏輯虛擬碼

#### 主流程

```
function NewHooksHandler(eventCh chan<- HookEvent) -> http.HandlerFunc:
    return func(w http.ResponseWriter, r *http.Request):
        // 第一步：讀取 Request Body
        body_bytes = ReadAll(r.Body)
        if err != nil:
            writeErrorResponse(w, 400, "failed to read body")
            logger.Error("failed to read request body", "layer", "hooks_handler", "error", err)
            return

        // 第二步：解析 JSON
        event = HookEvent{}
        err = json.Unmarshal(body_bytes, &event)
        if err != nil:
            writeErrorResponse(w, 400, "invalid JSON: " + err.Error())
            logger.Error("failed to parse hook event", "layer", "hooks_handler", "error", err)
            return

        // 第三步：驗證必填欄位
        if event.Type == "":
            writeErrorResponse(w, 400, "missing required field: type")
            logger.Error("missing required field", "layer", "hooks_handler", "field", "type")
            return

        if event.SessionID == "":
            writeErrorResponse(w, 400, "missing required field: session_id")
            logger.Error("missing required field", "layer", "hooks_handler", "field", "session_id")
            return

        // 第四步：檢查事件類型是否已知
        if not isKnownEventType(event.Type):
            writeJSONResponse(w, 200, nil)
            logger.Warn("unknown hook event type",
                "layer", "hooks_handler",
                "type", event.Type,
                "hint", "may be a new event type from newer Claude Code version")
            return

        // 第五步：嘗試將事件傳入 channel（非阻塞）
        select:
            case eventCh <- event:
                // 成功傳入
                logger.Info("hook event received",
                    "layer", "hooks_handler",
                    "type", event.Type,
                    "agent_id", event.AgentID,
                    "session_id", event.SessionID)

            default:
                // channel 已滿，事件被丟棄
                logger.Warn("hook event channel full, dropping event",
                    "layer", "hooks_handler",
                    "type", event.Type)

        // 第六步：回傳 200 OK
        writeJSONResponse(w, 200, nil)
```

#### 輔助函式

```
function isKnownEventType(eventType: string) -> bool:
    knownTypes = [
        HookEventSubagentStart,
        HookEventSubagentStop,
        HookEventTaskCompleted,
        HookEventTeammateIdle
    ]
    for knownType in knownTypes:
        if eventType == knownType:
            return true
    return false

function writeErrorResponse(w http.ResponseWriter, statusCode: int, errorMessage: string):
    w.Header().Set("Content-Type", "application/json")
    w.WriteHeader(statusCode)
    errorResp = errorResponse{Error: errorMessage}
    json.NewEncoder(w).Encode(errorResp)

function writeJSONResponse(w http.ResponseWriter, statusCode: int, data interface{}):
    w.Header().Set("Content-Type", "application/json")
    w.WriteHeader(statusCode)
    if data != nil:
        json.NewEncoder(w).Encode(data)
```

## 3. 資料結構選擇

### 3.1 HookEvent 結構體設計決策

| 欄位 | 型別 | JSON Tag | 設計理由 |
|------|------|----------|---------|
| Type | string | `json:"type"` | 必填，無 omitempty（JSON 解析失敗時欄位為空可立即偵測） |
| AgentID | string | `json:"agent_id"` | 可選（TaskCompleted/TeammateIdle 無此欄位） |
| AgentType | string | `json:"agent_type"` | 可選 |
| SessionID | string | `json:"session_id"` | 必填 |
| Timestamp | string | `json:"timestamp"` | 必填 |
| TranscriptPath | string | `json:"agent_transcript_path,omitempty"` | SubagentStop 專用，可空 |
| LastMessage | string | `json:"last_assistant_message,omitempty"` | SubagentStop 專用，可空 |
| ParentAgentID | string | `json:"parent_agent_id,omitempty"` | v0.3 預留，允許為空 |

### 3.2 Channel 設計

**類型**：`chan HookEvent`

**緩衝大小**：100（允許 Event Dispatcher 短暫停頓而不丟失事件）

**使用方式**：
- Handler 以 **non-blocking send** 方式傳遞事件（`select` + `default`）
- 若 channel 已滿，記錄 WARN log 但仍回傳 200（不阻塞 Claude Code 請求）
- Event Dispatcher 是唯一的消費者

## 7. 權宜方案與技術債務

### 7.1 最小可行實作

- **Channel 緩衝大小固定為 100**：暫未支援動態調整（可在 Phase 4 優化）
- **未實作事件去重**：事件去重由 Event Dispatcher 在 Phase 3b .3 實作，Handler 不負責
- **未實作 session 有效性檢查**：由 Event Dispatcher 檢查 session_id 是否存在於 Registry
- **未支援 HTTP 方法驗證**：由 main.go 中的 http.HandleFunc 路由層自動處理（404 on GET）

### 7.2 已知限制

| 限制 | 處理方式 | Phase 4 建議 |
|------|---------|------------|
| 未知事件類型被丟棄 | 記錄 WARN log 以便偵測 | 可積累為指標，未來版本自動識別 |
| channel 滿時丟棄事件 | JSONL watching 作為備用事件源 | 可優化 channel 緩衝策略或異步消費 |
| 無事件去重 | Event Dispatcher 在下游負責 | 可改為在 Handler 層去重以提高效率 |

### 7.3 技術債務標記

- **TD-001**：未來 v0.3 實作時，需驗證 Claude Code 實際推送的 `parent_agent_id` 欄位名稱（Phase 1 design 中的已知不確定點 §6.2）
- **TD-002**：Channel 滿時丟棄事件，可在 Phase 4 評估是否需要改進消費策略
- **TD-003**：未來支援 WorktreeCreate/WorktreeRemove 事件時，需在 constants.go 新增常數並在 isKnownEventType 中判斷

## 8. 語言特定實作注意事項

### 8.1 Go 考量

**標準庫使用**：
- `net/http` 建立 HTTP Handler
- `encoding/json` 解析 JSON（無需外部依賴）
- `log/slog` 記錄日誌（遵循 spec §3.4）
- `io` 讀取 Request Body

**命名規範**（遵循 quality-go.md）：
- 函式名：PascalCase（NewHooksHandler）
- 變數名：camelCase（eventCh, eventBody）
- 常數名：大寫蛇形（HookEventSubagentStart）

**常數管理**（強制，遵循 quality-go.md §2）：
- 在 `server/constants.go` 中定義事件類型常數
- HTTP 狀態碼常數（如果有多個）
- channel 緩衝大小常數：HookEventChanBufferSize = 100

**訊息管理**（強制，遵循 quality-go.md §3）：
- 在 `server/messages.go` 中定義 log 訊息和 API 回應訊息
- 例如：LogHookEventReceived = "hook event received"
- 例如：ErrCodeInvalidJSON = "invalid JSON"

**錯誤處理**：
- 遵循 quality-go.md §5 規範，使用 Sentinel error 或自訂錯誤型別
- 錯誤訊息必須包含上下文，回傳給 Client 的錯誤應使用預定義訊息（不直接暴露內部錯誤）

### 8.2 效能考量

- **JSON 解析**：使用 `json.Unmarshal` 直接反序列化至 struct（無需中間轉換）
- **Non-blocking send**：使用 `select` + `default` 確保 Handler 回應時間 < 100ms
- **Log 記錄**：使用 `log/slog` 的結構化日誌，避免字串拼接

### 8.3 可能的技術挑戰

| 挑戰 | 解決方案 |
|------|---------|
| JSON 欄位名稱大小寫問題 | 使用 JSON tag：`json:"agent_id"`（小寫）|
| omitempty 欄位解析 | `json:"field_name,omitempty"`，未提供時為空字串 |
| channel 接收型別 | 使用 `chan<- HookEvent`（send-only channel），確保 type safety |
| 時間戳格式驗證 | 接收為字串，不做解析驗證（委給 Event Dispatcher） |
