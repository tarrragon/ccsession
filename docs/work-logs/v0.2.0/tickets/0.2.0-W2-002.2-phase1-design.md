## 2. 資料結構定義

### 2.1 SessionListState（Notifier 狀態）

```dart
/// 需求：Session List Sidebar 的完整 UI 狀態
/// 約束：不可變（freezed），包含列表和選擇狀態
@freezed
abstract class SessionListState with _$SessionListState {
  const factory SessionListState({
    /// 完整 session 列表（來自 WebSocket session_list 訊息）
    @Default([]) List<SessionInfo> sessions,

    /// 當前選中的 session ID（null 表示未選擇）
    String? selectedSessionId,
  }) = _SessionListState;
}
```

### 2.2 SessionGroup（分組輔助）

分組不需要額外 model，直接在 Notifier 中以 getter 提供：

```dart
/// 按狀態分組的 session 列表（計算屬性，非儲存狀態）
Map<SessionStatus, List<SessionInfo>> get groupedSessions;
```

分組顯示順序固定：Active -> Idle -> Completed（按 enum 定義順序）。

### 2.3 專案名稱提取

```dart
/// 需求：從 projectPath 提取專案名稱（最後一段路徑）
/// 範例：'/Users/foo/Projects/myapp' -> 'myapp'
/// 邊界：空字串 -> ''；'/' -> ''
String extractProjectName(String projectPath);
```

此為純函式，放在 `session_list_utils.dart`。

## 3. API 介面定義

### 3.1 SessionListNotifier（Riverpod AsyncNotifier）

```dart
/// 檔案：ui/lib/features/session_list/presentation/session_list_notifier.dart
///
/// 需求：管理 session 列表狀態，消費 WebSocket 訊息
/// 約束：使用 @riverpod code generation
@riverpod
class SessionListNotifier extends _$SessionListNotifier {

  /// 初始建構：訂閱 serverMessageProvider，
  /// 發送 get_session_list 請求取得初始列表
  @override
  Future<SessionListState> build();

  /// 需求：使用者點擊 session 時更新選中狀態
  /// 輸入：sessionId - 被點選的 session ID
  /// 輸出：更新 state.selectedSessionId
  void selectSession(String sessionId);

  /// 需求：按狀態分組的 session 列表（計算屬性）
  /// 輸出：Map<SessionStatus, List<SessionInfo>>
  ///   - key 順序：active, idle, completed
  ///   - 每組內按 lastEventAt 降序排列（最近活動在前）
  /// 空組不顯示
  Map<SessionStatus, List<SessionInfo>> get groupedSessions;
}
```

**內部訊息處理邏輯**：

| 訊息類型 | 處理方式 |
|---------|---------|
| `session_list` | 替換整個 sessions 列表 |
| `session_status_change` | 找到對應 session，更新其 status |

### 3.2 selectedSessionIdProvider（便捷 Provider）

```dart
/// 檔案：ui/lib/features/session_list/presentation/session_list_notifier.dart
///
/// 需求：暴露當前選中的 session ID 供其他模組消費
/// 約束：從 SessionListNotifier 衍生，避免重複狀態
@riverpod
String? selectedSessionId(SelectedSessionIdRef ref);
```

### 3.3 Widget API

#### SessionListPage

```dart
/// 檔案：ui/lib/features/session_list/presentation/session_list_page.dart
///
/// 需求：Sidebar 根 Widget，顯示按狀態分組的 session 列表
```

顯示邏輯：
1. AsyncValue loading 時顯示 CircularProgressIndicator
2. AsyncValue error 時顯示錯誤訊息
3. AsyncValue data 時遍歷 groupedSessions，每組渲染 SessionGroupHeader + N 個 SessionListTile
4. 空列表時顯示「無 session」提示文字

#### SessionGroupHeader

```dart
/// 檔案：ui/lib/features/session_list/presentation/widgets/session_group_header.dart
///
/// 需求：分組標題，顯示狀態名稱和 session 計數
/// 範例：「Active (3)」「Idle (1)」「Completed (5)」
class SessionGroupHeader extends StatelessWidget {
  const SessionGroupHeader({
    super.key,
    required this.status,
    required this.count,
  });

  final int count;
}
```

#### SessionListTile

```dart
/// 檔案：ui/lib/features/session_list/presentation/widgets/session_list_tile.dart
///
/// 需求：單一 session 項目，顯示完整資訊和狀態指示燈
/// 約束：點擊觸發 selectSession
class SessionListTile extends ConsumerWidget {
  const SessionListTile({
    super.key,
    required this.session,
    required this.isSelected,
  });

  final SessionInfo session;
  final bool isSelected;
}
```

顯示欄位：

| 欄位 | 來源 | 顯示方式 |
|------|------|---------|
| 摘要 | `session.summary`（空時用 `session.lastMessage` 截取前 50 字元） | 主標題，單行截斷 |
| 專案名稱 | `extractProjectName(session.projectPath)` | 副標題 |
| Git branch | `session.agentName`（spec 對應 gitBranch，目前 model 無此欄位，用 agentName fallback） | 副標題，灰色文字 |
| 最後活動時間 | `session.lastEventAt` | 相對時間（如「2 分鐘前」） |
| 狀態指示燈 | `session.status` | 圓形 icon：green/amber/grey |

**Git branch 說明**：目前 SessionInfo model 無 `gitBranch` 欄位。spec 規格要求此欄位來自 sessions-index.json。本設計暫用 `agentName` 作為 fallback 顯示；待 Backend 補充 gitBranch 欄位後，Tile 只需切換資料來源。此為 model 層的未來擴展，不影響本 Ticket Presentation 層設計。

## 5. 資料流設計

### 5.1 初始載入流程

```
App 啟動
  |
  v
SessionListNotifier.build()
  |
  +-- ref.watch(serverMessageProvider) 訂閱訊息 stream
  |
  +-- ref.read(webSocketServiceProvider).requestSessionList()
  |     發送 get_session_list 請求
  |
  v
等待 WebSocket 回應
  |
  v
收到 session_list 訊息
  |
  v
SessionListNotifier._handleSessionList(SessionListData)
  |
  +-- state = AsyncData(SessionListState(sessions: data.sessions))
```

### 5.2 即時更新流程

```
Server 推送 session_status_change
  |
  v
serverMessageProvider stream 發出 ServerMessage
  |
  v
SessionListNotifier._handleMessage(ServerMessage)
  |
  +-- type == 'session_status_change'
  |     解析 SessionStatusChangeData
  |     找到 sessions 中 id 匹配的項目
  |     以 copyWith(status: newStatus) 建立新列表
  |     更新 state
  |
  +-- type == 'session_list'
       替換整個 sessions 列表
```

### 5.3 使用者互動流程

```
使用者點擊 SessionListTile
  |
  v
onTap callback
  |
  v
ref.read(sessionListNotifierProvider.notifier).selectSession(id)
  |
  v
state = state.copyWith(selectedSessionId: id)
  |
  v
SessionListTile 重建：isSelected 改變 → 顯示選中樣式
```

## 8. 邊界條件和異常處理

### 8.1 空值和極端情況

| 情境 | 處理方式 |
|------|---------|
| sessions 為空列表 | 顯示「沒有工作階段」提示 |
| session.summary 為空字串 | 用 session.lastMessage 前 50 字元作 fallback |
| session.summary 和 lastMessage 都為空 | 顯示 session.id 前 8 字元 |
| session.projectPath 為空字串 | extractProjectName 回傳空字串，不顯示專案名稱 |
| session.projectPath 為 '/' | extractProjectName 回傳空字串 |
| session_status_change 中 sessionId 不在列表中 | 忽略，不 throw |
| WebSocket 未連線時 | SessionListNotifier 處於 AsyncLoading 狀態 |
| WebSocket 斷線後重連 | 重連後自動重新 requestSessionList |

### 8.2 效能考量

| 考量 | 策略 |
|------|------|
| 大量 session（100+） | ListView.builder 懶載入，不一次渲染所有項目 |
| 頻繁 status change | Notifier 只更新變更的 session，不重建整個列表 |
| 分組計算 | groupedSessions 為 getter，每次存取重新計算（session 數量預期 < 100，效能可接受） |

## 9. 行為場景（Given-When-Then）

### 場景 1: 初始載入 — 成功

```
Given: App 已啟動，WebSocket 已連線
When: SessionListNotifier 初始化
Then: 發送 get_session_list 請求，收到回應後顯示按狀態分組的 session 列表
```

### 場景 2: 初始載入 — 空列表

```
Given: App 已啟動，WebSocket 已連線
When: Server 回應 session_list 但 sessions 為空
Then: 顯示「沒有工作階段」提示文字
```

### 場景 3: 即時狀態更新

```
Given: Sidebar 已顯示 session 列表，session A 狀態為 active
When: 收到 session_status_change 訊息，session A 狀態變為 idle
Then: session A 從 Active 組移動到 Idle 組，指示燈由綠色變為琥珀色
```

### 場景 4: 選擇 session

```
Given: Sidebar 已顯示 session 列表
When: 使用者點擊某個 session 項目
Then: selectedSessionId 更新為該 session 的 ID，該項目顯示選中樣式
```

### 場景 5: 選擇不同 session

```
Given: session A 已被選中
When: 使用者點擊 session B
Then: selectedSessionId 更新為 B，A 取消選中樣式，B 顯示選中樣式
```

### 場景 6: 分組排序

```
Given: Server 回傳多個 session，狀態混合
When: 列表渲染完成
Then: 分組順序為 Active -> Idle -> Completed，每組內按 lastEventAt 降序
```

### 場景 7: 摘要 fallback

```
Given: 某 session 的 summary 為空字串
When: 該 session 顯示在列表中
Then: 使用 lastMessage 前 50 字元作為摘要顯示
```

### 場景 8: 未知 session 狀態變更（邊界）

```
Given: Sidebar 已顯示 session 列表
When: 收到 session_status_change，但 sessionId 不在當前列表中
Then: 忽略此訊息，不 throw，列表不變
```

### 場景 9: WebSocket 斷線重連

```
Given: WebSocket 曾斷線後重新連線
When: 重連完成
Then: 自動重新 requestSessionList，刷新整個列表
```

### 場景 10: 空分組不顯示

```
Given: 所有 session 狀態都是 active，沒有 idle 或 completed
When: 列表渲染完成
Then: 只顯示 Active 分組標題和項目，不顯示 Idle 和 Completed 空分組
```
