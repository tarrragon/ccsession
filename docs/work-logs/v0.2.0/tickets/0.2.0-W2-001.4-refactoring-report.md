### Phase 1: 重構計劃

#### 重構動機與目標

Phase 4a 三人組審查發現三個優先級的問題：

1. **P0 — 並發安全**：`readPump`/`writePump` 雙重 `conn.Close()`，`close(client.send)` 缺乏冪等保護，`unregisterClient` 的 `clientCount()` 二次取鎖
2. **P1 — 重複程式碼**：`sendInitialSessionList` 與 `handleGetSessionList` 完全重複；`sendToClient`/`sendToClientUnsafe` 有重複的 marshal 邏輯
3. **P2 — 品質細節**：nil-to-empty 散落四處、硬編碼 log 字串、`interface{}` 應改 `any`、`before` 解析失敗靜默忽略

#### 影響範圍分析

### Phase 2: 重構執行記錄

#### P0: Channel 生命週期管理

1. `Client` 結構體新增 `closeOnce sync.Once`
2. `unregisterClient` 使用 `client.closeOnce.Do` 包裝 `close(client.send)`，並在持鎖期間直接讀 `len(s.clients)` 避免二次取鎖
3. `closeAllClients` 同樣使用 `closeOnce.Do` 保護
4. `writePump` 移除 `defer client.conn.Close()`，只由 `readPump` 負責關閉連線
5. `sendToClient` 的 backpressure 路徑也加上 `closeOnce.Do` 保護

#### P1: 移除未使用欄位 + 合併重複函式

1. 移除 `SessionEventData.Event` 欄位（從未被填入）
2. 刪除 `sendInitialSessionList`，`HandleWS` 直接呼叫 `handleGetSessionList`
3. 提取 `marshalMessage` 函式（共用 JSON 序列化）
4. 提取 `enqueueUnsafe` 函式（共用非阻塞 send 邏輯）
5. `broadcastSessionList`、`pushToSubscribers`、`broadcastStatusChange` 改為 marshal 一次再迭代 enqueue
6. 刪除 `sendToClientUnsafe`（被 `enqueueUnsafe` 取代）

#### P2: 小型修正

1. `interface{}` → `any`（Go 1.21+ 慣例）
2. 硬編碼 `"failed to marshal server message"` → `LogWSMarshalFailed` 常數
3. `before` 解析失敗時新增 `logger.Debug(LogWSInvalidBeforeFormat, ...)` 記錄
4. nil-to-empty slice 防禦：已集中在 `handleGetSessionList`（唯一入口）和 `handleGetSessionHistory` 各一處，`broadcastSessionList` 一處

#### 測試結果驗證

- 所有測試通過（PASS，0 失敗）
- `go vet` 0 問題
- 預期管理：100% 符合預期
