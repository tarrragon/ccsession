## Solution

### 實作內容

**1. event_dispatcher_constants.go** — 常數層
- EventSource 型別（JSONL、HTTP）
- ChangeType 型別（new、updated、status_changed）
- 時間參數（DedupWindowDuration=5s、DedupCleanupInterval=30s）
- 所有 log 訊息常數集中定義

**2. event_dispatcher.go** — 核心實作
- EventDispatcher struct：持有 registry、inputCh、outputCh、dedupTable
- NewEventDispatcher()：建構函式，支援時間注入（便於測試）
- Run(ctx)：主迴圈，管理 sessionEvCh、hookEvCh 的 select、定時掃描、去重清理
- processSessionEvent()：JSONL 事件處理
  - 建立 dedup key（MessageID + Type + 時間窗口）
  - HTTP 優先：检查去重表，若已有 HTTP 記錄則忽略
  - 更新 registry 後推導 ChangeType（new/updated/status_changed）
- processHookEvent()：HTTP 事件處理
  - 解析 RFC3339 timestamp（失敗用 now()）
  - 建立 dedup key（AgentID + Type + 時間窗口）
  - 更新 registry 後推導 ChangeType
- sendToOutCh()：non-blocking send，滿時丟棄
- performStatusScan()：定時掃描，為狀態變更推送事件
- cleanupDedupTable()：定期清理過期去重記錄

**3. event_dispatcher_test.go** — 8 個測試用例
- TestEventDispatcher_ProcessSessionEvent_NewSession：JSONL 新 session
- TestEventDispatcher_ProcessHookEvent_SubagentStart：HTTP 新 session
- TestEventDispatcher_ProcessHookEvent_SubagentStop_Completed：HTTP 強制完成
- TestEventDispatcher_Dedup_HTTPFirst_JSONLIgnored：HTTP 優先、JSONL 忽略
- TestEventDispatcher_Dedup_OutsideWindow：窗口外不去重
- TestEventDispatcher_OutChFull_DropsEvent：滿時丟棄、Registry 仍更新
- TestEventDispatcher_Run_ContextCancel：優雅停止
- TestEventDispatcher_StatusScan：定時掃描觸發狀態變更

### 設計決策

1. **去重策略**：HTTP 優先（3339-timestamp 保證一致性）
2. **時間窗口**：5 秒內相同鍵視為同事件
3. **定時週期**：掃描 30 秒，清理 30 秒（避免 GC 壓力）
4. **輸出通道**：non-blocking，優先保護 registry 更新
5. **測試注入**：所有時間透過 timeProvider 函式注入，支援完全確定的測試
