# 0.2.0-W3-002 Phase 2 測試設計

## HTTP Hooks 版本檢測與 fallback 降級機制

---

## 1. 測試策略總覽

### 1.1 測試分層決策

基於程式碼層級與複雜度：

| 模組 | Layer | 複雜度 | 測試策略 | 理由 |
|------|-------|--------|--------|------|
| ParseClaudeVersion | Domain 邏輯 | 中 | 單元測試 | 純字串解析，無依賴 |
| CompareVersions | Domain 邏輯 | 中 | 單元測試 | 純比較邏輯，無依賴 |
| DetectClaudeVersion | Business Logic | 高 | 單元測試 + Mock | 依賴外部命令執行，需 Mock |
| DisabledHooksHandler | HTTP 路由 | 低 | 整合測試 | HTTP 響應驗證 |

### 1.2 Sociable Unit Tests 原則

| 模塊層級 | Mock 策略 |
|---------|---------|
| CommandRunner（外部依賴） | Mock - 隔離 CLI 依賴 |
| VersionConfig（內部物件） | 不 Mock - 使用真實物件 |
| Logger（外部依賴） | Mock - 驗證 log 輸出，不影響邏輯 |

### 1.3 測試案例組織

測試分為 4 個群組（GWT scenario group）：

1. **TC-01~TC-07**: ParseClaudeVersion 正常與異常解析
2. **TC-08~TC-14**: CompareVersions 版本比較邏輯
3. **TC-15~TC-28**: DetectClaudeVersion 整合測試（含失敗降級）
4. **TC-29~TC-31**: DisabledHooksHandler HTTP 501 響應

## 2. 測試案例詳細設計

### 群組一：ParseClaudeVersion（TC-01~TC-07）

#### TC-01: 標準格式 "2.1.69"

```
Given: claude --version 輸出為 "Claude Code 2.1.69\n"
When:  ParseClaudeVersion("Claude Code 2.1.69\n") 被呼叫
Then:
  - 回傳 ("2.1.69", nil)
  - 錯誤為 nil
```

**測試實作**：
```go
func TestParseClaudeVersionStandardFormat(t *testing.T) {
    output := "Claude Code 2.1.69\n"
    version, err := ParseClaudeVersion(output)

    if err != nil {
        t.Fatalf("unexpected error: %v", err)
    }
    assertEqual(t, "version", version, "2.1.69")
}
```

#### TC-02: v 前綴 "v2.1.63"

```
Given: 輸出為 "claude v2.1.63 stable\n"
When:  ParseClaudeVersion("claude v2.1.63 stable\n") 被呼叫
Then:
  - 回傳 ("2.1.63", nil)
  - v 前綴被正確去除
```

**設計理由**：claude CLI 輸出可能含 v 前綴，必須正規化為 MAJOR.MINOR.PATCH 格式。

#### TC-03: Beta 版本後綴

```
Given: 輸出為 "Claude Code 2.1.70-beta.1\n"
When:  ParseClaudeVersion("Claude Code 2.1.70-beta.1\n") 被呼叫
Then:
  - 回傳 ("2.1.70", nil)
  - beta 後綴被正確過濾，只提取 MAJOR.MINOR.PATCH
```

**設計理由**：後綴（-beta、-rc、等）應被忽略，只比較官方版本號。

#### TC-04: 無版本號輸出

```
Given: 輸出為 "unknown format\n"
When:  ParseClaudeVersion("unknown format\n") 被呼叫
Then:
  - 回傳 ("", ErrVersionParseFailure)
  - 錯誤不為 nil
```

**測試實作**：
```go
func TestParseClaudeVersionNoVersionFound(t *testing.T) {
    output := "unknown format\n"
    version, err := ParseClaudeVersion(output)

    if err == nil {
        t.Fatalf("expected error, got nil")
    }
    assertEqual(t, "error", err, ErrVersionParseFailure)
    assertEqual(t, "version", version, "")
}
```

#### TC-05: 空字串

```
Given: 輸出為 ""
When:  ParseClaudeVersion("") 被呼叫
Then:
  - 回傳 ("", ErrVersionParseFailure)
```

**設計理由**：邊界情況，命令無輸出時應拋出錯誤。

#### TC-06: 多行輸出含版本

```
Given: 輸出為 "Claude Code\nVersion: 2.1.69\nAuthor: Anthropic\n"
When:  ParseClaudeVersion(...) 被呼叫
Then:
  - 回傳 ("2.1.69", nil)
  - 正規化提取第一個版本號
```

**設計理由**：CLI 輸出可能多行，正規表達式應提取版本號。

#### TC-07: 版本號在行尾

```
Given: 輸出為 "Claude Code 2.1.69" （無換行符）
When:  ParseClaudeVersion("Claude Code 2.1.69") 被呼叫
Then:
  - 回傳 ("2.1.69", nil)
  - 正常解析
```

**設計理由**：確保正規表達式不依賴換行符。

## 3. Mock 策略設計

### 3.1 CommandRunner Mock

**介面定義**（version_detect.go）：

```go
type CommandRunner interface {
    Run(name string, args ...string) (output []byte, err error)
}
```

**Mock 實作（version_detect_test.go）**：

```go
type mockCommandRunner struct {
    output []byte
    err    error
}

func (m *mockCommandRunner) Run(name string, args ...string) ([]byte, error) {
    // 驗證呼叫參數
    if name != ClaudeCLICommand || len(args) < 1 || args[0] != ClaudeCLIVersionFlag {
        return nil, errors.New("unexpected command")
    }
    return m.output, m.err
}
```

**Mock 建立輔助函式**：

```go
func newMockRunner(output string, err error) *mockCommandRunner {
    return &mockCommandRunner{
        output: []byte(output),
        err:    err,
    }
}
```

### 3.2 Logger Mock（驗證 Log 輸出）

**驗證方式**（而非 Mock）：

使用 `*testing.T` 的 `Logf` 記錄，或使用 `io.Discard` 以避免污染輸出，或建立 custom handler 驗證特定訊息：

```go
type logCapture struct {
    messages []string
}

func (lc *logCapture) Handle(ctx context.Context, r slog.Record) error {
    lc.messages = append(lc.messages, r.Message)
    return nil
}

// 在測試中
lc := &logCapture{}
handler := slog.NewTextHandler(io.Discard, nil)
logger := slog.New(handler)

cfg := DetectClaudeVersion(logger, runner)

// 驗證 log 是否包含期望訊息
// （實際實作可用 t.Logf 或匹配字串）
```

### 3.3 Context with Timeout Mock

版本檢測應接受 context 參數以支援超時測試：

```go
func DetectClaudeVersion(ctx context.Context, logger *slog.Logger, runner CommandRunner) VersionConfig {
    // 使用 ctx 建立超時 context
    ctx, cancel := context.WithTimeout(ctx, time.Duration(VersionCmdTimeoutSecs)*time.Second)
    defer cancel()

    // ...執行 runner.Run()...
}
```

測試超時：

```go
func TestDetectClaudeVersionTimeout(t *testing.T) {
    ctx, cancel := context.WithTimeout(context.Background(), 1*time.Millisecond)
    defer cancel()

    runner := &slowCommandRunner{delay: 100 * time.Millisecond}

    cfg := DetectClaudeVersion(ctx, logger, runner)

    assertEqualBool(t, "HTTPHooksEnabled", cfg.HTTPHooksEnabled, false)
    // ERROR log 應包含 LogVersionCmdTimeout
}
```

#### 行為鏈：成功版本檢測 → HTTP Hooks 啟用 → 事件處理

```
A: ParseClaudeVersion 成功解析版本號
  ├─ 前置驗證：輸出格式有效（測試輸入範圍）
  └─ 結果：返回有效版本字串

B: CompareVersions 比較版本與閾值
  ├─ 前置驗證：版本字串有效（A 的結果）
  ├─ 邏輯：計算 MAJOR/MINOR/PATCH 差異
  └─ 結果：返回比較結果（-1/0/1）

C: DetectClaudeVersion 決定功能開啟
  ├─ 前置驗證：CommandRunner 可執行（Mock 確保）
  ├─ 前置驗證：版本比較邏輯正確（B 測試驗證）
  ├─ 邏輯：根據版本判定 HTTPHooksEnabled / FullFeaturesAvailable
  └─ 結果：返回 VersionConfig

D: HTTP 路由層決定回應方式
  ├─ 前置驗證：VersionConfig 已初始化（C 的結果）
  ├─ 邏輯：判斷是否掛載 HooksHandler 或 DisabledHooksHandler
  └─ 結果：回傳 200 OK 或 501 Not Implemented
```

- TC-15~TC-28: 驗證決策邏輯正確性，含失敗降級 (C 完整覆蓋)
- TC-29~TC-31: 驗證 HTTP 路由判斷 (D 驗證)
