# 0.2.0-W4-001 Phase 1 功能規格設計：UC-004 多 Session 分割畫面

---

## 1. Purpose

### 核心問題

CLI 環境下同時運行多個 Claude Code agent 時，使用者無法同時監控所有 session。本功能讓使用者在單一畫面中以分割面板方式同時檢視 2-4 個 session 的即時對話。

### 使用者場景

- Developer 同時監控 main agent + 2 個 subagent 的即時進度
- Developer 比較兩個 session 的對話內容
- Developer 在 Grid 2x2 模式下總覽 4 個並行任務

### 2.1 LayoutMode enum

```dart
/// 需求：UC-004 佈局模式，4 種分割方式
enum LayoutMode {

  /// 左右並列 2 面板
  splitHorizontal,

  /// 上下並列 2 面板

```

**面板數量對照**：

| LayoutMode | 面板數 |
|------------|--------|
| single | 1 |
| splitHorizontal | 2 |
| splitVertical | 2 |

### 2.2 PanelState

```dart
/// 需求：單一面板的狀態
/// 約束：不可變（Equatable）
class PanelState extends Equatable {
  const PanelState({
    required this.panelIndex,
    this.sessionId,
  });

  /// 面板位置索引（0-based，對應 LayoutMode 的位置）
  final int panelIndex;

  /// 綁定的 session ID，null 表示空面板
  final String? sessionId;
}
```

**Phase 1 不包含 sizeRatio**：面板大小調整功能以等分為預設值，拖拉調整的比例持久化留待 Phase 4。運行時的拖拉調整仍然支援（由 Widget 層管理），但不持久化。

### 2.3 SplitViewState

```dart
/// 需求：分割畫面的完整 UI 狀態
/// 約束：不可變（Equatable）
class SplitViewState extends Equatable {
  const SplitViewState({
    this.layoutMode = LayoutMode.single,
    this.panels = const [],
    this.activePanelIndex = 0,
    this.maximizedPanelIndex,
  });

  /// 當前佈局模式
  final LayoutMode layoutMode;

  /// 各面板狀態（長度由 layoutMode 決定）
  final List<PanelState> panels;

  /// 當前焦點面板索引（用於 sidebar 點擊時確定目標面板）
  final int activePanelIndex;

  /// 最大化的面板索引，null 表示無面板最大化
  final int? maximizedPanelIndex;
}
```

### 2.4 持久化 JSON Schema

```json
{
  "layoutMode": "splitHorizontal",
  "panels": [
    { "panelIndex": 0, "sessionId": "abc-123" },
    { "panelIndex": 1, "sessionId": "def-456" }
  ]
}
```

**shared_preferences key**: `split_view_state`

**不持久化的欄位**（Phase 1）：`activePanelIndex`、`maximizedPanelIndex`、面板大小比例。

## 3. API 介面定義

### 3.1 SplitViewNotifier

```dart
/// 需求：管理分割畫面狀態
/// 約束：@riverpod code generation，與現有 Notifier 模式一致
@riverpod
class SplitViewNotifier extends _$SplitViewNotifier {

  /// 需求：初始建構，從持久化讀取狀態
  /// 約束：讀取失敗時 fallback 為 single 模式
  @override
  Future<SplitViewState> build();

  /// 需求：切換佈局模式
  /// 約束：
  ///   - 從 single → split/grid：保留 panel[0] 的 sessionId，新面板為空
  ///   - 從 grid → split：保留前 2 個面板，丟棄後 2 個
  ///   - 從 split → single：保留 activePanelIndex 對應的面板
  ///   - 切換後立即持久化
  void switchLayout(LayoutMode mode);

  /// 需求：為指定面板選擇 session
  /// 約束：
  ///   - 觸發該面板的 ConversationNotifier 載入新 session
  ///   - 同時設定 activePanelIndex 為該面板
  ///   - 選擇後立即持久化
  void selectSession({required int panelIndex, required String sessionId});

  /// 需求：調整面板大小比例（運行時，不持久化）
  /// 參數：panelIndex 為分隔線左/上方的面板，ratio 為該面板佔比 (0.0-1.0)
  /// 約束：Phase 1 僅 Widget 層管理，Notifier 不參與
  // void resizePanel({required int panelIndex, required double ratio});

  /// 需求：最大化指定面板
  /// 約束：設定 maximizedPanelIndex，其他面板暫時隱藏但不銷毀
  void maximizePanel(int panelIndex);

  /// 需求：還原最大化面板
  /// 約束：清除 maximizedPanelIndex，所有面板恢復顯示
  void restorePanel();

  /// 需求：關閉指定面板
  /// 約束：
  ///   - 移除面板，剩餘面板重新排列
  ///   - 若剩餘 1 個面板，自動切換到 single 模式
  ///   - 若關閉的是 activePanelIndex，焦點移到 index 0
  ///   - 關閉後立即持久化
  void closePanel(int panelIndex);

  /// 需求：設定焦點面板（點擊面板時觸發）
  void setActivePanel(int panelIndex);
}
```

**resizePanel 設計決策**：Phase 1 面板大小調整由 Widget 層的拖拉手勢直接管理（Flutter 原生行為），不經過 Notifier。Notifier 不持有面板比例狀態。Phase 4 若需持久化比例，再新增此方法。

### 3.4 SplitViewStorage

```dart
/// 需求：分割畫面狀態持久化
/// 約束：使用 shared_preferences，JSON 字串儲存
abstract class SplitViewStorage {
  /// 儲存分割畫面狀態
  /// 約束：只持久化 layoutMode 和 panels[].sessionId
  Future<void> save(SplitViewState state);

  /// 讀取分割畫面狀態
  /// 約束：檔案不存在或損壞時回傳 null
  Future<SplitViewState?> load();

  /// 清除持久化資料
  Future<void> clear();
}
```

```dart
/// 實作：基於 shared_preferences
class SharedPrefsSplitViewStorage implements SplitViewStorage {
  SharedPrefsSplitViewStorage(this._prefs);

  final SharedPreferences _prefs;
  static const _key = 'split_view_state';

  @override
  Future<void> save(SplitViewState state) async {
    final json = _stateToJson(state);
    await _prefs.setString(_key, jsonEncode(json));
  }

  @override
  Future<SplitViewState?> load() async {
    final raw = _prefs.getString(_key);
    if (raw == null) return null;
    try {
      final map = jsonDecode(raw) as Map<String, dynamic>;
      return _stateFromJson(map);
    } on Object {
      return null;
    }
  }

  @override
  Future<void> clear() async {
    await _prefs.remove(_key);
  }
}
```

## 5. 狀態流轉圖

### 5.1 佈局切換流程

```
使用者選擇新 LayoutMode
  → SplitViewNotifier.switchLayout(mode)
    → 計算新 panels 列表
      - 保留可延續的面板 sessionId
      - 新面板 sessionId = null
    → 更新 state（layoutMode + panels）
    → SplitViewStorage.save(state)
    → SplitViewContainer rebuild
      → 根據新 layoutMode 產生對應 Widget 佈局
```

**面板數量轉換規則**：

| 從 \ 到 | single(1) | split(2) | grid(4) |
|---------|-----------|----------|---------|
| single(1) | - | 保留 P0，新增空 P1 | 保留 P0，新增空 P1-P3 |
| split(2) | 保留 activePanel | - | 保留 P0+P1，新增空 P2-P3 |
| grid(4) | 保留 activePanel | 保留 P0+P1，丟棄 P2+P3 | - |

### 5.2 面板 session 選擇流程

```
使用者在 sidebar 點擊 session
  → SessionListNotifier.selectSession(sessionId)（現有行為不變）
  → SplitViewNotifier.selectSession(panelIndex: activePanelIndex, sessionId: sessionId)
    → 更新 panels[activePanelIndex].sessionId
    → SplitViewStorage.save(state)
    → ConversationNotifier(activePanelIndex).loadSession(sessionId)
```

**DashboardPage ref.listen 變更**：現有 `ref.listen(selectedSessionIdProvider)` 需改為由 SplitViewNotifier 橋接。當 `selectedSessionIdProvider` 變更時，SplitViewNotifier 將 sessionId 指派給 activePanelIndex。

### 5.3 持久化讀取時機

```
App 啟動
  → SplitViewNotifier.build()
    → SplitViewStorage.load()
      → 成功 → 驗證 panels 數量與 layoutMode 一致性
        → 不一致 → 以 layoutMode 為準補齊/裁剪
        → 驗證每個 panel.sessionId 是否存在於 session 列表
          → 不存在 → sessionId 設為 null
      → 失敗（null）→ 回退 SplitViewState() 預設值（single, 空 panels）
```

**sessionId 存在性驗證時機**：SplitViewNotifier 在 `build()` 中無法立即驗證 sessionId（session 列表尚未載入）。因此：
1. `build()` 時直接套用持久化的 sessionId
2. 各面板的 ConversationNotifier 嘗試 `loadSession(sessionId)` 時，若 server 回傳 error，面板顯示空狀態
3. 當 session 列表首次載入後，SplitViewNotifier 可選擇性清理不存在的 sessionId

### 5.4 持久化寫入時機

| 操作 | 持久化 |
|------|--------|
| switchLayout | 立即 |
| selectSession | 立即 |
| closePanel | 立即 |
| maximizePanel / restorePanel | 不持久化（Phase 1） |
| setActivePanel | 不持久化 |
| resizePanel | 不持久化（Phase 1） |

## 6. 行為場景（Given-When-Then）

### 場景 1: 佈局模式切換 — Single to Split Horizontal（驗收 1）

```
Given: 當前為 single 模式，panel[0] 顯示 session-A
When: 使用者切換到 splitHorizontal 模式
Then: 主區域分割為左右兩面板
  And: 左面板 (P0) 保留 session-A
  And: 右面板 (P1) 為空面板
```

### 場景 2: 佈局模式切換 — Single to Grid 2x2（驗收 1）

```
Given: 當前為 single 模式，panel[0] 顯示 session-A
When: 使用者切換到 grid2x2 模式
Then: 主區域分割為 2x2 四格
  And: P0 保留 session-A
  And: P1, P2, P3 為空面板
```

### 場景 3: 佈局模式切換 — Grid to Single（驗收 1）

```
Given: 當前為 grid2x2 模式，activePanelIndex = 2
When: 使用者切換到 single 模式
Then: 主區域只顯示 P2 的 session
  And: 其他面板的 session 訂閱被取消
```

### 場景 4: 面板獨立選擇 session（驗收 2）

```
Given: splitHorizontal 模式，P0 為空，P1 為空
When: 使用者點擊 P0 設定為焦點面板
  And: 使用者在 sidebar 點擊 session-A
Then: P0 顯示 session-A 的對話
When: 使用者點擊 P1 設定為焦點面板
  And: 使用者在 sidebar 點擊 session-B
Then: P1 顯示 session-B 的對話
  And: P0 仍顯示 session-A
```

### 場景 5: 所有面板同時即時更新（驗收 3）

```
Given: splitHorizontal 模式，P0 訂閱 session-A，P1 訂閱 session-B
When: session-A 和 session-B 同時有新事件
Then: P0 和 P1 的對話內容同時即時更新
  And: 各面板獨立運行 WebSocket 訂閱
```

### 場景 6: 面板大小拖拉調整（驗收 4）

```
Given: splitHorizontal 模式，兩面板等分
When: 使用者拖拉中間分隔線向右
Then: 左面板變大，右面板變小
  And: 對話內容自適應新寬度
  And: 調整過程流暢
```

### 場景 7: 面板最大化（驗收 5）

```
Given: splitHorizontal 模式，P0 和 P1 均顯示 session
When: 使用者雙擊 P0 的標題列
Then: P0 最大化填滿主區域
  And: P1 暫時隱藏
  And: layoutMode 不變（仍為 splitHorizontal）
```

### 場景 8: 面板還原（驗收 5）

```
Given: P0 處於最大化狀態
When: 使用者再次雙擊 P0 的標題列
Then: 還原為 splitHorizontal 佈局
  And: P0 和 P1 均恢復顯示
  And: 各面板綁定的 session 不變
```

### 場景 9: 面板關閉與自動填滿（驗收 6）

```
Given: splitHorizontal 模式，P0 顯示 session-A，P1 顯示 session-B
When: 使用者點擊 P1 的關閉按鈕
Then: P1 關閉
  And: P0 自動填滿整個主區域
  And: layoutMode 自動降級為 single
  And: session-A 繼續顯示
```

### 場景 10: layoutMode 持久化與恢復（驗收 7）

```
Given: 使用者設定 splitHorizontal 模式
When: 應用關閉並重啟
Then: layoutMode 恢復為 splitHorizontal
  And: 主區域顯示左右兩面板
```

### 場景 11: sessionId 持久化與恢復（驗收 8）

```
Given: splitHorizontal，P0 綁定 session-A，P1 綁定 session-B
When: 應用關閉並重啟
Then: P0 恢復顯示 session-A
  And: P1 恢復顯示 session-B
```

### 場景 12: 持久化 sessionId 不存在時優雅降級（驗收 9）

```
Given: 持久化記錄 P0.sessionId = "deleted-session"
When: 應用重啟，該 session 不存在
Then: P0 恢復為空面板（sessionId = null）
  And: 使用者可重新選擇 session
  And: 應用不崩潰
```

### 場景 13: 持久化檔案損壞時回退（驗收 10）

```
Given: shared_preferences 中的 split_view_state 為無效 JSON
When: 應用啟動
Then: SplitViewStorage.load() 回傳 null
  And: 回退到預設 single 模式
  And: 應用正常啟動
```

### 場景 14: 持久化檔案不存在時回退（驗收 10）

```
Given: shared_preferences 中無 split_view_state key
When: 應用啟動
Then: SplitViewStorage.load() 回傳 null
  And: 回退到預設 single 模式
```

### 場景 15: 持久化面板數與 layoutMode 不一致

```
Given: 持久化 layoutMode = grid2x2 但 panels 只有 2 筆
When: 應用啟動
Then: 以 layoutMode 為準
  And: 補齊 P2, P3 為空面板（sessionId = null）
```

```
A（狀態管理） → B（family 化） → C（Widget） → D（整合）
```

A 和 B 可平行開發（無直接依賴），但 B 會破壞現有測試，建議 A 先行。

## 8. 邊界條件

### 8.1 視窗太小無法容納多面板

**策略**：不做自動降級。面板按 Flex 等比縮小，內容自適應。極端小尺寸時 ConversationView 的 ListView 自然處理溢出。

**理由**：桌面應用視窗尺寸通常足夠；行動裝置上 split view 本身不實用，使用者不會主動選擇。

### 8.2 所有面板關閉後的行為

**不可能發生**：`closePanel` 邏輯中，當剩餘 1 個面板時自動切換到 single 模式，single 模式下不顯示關閉按鈕。因此面板數永遠 >= 1。

### 8.3 WebSocket 連線中斷時的面板行為

**策略**：各面板的 ConversationNotifier 獨立處理。連線中斷時：
- 所有面板同時停止更新（共用同一 WebSocket 連線）
- 重連後各面板自動恢復訂閱（現有 reconnect 邏輯觸發 `subscribeSession`）
- 不需額外處理

### 8.4 同一 session 被多個面板選擇

**允許**：使用者可以在多個面板選擇同一 session。各面板獨立持有 ConversationState，WebSocket 層對同一 session 發送多次 subscribe 是幂等操作（server 端處理）。

### 8.5 面板焦點判定

**activePanelIndex 更新時機**：
- 點擊面板任意區域
- 點擊面板標題列
- 在面板內進行搜尋操作

**sidebar 點擊行為**：session 選擇永遠套用到 activePanelIndex，不會彈出面板選擇器。
