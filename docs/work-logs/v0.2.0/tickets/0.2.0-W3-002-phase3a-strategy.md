# 0.2.0-W3-002 Phase 3a 實作策略規劃

## HTTP Hooks 版本檢測與 fallback 降級機制

---

## 1. 實作順序決策

### 1.1 測試群組分析

4 個測試群組按依賴關係排序：

| 序號 | 群組 | 測試數 | 依賴 | 優先級 | 說明 |
|------|------|--------|------|--------|------|
| 1 | ParseClaudeVersion（TC-01~TC-07） | 7 個 | 無 | **最高** | 純字串解析，無依賴，可獨立測試 |
| 2 | CompareVersions（TC-08~TC-14） | 7 個 | 無 | **最高** | 純版本比較，無依賴，可獨立測試 |
| 3 | DetectClaudeVersion（TC-15~TC-28） | 14 個 | 1, 2 | **高** | 整合函式，依賴 ParseClaudeVersion + CompareVersions + Mock CommandRunner |
| 4 | DisabledHooksHandler（TC-29~TC-31） | 3 個 | 3 | **高** | HTTP 路由層，依賴 VersionConfig |

### 1.2 實作建議順序

**第一批（獨立函式，並行實作）**：
1. **ParseClaudeVersion**（TC-01~TC-07）
   - 實作正規表達式提取版本號
   - 回傳 (version string, error)
   - 不依賴其他模組

2. **CompareVersions**（TC-08~TC-14）
   - 實作三段版本比較邏輯
   - 回傳 -1/0/1
   - 不依賴其他模組

**第二批（整合函式，序列）**：
3. **VersionConfig 結構體 + 常數定義**
   - 定義 VersionConfig 資料結構
   - 定義版本閾值常數（MinVersionHTTPHooks、MinVersionFullFeatures）
   - 定義錯誤變數（ErrVersionParseFailure 等）
   - 定義 CLI 常數（ClaudeCLICommand、ClaudeCLIVersionFlag、VersionCmdTimeoutSecs）

4. **CommandRunner 介面**
   - 定義 `type CommandRunner interface { Run(name string, args ...string) ([]byte, error) }`
   - 為生產環境實現 defaultCommandRunner（呼叫 exec.Command）
   - 為測試環境提供 mockCommandRunner

5. **DetectClaudeVersion**（TC-15~TC-28）
   - 依賴：ParseClaudeVersion、CompareVersions、CommandRunner、VersionConfig
   - 核心邏輯：執行命令 → 解析版本 → 比較版本 → 決定配置

6. **newDisabledHooksHandler**（TC-29~TC-31）
   - 依賴：VersionConfig、logger
   - 核心邏輯：HTTP handler，回傳 501 + 錯誤訊息

7. **main.go 整合**
   - 呼叫 DetectClaudeVersion
   - 根據 HTTPHooksEnabled 條件路由
   - 條件啟用 HTTP Hooks handler 或降級 handler

## 2. 核心函式虛擬碼設計

### 2.1 ParseClaudeVersion

```
函式 ParseClaudeVersion(output: string) -> (string, error)
    // 正規表達式：(\d+\.\d+\.\d+)
    // 目的：從 CLI 輸出提取 "MAJOR.MINOR.PATCH" 格式

    匹配結果 := 正規表達式.搜尋(output)

    若 匹配結果 為空:
        回傳 ("", ErrVersionParseFailure)

    版本字串 := 匹配結果.第一個分組()
    回傳 (版本字串, nil)
```

**邊界情況**：
- 多行輸出：取第一個匹配
- v 前綴和後綴：正規表達式自動過濾（只匹配數字.數字.數字）
- 空字串：無匹配，回傳 error

### 2.2 CompareVersions

```
函式 CompareVersions(a: string, b: string) -> int
    // 三段版本比較：MAJOR.MINOR.PATCH
    // 回傳：-1 (a<b), 0 (a==b), 1 (a>b)

    // Step 1: 分割字串
    a的段 := 分割(a, ".")  // 預期 3 段
    b的段 := 分割(b, ".")

    // Step 2: 字串轉整數
    對於 i = 0 到 2:
        a整數[i] := 轉換為整數(a的段[i])
        b整數[i] := 轉換為整數(b的段[i])

        若 轉換失敗:
            記錄WARN log
            回傳 0  // 安全降級

    // Step 3: 比較邏輯
    對於 i = 0 到 2:
        若 a整數[i] < b整數[i]:
            回傳 -1
        若 a整數[i] > b整數[i]:
            回傳 1

    回傳 0  // 相等
```

**錯誤處理**：
- 格式錯誤（少於 3 段或非數字）：回傳 0 + WARN log
- 溢出：Go int 足以表示版本號

### 2.3 DetectClaudeVersion

```
函式 DetectClaudeVersion(logger: Logger, runner: CommandRunner) -> VersionConfig
    // 核心流程：執行命令 → 解析 → 比較 → 決定配置
    // 設計原則：所有失敗均安全降級，不阻塞啟動

    配置 := VersionConfig{
        DetectedVersion: "",
        HTTPHooksEnabled: false,
        FullFeaturesAvailable: false,
    }

    // Step 1: 執行命令（帶逾時）
    輸出, 錯誤 := runner.Run(ClaudeCLICommand, ClaudeCLIVersionFlag)

    若 錯誤 ≠ nil:
        若 錯誤 == exec.ErrNotFound:
            logger.ERROR(LogVersionCmdNotFound)
        若 錯誤 == context.DeadlineExceeded:
            logger.ERROR(LogVersionCmdTimeout)
        其他:
            logger.ERROR(LogVersionCmdFailed, "exit_code", 取得退出碼(錯誤))
        回傳 配置  // 安全降級

    // Step 2: 解析版本號
    版本, 解析錯誤 := ParseClaudeVersion(字串(輸出))

    若 解析錯誤 ≠ nil:
        logger.WARN(LogVersionParseFailed, "output", 字串(輸出))
        回傳 配置  // 安全降級

    配置.DetectedVersion = 版本
    logger.INFO(LogVersionDetected, "version", 版本)

    // Step 3: 比較版本，決定功能啟用
    若 CompareVersions(版本, MinVersionHTTPHooks) >= 0:
        配置.HTTPHooksEnabled = true
        logger.INFO(LogHTTPHooksEnabled, "version", 版本)

        若 CompareVersions(版本, MinVersionFullFeatures) >= 0:
            配置.FullFeaturesAvailable = true
            logger.INFO(LogFullFeaturesEnabled, "version", 版本)
        其他:
            logger.INFO(LogFullFeaturesPartial, "version", 版本)
    其他:
        logger.INFO(LogHTTPHooksDisabled, "min_version", MinVersionHTTPHooks)

    回傳 配置
```

**錯誤分類與降級**：
| 錯誤類型 | Log 等級 | 回傳值 |
|---------|---------|--------|
| exec.ErrNotFound | ERROR | 全 false |
| Exit Code ≠ 0 | ERROR | 全 false |
| 解析失敗 | WARN | 全 false |
| Context Timeout | ERROR | 全 false |

### 2.4 newDisabledHooksHandler

```
函式 newDisabledHooksHandler(logger: Logger) -> HTTP Handler

    回傳函式 handler(w: ResponseWriter, r: Request):
        w.Header().Set("Content-Type", "application/json")
        w.WriteHeader(http.StatusNotImplemented)  // 501

        錯誤訊息 := {
            "error": ErrHTTPHooksNotAvailable
        }

        json.Marshal(錯誤訊息) -> JSON字節

```

## 3. 資料結構選擇

### 3.1 VersionConfig 結構體

```go
type VersionConfig struct {
    DetectedVersion        string  // 解析結果："2.1.69" 或 ""
    HTTPHooksEnabled       bool    // >= v2.1.63
    FullFeaturesAvailable  bool    // >= v2.1.69
}
```

**為什麼選擇這個設計**：
- 簡單：只需要 2 個 bool flags + 1 個 version string
- 無副作用：只是資料容器，不持有狀態
- 易傳遞：作為參數傳給 main() 的路由邏輯

### 3.2 CommandRunner 介面

```go
type CommandRunner interface {
    Run(name string, args ...string) (output []byte, err error)
}
```

**為什麼選擇介面**：
- 解耦：實作可注入，便於測試
- 生產環境：defaultCommandRunner 呼叫 exec.Command + context timeout
- 測試環境：mockCommandRunner 直接回傳預設值

### 3.3 錯誤定義

```go
var (
    ErrVersionParseFailure = errors.New("version: cannot parse version from output")
    ErrVersionCmdFailed    = errors.New("version: claude command failed")
    ErrVersionCmdNotFound  = errors.New("version: claude command not found")
    ErrVersionCmdTimeout   = errors.New("version: command timed out")
)
```

**為什麼 Sentinel errors**：
- 簡單：不複雜的錯誤分類，三種就夠
- 易判斷：`errors.Is(err, ErrVersionCmdNotFound)`
- 無需外部庫：標準 errors 套件

## 8. 技術債務與限制識別

### 8.1 最小可行實作的簡化

| 項目 | 簡化做法 | 技術債務標記 | Phase 4 建議 |
|------|---------|------------|------------|
| **版本比較** | 手工三段整數比較 | 無外部依賴，代碼重複 | 可提取為 semver 套件（低優） |
| **CommandRunner** | 簡單介面，無重試邏輯 | 命令失敗無自動重試 | 可加 exponential backoff（低優） |
| **Timeout 機制** | 固定 5 秒 | 不可配置 | 可從環境變數讀取（中優） |
| **Log 格式** | 使用簡單字串 + 參數 | 無結構化欄位名稱 | 完整結構化 log（低優） |
| **降級 handler** | 簡單 501 響應 | 無特殊重試指引 | 可提供更詳細的升級說明 URL（低優） |

### 8.2 已知限制

| 限制 | 原因 | 影響範圍 |
|------|------|---------|
| **無 exe 署名驗證** | 成本高 | 若 PATH 被污染，可能執行不安全的 claude 命令 |
| **無版本緩存** | 每次啟動都執行命令 | 無性能影響（啟動時一次） |
| **無失敗重試** | 簡化邏輯 | 若 CLI 短暫不可用，無法恢復 |
| **版本格式固定** | 假設 MAJOR.MINOR.PATCH | 若未來 Claude 改變版本格式，需修改 VersionPattern |

### 8.3 潛在改善方向（Phase 4 重構）

1. **版本緩存**（中優）：第一次檢測後快取結果，避免重複執行命令
2. **失敗重試**（中優）：命令失敗後重試 1-2 次
3. **版本格式驗證**（低優）：額外驗證版本格式是否符合預期
4. **效能指標**（低優）：記錄版本檢測耗時
5. **多平台測試**（中優）：在 Windows/Linux/macOS 驗證 CLI 兼容性

## 11. 語言特定實作注意事項

### Go 考量

#### 1. exec.Command 與 context

```go
// ✓ 正確：使用 context 控制超時
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
cmd := exec.CommandContext(ctx, "claude", "--version")

// ✗ 錯誤：無超時，可能卡住
cmd := exec.Command("claude", "--version")
```

#### 2. 錯誤型別判斷

```go
// ✓ 正確：使用 errors.Is 判斷特定錯誤
if errors.Is(err, exec.ErrNotFound) { ... }

// ✗ 錯誤：型別斷言不穩定
if _, ok := err.(*exec.ExitError); ok { ... }
```

#### 3. 字串分割與轉換

```go
// ✓ 正確：處理分割結果長度
parts := strings.Split("2.1.69", ".")
if len(parts) != 3 { ... }

// ✗ 錯誤：假設分割結果一定 3 段
parts := strings.Split(versionStr, ".")
major := parts[0]  // 可能 panic
```

#### 4. slog 日誌使用

```go
// ✓ 正確：使用結構化欄位
logger.Error(LogVersionCmdFailed, "exit_code", exitCode, "stderr", stderr)

// ✗ 錯誤：字串連接
logger.Error("command failed: " + stderr)
```

#### 5. 常數命名

```go
// ✓ 正確：大寫蛇形（Go 風格）
const MinVersionHTTPHooks = "2.1.63"
const ClaudeCLICommand = "claude"

// ✗ 錯誤：駝峰或其他風格
const minVersionHttpHooks = "2.1.63"
```
