## 2. 子任務 A 虛擬碼/策略

### 2.1 LayoutMode 實作策略

簡單列舉型別，4 個值。新增輔助函式回傳該模式的面板數量：

```
ENUM LayoutMode:
  single, splitHorizontal, splitVertical, grid2x2

FUNCTION panelCount(mode):
  SWITCH mode:
    single -> RETURN 1
    splitHorizontal, splitVertical -> RETURN 2
    grid2x2 -> RETURN 4
```

### 2.2 PanelState 實作策略

不可變值物件，繼承 Equatable。兩個欄位：panelIndex（整數）、sessionId（可空字串）。

```
CLASS PanelState EXTENDS Equatable:
  FIELDS: panelIndex (int), sessionId (string?)
  CONSTRUCTOR: 接收 panelIndex（必填）、sessionId（選填，預設 null）
  PROPS: [panelIndex, sessionId]
```

不需要 copyWith（Phase 1 中 PanelState 更新透過建構新物件）。

### 2.3 SplitViewState 實作策略

不可變值物件，繼承 Equatable，需要 copyWith。

```
CLASS SplitViewState EXTENDS Equatable:
  FIELDS:
    layoutMode (LayoutMode, default: single)
    panels (List<PanelState>, default: [])
    activePanelIndex (int, default: 0)
    maximizedPanelIndex (int?, default: null)

  FUNCTION copyWith(...):
    // maximizedPanelIndex 需 sentinel 模式區分「未傳入」和「明確傳 null」
    // 參考現有 ConversationState.copyWith 的 _sentinel 模式

  PROPS: [layoutMode, panels, activePanelIndex, maximizedPanelIndex]
```

### 2.4 SplitViewNotifier 核心方法虛擬碼

#### build()

```
ASYNC FUNCTION build():
  storage = ref.read(splitViewStorageProvider)
  loaded = AWAIT storage.load()

  IF loaded == null:
    RETURN SplitViewState(single, panels: [PanelState(0)])

  // 驗證面板數與 layoutMode 一致性
  expectedCount = panelCount(loaded.layoutMode)
  panels = loaded.panels

  IF panels.length < expectedCount:
    // 補齊空面板
    FOR i FROM panels.length TO expectedCount - 1:
      panels.ADD(PanelState(panelIndex: i, sessionId: null))
  ELSE IF panels.length > expectedCount:
    // 裁剪多餘面板
    panels = panels.TAKE(expectedCount)

  // 重新指派 panelIndex（確保連續）
  panels = panels.ENUMERATE().MAP((i, p) -> PanelState(i, p.sessionId))

  RETURN SplitViewState(loaded.layoutMode, panels, activePanelIndex: 0)
```

#### switchLayout(mode)

```
FUNCTION switchLayout(mode):
  current = state.value
  IF current.layoutMode == mode: RETURN  // 同模式無操作

  oldPanels = current.panels
  newCount = panelCount(mode)
  newPanels = []

  // 面板轉換邏輯
  IF newCount == 1:
    // 降級為 single：保留 activePanel
    activeSession = oldPanels[current.activePanelIndex].sessionId
    newPanels = [PanelState(0, activeSession)]

  ELSE IF newCount >= oldPanels.length:
    // 升級：保留全部舊面板，補齊新面板
    FOR i FROM 0 TO newCount - 1:
      IF i < oldPanels.length:
        newPanels.ADD(PanelState(i, oldPanels[i].sessionId))
      ELSE:
        newPanels.ADD(PanelState(i, null))

  ELSE:
    // 降級到較少面板：保留前 newCount 個
    FOR i FROM 0 TO newCount - 1:
      newPanels.ADD(PanelState(i, oldPanels[i].sessionId))

  // activePanelIndex 修正
  newActiveIndex = MIN(current.activePanelIndex, newCount - 1)

  newState = SplitViewState(mode, newPanels, newActiveIndex)
  state = AsyncData(newState)
  AWAIT storage.save(newState)
```

**同面板數切換**（splitHorizontal <-> splitVertical）：面板保留不變，只換 layoutMode。上述邏輯中 `newCount == oldPanels.length` 會走「升級」分支但實際不補齊，行為正確。

#### selectSession(panelIndex, sessionId)

```
FUNCTION selectSession(panelIndex, sessionId):
  current = state.value
  IF panelIndex >= current.panels.length: RETURN  // 超出範圍防護

  newPanels = current.panels.MAP((i, p) ->
    IF i == panelIndex: PanelState(i, sessionId)
    ELSE: p
  )

  newState = current.copyWith(
    panels: newPanels,
    activePanelIndex: panelIndex
  )
  state = AsyncData(newState)
  AWAIT storage.save(newState)
```

#### closePanel(panelIndex)

```
FUNCTION closePanel(panelIndex):
  current = state.value
  IF current.panels.length <= 1: RETURN  // single 模式不可關閉

  remaining = current.panels.WHERE(p -> p.panelIndex != panelIndex)

  // 重新指派 panelIndex
  newPanels = remaining.ENUMERATE().MAP((i, p) -> PanelState(i, p.sessionId))

  // 決定新 layoutMode
  IF newPanels.length == 1:
    newMode = LayoutMode.single
  ELSE IF newPanels.length == 2:
    // grid2x2 關閉 1 面板 → 降級策略（見技術決策 6.1）
    newMode = LayoutMode.splitHorizontal
  ELSE IF newPanels.length == 3:
    // grid2x2 關閉 1 面板 → 保持 grid2x2（3 面板 + 1 空面板）
    // 或降級為 splitHorizontal 保留前 2 面板
    // ** 設計決策：降級為 splitHorizontal，保留前 2 面板 **
    newPanels = newPanels.TAKE(2)
    newPanels = newPanels.ENUMERATE().MAP((i, p) -> PanelState(i, p.sessionId))
    newMode = LayoutMode.splitHorizontal

  // activePanelIndex 修正
  newActiveIndex = IF panelIndex == current.activePanelIndex THEN 0
                   ELSE MIN(current.activePanelIndex, newPanels.length - 1)

  // 清除 maximizedPanelIndex
  newState = SplitViewState(newMode, newPanels, newActiveIndex, maximized: null)
  state = AsyncData(newState)
  AWAIT storage.save(newState)
```

#### maximizePanel / restorePanel / setActivePanel

```
FUNCTION maximizePanel(panelIndex):
  current = state.value
  IF panelIndex >= current.panels.length: RETURN
  state = AsyncData(current.copyWith(maximizedPanelIndex: panelIndex))
  // 不持久化

FUNCTION restorePanel():
  state = AsyncData(state.value.copyWith(maximizedPanelIndex: null))
  // 不持久化

FUNCTION setActivePanel(panelIndex):
  current = state.value
  IF panelIndex >= current.panels.length: RETURN
  state = AsyncData(current.copyWith(activePanelIndex: panelIndex))
  // 不持久化
```

### 2.5 SplitViewStorage 實作策略

```
ABSTRACT CLASS SplitViewStorage:
  save(state) -> async void
  load() -> async SplitViewState?
  clear() -> async void

CLASS SharedPrefsSplitViewStorage IMPLEMENTS SplitViewStorage:
  CONSTRUCTOR(SharedPreferences prefs)
  KEY = "split_view_state"

  FUNCTION save(state):
    json = {
      "layoutMode": state.layoutMode.name,
      "panels": state.panels.MAP(p -> {
        "panelIndex": p.panelIndex,
        "sessionId": p.sessionId
      })
    }
    prefs.setString(KEY, jsonEncode(json))

  FUNCTION load():
    raw = prefs.getString(KEY)
    IF raw == null: RETURN null
    TRY:
      map = jsonDecode(raw)
      layoutMode = LayoutMode.values.byName(map["layoutMode"])
      panels = map["panels"].MAP(p -> PanelState(p["panelIndex"], p["sessionId"]))
      RETURN SplitViewState(layoutMode, panels)
    CATCH any:
      RETURN null

  FUNCTION clear():
    prefs.remove(KEY)
```

### 2.6 FakeSplitViewStorage 測試替身

```
CLASS FakeSplitViewStorage IMPLEMENTS SplitViewStorage:
  FIELD: savedState (SplitViewState?)
  FIELD: loadResult (SplitViewState?)  // 可預設回傳值
  FIELD: saveCallCount (int, default: 0)
  FIELD: shouldThrow (bool, default: false)

  FUNCTION save(state):
    IF shouldThrow: THROW Exception
    savedState = state
    saveCallCount++

  FUNCTION load():
    IF shouldThrow: THROW Exception
    RETURN loadResult ?? savedState

  FUNCTION clear():
    savedState = null
```

### 4.1 SplitViewContainer 佈局邏輯

```
CLASS SplitViewContainer (ConsumerWidget):
  FUNCTION build(context, ref):
    asyncState = ref.watch(splitViewNotifierProvider)

    RETURN asyncState.when(
      loading: -> 載入指示器,
      error: -> 錯誤提示,
      data: (state) -> _buildLayout(state)
    )

  FUNCTION _buildLayout(state):
    // 最大化面板優先
    IF state.maximizedPanelIndex != null:
      RETURN SessionPanel(panelIndex: state.maximizedPanelIndex)

    SWITCH state.layoutMode:
      single:
        RETURN SessionPanel(panelIndex: 0)

      splitHorizontal:
        RETURN Row [
          Expanded(flex: leftFlex, SessionPanel(0)),
          ResizableDivider(axis: horizontal, onDrag: updateFlex),
          Expanded(flex: rightFlex, SessionPanel(1))
        ]

      splitVertical:
        RETURN Column [
          Expanded(flex: topFlex, SessionPanel(0)),
          ResizableDivider(axis: vertical, onDrag: updateFlex),
          Expanded(flex: bottomFlex, SessionPanel(1))
        ]

      grid2x2:
        RETURN Column [
          Expanded(
            Row [
              Expanded(SessionPanel(0)),
              ResizableDivider(horizontal),
              Expanded(SessionPanel(1))
            ]
          ),
          ResizableDivider(vertical),
          Expanded(
            Row [
              Expanded(SessionPanel(2)),
              ResizableDivider(horizontal),
              Expanded(SessionPanel(3))
            ]
          )
        ]
```

**面板比例管理**：SplitViewContainer 為 StatefulWidget（非 ConsumerWidget），本地 State 持有各 flex 比例。初始等分（flex = 1），拖拉時更新 flex 值。不持久化。

ref.listen(selectedSessionIdProvider, (previous, next) ->

## 6. 技術決策記錄

### 6.1 grid2x2 關閉 1 面板降級策略

**問題**：grid2x2（4 面板）關閉 1 個面板後剩餘 3 個，沒有對應的 LayoutMode。

**決策**：降級為 `splitHorizontal`，保留前 2 個剩餘面板，丟棄第 3 個。

**理由**：
- 沒有「3 面板」模式，無法精確對應
- 保持簡單的面板數量對照（每個 LayoutMode 有固定面板數）
- 使用者可重新切換到 grid2x2 並選擇 session

**替代方案（不採用）**：
- 保持 grid2x2 但留一個空面板 → 增加邊界狀態複雜度
- 新增 3 面板模式 → 超出 Phase 1 範圍

### 6.2 Riverpod codegen family provider 語法

codegen 的 family 化只需在 `build` 方法加參數：

```dart
// 加參數即可，codegen 自動產生 family
@override
Future<ConversationState> build(int panelIndex) async { ... }
```

呼叫端：`ref.watch(conversationNotifierProvider(0))`

### 6.3 SharedPreferences 初始化策略

**方案 A：ProviderScope overrides（建議）**

在 `main()` 中提前初始化 SharedPreferences，透過 ProviderScope overrides 注入：

```
main():
  prefs = AWAIT SharedPreferences.getInstance()
  storage = SharedPrefsSplitViewStorage(prefs)

  runApp(
    ProviderScope(
      overrides: [
        splitViewStorageProvider.overrideWithValue(storage)
      ],
      child: App()
    )
  )
```

**理由**：SharedPreferences.getInstance() 是異步的，但 SplitViewNotifier.build() 已是 async，因此也可在 build() 內初始化。但 ProviderScope overrides 更明確，且測試時容易替換為 FakeSplitViewStorage。

**方案 B：lazy init in build()（備選）**

SplitViewNotifier.build() 內部 `await SharedPreferences.getInstance()`。缺點是每次 rebuild 都會呼叫（雖然 Flutter 內部有快取）。

**建議採用方案 A**。

## 7. Phase 3b 拆分建議

### 7.1 是否需要拆分為多個並行子 Ticket

**建議**：序列派發 4 個子任務，不並行。

**理由**：
- A → B → C → D 有嚴格依賴鏈
- A 和 B 雖無直接程式碼依賴，但 B 的 codegen 後測試必須通過，A 的型別定義也需確定才能讓 C 正確引用
- 各子任務的修改檔案無交集，不會產生合併衝突

### 7.2 每個子任務的修改檔案交集

| 子任務對 | 檔案交集 |
|---------|---------|
| A - B | 無 |
| A - C | 無（A 新增 domain/presentation 檔，C 新增 widgets 檔） |
| A - D | 無 |
| B - C | 無（B 改 notifier，C 改 view） |
| B - D | 無 |
| C - D | 無（C 改 conversation_view，D 改 dashboard_page） |

### 7.3 建議派發策略

| 子任務 | 派發順序 | 測試目標數 | 預估複雜度 |
|--------|---------|-----------|-----------|
| A | 1 | ~25 個測試案例 | 中（純新增，邏輯集中在 Notifier） |
| B | 2 | ~5 個新測試 + 更新現有測試 | 低（簽名變更，內部邏輯不變） |
| C | 3 | ~15 個 Widget 測試 | 中（多個新 Widget，手勢互動） |
| D | 4 | ~3 個整合測試 | 低（橋接修改） |

每個子任務完成後執行全量測試，確認不破壞現有測試，再進入下一個。
