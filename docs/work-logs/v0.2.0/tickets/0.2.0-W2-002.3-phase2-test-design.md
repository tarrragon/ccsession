| 層級 | 目標 | 測試類型 | 優先級 |

## 4. 測試案例設計（Given-When-Then）

### TG-20: ConversationNotifier 測試群組

#### TC-20-01: 載入 session 歷史 — 成功

```
Given: Notifier 已初始化，WebSocket messageStream 已連接
  前置驗證: state.events 為空列表
  前置驗證: state.isLoadingHistory == false
When: 呼叫 loadSession('session-1')
Then: state.isLoadingHistory 變為 true
  傳送 session_history 回應（含 3 筆事件，hasMore=false）後：
  state.events.length == 3
  state.sessionId == 'session-1'
  state.hasMore == false
  state.isLoadingHistory == false
```

#### TC-20-02: 載入 session 歷史 — 空 session

```
Given: Notifier 已初始化
  前置驗證: state.events 為空列表
When: 呼叫 loadSession('empty-session')
  傳送 session_history 回應（events=[], hasMore=false）
Then: state.events 為空列表
  state.sessionId == 'empty-session'
  state.isLoadingHistory == false
  state.hasMore == false
```

#### TC-20-03: 載入 session 歷史 — 有更多分頁

```
Given: Notifier 已初始化
When: 呼叫 loadSession('session-1')
  傳送 session_history 回應（含 100 筆事件，hasMore=true）
Then: state.events.length == 100
  state.hasMore == true
```

#### TC-20-04: 載入更多歷史 — 分頁 prepend

```
Given: 已載入 session 歷史（events.length == 3, hasMore == true）
  前置驗證: state.events.length == 3
  前置驗證: state.hasMore == true
When: 呼叫 loadMoreHistory()
  傳送 session_history 回應（含 2 筆更早事件，hasMore=false）
Then: state.events.length == 5
  state.events[0] 為最早的事件（prepend 的）
  state.events[4] 為原本最新的事件
  state.hasMore == false
```

#### TC-20-05: 載入更多歷史 — hasMore 為 false 時忽略

```
Given: 已載入 session 歷史（hasMore == false）
  前置驗證: state.hasMore == false
When: 呼叫 loadMoreHistory()
Then: 無任何請求發送（verify requestSessionHistory 未被呼叫）
  state 不變
```

#### TC-20-06: 載入更多歷史 — 正在載入時忽略

```
Given: 已呼叫 loadMoreHistory() 但尚未收到回應（isLoadingHistory == true）
  前置驗證: state.isLoadingHistory == true
When: 再次呼叫 loadMoreHistory()
Then: 無重複請求發送
```

#### TC-20-07: 即時事件接收 — sessionId 匹配

```
Given: 已載入 session-1 歷史（events.length == 2）
  前置驗證: state.sessionId == 'session-1'
  前置驗證: state.events.length == 2
When: 收到 session_event（sessionId='session-1', type='assistant', text='hello'）
Then: state.events.length == 3
  state.events.last.type == 'assistant'
  state.events.last.content.text == 'hello'
```

#### TC-20-08: 即時事件接收 — sessionId 不匹配則忽略

```
Given: 已載入 session-1 歷史（events.length == 2）
  前置驗證: state.sessionId == 'session-1'
When: 收到 session_event（sessionId='session-other'）
Then: state.events.length == 2（不變）
```

#### TC-20-09: 即時事件接收 — 格式異常容錯

```
Given: 已載入 session-1 歷史（events.length == 2）
When: 收到格式異常的 session_event（data 缺少必要欄位）
Then: state.events.length == 2（不變，不中斷）
  後續正常事件仍可接收
```

#### TC-20-10: 切換 session — 正確清理和重新載入

```
Given: 已載入 session-A 歷史（events.length == 3）
  前置驗證: state.sessionId == 'session-A'
When: 呼叫 loadSession('session-B')
Then: verify unsubscribeSession('session-A') 被呼叫
  state.events 先被清空
  傳送 session-B 的 session_history 回應後：
  state.sessionId == 'session-B'
  state.events 為 session-B 的事件
```

#### TC-20-11: 切換 session — 前 session 事件不再處理

```
Given: 已切換到 session-B
  前置驗證: state.sessionId == 'session-B'
When: 收到 session_event（sessionId='session-A'）
Then: state.events 不變（session-A 事件被忽略）
```

#### TC-20-12: leaveSession — 取消訂閱並清空

```
Given: 已載入 session-1
  前置驗證: state.sessionId == 'session-1'
When: 呼叫 leaveSession()
Then: verify unsubscribeSession('session-1') 被呼叫
  state.sessionId == null
  state.events 為空列表
```

#### TC-20-13: setAutoScroll — 狀態切換

```
Given: 初始 state.isAutoScrollEnabled == true
When: 呼叫 setAutoScroll(false)
Then: state.isAutoScrollEnabled == false
When: 呼叫 setAutoScroll(true)
Then: state.isAutoScrollEnabled == true
```

#### TC-20-14: loadSession 發送正確請求

```
Given: Notifier 已初始化
When: 呼叫 loadSession('session-1')
Then: verify requestSessionHistory('session-1') 被呼叫
  verify subscribeSession('session-1') 被呼叫
```

#### TC-20-15: get_session_history 回傳 error — 設定 errorMessage

```
Given: Notifier 已初始化
When: 呼叫 loadSession('bad-session')
  收到 error 回應（code: 'SESSION_NOT_FOUND'）
Then: state.errorMessage 不為 null
  state.events 為空列表
  state.isLoadingHistory == false
```

## 5. 行為鏈式推演

### 5.1 主要行為鏈：載入 session 對話

```
起點: 使用者選擇 session
  A: Notifier 已初始化（WebSocket 連線中）
  → B: 呼叫 loadSession(sessionId)
    → B1: 發送 requestSessionHistory
    → B2: 發送 subscribeSession
  → C: 收到 session_history 回應
    → C1: events 填充、isLoadingHistory=false
  → D: UI 渲染訊息列表
    → D1: 各 Bubble 正確對應類型
  → E: 後續 session_event 即時 append
    → E1: isAutoScrollEnabled=true 時自動捲動
```

### 5.2 四個維度分支窮舉

| 維度 | 場景 | 測試案例 |
|------|------|---------|
| **正常流程** | 載入歷史成功 + 即時事件 | TC-20-01, TC-20-07 |
| **正常流程** | 5 種訊息類型各自渲染 | TC-22-01~07 |
| **異常流程** | 歷史載入失敗（error） | TC-20-15 |
| **異常流程** | session_event JSON 解析失敗 | TC-20-09 |
| **異常流程** | 未知訊息類型 | TC-22-09 |
| **邊界條件** | 空 session（無事件） | TC-20-02, TC-21-01 |
| **邊界條件** | hasMore 為 false 時呼叫 loadMore | TC-20-05 |
| **邊界條件** | isLoadingHistory 為 true 時重複呼叫 | TC-20-06 |
| **邊界條件** | toolInput 為 null | TC-22-04 |
| **邊界條件** | thinking.text 為空 | TC-22-08 |
| **中斷操作** | 切換 session 中斷前一個 | TC-20-10, TC-20-11 |
| **中斷操作** | leaveSession 中斷 | TC-20-12 |

### 7.3 設計決策記錄

| 決策 | 理由 |
|------|------|
| 自動捲動行為不在 Notifier test 中測試 ScrollController | ScrollController 是 Flutter framework 層，在 Widget test 中驗證更合適；Notifier 只負責 isAutoScrollEnabled 狀態 |
| session_event 直接用 SessionEvent.fromJson 解析而非 SessionEventData | Phase 1 設計建議繞過不完整的 SessionEventData |
| Bubble Widget 測試獨立於 ConversationView | 各 Bubble 為 StatelessWidget，可獨立 pump 測試，降低耦合 |
