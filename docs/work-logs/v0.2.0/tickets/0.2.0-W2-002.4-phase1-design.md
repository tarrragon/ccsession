## 1. 功能需求分析

### 1.1 核心問題

本 Ticket 解決的核心問題：將已實作完成的 `SessionListPage`（sidebar）和 `ConversationView`（main area）組裝成完整的主畫面，並透過 `selectedSessionId` 狀態橋接兩個 Provider，實現點擊 sidebar session → main area 顯示對應對話內容的端對端流程。

同時，主畫面需要顯示 WebSocket 連線狀態指示器，讓使用者隨時了解連線健康狀態。

### 1.2 使用者場景

| 場景 | 描述 |
|------|------|
| 初次進入 | 使用者開啟應用，看到雙欄佈局：左側 session 列表（分 Active/Idle/Completed 分組），右側顯示空白提示 |
| 選擇 session | 使用者點擊 sidebar 的某個 session，main area 載入並顯示對應對話內容 |
| 切換 session | 使用者點擊另一個 session，sidebar 更新選中狀態，main area 切換到新的對話 |
| 連線中斷 | WebSocket 斷線，頂部/底部連線狀態指示器顯示紅色 + 重連中 |
| 即時更新 | active session 持續收到新事件，main area 的 ConversationView 自動 append 並捲動 |

### 1.3 關鍵設計問題：selectedSessionId 狀態流通

`selectedSessionId` 是橋接 sidebar 選取和 conversation 顯示的核心狀態。目前架構：

- `SessionListNotifier` 內部持有 `selectedSessionId`（在 `SessionListState` 中）
- 已有 `selectedSessionIdProvider`（衍生 Provider）暴露給外部消費
- `ConversationNotifier.loadSession()` 需要在 `selectedSessionId` 變更時被呼叫

**關鍵決策**：`DashboardPage` 需要 watch `selectedSessionIdProvider`，當值變更時呼叫 `conversationNotifierProvider.notifier.loadSession(newId)`。這透過 Riverpod 的 `ref.listen` 機制實現，在 `ConsumerWidget.build` 或 `ConsumerStatefulWidget` 的 `build` 方法中監聽。

### 2.2 DashboardPage

```dart
/// 需求：主畫面根 Widget，組裝 sidebar + main area 雙欄佈局
/// 約束：ConsumerStatefulWidget，需要 ref.listen 橋接 selectedSessionId -> loadSession
class DashboardPage extends ConsumerStatefulWidget {
  const DashboardPage({super.key});

  @override
  ConsumerState<DashboardPage> createState() => _DashboardPageState();
}

class _DashboardPageState extends ConsumerState<DashboardPage> {
  /// 需求：監聽 selectedSessionId 變更，觸發 ConversationNotifier.loadSession
  /// 約束：只在 selectedSessionId 不為 null 時觸發；前一個 session 清理由 loadSession 內部處理
  @override
  void initState() {
    super.initState();
    // ref.listen 在 initState 內不可用，改在 build 中使用
  }

  @override
  Widget build(BuildContext context) {
    // 橋接：selectedSessionId 變更 → 觸發 loadSession
    ref.listen<String?>(selectedSessionIdProvider, (previous, next) {
      if (next != null && next != previous) {
        ref.read(conversationNotifierProvider.notifier).loadSession(next);
      }
    });

    return Scaffold(
      body: Row(
        children: [
          SizedBox(
            width: DashboardConstants.sidebarWidth,
            child: Column(
              children: [
                const ConnectionStatusBar(),
                const Expanded(child: SessionListPage()),
              ],
            ),
          ),
          const VerticalDivider(width: 1),
          const Expanded(child: _MainArea()),
        ],
      ),
    );
  }
}

/// 需求：main area，根據是否選中 session 顯示對話或空白提示
/// 約束：ConsumerWidget，watch selectedSessionIdProvider
class _MainArea extends ConsumerWidget {
  const _MainArea();

  @override
  Widget build(BuildContext context, WidgetRef ref) {
    final selectedId = ref.watch(selectedSessionIdProvider);
    if (selectedId == null) {
      return const _EmptySelectionPlaceholder();
    }
    return const ConversationView();
  }
}

/// 需求：未選中 session 時的佔位提示
class _EmptySelectionPlaceholder extends StatelessWidget {
  const _EmptySelectionPlaceholder();

  @override
  Widget build(BuildContext context) {
    // TODO: i18n — 遷移至 ARB
    return const Center(child: Text('Select a session to view conversation'));
  }
}
```

### 2.3 ConnectionStatusBar

```dart
/// 需求：WebSocket 連線狀態指示器，顯示於 sidebar 頂部
/// 約束：ConsumerWidget，watch connectionStateProvider
/// 視覺：彩色圓點（綠/黃/紅）+ 文字狀態描述
class ConnectionStatusBar extends ConsumerWidget {
  const ConnectionStatusBar({super.key});

  @override
  Widget build(BuildContext context, WidgetRef ref) {
    final connectionStateAsync = ref.watch(connectionStateProvider);
    final wsState = connectionStateAsync.valueOrNull
        ?? WsConnectionState.connecting;
    return _buildBar(wsState);
  }
}

/// 連線狀態 -> 圓點顏色映射
/// connected   -> 綠色（Colors.green）
/// connecting  -> 黃色（Colors.amber）
/// reconnecting-> 黃色（Colors.amber）
/// disconnected-> 紅色（Colors.red）

/// 連線狀態 -> 文字描述映射
/// connected    -> 'Connected'
/// connecting   -> 'Connecting...'
/// reconnecting -> 'Reconnecting...'
/// disconnected -> 'Disconnected'
```

## 4. 狀態管理設計

### 4.1 Provider 依賴關係

```
webSocketServiceProvider (singleton)
    |
    ├── connectionStateProvider (Stream<WsConnectionState>)
    │       消費者：ConnectionStatusBar
    │
    ├── sessionListNotifierProvider (AsyncNotifier<SessionListState>)
    │       消費者：SessionListPage
    │       公開：selectedSessionIdProvider
    │
    └── conversationNotifierProvider (AsyncNotifier<ConversationState>)
            消費者：ConversationView
            觸發來源：DashboardPage via ref.listen(selectedSessionIdProvider)
```

### 4.2 selectedSessionId 狀態流

```
使用者點擊 SessionListTile
    |
    v
SessionListNotifier.selectSession(sessionId)
    → state.selectedSessionId = sessionId
    |
    v
selectedSessionIdProvider 更新（衍生 Provider）
    |
    v
DashboardPage ref.listen 觸發
    → ConversationNotifier.loadSession(sessionId)
    |
    v
_MainArea 偵測 selectedId != null
    → 渲染 ConversationView
    |
    v
ConversationView watch conversationNotifierProvider
    → 顯示對話內容
```

### 4.3 連線狀態橋接

`connectionStateProvider` 是 `Stream<WsConnectionState>` 型別，在 Riverpod 中以 `AsyncValue<WsConnectionState>` 包裝。`ConnectionStatusBar` 使用 `valueOrNull` 取得當前狀態，null 時 fallback 為 `connecting`（初始化期間）。

## 5. 流程設計

### 5.1 應用啟動流程

```
main() → ProviderScope → App.build()
    |
    v
ref.read(webSocketServiceProvider).connect()
    → 觸發 WebSocket 連線至 localhost:8765/ws
    |
    v
connectionStateProvider 更新為 connecting
ConnectionStatusBar 顯示黃色「Connecting...」
    |
    v
連線成功 → connectionStateProvider 更新為 connected
ConnectionStatusBar 顯示綠色「Connected」
    |
    v
SessionListNotifier 自動 requestSessionList()
    → sidebar 顯示 session 列表
```

### 5.2 選擇 session 流程

```
使用者點擊 sidebar 的 session
    |
    v
SessionListNotifier.selectSession(sessionId)
    → selectedSessionId 更新
    |
    v
DashboardPage ref.listen(selectedSessionIdProvider) 觸發
    → conversationNotifier.loadSession(sessionId)
    |
    ├── 取消前 session 訂閱（若有）
    ├── 重置 ConversationState（events=[], isLoadingHistory=true）
    ├── 發送 get_session_history(sessionId)
    └── 發送 subscribe_session(sessionId)
    |
    v
_MainArea 偵測 selectedId != null → 渲染 ConversationView
    → ConversationView 顯示載入指示器（isLoadingHistory=true, events 空）
    |
    v
收到 session_history 回應 → ConversationView 顯示訊息列表
    |
    v
後續即時 session_event → ConversationView append 並自動捲動
```

### 5.3 連線狀態切換流程

```
WebSocket 連線中斷
    |
    v
WsConnectionState 更新為 disconnected 或 reconnecting
ConnectionStatusBar 更新顏色為紅色/黃色 + 對應文字
    |
    v
ReconnectStrategy 自動重連（1s → 2s → 4s ... max 30s）
    |
    v
重連成功 → WsConnectionState 更新為 connected
ConnectionStatusBar 更新為綠色「Connected」
```

## 6. 邊界條件與異常處理

### 6.1 邊界條件

| 條件 | 預期行為 |
|------|---------|
| 首次進入，無選中 session | main area 顯示「Select a session to view conversation」 |
| session 列表為空（無任何 session） | sidebar 顯示「No sessions」（SessionListPage 現有行為） |
| 點擊同一個 session 兩次 | ref.listen 前後值相同（`next == previous`），不重複呼叫 loadSession |
| 快速連續切換 session | loadSession 每次都先取消前一個訂閱，避免競態 |
| WebSocket 未連線時選擇 session | loadSession 發送請求，WebSocket 重連後自動補發 |
| 螢幕寬度極窄（< 280px） | sidebar 可能被截斷（目前固定寬度，後續版本可改為 responsive） |

### 6.2 錯誤處理

| 錯誤情境 | 處理方式 |
|---------|---------|
| WebSocket 連線失敗 | ConnectionStatusBar 顯示「Disconnected」，ReconnectStrategy 自動重試 |
| sessionListNotifierProvider 載入失敗 | SessionListPage 顯示「Failed to load sessions」（現有行為） |
| conversationNotifierProvider 載入失敗 | ConversationView 顯示錯誤訊息（現有行為） |
| App.connect() 回傳異常 | 靜默處理，WebSocket 狀態更新為 disconnected |

## 8. 行為場景提取（Given-When-Then）

### 場景 1: 雙欄佈局初始狀態

```
Given: 使用者開啟應用，WebSocket 已連線
When: DashboardPage 渲染完成
Then: 左側顯示 sidebar（SessionListPage + ConnectionStatusBar）
      右側顯示空白提示（未選中 session）
```

### 場景 2: 連線狀態指示 — 已連線

```
Given: WebSocket 連線成功
When: ConnectionStatusBar 渲染
Then: 顯示綠色圓點 + 文字「Connected」
```

### 場景 3: 連線狀態指示 — 重連中

```
Given: WebSocket 連線中斷後自動觸發重連
When: ConnectionStatusBar 偵測到 reconnecting 狀態
Then: 顯示黃色圓點 + 文字「Reconnecting...」
```

### 場景 4: 連線狀態指示 — 已斷線

```
Given: WebSocket 連線中斷且未重連
When: ConnectionStatusBar 偵測到 disconnected 狀態
Then: 顯示紅色圓點 + 文字「Disconnected」
```

### 場景 5: 選擇 session — 第一次

```
Given: 使用者在初始狀態（無選中 session），sidebar 顯示 session 列表
When: 使用者點擊某個 session（如 sess-1）
Then: sidebar 的 sess-1 Tile 顯示選中樣式
      main area 切換為 ConversationView，載入 sess-1 的對話內容
```

### 場景 6: 切換 session

```
Given: 使用者已選中 sess-1，main area 顯示 sess-1 的對話
When: 使用者點擊 sess-2
Then: sidebar 更新選中樣式（sess-2 高亮）
      main area 清空並重新載入 sess-2 的對話內容
      sess-1 的 WebSocket 訂閱被取消
```

### 場景 7: 點擊相同 session（重複點擊）

```
Given: 使用者已選中 sess-1
When: 使用者再次點擊 sess-1
Then: selectedSessionId 未變更（prev == next），loadSession 不觸發
      main area 保持顯示 sess-1 的對話，無閃爍
```

### 場景 8: 即時事件串流整合

```
Given: 使用者已選中一個 active session
When: Backend 推送新的 session_event
Then: ConversationView 的訊息列表 append 新事件
      延遲小於 1 秒（從 Go Backend 推送到 UI 渲染完成）
```

### 場景 9: 未選中 session 時的空白狀態

```
Given: 應用剛啟動，sidebar 顯示 session 列表，無選中
When: _MainArea 渲染
Then: 顯示提示文字「Select a session to view conversation」
      不顯示 ConversationView（避免不必要的 Provider 初始化）
```

## 9. 實作注意事項

### 9.1 ProviderScope 修正（重要）

目前 `main.dart` 的 `App` 是 `StatelessWidget`，**缺少 `ProviderScope`**，導致所有 Riverpod Provider 無法正常運作。`app.dart` 建立後，`main.dart` 必須修改：

```dart
void main() {
  runApp(const ProviderScope(child: App()));
}
```

### 9.2 WebSocket 初始化時機

`App` 改為 `ConsumerWidget` 後，可在 `build` 中 `ref.read(webSocketServiceProvider).connect()` 觸發連線。但需確保只呼叫一次，避免重複連線。

**建議**：將 `connect()` 呼叫放在 `ref.read`（非 `watch`），並加 `if (service.connectionState == WsConnectionState.disconnected)` 守護判斷。或者，考慮由 `webSocketServiceProvider` 在建立時自動連線（在 provider 的 body 中呼叫）。

**最終決策**：`connect()` 由 provider 建立時自動呼叫（在 `WebSocketServiceProvider` 的 `keepAlive` 處理），App 層不需要手動呼叫。此決策留待 Phase 2/3 測試設計時確認。

### 9.3 ref.listen 的正確使用位置

`ref.listen` 必須在 `build` 方法內呼叫（Riverpod 規定），不可在 `initState` 或其他地方。`DashboardPage` 因此使用 `ConsumerStatefulWidget`，在 `_DashboardPageState.build` 中呼叫 `ref.listen`。

### 9.4 不引入 DashboardNotifier

Dashboard 本身不需要獨立的 Notifier，原因：
- sidebar 選取狀態已由 `SessionListNotifier` 管理（`selectedSessionId`）
- 對話狀態已由 `ConversationNotifier` 管理
- Dashboard 只做「組裝」，透過 `ref.listen` 橋接兩者即可
- 增加 DashboardNotifier 會增加不必要的間接層和複雜度
