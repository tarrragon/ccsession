## 2. 資料結構選擇

### 2.1 Widget 選擇

| 元件 | 型別 | 理由 |
|------|------|------|
| DashboardPage | ConsumerStatefulWidget | 需要在 build 中呼叫 `ref.listen`（Riverpod 規定） |
| _MainArea | ConsumerWidget | 只監聽 selectedSessionIdProvider，無狀態變更 |
| ConnectionStatusBar | ConsumerWidget | 只監聽 connectionStateProvider |
| _EmptySelectionPlaceholder | StatelessWidget | 純 UI，無依賴 |
| App | ConsumerWidget | 需要讀取 webSocketServiceProvider 觸發連線 |

### 2.2 狀態管理

| Provider | 來源 | 消費 | 職責 |
|----------|------|------|------|
| sessionListNotifierProvider | SessionListNotifier | SessionListPage、DashboardPage（ref.listen） | 管理 session 列表和選取狀態 |
| selectedSessionIdProvider | sessionListNotifier.selectedSessionId | _MainArea、DashboardPage（ref.listen） | 衍生 provider，暴露選取 ID |
| conversationNotifierProvider | ConversationNotifier | ConversationView、DashboardPage（ref.listen） | 管理對話狀態 |
| connectionStateProvider | webSocketServiceProvider | ConnectionStatusBar | WebSocket 連線狀態 stream |
| webSocketServiceProvider | WebSocketService 單例 | App、其他 notifier | WebSocket 連線和訊息 |

### 2.3 狀態流通

```
使用者點擊 session
    ↓
SessionListNotifier.selectSession(id)
    → state.selectedSessionId = id
    ↓
selectedSessionIdProvider 自動更新（衍生 provider）
    ↓
DashboardPage.ref.listen 觸發
    → next != previous && next != null
    ↓
ConversationNotifier.loadSession(id)
    → 取消前 session 訂閱
    → 重置 state（events=[], isLoadingHistory=true）
    → 發送 get_session_history + subscribe_session
    ↓
ConversationNotifier state 更新
    ↓
_MainArea.ref.watch 偵測變更
    → 因為 selectedSessionId 已非 null
    → 渲染 ConversationView
```

### 2.4 特殊處理

**ref.listen 語義**：
- Riverpod 的 `ref.listen<T>(provider, (previous, next) { ... })` 會在每次 provider 值變更時呼叫 callback
- 內建去重機制：相同值（按 `==` 比較）不觸發
- 必須在 `build` 方法中呼叫，不可在 `initState`

**ConsumerStatefulWidget 用法**：
```
class DashboardPage extends ConsumerStatefulWidget {
  @override
  ConsumerState<DashboardPage> createState() => _DashboardPageState();
}

class _DashboardPageState extends ConsumerState<DashboardPage> {
  @override
  Widget build(BuildContext context, WidgetRef ref) {
    // ref.listen 必須在此呼叫
    ref.listen<String?>(selectedSessionIdProvider, (prev, next) {
      if (next != null && next != prev) {
        ref.read(conversationNotifierProvider.notifier).loadSession(next);
      }
    });

    return Scaffold(...);
  }
}
```

## 7. 語言特定實作注意事項

### 7.1 Dart/Flutter 考量

**Riverpod 生命週期**：
- `ConsumerStatefulWidget` 的 `build` 會在 provider 變更時重新執行
- `ref.listen` 每次 build 都會執行，但 Riverpod 內建去重機制，不會重複訂閱
- `ref.watch` 會重新構建 widget，`ref.read` 不會
- 選擇 `ref.listen` 而非 `ref.watch(selectedSessionIdProvider).whenData(...)` 的理由：
  - `ref.listen` 適合副作用（調用 loadSession）
  - `ref.watch` 適合依賴 provider 值進行渲染

**AsyncValue 處理**：
- `connectionStateProvider` 返回 `Stream<WsConnectionState>`，被 Riverpod 包裝為 `AsyncValue<WsConnectionState>`
- 使用 `valueOrNull ?? defaultValue` 取得值（避免 null coalescing 引起的 null safety 問題）

**Equatable 相等性**：
- `SessionListState` 使用 `Equatable` mixin，`copyWith` 產生新物件
- `selectedSessionId` 變更時，provider 會通知訂閱者（相等性檢查由 Equatable 保證）

**Package 導入**：
- 所有導入使用 `package:ccsession/...` 格式（全專案統一規範）
- 禁止相對路徑導入（package import methodology）

### 7.2 效能最佳化建議

**rebuild 最小化**：
- ConnectionStatusBar 和 SessionListPage 各自獨立 ConsumerWidget，無交叉依賴
- _MainArea 只監聽 selectedSessionIdProvider，變更時才重建（不監聽 connectionStateProvider）
- DashboardPage 監聽 selectedSessionIdProvider 僅用於副作用（ref.listen），不影響佈局重建

**provider 去重**：
- Riverpod 內建 `==` 去重，無需手動判斷
- 確保 `SessionListState` 的 `Equatable` 實作正確，`selectedSessionId` 變更時 provider 值才會改變

**避免過度 watch**：
- 不在 DashboardPage 中 `watch(connectionStateProvider)`，只在 ConnectionStatusBar 監聽
- 遵循「單一職責」：DashboardPage 只負責佈局和 selectedSessionId 橋接

### 7.3 可能的技術挑戰

| 挑戰 | 可能原因 | 解決方案 |
|------|---------|---------|
| ref.listen 不觸發 | build 不執行 / listener 邏輯有誤 | 檢查 `next != previous && next != null` 條件 |
| loadSession 重複呼叫 | listener 在每次 build 時重新訂閱 | Riverpod 自動去重，不應發生；若發生檢查 state 邏輯 |
| _MainArea 沒有切換 ConversationView | selectedSessionId 仍為 null | 檢查 SessionListNotifier.selectSession 是否被呼叫 |
| ConnectionStatusBar 顏色錯誤 | 狀態映射邏輯反轉 | 驗證 _colorForState() 映射表 |
| ProviderNotFoundException | ProviderScope 缺少 override | 確認 main.dart 加入 ProviderScope(child: App()) |
| await tester.pumpAndSettle() 超時 | 非同步操作未完成 | Fake Notifier 的 loadSession 應為 async 但立即完成 |
